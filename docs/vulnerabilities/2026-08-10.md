### 1.3 今日重点关注

1. **`CVE-2026-6637`：PostgreSQL refint 模块栈缓冲区溢出与 SQL 注入（CVSS 8.8）**  
   影响 PostgreSQL 14–18 全部受支持分支。未授权数据库用户可利用 refint 模块的栈缓冲区溢出，**以数据库运行 OS 用户身份执行任意代码**；另一攻击路径可在应用将用户可控列声明为 refint 级联主键时触发 SQL 注入。当前状态为 **无公开 PoC、无在野利用、官方补丁已发布**，建议尽快升级。

2. **`CVE-2026-6473`：PostgreSQL 整数回绕导致越界写（CVSS 8.8）**  
   影响 PostgreSQL 14–18。多个服务器特性存在整数回绕，攻击者可使服务器分配不足并越界写入，可能以数据库 OS 用户身份执行任意代码或导致段错误；应用向相关函数传入 GB 级输入时即可触发。

3. **`CVE-2026-6477`：PostgreSQL libpq `lo_*` 函数客户端栈内存覆盖（CVSS 8.8）**  
   影响 PostgreSQL 14–18 的 libpq 客户端。libpq 的 `lo_export()`/`lo_read()`/`lo_lseek64()`/`lo_tell64()` 使用类似 `gets()` 的危险函数，**恶意或被攻破的数据库服务器可覆盖 psql、pg_dump 等客户端工具的栈内存**，威胁 DBA 运维终端安全。

本期漏洞集中于 PostgreSQL 官方 2026-05-14 安全更新批次（HKCERT 2026-08-10 中文公告），影响 PostgreSQL 14–18 全部受支持分支，其中 6 个高危、4 个 CVSS 8.8，部分漏洞可使未授权数据库用户以数据库 OS 用户身份执行任意代码，或使恶意数据库服务器反制 DBA 客户端工具。PostgreSQL 是互联网与企业环境部署最广泛的数据库之一，升级覆盖范围大；但当前**无公开 PoC、无已确认在野利用**，HKCERT 评定为"中度风险"，故本期情报等级定为"重要"而非"紧急"。数据库属关键信息基础设施组件，建议按 P1 时限（3 个工作日内）完成版本升级或部署临时缓解。

### 3.1 CVE-2026-6637 — PostgreSQL refint 模块栈缓冲区溢出与 SQL 注入（RCE）

!!! danger "高危漏洞"

#### 3.1.2 漏洞摘要

该漏洞存在于 PostgreSQL contrib 模块 **refint**（外键完整性触发器模块）。refint 模块在处理特定输入时存在栈缓冲区溢出，**未授权数据库用户**（仅需具备普通数据库连接权限）即可触发，进而以数据库运行时的操作系统用户身份执行任意代码——这是数据库服务向操作系统层面的权限跨越。

独立的第二条攻击路径为 SQL 注入：若应用程序将用户可控的列声明为 refint 级联主键（cascade primary key）并允许用户控制该列的主键更新值，则主键更新值的提供者可执行任意 SQL，且以执行该主键更新的数据库用户身份生效。该漏洞由 PostgreSQL 项目感谢 Nikolay Samokhvalov 报告。

> 漏洞影响 PostgreSQL 14–18 全部受支持分支，属于官方 2026-05-14 安全更新批次修复的 11 个漏洞之一。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需可连接 PostgreSQL 服务（默认 5432 端口） |
| 身份认证 | 普通用户 | 需具备普通数据库用户权限（PR:L），无需超级用户 |
| 用户交互 | 不需要 | 栈溢出路径无需交互；SQL 注入路径依赖应用侧设计 |
| 特定配置 | 是 | refint 模块需被使用（contrib 触发器）；SQLi 路径需应用声明 refint 级联主键 |
| 利用复杂度 | 低 | NVD 向量 AC:L |

**技术原理：**

refint 模块为外键完整性触发器实现，在处理触发参数与约束检查时对输入长度与栈缓冲区的边界检查不足，攻击者可构造特定输入使数据写入超出栈缓冲区边界，覆盖返回地址等关键栈数据，最终实现以数据库进程（OS 用户）身份执行任意代码。SQL 注入路径则是由于 refint 级联主键更新场景中对列名/值的拼接缺乏参数化处理。

**核心利用链：**

```text
攻击者（普通数据库用户）
  └─ 连接暴露的 PostgreSQL 服务（5432）
      └─ 调用触发 refint 触发器函数的恶意 SQL
          └─ 触发栈缓冲区溢出（越界写入栈数据）
              └─ 劫持控制流 / 覆盖关键栈数据
                  └─ 以数据库 OS 用户身份执行任意代码
```

### 3.2 CVE-2026-6473 — PostgreSQL 整数回绕导致分配不足与越界写（RCE/DoS）

!!! danger "高危漏洞"
    影响 PostgreSQL 14–18：多个服务器特性存在整数回绕，攻击者可令服务器分配不足并越界写入，可能以数据库运行 OS 用户身份执行任意代码；应用向相关数据库函数传入 GB 级输入时即可触发段错误。

#### 3.2.2 漏洞摘要

该漏洞存在于 PostgreSQL 服务器的**多个特性**中：对涉及大尺寸输入的内存分配计算存在**整数回绕（integer wraparound）**，导致服务器为数据分配的内存不足（undersize allocation），随后写入超出分配边界（out-of-bounds write）。未授权数据库用户可借此使服务器发生段错误（DoS），或进一步**以数据库运行 OS 用户身份执行任意代码**（NVD 描述明确"may execute arbitrary code as the operating system user running the database"）。

触发条件为应用向相关数据库函数传入**GB 级（gigabyte-scale）用户输入**，输入提供者即可触发。该漏洞由 PostgreSQL 项目感谢 Anemone、A1ex、Xint Code、Jihe Wang、Jingzhou Fu、Pavel Kohout、Petr Simecek、www.aisle.com、Bruce Dang（Calif.io）、Sven Klemm 等报告。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需可连接 PostgreSQL 服务（默认 5432 端口） |
| 身份认证 | 普通用户 | 需具备普通数据库用户权限（PR:L） |
| 用户交互 | 不需要 | 全程无用户参与 |
| 特定配置 | 是 | 需应用向相关数据库函数传入 GB 级输入（如大批量数据操作） |
| 利用复杂度 | 低 | NVD 向量 AC:L |

**技术原理：**

PostgreSQL 多个服务器特性在计算内存分配大小时使用固定宽度整数，当输入尺寸达到 GB 级时乘法/加法运算发生整数回绕，得到小于实际需要的内存分配量（undersize allocation）；后续数据写入时超出分配边界（OOB write），轻则触发段错误导致服务崩溃，重则破坏堆元数据、劫持控制流，以数据库进程（OS 用户）身份执行任意代码。由于分配尺寸由攻击者可控输入推导，利用条件可被主动构造。

**核心利用链：**

```text
攻击者（普通数据库用户）
  └─ 向相关数据库函数传入 GB 级恶意输入
      └─ 服务器整数回绕 → 分配不足（undersize allocation）
          └─ 数据写入越界（out-of-bounds write）
              └─ 触发段错误（DoS）或劫持控制流
                  └─ 以数据库 OS 用户身份执行任意代码
```

#### 3.3.2 漏洞摘要

该漏洞位于 PostgreSQL 官方客户端库 **libpq** 的大对象（large object）函数中。libpq 的 `lo_export()`、`lo_read()`、`lo_lseek64()`、`lo_tell64()` 内部调用了固有危险的函数 `PQfn(..., result_is_int=0, ...)`——该函数与 `gets()` 类似，会把**服务器决定的任意长度数据**写入大小未指定的客户端缓冲区，从而覆盖客户端栈内存。

攻击场景具有"反向"特征：**恶意或被攻破的 PostgreSQL 服务器超级用户**可以构造响应，覆盖连接该服务器的客户端工具（psql、pg_dump）的栈内存。由于 psql 的 `\lo_export` 命令与 pg_dump 都会调用 `lo_read()`，DBA 在备份、导出大对象时即可能触发，进而在 **DBA 运维终端**上执行任意代码。该漏洞由 PostgreSQL 项目感谢 Yu Kunpeng 与 Martin Heistermann 报告。

| 条件 | 状态 | 说明 |

**技术原理：**

**核心利用链：**

```text
恶意/被攻破的 PostgreSQL 服务器（超级用户）
  └─ 诱使 DBA 使用 psql/pg_dump 连接（\lo_export、备份等常规操作）
      └─ 服务器返回任意长度的超大响应
          └─ PQfn(result_is_int=0) 写入未检查大小的客户端缓冲区
              └─ 覆盖 psql/pg_dump 客户端栈内存
                  └─ 在 DBA 运维终端执行任意代码
```

### 3.5 CVE-2026-6476 — PostgreSQL pg_createsubscriber 订阅名 SQL 注入提权

!!! danger "高危漏洞"
    影响 PostgreSQL 17–18：拥有 `pg_create_subscription` 权限的攻击者可利用 `pg_createsubscriber` 工具对订阅名的 SQL 注入，在工具下次运行时以超级用户身份执行任意 SQL，实现权限提升。

#### 3.5.2 漏洞摘要

该漏洞位于 PostgreSQL 逻辑复制辅助工具 **`pg_createsubscriber`** 中。攻击者若拥有 **`pg_create_subscription`** 权限，可在创建订阅时构造恶意的**订阅名称**，注入 SQL 载荷。由于 `pg_createsubscriber` 以**超级用户**身份处理订阅信息，注入的 SQL 会在工具**下次运行**时以超级用户权限执行，形成从低权限数据库用户到超级用户的权限提升。该漏洞影响 PostgreSQL 17 与 18 两个主版本（16 及更早不受影响），由 PostgreSQL 项目感谢 Yu Kunpeng 报告。

#### 3.5.3 影响产品与版本

| 厂商 | 产品/组件 | 受影响版本 | 修复版本 | 部署形态 |

!!! warning "版本说明"
    版本范围以 [PostgreSQL 官方安全公告 CVE-2026-6476](https://www.postgresql.org/support/security/CVE-2026-6476/) 为准：仅 17、18 受影响；PostgreSQL 16 及更早不受影响。

#### 3.5.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需可连接 PostgreSQL 服务 |
| 身份认证 | 普通用户 | 需拥有 `pg_create_subscription` 权限（PR:H，需数据库管理员授予） |
| 用户交互 | 不需要 | 无需交互，但攻击在 pg_createsubscriber 下次运行时生效 |
| 特定配置 | 是 | 需使用逻辑复制并运行 pg_createsubscriber；需具备 pg_create_subscription 权限 |
| 利用复杂度 | 低 | NVD 向量 AC:L |

**技术原理：**

`pg_createsubscriber` 在将订阅信息写入配置或执行复制初始化 SQL 时，对**订阅名称**的拼接缺乏参数化处理。攻击者在 `CREATE SUBSCRIPTION` 时把 SQL 载荷放入订阅名，工具以超级用户身份执行该载荷，实现权限提升。注入执行时机为工具下次运行（如后续复制维护操作）时。

**核心利用链：**

```text
攻击者（具备 pg_create_subscription 权限）
  └─ 创建订阅，订阅名中嵌入 SQL 注入载荷
      └─ 管理员/运维下次运行 pg_createsubscriber
          └─ 工具以超级用户身份拼接并执行订阅名
              └─ 注入 SQL 以超级用户权限执行
                  └─ 创建超级用户账号 / 读取全部数据 / 持久化后门
```

### 3.6 CVE-2026-6479 — PostgreSQL SSL/GSS 协商不受控递归 DoS

!!! danger "高危漏洞"
    影响 PostgreSQL 14–18：SSL 与 GSS 协商过程存在不受控递归（uncontrolled recursion），能连接 PostgreSQL AF_UNIX 套接字的攻击者可造成持续性拒绝服务；若 SSL 与 GSS 均被禁用，攻击者经 TCP 套接字亦可触发。

#### 3.6.2 漏洞摘要

该漏洞存在于 PostgreSQL 服务器的 **SSL 与 GSS（Kerberos）协商初始化**流程中：相关处理逻辑存在**不受控递归（uncontrolled recursion）**，攻击者在特定条件下可使服务器陷入深度递归，造成**持续的拒绝服务**。

触发条件：攻击者若能连接 PostgreSQL 的 **AF_UNIX 套接字**即可触发；若服务器同时禁用 SSL 与 GSS，则攻击者经 **TCP 套接字**亦可触发。该漏洞无需身份认证（PR:N）、无用户交互，可用于瘫痪数据库服务可用性。由 PostgreSQL 项目感谢 Calif.io 与 Claude/Anthropic Research 合作报告。

#### 3.6.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需可连接 PostgreSQL（AF_UNIX 或 TCP） |
| 身份认证 | 无需 | 协商阶段即可触发（PR:N） |
| 用户交互 | 不需要 | 全程无用户参与 |
| 特定配置 | 是 | TCP 场景需 SSL 与 GSS 均禁用；AF_UNIX 场景无此限制 |
| 利用复杂度 | 低 | NVD 向量 AC:L |

**技术原理：**

SSL/GSS 协商初始化函数在处理特定的协商状态与输入序列时存在递归调用路径，递归深度不受控制（uncontrolled recursion）。攻击者构造特定的协商握手序列，使服务器在处理连接时不断递归直至资源耗尽（栈溢出/超时），导致连接处理线程崩溃或长时间不可用，形成持续性拒绝服务。

**核心利用链：**

```text
攻击者
  └─ 连接 PostgreSQL（AF_UNIX；或 SSL/GSS 禁用时的 TCP）
      └─ 构造特定 SSL/GSS 协商握手序列
          └─ 触发不受控递归（协商初始化逻辑）
              └─ 资源耗尽 / 处理线程崩溃
                  └─ 数据库服务不可用（DoS）
```

## 五、当日处置建议

1. **PostgreSQL 全线升级（P1，3 个工作日内）**：将 PostgreSQL 升级至 `18.4` / `17.10` / `16.14` / `15.18` / `14.23`（2026-05-14 官方发布，修复 11 个安全漏洞与 60+ 缺陷）；高价值生产库与公网暴露实例优先。
2. **同步升级客户端与运维工具**：`CVE-2026-6477` 影响 libpq/psql/pg_dump 客户端（恶意服务器可反制 DBA 终端），`CVE-2026-6475` 影响 pg_basebackup/pg_rewind，客户端工具须与服务器同步升级。
3. **收敛数据库暴露面**：限制 5432 端口仅允许应用网段访问；AF_UNIX 套接字实施权限控制；收紧 `pg_create_subscription`、schema 创建等敏感权限授予。
4. **口令策略核查**：`CVE-2026-6478` 提示将存量 MD5 口令迁移至 scram-sha-256（默认方式），优先处置从 PostgreSQL 13 及更早升级的实例。
5. **持续关注事件动态**：Framework 数据泄露（Metabase 零日关联）与 Oracle 数据库跳板事件提示，数据库与 BI 平台类资产应纳入高优先级监控；Webmail CSS 研究提示邮件类 AI 工具接入需评估数据操纵风险。
6. 对疑似遭受攻击的系统保留日志、流量、进程、文件及内存证据；完成修复后进行复测，并更新资产台账和漏洞处置记录。
