### 1.3 今日重点关注

1. **`CVE-2026-102764`：BeyondTrust Remote Support 内部组件未校验消息来源致文件操作（9.3，KEV，EPSS 20.3%）**  
   BeyondTrust Remote Support 的内部组件**未充分校验所接收消息的来源**（`CWE-290`），在特定条件下攻击者可对设备执行文件操作。该编号已被 CISA 收录进 KEV（期限 10-19），EPSS 20.3%。BeyondTrust 是特权访问管理（PAM）领域的核心产品，其 Remote Support 常被用于对边界设备与服务器做带外运维，**往往具备到内网纵深的高权限通道**；一旦被用于写入文件，攻击者可植入后门或替换组件，而不必直接拿到 shell。PAM 产品被列入 KEV，本身就说明“攻击者的目标已经转向凭据与运维通道”。

2. **`CVE-2026-92262`：MariaDB `#mysql50#` 前缀绕过表名编码：可致数据泄露与 RCE（9.9）**  
   MariaDB 10.6.1 至各分支修复版本之前，`#mysql50#` 保留前缀可**绕过正常的表名文件系统编码**。攻击者先用该前缀创建表名，再用该表名访问其“未编码旧名”对应的文件，从而造成崩溃、数据损坏、**数据外泄甚至远程代码执行**。CVSS 9.9（`CWE-706` 使用错误解决方案）。同批的 `CVE-2026-85746`（9.9）则是 `ST_AsText` 在序列化深层嵌套 GeometryCollection 时**递归计算不足导致输出缓冲区越界写**，低权限远程攻击者提交特制 GIS 对象即可破坏内存。**数据库层的两条 9.9 同时出现，且都要求“先有账号”，对企业内网的横向移动意义重大。**

3. **`CVE-2026-111283`：BMC Helix Network Management：配置 SAML 后任意口令即可登录本地管理员（9.5）**  
   BMC Helix Network Management on-prem 26.3.00（<26.3.01）在**配置了 SAML 单点登录**的情况下，未认证攻击者在 Web 登录页提交管理员用户名 + **任意口令**即可获得 SuperAdmin 会话，进而修改设备凭据、执行设备命令、篡改审计记录。这是“SAML 分支走错”的典型——安全控制被“为了兼容 SSO 而跳过本地校验”这一逻辑反转。网络管理平台掌握全网设备凭据，**被拿下等于拿到整网设备的配置权**。

4. **`CVE-2026-108709`：Apache Kylin 三条 9.8：认证绕过 ×2 + 反序列化**  
   Kylin 4.0.4–5.0.4（部分条目为 4–5.0.4）同时存在：`CVE-2026-108709` 内网场景认证绕过、`CVE-2026-68573` 未认证用户可访问系统清理动作、`CVE-2026-64610` 因外部缓存服务损坏导致的**不安全 Java 反序列化**（可致 RCE）。官方说明“主要影响直接暴露公网的 Kylin 服务，纯内网部署大多不受影响”，但这恰恰提示：**问题的关键在于暴露面而非部署位置**，只要 Kylin 有任何一个入口可从办公网或 DMZ 触达，风险即成立。修复版本统一为 5.0.5。

### 1.4 综合研判

本期 544 条，严重 62 条（11.4%）、高危 219 条（40.3%）。结构上可分三层看。**第一层是“运维与凭据通道”**：BeyondTrust Remote Support（KEV、EPSS 20.3%）与 BMC Helix Network Management（SAML 配置后任意口令登管理员）——两者都是“管理管理者的系统”，失陷后攻击者不需要再找漏洞，直接用合法凭据操作全网设备。**第二层是数据底座**：MariaDB 两条 9.9（表名编码绕过、GIS 越界写），加上 Apache Kylin 的反序列化与两条认证绕过，构成“数据库 → 数据平台”的连续风险面；这类组件的共同点是**补丁窗口长、重启成本高**，因此更容易被长期利用。**第三层是庞大的 Web 生态长尾**：WordPress 插件/主题的任意文件上传、权限提升与对象注入（`CVE-2026-94169`、`CVE-2026-89079`、`CVE-2026-103768`、`CVE-2026-104798` 等，多条被 Nuclei 覆盖），以及 Chrome 的沙箱外代码执行（`CVE-2026-110916`，9.6，Chromium 自评 Medium 但向量为“沙箱外任意代码执行”）、WEINVIEW EBPro 的缓冲区溢出（`CVE-2026-26846`，9.8，工控 HMI 组态软件）、RIOT OS 的越界读（9.8，IoT 操作系统）。KEV 侧除 BeyondTrust 外还有 Fortinet 历史编号补录，两条期限均为 10-19；与上期 10-16 到期的 Ivanti、Windows 形成“连续到期”的节奏。整体判断：本期**没有“披露即武器化”的爆点，但存在两条“高 EPSS + KEV”的确定性威胁**，且都落在管理平面上，处置价值高于同分的应用层漏洞。

!!! danger "研判结论：较高风险"
    本期风险集中在“**管理平面**”：BeyondTrust Remote Support 已确认在野（KEV + EPSS 20.3%），BMC Helix 的 SAML 分支可被任意口令绕过。两者失陷的后果不是单机而是全网设备控制权。建议：① 在 10-19 前完成 BeyondTrust 补丁与文件完整性核查（PAM 设备被写入文件必须视为失陷）；② 检查 BMC Helix 是否启用 SAML，若启用则立即升级至 26.3.01；③ MariaDB 与 Kylin 按维护窗口安排升级（重启成本高，需提前排期）；④ WordPress 与工控 HMI 分别按批量作业与专项核查处理。

#### 3.1.2 漏洞摘要

BeyondTrust Remote Support 的内部组件**未能充分验证所接收消息的来源**（`CWE-290` 使用欺骗绕过认证），在特定条件下可允许攻击者**对设备执行文件操作**。CVSS 9.3，已被 CISA 收录进 KEV（2026-10-16 收录，期限 2026-10-19），EPSS 20.3%——本窗口最高。BeyondTrust 属特权访问管理（PAM）产品线，Remote Support 常被用于对边界设备、服务器与网络设备做带外运维，**其自身往往持有到内网纵深的高权限通道与凭据库**。因此“文件操作”这一看似有限的后果，实际可能意味着：替换组件二进制、写入计划任务、篡改审计日志，甚至读取配置中的会话密钥。PAM 设备进入 KEV 是一个值得警惕的信号——**攻击者的目标正从“边界应用”转向“管理边界应用的那一层”**，因为拿下这一层后，后续所有横向动作都使用合法凭据，难以被检测。 需补充：编制时可回溯看到 GitHub 上已有 3 个围绕该编号的仓库（检测脚本与复现工具，创建于 10-21 至 10-23），虽晚于本报告日期，但说明该漏洞的公开验证工具在收录 KEV 后 3–5 天内即出现，**处置窗口应按“周”而非“月”计算**。

> 原文摘要（NVD）：The vulnerability exists within internal components of BeyondTrust’s Remote Support product. The components did not adequately validate the origin of the messages it received. Under the right conditions, this could allow an attacker to perform file operations on the appliance.

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 设备管理面与内部组件通信通道 |
| 身份认证 | 无需 | 无需任何凭据即可触发 |
| 用户交互 | 不需要 | 无需受害者交互 |
| 特定配置 | 否 | 受影响版本默认存在；无需特殊配置 |
| 利用复杂度 | 低 | 中（需到达内部组件通信位置） |

**技术原理：**

设备内部各组件之间通常通过消息总线或内部 RPC 通信，并假定“内网消息可信”。当组件不校验消息发送方身份（例如不验证签名、不检查来源地址、不校验消息序号）时，攻击者一旦能在设备上或相邻网络位置注入消息，即可伪装成内部组件，调用文件写入类接口。`CWE-290` 的本质是“用可伪造的标识代替密码学证明”。这类缺陷的利用前提通常是“已在设备可达的位置”，因此常见于“先拿下低权限组件 → 再横向到内部组件”的多段攻击。

**核心利用链：**

```text
攻击者
  └─ 定位暴露的 remote_support（beyondtrust）
      └─ 直接访问受保护接口或伪造身份
          └─ 触发 CWE-290 对应处理逻辑
              └─ 绕过认证获得未授权能力
                  └─ 横向利用或持久化（视环境）
```

#### 3.2.2 漏洞摘要

MariaDB 自 10.6.1 起至各分支修复版本（10.6.28、10.11.19、11.4.13、11.8.9、12.3.3、13.0.2）存在 `#mysql50#` 前缀绕过问题（`CWE-706` 使用错误解决方案）。`#mysql50#` 是 MySQL 5.0 时代的保留前缀，用于表示“表名未经文件系统编码”。当服务端允许用户以该前缀创建表名时，**后续访问会绕过正常编码逻辑，直接映射到“旧名”对应的文件**。攻击者可借此读取其他表甚至非数据库文件的底层路径，造成崩溃、数据损坏、**数据外泄，并在特定条件下达成远程代码执行**。CVSS 9.9。同批的 `CVE-2026-85746`（9.9，`CWE-787`）是 `ST_AsText` 在递归序列化深层嵌套 GeometryCollection 时，**未累计已消耗字节、未预留足够空间**，导致输出缓冲区越界写；低权限远程攻击者提交特制 GIS 对象即可破坏内存，与另一漏洞组合可提权至代码执行。两条缺陷的共同点是**都要求一个数据库账号**，因此它们对“内网横向移动”的价值远高于对外部攻击者的价值——攻击者先用弱口令或应用漏洞拿到一个低权限库账号，再用这两条扩大战果。

> 原文摘要（NVD）：MariaDB server is a community developed fork of MySQL server. From 10.6.1 until 10.6.28, 10.11.19, 11.4.13, 11.8.9, 12.3.3, and 13.0.2, the #mysql50# bypass prefix is affected because it allows the #mysql50# prefix to bypass normal table-name filesystem encoding. An attacker can trigger the issue with a table name using the #mysql50# prefix, then use a #mysql50# table name to access files under their legacy unencoded name and cause crashes, data corruption, data exfiltration, or remote code execution. This issue is fixed in versions 10.6.28, 10.11.19, 11.4.13, 11.8.9, 12.3.3, and 13.0.2.


## 五、当日处置建议

1. **PAM 设备按“可能已被写入”处置**：BeyondTrust 的漏洞后果是文件操作，这类设备上任何非预期文件都应视为后门。建议升级前后各做一次完整性校验，并轮换被托管的凭据。
2. **检查 NMS 是否启用 SAML**：BMC Helix 的绕过只在启用 SAML 时成立，而这恰好是“以为更安全”的配置。建议对全部“本地+SAML 双认证”的系统做一次逻辑验证：本地账号在 SAML 启用后是否仍校口令。
3. **数据库升级要排期，但账号权限可立刻收紧**：MariaDB 两条 9.9 都需先有账号，因此短期最有效的缓解是收紧账号权限（禁止业务账号建表、禁 FILE 权限）与拦截 `#mysql50#` 语句。
4. **大数据平台的“内网假设”需要重新评估**：Kylin 官方称内网部署大多不受影响，但办公网可达同样是风险。建议以“谁能连到这个端口”为口径重新定义暴露面，而非以“是否公网”划分。
5. **工控组态软件单独建账**：WEINVIEW EBPro 的缓冲区溢出（9.8）说明 HMI 组态软件仍在产生高危缺陷。这类软件通常装在工程师站，**与生产网直连**，应纳入 OT 资产台账并限制其网络位置。
6. **留意“披露即带 PoC”的本地类漏洞**：DeepSeek Harness 的 `CWE-426` 需要本地文件替换，远程不可直接用，但若攻击者已能写入用户目录（如经其他漏洞或钓鱼），它就成为可靠的持久化手段。
