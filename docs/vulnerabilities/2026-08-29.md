#### 3.1.2 漏洞摘要

该漏洞存在于 Nacos 3.x 的用户/角色/权限管理接口（`UserControllerV3` / `RoleControllerV3` / `PermissionControllerV3`）中。根因是 `createUser` 等接口的 `@Secured` 鉴权注解缺少 `apiType` 参数：注解默认值为 `ApiType.OPEN_API`，请求因此被分流至 OPEN_API 鉴权作用域，而该作用域的鉴权开关 `nacos.core.auth.enabled` **默认关闭**，鉴权过滤器直接放行；同时控制台鉴权过滤器（`NacosConsoleAuthFilter`）的扫描范围仅覆盖 console 模块，无法覆盖 auth-plugin 模块的 V3 控制器。双重缺陷导致用户/角色/权限三类 V3 管理接口完全无鉴权，任何匿名请求均可直达业务逻辑。

攻击者可利用该缺陷在未授权状态下：① 创建任意用户名账户；② 创建角色并绑定该用户；③ 授予全资源读写权限（`namespace:group:dataId = *:*:*`），最终获得具备管理员操作权限的账号，或通过 `createAdminUser` 接口（无任何鉴权注解，仅校验"系统是否已存在 admin 角色"）在全新部署上直接创建管理员。成功利用后可窃取所有微服务配置（数据库连接字符串、API 密钥等）、修改配置导致业务中断、创建后门账户实现持久化，并利用获取的凭证横向移动至企业内网其他系统。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 Nacos Server API（默认 `8848`，含 context path `/nacos`）或控制台（`8080`） |
| 身份认证 | 无需 | 完全匿名，无需任何已有凭据 |
| 用户交互 | 不需要 | 无交互要求 |
| 特定配置 | 否 | 默认配置即受影响（OPEN_API 鉴权开关默认关闭） |
| 利用复杂度 | 低 | 三步标准 API 调用即可完成管理员账号创建 |

**技术原理：**

Nacos 3.x 按 `@Secured` 注解的 `apiType` 属性将请求分流至不同鉴权过滤器：`OPEN_API` → `AuthFilter`（开关 `nacos.core.auth.enabled`，**默认 false**）；`ADMIN_API` → `AuthAdminFilter`（默认 true）；`CONSOLE_API` → `NacosConsoleAuthFilter`（默认 true）。`UserControllerV3.createUser()` 等 V3 管理接口的 `@Secured` 注解缺少 `apiType` 参数，回退到默认值 `OPEN_API`，落入默认关闭鉴权的过滤器分支；且 `NacosConsoleAuthFilter` 的方法缓存仅扫描 `com.alibaba.nacos.console.controller` 包，扫不到 auth-plugin 模块的控制器，控制台过滤器亦无法兜底。最终用户/角色/权限三类 V3 管理接口完全无鉴权，匿名请求直达业务逻辑（本质为访问控制作用域错配，对应 CWE-863）。

**核心利用链：**

```text
攻击者
  └─ 发现可达的 Nacos Server API（8848/nacos 或 8080 控制台）
      └─ 前置检测：匿名 GET /v3/auth/user/list（确认 3.x 漏洞面存在）
          └─ POST /v3/auth/user        匿名创建任意用户
              └─ POST /v3/auth/role    创建角色并绑定该用户
                  └─ POST /v3/auth/permission  授予全资源读写（*:*:*）
                      └─ 获得管理员权限账号，完全接管 Nacos 服务端
                          └─ 窃取全部微服务配置（DB 连接串、API 密钥等）
                              └─ 创建后门账户持久化、修改配置致业务中断、横向移动
```

#### 3.1.11 风险影响

- 供应链风险：Nacos 作为配置中心被控后，可向全部接入微服务下发恶意配置。
