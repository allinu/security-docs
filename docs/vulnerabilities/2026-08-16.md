### 3.1 CVE-2026-58231 — SAP Commerce Cloud Data Hub Adapter 未授权远程代码执行漏洞（在野利用）

!!! danger "严重漏洞"

#### 3.1.2 漏洞摘要

该漏洞存在于 SAP Commerce Cloud（原 Hybris）的 **Data Hub Adapter** 组件，影响 COM_CLOUD 2211 与 2211-JDK21 版本线。适配器的数据导入端点 `/datahubadapter/import/**` 在接收数据时未正确校验调用方身份，未认证远程攻击者可直接访问该端点并提交精心构造的数据，适配器会将其作为可信输入处理，最终可能导致任意代码执行，并进一步危害与 Commerce Cloud 集成的内部组件。

SAP 官方描述为：未认证攻击者可滥用默认认证客户端，向缺乏充分校验的特定函数提交特制输入，成功利用可造成任意代码执行，对应用的机密性、完整性与可用性产生高影响。此前多个 SAP 关键漏洞曾被中国背景 APT（UNC5221、UNC5174）及勒索软件团伙利用，本次利用者身份尚不明确。

> 该漏洞为授权检查不足（Improper Authorization）叠加输入验证缺失的典型组合：端点本身缺少身份校验，输入数据又缺少消毒处理，二者叠加形成未认证 RCE。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可访问 Data Hub Adapter 导入端点（`/datahubadapter/import/**`） |
| 身份认证 | 无需 | 未认证即可访问，可滥用默认认证客户端 |
| 用户交互 | 不需要 | 无需点击链接或打开文件 |
| 特定配置 | 是 | 使用默认认证客户端的 Commerce Cloud 环境受影响 |
| 利用复杂度 | 低 | 构造特制请求即可，无需前置条件 |

**技术原理：**

Data Hub Adapter 的导入端点缺少对调用方身份的充分授权校验（CWE-284 相关），同时提交的数据缺乏输入验证与消毒（CWE-94 相关），导致攻击者提交的恶意数据被当作可信输入处理，触发任意代码执行。

**核心利用链：**

```text
攻击者
  └─ 发现暴露的 Data Hub Adapter 导入端点 /datahubadapter/import/**
      └─ 构造恶意导入数据（无需身份认证）
          └─ 滥用默认认证客户端提交至缺乏校验的函数
              └─ 数据被当作可信输入处理
                  └─ 触发任意代码执行，危及内部组件
```

### 3.2 CVE-2026-65400 — macOS Screen Sharing 认证绕过漏洞（在野利用，公开利用代码）

!!! danger "严重漏洞"

#### 3.2.2 漏洞摘要

该漏洞位于 macOS 内置远程桌面功能 Screen Sharing（基于 VNC/RFB 协议，监听 TCP 5900 端口）的系统守护进程 `screensharingd`。Apple 官方描述为"通过改进状态管理修复了认证问题，网络攻击者可在没有有效凭证的情况下认证到 Screen Sharing"。安全研究者（Huntress/fG!/blasty）进一步指出，根因是 `screensharingd` 的 **SRP（Secure Remote Password）帧长度校验缺失错误返回**，属逻辑缺陷而非内存破坏：攻击者按特定顺序重放握手即可被当作已登录用户。

Screen Sharing 服务由两个以高权限运行的文件助手进程 `SSFileCopySender` / `SSFileCopyReceiver` 支撑文件操作，二者继承 Apple 签名授权 `kTCCServiceSystemPolicyAllFiles`（全磁盘访问权限，可绕过 TCC 防护）。利用该认证绕过可触发文件复制功能读取任意文件，在部分条件下可实现预认证远程代码执行。荷兰 NCSC-NL 确认的在野攻击中，攻击者获取 **root 权限** 并植入门罗币（Monero）挖矿程序。

> 该漏洞无需任何凭证、无需用户交互，仅需目标 Mac 的 Screen Sharing 对攻击者网络可达。研究者 @osxreverser 扫描估计互联网上暴露 Screen Sharing 的 Mac 约 **4 万台**（近半数位于美国），覆盖家庭、高校与企业服务器。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 目标 5900 端口（Screen Sharing/VNC）对攻击者网络可达 |
| 身份认证 | 无需 | 认证绕过，无需任何账号凭证 |
| 用户交互 | 不需要 | 无需点击链接或打开文件 |
| 特定配置 | 是 | Screen Sharing 功能启用且可被网络访问（互联网暴露即高危） |
| 利用复杂度 | 低 | 逻辑缺陷，无需内存破坏利用链 |

**技术原理：**

`screensharingd` 在 SRP 认证帧长度校验中缺少错误返回（missing error-return），导致认证状态管理缺陷：攻击者可构造异常握手序列，使服务在未提供有效凭证的情况下将连接标记为已认证。认证通过后，攻击者可调用以 root 权限运行、持有全磁盘访问授权（`kTCCServiceSystemPolicyAllFiles`）的 `SSFileCopySender`/`SSFileCopyReceiver` 文件助手，读取系统任意文件；结合文件写入能力可进一步实现远程代码执行。

**核心利用链：**

```text
攻击者（网络可达 5900 端口）
  └─ 构造异常的 SRP 认证握手帧序列
      └─ 触发 screensharingd 帧长度校验缺失错误返回
          └─ 绕过凭证校验，被标记为已认证
              └─ 调用 root 权限文件助手（SSFileCopySender/Receiver）
                  └─ 读取任意文件（绕过 TCC）/ 写入文件
                      └─ 获取 root 权限并植入挖矿程序等载荷
```

#### 3.3.2 漏洞摘要

GeoServer 是广泛部署于政府、企业与科研机构的开源地理空间数据服务器。该零日漏洞位于 **OGC Filters 配合 PostGIS DataStore 实现的 `jsonArrayContains` 函数**：GeoServer 项目维护者确认"当执行 OGC Filters 且使用 PostGIS DataStore 实现时，`jsonArrayContains` 函数存在 SQL 注入漏洞"，要求 **PostGIS 12 及以上版本且数据列为 String 或 JSON 字段**；对于 PostGIS 12 及以上，`jsonArrayContains(<column>, <pointer>, <value>)` 函数将 `<value>` **未转义直接写入生成的 SQL**。

未认证攻击者可借此注入 SQL 语句；在数据库账号为高权限（如系统管理员 sa）的配置下，可自然升级为远程代码执行。该漏洞为 2023 年 `CVE-2023-25158`（CVSS 9.8）的**回归**。受影响 Maven 包为 `org.geotools:gt-jdbc-postgis`。

研究者 @q1uf3ng 于 2026-08-12 10:46 UTC 在 X 平台公开漏洞；watchTowr 在公开后数小时内即观测到数百次探测尝试（触发错误响应、比对响应以建立漏洞清单），主要来自少量源 IP；随后奇安信 CERT 于 2026-08-14 发布 QVD-2026-52627 "已复现"通告。

> 披露当天（2026-08-12）即为"公开即被探测"的典型：攻击者无需等待成熟利用代码，仅凭公开技术细节即可批量扫描比对响应。

#### 3.3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 可访问 GeoServer OGC 服务端点（WFS/WMS 等） |
| 身份认证 | 无需 | 未授权即可触发过滤器执行 |
| 用户交互 | 不需要 | 无需点击链接或打开文件 |
| 特定配置 | 是 | PostGIS 12+ DataStore 且字段为 String/JSON 类型；数据库账号高权限时可 RCE |
| 利用复杂度 | 低 | 构造含 `jsonArrayContains` 的 OGC Filter 请求即可 |

**技术原理：**

`jsonArrayContains(<column>, <pointer>, <value>)` 在 PostGIS 12 及以上版本将 `<value>` 参数**未转义直接拼接**进生成的 SQL 语句，构成 SQL 注入。该缺陷是 2023 年 `CVE-2023-25158` 的回归。攻击者通过 OGC 过滤表达式（Filter Encoding）构造恶意 `<value>` 载荷，在数据库账号具备高权限（如 sa）时可进一步实现远程代码执行。

**核心利用链：**

```text
攻击者
  └─ 发现暴露的 GeoServer OGC 服务（WFS/WMS 等）
      └─ 构造含 jsonArrayContains 过滤器的请求，注入恶意 SQL 值
          └─ 触发 PostGIS DataStore 未转义拼接 <value>
              └─ 注入 SQL 语句执行（数据库 sa/高权限账号）
                  └─ 特定配置下实现远程代码执行
```

#### 3.4.2 漏洞摘要

该漏洞存在于 Windows Cross Device Service（Windows 跨设备服务，与手机连接/跨设备体验相关），属于不正确的访问控制（CWE-284）：已授权（低权限）攻击者可利用该缺陷本地提升权限，以更高权限执行代码，最终可提权至 SYSTEM。微软在 2026 年 8 月补丁日（2026-08-11）发布修复，并于 2026-08-14 修订公告，共映射 9 个受影响 Windows 产品条目及对应修复版本。

奇安信 CERT 于 2026-08-14 发布"【已复现】Windows Cross Device Service 本地权限提升漏洞(CVE-2026-66804)安全风险通告"。公开 PoC 显示可利用 **Cross Device 虚拟摄像头（virtual camera）功能**实现从标准用户到 SYSTEM 的权限提升。

> 本地提权类漏洞常被用作高级攻击链的组成部分（如浏览器/文档漏洞利用后的权限提升环节），在多阶段攻击中价值较高。

#### 3.4.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 否（本地利用） | 需可在目标主机执行代码（本地用户会话） |
| 身份认证 | 普通用户 | 已授权（低权限）账户 |
| 用户交互 | 不需要 | 无需点击链接或打开文件 |
| 特定配置 | 是 | Cross Device Service 相关功能（虚拟摄像头等）可用 |
| 利用复杂度 | 低 | 公开 PoC 可直接编译利用（C 语言） |

**技术原理：**

Windows Cross Device Service 对相关功能（如跨设备虚拟摄像头）的访问控制不充分，低权限用户可调用本应受限的接口/对象，借以在更高权限上下文（SYSTEM）执行代码，实现本地权限提升。公开 PoC 将该服务中的虚拟摄像头组件作为提权入口。

**核心利用链：**

```text
低权限攻击者（本地会话）
  └─ 利用 Cross Device Service 访问控制缺陷
      └─ 操纵虚拟摄像头等跨设备功能组件
          └─ 在 SYSTEM 上下文执行代码
              └─ 获取系统最高权限
```

### 3.5 CVE-2026-14669 — PostgreSQL to_char(timestamptz) 堆溢出远程代码执行漏洞

!!! danger "高危漏洞"
    PostgreSQL 的 `to_char(timestamptz)` 函数在处理超长 POSIX 时区缩写时存在堆缓冲区溢出，选择时区的一方（数据库低权限用户）可以数据库运行操作系统用户身份执行任意代码。

#### 3.5.2 漏洞摘要

该漏洞存在于 PostgreSQL 的 `to_char(timestamptz)` 函数中：处理超长的 POSIX 时区缩写时发生**堆缓冲区溢出**，"选择时区的一方"（即向数据库提交含恶意时区参数查询的低权限用户）可以**数据库运行的操作系统用户身份**执行任意代码。受影响版本为 PostgreSQL 18.5、17.11、16.15、15.19、14.24 之前的所有版本线。

国内方面，微步在线于 2026-08-14 发布原创漏洞通告"PostgreSQL to_char 堆溢出远程代码执行漏洞"。由于 PostgreSQL 广泛部署于各类业务系统，且漏洞利用仅需低权限数据库账号（PR:L），配合数据库服务网络可达（AV:N）即构成高危风险：攻击者先获取任意低权限数据库账号（常见于应用账号泄露、弱口令），即可提权至数据库进程运行用户（常为操作系统普通用户乃至高权限用户），进一步控制主机。

> 该漏洞价值在于"数据库低权限 → 操作系统代码执行"的越权跨越：数据库账号权限边界被打破，是典型的横向提权型漏洞。

#### 3.5.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 可访问 PostgreSQL 服务（默认 5432 端口） |
| 身份认证 | 普通用户 | 需低权限数据库账号（PR:L） |
| 用户交互 | 不需要 | 无需点击链接或打开文件 |
| 特定配置 | 是 | 需调用 `to_char(timestamptz)` 且由用户可控时区参数 |
| 利用复杂度 | 低 | 构造超长 POSIX 时区缩写触发堆溢出 |

**技术原理：**

`to_char(timestamptz)` 在格式化带时区的时间戳时处理 POSIX 时区缩写，对超长缩写缺少正确的长度校验与边界处理，导致堆缓冲区溢出（CWE-122）。攻击者以低权限数据库账号提交包含超长 POSIX 时区缩写参数的查询，即可在数据库进程内触发溢出，进而以数据库运行用户身份执行任意代码。

**核心利用链：**

```text
低权限数据库账号（网络可达 5432）
  └─ 构造含超长 POSIX 时区缩写的 to_char(timestamptz) 查询
      └─ 触发堆缓冲区溢出（CWE-122）
          └─ 控制数据库进程执行流
              └─ 以数据库运行操作系统用户身份执行任意代码
```

2. **P0 优先处置 `CVE-2026-65400`（macOS Screen Sharing）**：24 小时内将 macOS 升级至 Tahoe 26.6.1 / Sequoia 15.7.9 / Sonoma 14.8.9；未升级前关闭屏幕共享或限制 5900 端口仅可信来源访问；对互联网暴露的 Mac 重点核查挖矿进程与 root 入侵痕迹（该漏洞公开利用代码已出现且已在野利用）；
3. **P1 处置 `QVD-2026-52627`（GeoServer）**：升级至 3.0.1 / 2.28.5 / 2.27.6；无法升级的收敛 OGC 服务（WFS/WMS）互联网暴露、收紧数据库账号权限（禁用 sa/superuser 连接）、WAF 拦截 `jsonArrayContains` 注入特征；核查公开后（08-12 起）的异常请求日志；
4. **P1 处置 `CVE-2026-66804`（Windows Cross Device Service）**：随 2026-08 补丁日更新统一部署（Win10 22H2 ≥ 19045.7663；Win11 24H2 ≥ 26100.9106 / 25H2 ≥ 26200.9106 / 26H1 ≥ 28000.2704），并核查终端提权行为告警；
5. **P2 处置 `CVE-2026-14669`（PostgreSQL）**：3 个工作日内升级至 18.5 / 17.11 / 16.15 / 15.19 / 14.24；审查低权限数据库账号、收敛 5432 端口暴露；
6. **针对 macOS 窃密木马与钓鱼态势**：提醒用户警惕"粘贴命令安装软件"类诱导（ClickFix/假 GitHub 页面），核查浏览器扩展、钥匙串异常与启动项；
7. **对疑似遭受攻击的系统**保留日志、流量、进程、文件及内存证据，开展 WebShell、恶意进程、异常账号及横向移动排查；
