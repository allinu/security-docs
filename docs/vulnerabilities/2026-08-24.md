#### 3.1.2 漏洞摘要

该漏洞存在于 WordPress W3 Total Cache 插件的页面缓存（Page Cache）机制中。插件在构造缓存文件名时使用请求路径作为缓存键（cache key）的一部分，但对路径内容缺少正确的规范化与校验，攻击者可在请求路径中注入路径穿越序列（如 `../` 及其 URL 编码变体），使插件将缓存写入操作重定向到服务器上的任意已存在目录，写入文件并覆盖占用目标名称的现有文件；Apache 环境下同一缺陷可覆盖站点根目录的 `.htaccess` 文件，直接破坏站点运行并清除依赖 `.htaccess` 的 URL 重写与安全加固规则。

漏洞利用无需任何身份认证，攻击者只需向目标站点的 HTTP 服务（通常 80/443）发送构造的请求即可触发，利用复杂度低。WPScan 将其评级为 CVSS 3.1 **10.0（严重）**，向量为 `AV:N/AC:L/PR:N/UI:N/S:C/C:N/I:H/A:H`（网络可达、低复杂度、无需认证、无用户交互、作用域变更、机密性无直接影响、完整性/可用性高影响）。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 面向公众的 WordPress 站点 HTTP/HTTPS 服务（80/443） |
| 身份认证 | 无需 | 未认证攻击者即可触发 |
| 用户交互 | 不需要 | 无需受害者点击链接或打开文件 |
| 特定配置 | 是 | 需启用 W3 Total Cache 页面缓存功能（漏洞位于页面缓存键处理逻辑） |
| 利用复杂度 | 低 | 直接构造恶意请求路径即可，无需前置条件 |

**技术原理：**

插件在页面缓存机制中使用请求 URI 构造缓存文件名（缓存键），但未对该路径进行严格的规范化校验与目录边界限制。攻击者在请求路径中注入路径穿越序列（`../`、`%2e%2e%2f` 等编码变体），使缓存写入操作解析到站点根目录之外或任意已存在目录；由于缓存写入逻辑以服务器进程（Web 用户）权限执行，攻击者可覆盖目标目录中同名文件的内容。在 Apache 部署环境下，覆盖 `.htaccess` 可直接改写站点重写规则与安全加固配置（如防护规则、访问控制），导致站点故障或防护失效。

**核心利用链：**

```text
攻击者
  └─ 发现启用 W3 Total Cache 页面缓存的 WordPress 站点（80/443）
      └─ 构造携带路径穿越序列的缓存键请求（未认证）
          └─ 触发页面缓存写入逻辑
              └─ 路径未经规范化校验，解析至任意已存在目录
                  └─ 覆盖目标文件（Apache 下可覆盖 .htaccess）
                      └─ 站点服务中断 / 安全加固规则被清除
```

#### 3.1.11 风险影响

漏洞成功利用后，可能导致：

- 覆盖服务器任意已存在目录中的文件（站点根目录内外均可），破坏业务文件与站点运行；
- Apache 环境下覆盖 `.htaccess`，导致站点故障、URL 重写规则失效，并清除依赖 `.htaccess` 的安全加固规则（防护配置、访问控制）；
- 若被覆盖目标为可执行文件/配置文件（视部署权限），可能进一步扩大为恶意内容植入或持久化；
- 影响插件全部部署站点（W3 Total Cache 活跃安装量超 100 万），攻击面大；
- 本漏洞 CVSS 机密性（C）为无直接影响，主要影响为完整性（I:H）与可用性（A:H）。

- 临时禁用 W3 Total Cache 页面缓存功能（或整体暂停插件），待升级后恢复；

- 对 `wp-content/cache` 目录设置文件变更审计，发现异常写入立即告警；

1. **优先处置（P1）— W3 Total Cache `CVE-2026-18051`（CVSS 10.0）：** 所有部署 W3 Total Cache 的 WordPress 站点立即升级至 `2.10.5+`；升级前备份 `.htaccess` 与 `wp-content/cache`；升级后核查 `.htaccess` 与缓存目录是否有异常变更；无法立即升级的站点在 WAF/代理层拦截路径穿越编码请求并监控文件完整性。

6. **常规要求：** 对疑似遭受攻击的系统保留日志、流量、进程、文件及内存证据；完成修复后进行复测，并更新资产台账和漏洞处置记录。
