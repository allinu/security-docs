#### 3.1.2 漏洞摘要

Gitea 是广泛使用的自托管 Git 代码托管平台（GitHub/GitLab 的开源替代）。漏洞位于 diffpatch API 对应的 `services/repository/files/patch.go`：该接口以 `git apply --index --recount --cached --binary`（Git ≥ 2.32 时追加 `-3` 三路合并参数）在共享的裸临时克隆中应用攻击者可控补丁。**对同一补丁重复提交两次会制造 add/add 冲突，Git 的三路回退逻辑会将该路径内容检出**——由于裸克隆的仓库根目录即 `$GIT_DIR`，一个名为 `hooks/post-index-change` 的可执行条目在写入索引时被 Git 作为**实时 Git hook 调用**，从而执行攻击者提供的任意命令。hook 的返回值不会回传至 diffpatch 响应，隐蔽性较强；GHSA 附带的 PoC 将命令输出写入 Git 对象并创建分支，经认证 smart HTTP 拉取结果，无需出站连接。

默认配置下 Gitea **开放注册**（open registration），未认证访客注册账号、创建仓库后即获得所需写权限；已注册用户更可直接利用。成功利用后以 Gitea 服务账号执行命令，可能进一步获取 `app.ini`、应用密钥、数据库凭据、OAuth/集成凭据及可达内部服务的访问能力。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 Gitea Web 服务（默认 HTTP 3000 端口，常经反代暴露于 80/443） |
| 身份认证 | 无需（默认开放注册）/ 普通用户 | 开放注册实例：注册账号即可；关闭注册的实例：需任意仓库写权限用户 |
| 用户交互 | 不需要 | 全程无受害者交互 |
| 特定配置 | 是 | 需启用 diffpatch 路由；Git ≥ 2.32（触发 `-3` 三路合并）；可写且可执行的临时文件系统；默认开放注册为"无凭据攻击路径"的前提 |
| 利用复杂度 | 低 | 攻击步骤为常规 API 调用序列 |

**技术原理：**

`services/repository/files/patch.go` 在共享裸临时克隆中以 `git apply --index --recount --cached --binary` 应用攻击者补丁（Git ≥ 2.32 追加 `-3`）。**同一补丁提交两次**触发 add/add 冲突，三路合并回退将索引路径内容检出；裸克隆中仓库根目录即 `$GIT_DIR`，故可执行条目 `hooks/post-index-change` 成为**存活 Git hook**，Git 在写入索引时自动调用该 hook，执行其中内容（作为 Gitea 服务账号）。根本原因是对用户可控补丁内容的路径与 hook 语义校验缺失（CWE-94）。

**核心利用链：**

```text
攻击者
  └─ 访问暴露的 Gitea 实例（默认开放注册）
      └─ 注册账号 → 创建仓库（获得仓库写权限）
          └─ 构造含 hooks/post-index-change 可执行条目的补丁
              └─ 经 diffpatch API 重复提交两次（add/add 冲突）
                  └─ Git 三路合并检出该路径 → 植入存活 Git hook
                      └─ 写索引时 hook 自动执行 → Gitea 服务账号 RCE
                          └─ 结果写入 Git 对象分支，经认证 HTTP 回传（无需出站）
```

#### 3.2.2 漏洞摘要

Microsoft SharePoint Server 的 Business Data Connectivity（BDC）子系统用于将外部业务数据（数据库、Web 服务等）接入 SharePoint。该组件在处理用户上传的 BDC 模型 XML 时，对其中声明的 .NET 类型名**未做白名单/黑名单校验**，可直接实例化任意 .NET 类型。攻击者将类型指向 `ObjectDataProvider`（经典 .NET 反序列化/类型实例化 gadget，可在属性设置阶段触发 `Process.Start()`），即可在 SharePoint 应用池（w3wp.exe）进程内执行任意命令。

微软官方（NVD）描述为"Microsoft Office SharePoint 输入验证不当，允许未授权攻击者通过网络执行代码"，CVSS 8.1（利用复杂度：高，无需认证，影响机密性/完整性/可用性）。公开链式 PoC 仓库进一步声称：`CVE-2026-63520` 本身需要认证，与 `CVE-2026-55040`（SharePoint S2S JWT 令牌验证的四个弱点——`RequireSignedTokens=false`、`x5t` 解析不验签、颁发者校验接受未知证书、非密码学"签名"检查——可伪造任意用户 JWT）组合后，可实现**未认证 RCE**；该链式结论仅出自单一 0-star 仓库（2026-08-26 创建），**未经独立验证**，报告中仅作线索提示。

| 网络可达 | 是 | 需可达 SharePoint Web 服务（80/443） |
| 身份认证 | 无需（NVD 向量 PR:N；AC:H）/ 需认证（链式 PoC 口径） | 单独利用按 NVD 需一定复杂度；链式 PoC 称与 `CVE-2026-55040` 组合免认证 |
| 用户交互 | 不需要 | — |
| 特定配置 | 是 | 需启用/使用 BDC 服务；链式利用需目标存在 S2S 认证缺陷（`CVE-2026-55040` 未修复） |
| 利用复杂度 | 高（NVD 口径 AC:H） | 链式利用复杂度取决于两个漏洞的组合 |

**技术原理：**

BDC 子系统解析上传的 BDC 模型 XML 时，对 XML 中声明的 .NET 类型名直接解析并实例化，**无类型白名单**。经典攻击路径：将类型指向 `System.Windows.Data.ObjectDataProvider`，利用其 `ObjectInstance`/`MethodName` 属性机制在实例化/属性设置阶段调用任意静态方法（如 `System.Diagnostics.Process.Start`），实现命令执行（CWE-20 输入验证不当导致的不安全类型实例化）。链式场景中，前置的 `CVE-2026-55040` 使攻击者可伪造 SharePoint S2S JWT（`alg:none` 无签名 + `x5t` 证书指纹解析不验签 + 颁发者校验失效），以站点管理员身份获得上传 BDC XML 的权限，从而串联为未认证 RCE。

**核心利用链：**

```text
攻击者
  └─ 获取/伪造 SharePoint S2S JWT（CVE-2026-55040：alg:none、x5t 免验签，链式场景）
      └─ 以管理员身份上传含恶意 .NET 类型名的 BDC 模型 XML（CVE-2026-63520）
          └─ BDC 子系统无白名单实例化类型（ObjectDataProvider）
              └─ 触发 Process.Start() → SharePoint 应用池（w3wp.exe）代码执行
```

#### 3.3.2 漏洞摘要

IBM Db2 的 Data Server driver for JDBC and SQLJ（即 Db2 官方 JDBC 驱动，随 Db2 客户端/应用随附分发）在**JDBC URL 由用户控制**的场景下存在远程代码执行漏洞。JDBC URL 除数据库地址外还承载大量驱动属性（如 `connectionRetryCount`、类加载相关属性、`properties` 参数等），驱动对这些属性的解析/加载过程存在可注入点（IBM 官方不披露具体机制，APAR `DT471454`），攻击者可通过恶意构造的 JDBC URL 触发驱动加载危险组件，从而在运行应用的 JVM 进程中执行任意代码。

典型受影响的业务场景：应用程序存在"数据库连接串"配置入口且未对输入做白名单校验（如 SaaS 后台管理界面、数据集成/BI 工具、运维平台等允许管理员或低权限用户填写 JDBC URL 的功能）。此类场景下攻击者可以应用进程权限执行命令，进一步获取数据库凭据、业务数据与主机控制权。IBM 在公告中明确"不披露关键功能与复现步骤，以避免向潜在恶意攻击者提供过多信息"。

**技术原理：**

IBM 官方未公开根因细节。按 CWE-94（代码注入）与 JDBC 驱动通用机制推断：JDBC URL 及内嵌属性（如 `PropertyList`/`properties`、连接属性中的类名与工厂参数等）在驱动解析阶段被作为配置输入，若其中存在可导向恶意类加载/对象实例化（如类似反序列化 gadget 的机制）的属性，攻击者可通过精心构造的连接串触发代码执行。IBM 表示"不披露关键功能与复现步骤"，此处仅作机制层面说明，**不包含任何可利用载荷**。

**核心利用链：**

```text
攻击者
  └─ 获得应用内 JDBC 连接串配置入口（或可篡改应用配置）
      └─ 构造恶意 JDBC URL（含危险驱动属性/类加载参数）
          └─ 触发受影响 Db2 JDBC/SQLJ 驱动的解析与加载过程
              └─ 在应用 JVM 进程中执行任意代码（CWE-94）
```
