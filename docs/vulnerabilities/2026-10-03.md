#### 3.1.2 漏洞摘要

该组漏洞存在于 Teledyne FLIR Aware2 软件（PackBot、FirstLook 机器人所使用的地面控制软件）中。`CVE-2026-55393` 的根因是 Web 界面在把用户可控的路径片段映射为文件系统/资源路径时未做规范化与目录边界校验，导致**远程未认证攻击者经路径遍历读取机器人配置与安全参数**；`CVE-2026-55395` 则是访问控制环节使用了**硬编码口令**，攻击者只需从固件镜像或产品文档中读取口令即可登录并**访问、重配置机器人**；`CVE-2026-55396` 指操控单元与机器人之间的 UDP 控制流量**以明文传输且缺少加密完整性校验**，使邻近攻击者能够嗅探、劫持或篡改控制指令。  

> 三者叠加后形成“读取配置 → 拿到硬编码口令 → 劫持/篡改控制链路”的现实攻击链，且受影响设备为警用/军用级排爆与侦察机器人，一旦被接管可能造成物理世界安全后果，故尽管 PoC 未公开，仍应视为高优先级处置对象。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 55393 需可访问 Aware2 Web 界面（`AV:N`）；55395 需可达访问控制接口；55396 需处于操控单元与机器人同一局域网段（`AV:A`） |
| 身份认证 | 无需 | 55393、55395 向量均为 `PR:N`；55396 亦为 `PR:N` |
| 用户交互 | 不需要 | 三者 `UI:N` |
| 特定配置 | 否 | 默认部署即可能受影响 |
| 利用复杂度 | 低 | 均为 `AC:L`、`AT:N`，攻击路径直接 |

**技术原理：**

- `CVE-2026-55393`：Web 界面把用户可控路径直接拼接为资源定位路径，未做 canonicalization 与受限目录边界判断，也未拒绝 `../` 及编码变体，导致读取本不应暴露的配置文件与安全参数；
- `CVE-2026-55395`：访问控制逻辑依赖**硬编码口令**，口令固化于固件或随产品文档发布，攻击者获取后即可通过合法认证流程登录并重配置设备，属于典型的“凭据无法轮换、无法收敛”问题；
- `CVE-2026-55396`：操控单元与机器人之间的 UDP 控制流量以明文承载且**缺少加密完整性校验**，邻近攻击者可在链路层进行嗅探、重放、劫持或篡改。

**核心利用链：**

```text
攻击者（网络可达 Aware2 Web 界面）
  └─ 经路径遍历读取机器人配置文件与安全参数（CVE-2026-55393）
      └─ 从固件/文档获得硬编码口令并登录访问控制接口（CVE-2026-55395）
          └─ 结合邻近网络嗅探/劫持明文 UDP 控制流量（CVE-2026-55396）
              └─ 重配置机器人或篡改控制指令
                  └─ 造成机器人被接管 / 任务失败 / 物理世界安全后果
```

#### 3.2.2 漏洞摘要

Zammad 是广泛部署的开源工单/客服系统，常直接暴露于互联网供客户与员工访问。`CVE-2026-102489` 为**会话劫持（会话固定）**缺陷：攻击者可使受害者使用攻击者已知的会话标识完成认证，从而劫持其会话，并进一步以 **zammad 服务用户**身份实现远程代码执行；该缺陷影响 Zammad 6.3.0–6.5.4，7.0.0–7.1.3 亦存在但因环境条件不可利用。`CVE-2026-102490` 为**本地权限管理不当**：zammad 服务用户可利用该缺陷**提权至 root**，且影响含最新 alpha 在内的所有版本。两者串联后，攻击者可从“匿名互联网访问者”一路走到“服务器 root”，DIVD 自曝其自身系统即因此在数秒内被攻陷。  

> 该链条的可怕之处在于**利用门槛低、串联顺畅、后果为完全控制**。自 2026-10-02 起，CISA 已将其纳入 KEV，运维方不应再以“暂无公开 PoC”为由延后处置。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需可访问 Zammad Web 界面 |
| 身份认证 | 无需（对 102489）；本地用户（对 102490） | 102489 向量为 `PR:N`；102490 需已获得 zammad 用户上下文 |
| 用户交互 | 不需要 | `UI:N` |
| 特定配置 | 否 | 默认部署即可能受影响 |
| 利用复杂度 | 低 | `AC:L`、`AT:N` |

**技术原理：**

- `CVE-2026-102489`：Web 层在有/无认证状态切换时**未重新生成会话标识**（会话固定），使攻击者能让受害者携带攻击者预置的会话完成认证，进而劫持其会话；在已认证上下文下，攻击者可调用受限功能实现以 **zammad 服务用户** 执行的任意代码。
- `CVE-2026-102490`：服务进程（zammad 用户）在本地执行特权操作时**权限校验不当**（可能涉及以 root 运行的外部命令、文件权限或 sudo/包装脚本），使本地 zammad 用户可直接提权至 root。

**核心利用链：**

```text
攻击者（互联网）
  └─ 预置会话标识并诱导受害者登录（会话固定，CVE-2026-102489）
      └─ 劫持已认证会话，以 zammad 用户执行任意代码
          └─ 在已获得 zammad 用户上下文后利用本地提权缺陷（CVE-2026-102490）
              └─ 提权至 root
                  └─ 完全控制服务器、横向移动、窃取工单与凭据数据
```

### 3.3 Apache Thrift 0.25.0 修复批次 — CVE-2026-91135 / CVE-2026-83632 领衔（同批 40 余条跨语言缺陷）

!!! danger "严重漏洞"

#### 3.3.2 漏洞摘要

Apache Thrift 是跨语言的 RPC/序列化框架，被大量后端服务、数据管道与微服务用于通信。本批 40 余条缺陷是 Apache 对 Thrift 各语言绑定进行**系统性安全审计**后的集中修复，共性问题包括：**缓冲区越界读写**（`CVE-2026-91135` 在启用 ZLIB 变换时，`THeaderTransport::transform()` 未校验压缩后帧长度即写入写缓冲，导致随帧增大而增长的堆越界写；`CVE-2026-93925` C++ `THeaderProtocol` 栈溢出；`CVE-2026-82459` 32 位越界写；`CVE-2026-66837` PHP 栈溢出）、**资源无限制/整数溢出**（`CVE-2026-83632` 等大量 CWE-770/190）、**不受控递归与死循环导致 DoS**（`CVE-2026-85493`、`CVE-2026-96288`、`CVE-2026-85476` 等）、以及 **Node.js 绑定的原型链污染**（`CVE-2026-86535`/`86536`）。  

> 该批次的特点是“**单条多半为 DoS，但 C++ 侧存在可升级为内存破坏的堆溢出**”，且 Thrift 作为基础组件往往被间接依赖，实际受影响资产需经依赖清单排查；统一动作即“升级 0.25.0”，性价比极高。

#### 3.3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可向使用 Thrift 的服务发送构造帧（`AV:N`） |
| 身份认证 | 多数无需 | 向量 `PR:N`（部分需目标启用特定传输/协议/变换） |
| 用户交互 | 不需要 | `UI:N` |
| 特定配置 | 是（部分条目） | 如 `CVE-2026-91135` 需应用启用 ZLIB 变换、`CVE-2026-83632` 需触发特定解析路径 |
| 利用复杂度 | 低–高 | 91135 为 `AC:L`；83632 为 `AC:H`；DoS 类易触发，内存破坏类受内存布局影响 |

**技术原理：**

- `CVE-2026-91135`：启用 ZLIB 变换的帧在压缩**不缩小反而增大**（如已压缩内容）时，`THeaderTransport::transform()` 未确保压缩结果装得下写缓冲即执行拷贝，越界量随帧大小增长；大帧还会读越过变换缓冲末尾（`CWE-122`）。
- `CVE-2026-83632`：资源分配无上限与整数回绕叠加，导致堆缓冲区溢出（`CWE-770`/`CWE-190`/`CWE-122`）。
- 其余条目：各语言绑定在长度/数量字段校验、递归深度限制、异常与资源释放处理上不一致，形成大量 DoS 与少量内存破坏原语。Node.js 绑定存在原型链污染，可影响宿主应用逻辑。

**核心利用链：**

```text
攻击者
  └─ 定位使用 Apache Thrift 的服务及其启用的传输/协议/变换
      └─ 构造恶意 Thrift 帧（超长压缩帧 / 深层嵌套字段 / 巨量长度字段）
          └─ 触发对应语言绑定的解析或变换逻辑
              └─ 造成堆/栈越界、整数回绕、递归溢出或资源耗尽
                  └─ 服务崩溃/拒绝服务，或在具备条件时内存破坏以执行代码
```

### 3.4 CVE-2026-93698 / CVE-2026-93697 / CVE-2026-93029 — cPanel / WHM 托管面板命令执行与存储型 XSS

!!! danger "严重漏洞"
    cPanel / WHM 托管面板存在多条严重缺陷：`CVE-2026-93698`（CVSS 3.0 = 9.9）为校验不足导致经 **Multilang adminbin 执行任意命令**；`CVE-2026-93697`（9.0）为 **WHM Mass Modify Accounts 界面存储型 XSS**；`CVE-2026-93029`（9.0）为 **WHM Manage SSL Hosts 界面存储型 XSS**，两条 XSS 均可“允许任意代码执行”。cPanel/WHM 是多租户虚拟主机的控制枢纽，一旦失守即等同大批站点被控。供应商已在 110/134/136/138 等分支的变更日志中修复，并同步修复 WP Squared。

#### 3.4.2 漏洞摘要

cPanel / WHM 是主机商与运维团队广泛使用的多租户 Web 托管控制面板，其进程常以高权限（root/特权服务）运行，是典型的“权限枢纽”。`CVE-2026-93698` 位于 Multilang 管理二进制（adminbin）中，**校验不足**导致已认证但低权限的操作者（`PR:L`，向量 `S:C` 表示可影响其他安全域）可**执行任意命令**，获取更高权限甚至 root 上下文；`CVE-2026-93697`、`CVE-2026-93029` 则分别是 WHM “Mass Modify Accounts” 与 “Manage SSL Hosts” 界面的**存储型 XSS**，攻击者可通过注入脚本在管理员会话中执行任意代码（`UI:R`）。由于控制面板管理员权限极大，XSS 提权后即可横向控制其下所有站点与数据库。  

> 控制面板类漏洞的“杠杆”极高：一次利用可波及其承载的全部虚拟主机，故即便需要低权限/需用户交互，也应优先处置。

#### 3.4.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可访问 cPanel/WHM 面板（2082/2083/2086/2087 等端口） |
| 身份认证 | 普通用户（93698，`PR:L`）；管理员会话（XSS，`UI:R`） | 93698 需已认证的低权限账号；XSS 需诱导管理员查看被注入内容 |
| 用户交互 | 93698 不需要；XSS 需要 | `UI:N` / `UI:R` |
| 特定配置 | 否 | 默认部署即可能受影响 |
| 利用复杂度 | 低 | `AC:L` |

**技术原理：**

- `CVE-2026-93698`：Multilang adminbin 在处理调用参数时未充分校验/转义，使已认证低权限用户可通过构造参数**注入并执行系统命令**（`CWE-78`）；向量 `S:C` 表明影响可跨安全域，即从普通用户域越界到面板特权域。
- `CVE-2026-93697` / `CVE-2026-93029`：WHM 的 “Mass Modify Accounts” 与 “Manage SSL Hosts” 界面把用户可控输入**以未净化形式存储并在管理员界面渲染**，形成存储型 XSS（`CWE-79`）；管理员访问即触发，可在其会话中执行任意操作。

**核心利用链：**

```text
攻击者
  └─（93698）以低权限账号登录 cPanel/WHM
      └─ 向 Multilang adminbin 提交构造参数
          └─ 注入并执行系统命令，跨安全域获取更高权限
              └─ 控制面板与承载站点
  └─（93697/93029）向 WHM 界面注入存储型 XSS 载荷
      └─ 管理员访问 Mass Modify Accounts / Manage SSL Hosts
          └─ 在管理员会话中执行任意代码，接管面板
```

#### 3.5.2 漏洞摘要

- `CVE-2026-103956`：Loom for AWS 是 AWS 实验室（awslabs）开源的智能体（agent）控制面。在**未配置身份提供方（Identity Provider）**的部署中，其认证依赖存在**关键功能缺失认证**缺陷，任何向应用 API 发起的请求都会被赋予**超级管理员**权限。攻击者可据此注册任意工具服务器、读取已存储的集成凭据、并**改写受管代理角色所绑定的 IAM 角色策略**，从而把“应用层失陷”升级为“云账户权限失陷”。受影响版本为 **Loom for AWS before 1.6.1**。
- `CVE-2026-104019`：Amazon SageMaker Distribution 的 Studio Space 启动校验脚本（用于 Amazon SageMaker Unified Studio）在把**连接资源属性**插值进 shell 调用时未做中和处理，拥有**项目贡献者权限**的已认证远程用户可构造恶意属性，在**其他项目成员的 Studio Space** 中执行任意命令，并获取该成员的**临时执行角色凭据**。受影响范围覆盖 2.x/3.x/4.x 多条分支，修复版本为 2.14.12 / 3.9.12 / 4.0.11 / 4.1.11 / 4.2.8 / 4.3.5 / 4.4.3（按所在小版本线），**已达 EOL 的小版本线不再修复**。

> 两者共同的风险点是“**从应用层/项目层越权到云身份与凭据**”：Loom 直接触及 IAM 角色策略，SageMaker 触及项目成员的临时执行角色——这正是云上攻击者最想要的“跳板凭据”。

#### 3.5.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 Loom 应用 API（103956）；需为项目贡献者（104019） |
| 身份认证 | 无需（103956，未配置 IdP 时）；已认证项目贡献者（104019） | 103956 向量 `PR:N`；104019 为 `PR:L` |
| 用户交互 | 103956 不需要；104019 需要（受害者成员触发） | `UI:N` / `UI:P` |
| 特定配置 | 是 | 103956 依赖“未配置 IdP”；104019 依赖存在连接资源属性插值 |
| 利用复杂度 | 低 | `AC:L` |

**技术原理：**

- `CVE-2026-103956`：认证依赖在“未配置 IdP”这一默认/常见部署形态下**失效**（`CWE-306` + `CWE-1188`），导致 API 请求默认取得超级管理员身份；由于 Loom 具备“注册工具服务器、读取集成凭据、改写 IAM 角色策略”的合法能力，一旦认证失效，这些能力即被攻击者直接继承，形成从应用面到云身份面的越权。
- `CVE-2026-104019`：启动校验脚本把**连接资源属性**直接拼接到 shell 命令字符串中，未做转义/白名单（`CWE-78`），使贡献者可通过构造属性在他人的 Studio Space 会话中注入并执行命令，并借助该 Space 的临时执行角色凭据进一步访问云资源。

**核心利用链：**

```text
攻击者
  └─（103956）发现未配置 IdP 的 Loom 部署
      └─ 向应用 API 发起任意请求，获得超级管理员权限
          └─ 注册恶意工具服务器 / 读取集成凭据 / 改写 IAM 角色策略
              └─ 云账户权限面失守
  └─（104019）以项目贡献者权限提交含恶意属性的连接资源
      └─ 属性被插值进启动校验脚本的 shell 调用
          └─ 在其他成员的 Studio Space 中执行命令
              └─ 窃取该成员临时执行角色凭据并访问云资源
```

GitLab AI Gateway 是 GitLab Duo Agent Platform 的模型网关组件，承担提示模板渲染与模型调用编排。`CVE-2026-90970` 的根因是**模板引擎注入（CWE-1336）**：AI Gateway 在渲染提示模板/流程配置时未充分隔离用户可控的 flow 配置，使拥有 Duo Agent Platform 访问权限的**已认证用户**能够构造特制 flow，**逃逸提示模板沙箱**并在网关进程内执行任意命令。CVSS 向量中的 `S:C`（Scope Changed）表明影响可跨越安全域——攻击者从“模型网关用户域”逃逸到“网关宿主域”。  

> AI Gateway 是 GitLab 实例内一个高价值枢纽，可访问模型凭据、内部网络与其他 Duo 组件；一旦 RCE，攻击者往往可进一步触及代码仓库与 CI/CD 环境。

### 3.7 CVE-2026-104846 / CVE-2026-104848 / CVE-2026-104849 — Seroval 反序列化与 Tinypool 原型链污染（Node.js 生态供应链 RCE）

#### 3.7.2 漏洞摘要

- `CVE-2026-104846`：Seroval 提供超越 `JSON.stringify` 的复杂 JS 值序列化/反序列化能力。自 0.12.0 至 1.6.2 之前，`fromJSON` 反序列化一个 fulfilled Promise 控制节点时，可把**插件产生的、携带可调用对象的 thenable** 传给原生 Promise resolver；ECMAScript 的 thenable 同化机制随后**意外调用**该可调用对象，使攻击者可控 JSON 触发代码执行。该路径**绕过了 1.5.3 针对 `CVE-2026-59940` 的类型混淆修复**，因意外调用发生在值被反序列化之后的原生 Promise 结算阶段。修复版本 1.6.2。
- `CVE-2026-104848` / `CVE-2026-104849`：Tinypool 是 Node.js 轻量 worker 线程池。104848 中，Tinypool 从普通 options 对象构造 `ThreadPool.options` 并读取 `execArgv`/`env`，使**被污染 `Object.prototype` 上的继承值**被复制为自有属性并传给 `worker_threads.Worker`，攻击者只要先污染该属性，即可让每个新 worker 经命令行 preload 参数或 `NODE_OPTIONS` 加载攻击者选定的 JS；104849 中，`pool.run(task, options)` 读取 `filename` 时不要求自有属性，被污染的 `Object.prototype.filename` 可替换预期 worker 模块。二者均导致**以宿主进程权限执行代码**，并可访问 CI 密钥、签名材料与构建产物。

> 这类“依赖原型链污染 + worker 加载路径”的组合是**供应链攻击**的典型形态：单次污染可能被忽视，但会级联放大为构建环境的代码执行。

#### 3.7.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是（远端输入到达反序列化/worker 路径） | 需应用将攻击者可控 JSON 交给 Seroval 反序列化，或先污染原型 |
| 身份认证 | 无需（若应用暴露相关路径） | `PR:N` |
| 用户交互 | 不需要 | `UI:N` |
| 特定配置 | 是 | Seroval 需使用“支持插件”的版本；Tinypool 的 104849 需应用向 `pool.run` 传入自定义第二参数 |
| 利用复杂度 | 低（`AC:L`），但需满足 `AT:P`（前置条件成立） | 仍需先制造/触发原型污染 |

**技术原理：**

- `CVE-2026-104846`：反序列化流程对 Promise 控制节点做了类型混淆相关处理，但**在原生 Promise 结算阶段**仍会把携带可调用对象的 thenable 同化调用（`CWE-843`），使数据变成可执行代码。
- `CVE-2026-104848`/`104849`：`options` 与 `filename` 读取**未限制为自有属性**，继承了被污染 `Object.prototype` 的值（`CWE-1321`），并被用于 worker 的 preload/`NODE_OPTIONS` 或模块路径（`CWE-94`），最终在 worker 中以宿主权限执行任意 JS。

**核心利用链：**

### 3.8 CVE-2026-86325 / CVE-2026-86326 — Moxa 协议网关栈缓冲区溢出与固件签名校验不当

#### 3.8.2 漏洞摘要

Moxa 协议网关广泛用于电力、轨交、制造等 OT 现场，连接现场串口/协议设备与上层网络，常部署于生产网络边界。`CVE-2026-86325`：Web 管理界面的账号管理接口在处理 `account_name` 参数时**未做长度校验**，超长账号名溢出内部栈缓冲区，导致程序执行流被破坏；成功利用可读取设备内存（包括凭据）、修改任意内存内容并影响设备可用性。攻击者需要先拥有**只读权限**（`PR:L`）的 Web 管理账号，但向量 `SC:H/SI:H/SA:H` 表示影响可跨安全域，危害放大。`CVE-2026-86326`：设备在安装固件前**未正确校验固件密码学真实性**，高权限攻击者可提交特制/被修改的固件镜像并使其被安装，实现未授权代码执行与跨升级持久化。  

> OT 设备通常补丁周期长、停机窗口小，且往往直接接入现场网络，故即便 86325 需只读账号，也应视为高优先级；86326 的“持久化固件后门”对关键基础设施威胁尤大。

#### 3.8.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可访问设备 Web 管理界面/固件更新接口 |

**技术原理：**

- `CVE-2026-86325`：账号管理请求中的 `account_name` 被拷贝进固定大小的栈缓冲区前**未校验长度**（`CWE-121`），超长输入覆盖相邻栈数据（含返回地址/变量），破坏执行流；由于可读取设备内存并修改任意内存，具备泄露凭据与进一步利用的潜力。
- `CVE-2026-86326`：固件更新流程**未正确验证固件镜像的密码学签名**（`CWE-347`），使被篡改/伪造的固件可通过校验并被安装，攻击者借此在设备上执行未授权代码，且因固件被替换，恶意修改**可跨后续升级持续存在**。

**核心利用链：**

```text
攻击者
  └─（86325）以只读账号登录设备 Web 管理界面
      └─ 提交超长 account_name
          └─ 触发栈缓冲区溢出，破坏执行流
              └─ 读取设备内存（含凭据）/ 修改内存 / 影响可用性
  └─（86326）以高权限访问固件更新接口
      └─ 提交特制/被修改的固件镜像（签名校验缺失）
          └─ 固件被安装，执行未授权代码
              └─ 恶意修改跨升级持久化，长期控制设备
```

#### 3.8.11 风险影响
