#### 3.1.2 漏洞摘要

该漏洞存在于 WordPress 登录页（`wp-login.php`）的错误回显处理流程中。当用户提交不存在的用户名时，WordPress 通过 `wp_signon()` → `wp_authenticate()` 生成错误信息，将用户提交的用户名原样回显；回显前先经 PHP `strip_tags()` 过滤 HTML 标签，再经 WordPress 自身的 `wp_kses_post()` 净化。两个净化器对标签的解析规则不一致：`strip_tags()` 仅识别"`<` 后紧跟字母"的标签，`< area id=ajaxurl>` 这类尖括号后带空格的字符串可完整绕过；而 `wp_kses_post()` 的解析器容忍该空白，将其视为合法的 `<area>` 元素输出为真实 HTML，形成反射型 XSS。

Pwn 研究团队进一步利用浏览器"命名属性"特性（window 对象暴露所有带 `id` 属性的 HTML 元素）实现 **DOM clobbering**：注入的 `<area id=ajaxurl>` 覆盖 WordPress 登录页加载的 `user-profile.js`（本用于个人资料页，因登录页同时承担密码重置功能被一并加载）中未定义的 `ajaxurl` 变量，配合 `#color-picker` 等注入元素，脚本会自动向攻击者控制的 URL 发起请求。通过 REST API 的 `_jsonp` 回调（接受点号，可跨窗口遍历属性链）与 2022 年公开的跨窗口点击技术，攻击者可在一个隐藏窗口中打开 WordPress 应用密码审批页，并在已登录管理员的真实会话中自动点击"批准"，从而获取管理员 Application Password。该密码可经 REST API 的 HTTP Basic 认证从任意来源调用；单站点管理员默认具备 `unfiltered_html` 权限，可发布含攻击脚本的页面并上传恶意插件，最终以 Web 服务用户权限执行任意 PHP 命令。整条链路预认证触发、受害者仅需访问攻击者页面（无需点击），PoC 已证明可对默认配置 WordPress 实现 RCE 并自动清理痕迹。

> 该漏洞自 WordPress 早期版本即存在，影响所有受维护分支，覆盖全球超 43% 互联网网站（估计 5 亿+ 站点）。2026-07-26 由 Pwn 团队发现并完整复现，07-27 报告 WordPress，官方 08-06 紧急发布 7.0.3 并将修复回溯至 4.7 起所有受维护分支。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需互联网可达的 WordPress 站点及受害者浏览器 |
| 身份认证 | 无需 | 预认证触发（PR:N）；RCE 阶段需受害者为已登录管理员（UI:A） |
| 用户交互 | 需要 | 受害者需访问攻击者构造的恶意页面（UI:A）；无需点击 |
| 特定配置 | 否 | 默认配置即受影响；单站点管理员默认具备 `unfiltered_html` 权限 |
| 利用复杂度 | 高 | NVD 向量 AC:H（RCE 需管理员在线访问页面等条件配合） |

**技术原理：**

根本原因为两个净化器解析不一致导致的输入校验缺失：`strip_tags()`（按"`<`+字母"识别标签）与 `wp_kses_post()`（容忍尖括号后空白）对同一字符串给出不同结果，使 `< area id=...>` 绕过首层过滤并以合法元素输出。随后利用浏览器命名属性机制（HTML 规范 7.3.3：带 `id` 的元素成为 `window` 的属性）进行 DOM clobbering，劫持登录页 `user-profile.js` 中未定义的 `ajaxurl` 变量，形成无需用户点击的自动请求；再经 REST API `_jsonp` 回调（校验 `^[a-zA-Z0-9_.]+$`，允许点号遍历属性链）与跨窗口点击技术，在管理员真实会话中自动批准应用密码申请，最终借 `unfiltered_html` 权限发布恶意页面并上传插件实现代码执行。

**核心利用链：**

```text
攻击者
  └─ 构造恶意页面（表单自动提交至 TARGET/wp-login.php）
      └─ 提交不存在用户名，携带 < area id=ajaxurl href=...>< div id=color-picker ...>< button ...>
          └─ strip_tags() 放行 → wp_kses_post() 输出真实 HTML（反射型 XSS）
              └─ DOM clobbering 劫持 user-profile.js 的 ajaxurl
                  └─ REST API _jsonp 回调跨窗口遍历属性链（window.opener.approve.click）
                      └─ 在管理员会话中自动批准 Application Password
                          └─ 经 REST API Basic 认证发布恶意页面、上传恶意插件
                              └─ 以 Web 服务用户权限执行任意 PHP 代码（RCE）
```

#### 3.1.11 风险影响

漏洞成功利用后，可能导致：

- 在 WordPress 源执行任意 JavaScript（XSS），窃取会话或伪造页面；
- 获取管理员 Application Password，接管 WordPress 管理权限；
- 以 Web 服务用户权限远程执行任意 PHP 代码（RCE）；
- 篡改站点页面与内容，植入恶意脚本或后门；
- 窃取数据库凭据、配置与业务数据；
- 以站点为跳板横向移动至同服务器其他应用；
- 大规模站点被批量利用形成供应链投毒或挂马网络。

#### 3.1.13 修复与缓解措施

#### 官方修复

1. 将 WordPress 升级至 `7.0.3` 或所属受维护分支（4.7 起）的最新安全版本（管理后台"更新"页面或[官方下载](https://wordpress.org/download/)）；
2. 无法直接升级的，等待并安装对应分支的安全补丁（官方已回溯修复所有受维护分支）；
3. 升级前完成站点文件、数据库与配置备份；
4. 在测试环境验证插件/主题兼容性及回退方案；
5. 升级后核验版本号、登录页与 REST API 功能正常；
6. 对曾暴露且未及时修复的站点按失陷假设开展日志与文件排查。

#### 临时缓解

无法立即升级时，可采取：

- 在 WAF/网关对 `/wp-login.php` 的 `log` 参数增加 XSS 注入特征拦截规则（`< area`、`< div`、`< button`、`reset-pass-submit` 等特征）；
- 临时禁用 Application Passwords 功能（`wp-config.php` 中 `define( 'WP_APPLICATION_PASSWORDS', false );`，注意会一并影响正常 API 应用）；
- 限制管理后台与登录页的访问来源（IP 白名单、VPN）；
- 加强登录审计与文件完整性监控；
- 对高风险站点实施网络隔离或访问收敛。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者向受害者投递恶意 HTML 页面 |
| 身份认证 | 无需 | 访问恶意页面即可触发（PR:N） |
| 用户交互 | 需要 | 受害者需访问恶意页面（UI:R） |
| 特定配置 | 否 | 默认配置即受影响 |
| 利用复杂度 | 低 | NVD 向量 AC:L（9.6 各项）；沙箱逃逸需先攻陷渲染器（部分 CVE 标 AC:H） |

**技术原理：**

释放后使用（UAF）指对象释放后仍被引用，攻击者可操纵内存布局使释放的内存被恶意数据填充，进而劫持控制流；越界写（OOB write）指向分配边界外写入数据，可破坏相邻内存结构。这些缺陷位于渲染器进程的图形、排版、脚本引擎等组件中，通过精心构造的 HTML/CSS/WebGL 内容即可触发。成功利用后攻击者先获得渲染器进程内的代码执行，再借助 UAF/越界写跨越浏览器沙箱边界，在更高权限进程中执行任意代码。Chrome 官方将此类"远程攻击者可借构造页面实现沙箱逃逸"的漏洞定级为 Critical。

**核心利用链：**

```text
攻击者
  └─ 构造恶意 HTML 页面（含 WebGL/Skia/ANGLE 触发载荷）
```

#### 3.3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需网络可达目标主机的屏幕共享服务（AV:N） |

| 利用复杂度 | 低 | NVD 向量 AC:L |

**技术原理：**

屏幕共享（Screen Sharing，基于 VNC/Apple 远程管理协议）组件的认证状态管理存在缺陷，攻击者可绕过凭据校验进入认证后的会话状态。NVD 向量显示利用需低权限前置（PR:L）或受限于网络位置，成功利用后造成高机密性影响（读取屏幕内容）与低完整性影响（C:H/I:L）。具体技术细节 Apple 未披露。

**核心利用链：**

```text
攻击者
  └─ 发现暴露的 macOS 屏幕共享服务（端口 5900/VNC 或 3283 等）
      └─ 构造绕过认证的会话建立请求
          └─ 触发认证状态管理缺陷（CVE-2026-65400）
              └─ 无凭据进入已认证会话
                  └─ 读取屏幕内容 / 控制远程桌面（视会话权限）
```

## 四、其他漏洞简报

### Zbtlink 路由器内置后门 ENDLESSDOORS（供应链后门，无 CVE）

| 字段 | 内容 |
| --- | --- |
| 事件类型 | 厂商内置后门（供应链风险，非漏洞公告，无 CVE 编号） |
| 影响对象 | Zbtlink（深圳智博通电子 Shenzhen Zhibotong）路由器 20 个型号（白牌品牌：Wiflyer、ZBT、ZBTWiFi 等，在 Amazon/Alibaba/Shopify 销售） |
| 发现者 | VulnCheck（Jacob Baines），2026-08-07 公开 |
| 来源 | [Security Affairs](https://securityaffairs.com/196785/security/researchers-discover-hidden-backdoor-in-20-router-models-allowing-remote-root-access.html)、VulnCheck 报告 |

**事件描述：**  
VulnCheck 研究人员在 Zbtlink AX3000 路由器中发现内置后门（命名 **ENDLESSDOORS**）：固件中两个以 root 权限运行的普通用户态进程伪装成内核线程 `kworker`（内核线程在进程列表中带方括号，这两个无方括号），基于 2015 年的开源工具 `rctl` 构建，由厂商自带启动脚本 `skworker` 随开机自启。植入体向外拨号（而非监听端口），向硬编码命令服务器发送固定 39 字节注册信息（33 字节类标签 + LAN MAC 地址），**无任何握手、密钥交换或校验**；服务器返回的任何内容都交给 `popen()` 以 uid 0 执行，保留字 `rctlbash` 可令其开放 7001 端口返回交互式 root shell。VulnCheck 自建服务器冒充命令端，2 秒内即获得 root shell。20 个型号均向仅 4 个命令服务器地址回连（阿里云上海 47.100.190.96、阿里云深圳 47.107.224.89、Vultr 45.32.81.152、江苏东云 43.248.136.125，对应域名 zbtctl.epplink[.]net、online-string.com、rbdg4nzqadui[.]wikaba[.]com）。因路由器主动外拨，常规防火墙对外部入站流量的防护无效。Zbtlink 回应称该功能仅用于售后维护、仅保留在样品机，但同时下架了固件下载并承认存在固件安全漏洞。**无修复固件可期**，VulnCheck 建议按"设备已失陷"处置，在防火墙阻断 4 个命令服务器地址，重要设备直接更换。

**IOC：**

| 类型 | IOC | 说明 | 可信度 |
| --- | --- | --- | --- |
| IP | `47.100.190.96` | 主命令服务器（阿里云上海） | 高 |
| IP | `47.107.224.89` | 主命令服务器（阿里云深圳） | 高 |
| IP | `45.32.81.152` | 备用命令服务器（Vultr） | 高 |
| IP | `43.248.136.125` | 备用命令服务器（江苏东云） | 高 |
| 域名 | `zbtctl.epplink[.]net` | 主命令域 | 高 |
| 域名 | `online-string.com` | 备用命令域 | 高 |
| 域名 | `rbdg4nzqadui[.]wikaba[.]com` | 备用命令域 | 高 |
| 进程 | `kworker`（无方括号、真实内存占用） | 伪装内核线程的植入进程 | 高 |
| 启动脚本 | `skworker` | 后门自启脚本 | 高 |

**处置建议：**  
对照型号清单（按型号而非外壳品牌核对）排查受影响路由器；防火墙/出口网关阻断上述 4 个命令服务器地址与 7001 端口外联；处理重要业务的设备直接更换并更换相关凭据；持续监控设备外联行为。

**ATT&CK 映射：** 供应链预装植入对应 `T1195`（Supply Chain Compromise），外联回传对应 `T1071`（Application Layer Protocol），命令执行对应 `T1059`（Command and Scripting Interpreter）。
