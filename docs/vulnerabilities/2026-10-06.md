### 1.3 今日重点关注

1. **`CVE-2026-61500`：Rejetto HFS 会话签名密钥弱随机致认证绕过与远程代码执行（已在野利用 + 公开 PoC）**  
   影响 Rejetto HFS 3.0.0–3.2.0，攻击者无需认证即可经 `loginSrp1` 响应恢复 V8 PRNG 状态、伪造管理员 Session，并借 `server_code` 执行服务端代码。当前状态为 **安全媒体披露已在野利用、GitHub 已有公开复现仓库**，建议 **立即升级至 3.2.1，并显式配置强 `COOKIE_SIGN_KEYS`**。

2. **`CVE-2026-104286`：Fortinet FortiMail 路径遍历致未认证任意文件写（KEV，已逾期）**  
   影响 FortiMail 8.0.0–8.0.1 / 7.6.0–7.6.6 / 7.4.0–7.4.8 / 7.2.0–7.2.9，**未认证攻击者可通过构造 HTTP/HTTPS 请求在系统底层写入任意文件（CVSS 9.8）**，可进一步植入 WebShell。**CISA KEV 整改期限 2026-10-04 已逾期 1 天**，请立即闭环。

3. **`CVE-2026-88779`：Citrix NetScaler ADC / Gateway 内存缓冲区越界（KEV，剩余 1 天）**  
   未经认证的网络攻击者可触发内存越界，导致进程崩溃或潜在代码执行。**KEV 整改期限 2026-10-07**，与已逾期的同系列旧条目（`CVE-2026-88771`/`88772`）叠加，Citrix 边界网关闭环压力显著。

4. **`CVE-2026-100103` / `CVE-2026-100102` / `CVE-2026-103510`：Perforce P4 Search 认证缺陷集群**  
   P4 Search 容器镜像（< 2026.4.2）存在 **默认认证令牌（CVSS 4.0 = 10.0）**、**暴露 JDWP 调试接口致未认证 RCE（9.5）**、**空令牌 fail-open（9.5）** 三条严重缺陷，均可导致最高应用权限甚至 P4 Server 失陷，建议 **立即升级至 2026.4.2**。

5. **Plane 项目管理平台缺陷集群 + Penpot SVG 命令注入**  
   `CVE-2026-105636`（Webhook 重定向 SSRF 至云元数据，9.9）、`CVE-2026-105639`（注册流程邮箱未验证致邀请接管，9.8）、`CVE-2026-105641`（默认 SECRET_KEY，9.8）等 10 余条 Plane 缺陷均修复于 **1.4.0**；`CVE-2026-105691`（Penpot SVG 导出命令注入，9.9）修复于 **2.18.0**。建议对自建协作与设计平台统一排查升级。

### 3.1 CVE-2026-61500 — Rejetto HFS 会话签名密钥弱随机致认证绕过与远程代码执行（已在野利用）

!!! danger "严重漏洞（已在野利用，且已有公开 PoC）"
    Rejetto HFS 3.0.0–3.2.0 使用 JavaScript `Math.random()` 生成 Koa 会话 Cookie 的签名密钥，并在未认证的 SRP 登录握手中泄露同一 PRNG 的输出。攻击者可采集少量登录响应重建 PRNG 状态、恢复签名密钥、伪造管理员会话，并借助 `server_code` 配置功能以服务进程权限执行代码。

#### 3.1.2 漏洞摘要

该漏洞影响 Rejetto HFS（HTTP File Server）3.0.0 至 3.2.0。HFS 使用 Koa 框架的签名 Cookie 保存会话，而其签名密钥（signing key）由 JavaScript 的 `Math.random()` 生成——该生成器底层为 V8 引擎的 `xorshift128+` 非密码学算法；同时，未认证的 SRP 登录接口（`loginSrp1`）会向客户端返回同一 PRNG 的输出（数值化的 `loggingIn.sid`），使状态可被反推。

攻击者无需任何凭据即可：向已知账号 `admin` 发送约 6 次 `loginSrp1` 请求，采集响应中的 PRNG 观测值，暴力还原被省略的低位比特并推进 V8 的 `xorshift128+` 递推，恢复签名密钥；随后伪造包含 `username: admin` 的会话 Cookie，经 `get_config` 验证管理员权限，最后通过 `set_config` 注入 `server_code` 模块执行服务端 JavaScript，实现远程代码执行。**安全媒体披露该漏洞已在野被实际利用，且 GitHub 已出现完整可复现的 PoC 与隔离 Docker 实验环境。** 上游已通过改用 Node.js `randomBytes()`（32 字节）生成密钥、并以 `randomUUID()` 替换对外暴露的数值登录标识进行修复。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 HFS 的 HTTP 服务端口（默认 80/443） |
| 身份认证 | 无需 | 攻击发生于未认证的 `loginSrp1` 握手 |
| 用户交互 | 不需要 | 直接构造 HTTP 请求 |
| 特定配置 | 否 | 默认配置即可；已知账号名（如 `admin`）需存在 |
| 利用复杂度 | 低 | 黑盒 HTTP 链路，公开 PoC 已封装全流程 |

**技术原理：**

HFS 将会话 Cookie 的签名密钥委托给 `Math.random()`，而 V8 的 `Math.random()` 实现为可预测的 `xorshift128+` 状态机；登录握手又直接泄露该生成器的输出，使得仅凭少量样本即可在可行算力内还原内部状态与密钥。密钥一旦恢复，攻击者即可离线构造任意合法签名会话，完全绕过认证。获得管理员会话后，`set_config` 会加载并执行 `server_code` 指定的服务端 JavaScript 模块，等价于任意代码执行。

**核心利用链：**

```text
攻击者
  └─ 定位公网可达的 Rejetto HFS（3.0.0–3.2.0）
      └─ 对已知账号（如 admin）反复调用未认证的 loginSrp1 接口
          └─ 采集响应中泄漏的 PRNG 输出（数值 sid）
              └─ 还原 V8 xorshift128+ 状态并恢复会话签名密钥
                  └─ 伪造 username=admin 的管理员会话 Cookie
                      └─ set_config 注入 server_code 模块 → 远程代码执行
```

#### 3.1.11 风险影响

- 被勒索软件、挖矿木马或僵尸网络二次利用。

#### 3.1.13 修复与缓解措施

#### 官方修复

1. 将 Rejetto HFS 升级至 `3.2.1` 或更高版本（修复 commit `59472e53`）；
2. 显式配置强随机的 `COOKIE_SIGN_KEYS`（32 字节随机值）并轮换既有会话密钥；
3. 升级前备份共享目录与配置文件；
4. 在测试环境验证兼容性与回退方案；
5. 升级后重新执行会话安全检测并留存证据。

#### 临时缓解

无法立即升级时，可采取：

- 关闭服务的公网暴露，仅允许可信 IP / 内网访问；
- 显式设置强 `COOKIE_SIGN_KEYS`，并强制使既有会话全部失效；
- 在 WAF/网关拦截异常的 `loginSrp1` 高频请求与对 `set_config` 的外部访问；
- 对共享目录实施只读与最小权限，禁用或限制 `server_code` 功能；
- 加强日志审计、主机监控和异常外联检测。

### 3.4 CVE-2026-100103 / CVE-2026-100102 / CVE-2026-103510 — Perforce P4 Search 认证缺陷集群

!!! danger "严重漏洞（默认令牌认证绕过 + 裸露调试口 RCE + 空令牌 fail-open）"
    Perforce P4 Search 容器镜像（< 2026.4.2）存在三条严重认证缺陷：服务认证令牌被重置为公开默认值、启用未认证 Java 调试接口（JDWP）、令牌为空时未安全失败。三者均可让网络可达的未认证攻击者获得最高应用权限，甚至危及所连接的 P4 Server。

#### 3.4.2 漏洞摘要

该集群影响 Perforce P4 Search 的容器镜像（版本早于 2026.4.2）。三条缺陷分别对应攻击面中的三个“低成本入口”：

- `CVE-2026-100103`（10.0）：**服务认证令牌被重置为公开记录的默认值**，任何具备网络访问能力的未认证攻击者即可获得最高应用权限，可能导致任意代码执行并危及所连接的 P4 Server；
- `CVE-2026-100102`（9.5）：容器镜像**启用了未认证的 Java 调试接口（JDWP）**，网络可达该调试口的攻击者可**以 P4 Search 服务账号身份执行任意代码**；
- `CVE-2026-103510`（9.5）：**服务认证令牌为空时未安全失败（fail-open）**，在受影响配置下未认证攻击者可获得最高应用权限，进而危及 P4 Search 及所连接的 P4 Server。

三条缺陷均指向“P4 Search 若以默认或不当配置暴露于网络，即等同未认证失陷”，处置上应统一升级至 2026.4.2 并核查暴露面。

#### 3.4.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 P4 Search 服务或被映射的 JDWP 调试端口 |
| 身份认证 | 无需 | 三条缺陷均在认证前 / 凭借默认凭据成立 |
| 用户交互 | 不需要 | 直接构造请求或使用调试协议 |
| 特定配置 | 是 | 100103 依赖默认令牌未覆盖；100102 依赖调试口暴露；103510 依赖令牌为空 |
| 利用复杂度 | 低 | 默认配置或仅需网络可达即可 |

**技术原理：**

P4 Search 的服务认证令牌在容器镜像中硬编码了公开默认值，且部分部署未强制覆盖；JDWP（Java Debug Wire Protocol）调试代理在镜像中被默认启用并监听，攻击者可通过调试协议注入任意代码；令牌校验路径在“令牌为空”时直接放行（fail-open），而非拒绝访问。三者共通点是**认证边界在默认/异常配置下失效**，导致未认证访问直达最高权限。

**核心利用链：**

```text
攻击者
  └─ 定位网络可达的 Perforce P4 Search 服务
      ├─ 使用公开默认令牌直接调用管理接口（CVE-2026-100103）
      ├─ 连接未认证 JDWP 调试口注入代码（CVE-2026-100102）
      └─ 在令牌为空的部署中直接绕过认证（CVE-2026-103510）
          └─ 获得最高应用权限 / 以服务账号执行代码
              └─ 危及关联的 P4 Server 与代码资产
```

!!! danger "严重漏洞"

#### 3.5.2 漏洞摘要

该漏洞位于 Penpot 的 SVG 导出器（exporter）。导出器在处理文本对象时，把攻击者可控的 `fill-color` 值直接拼接进 `ppmcolormask` 命令字符串，并通过 `child_process.exec` 执行该字符串；由于未对 shell 元字符做过滤，攻击者可在填充色中存入命令注入载荷，并在触发 SVG 导出时以**导出服务进程权限**执行任意命令。触发者只需具备“可编辑某文件”的低权限即可，且同样的导出还可通过**指向恶意文件的公开分享链接**被触发（即受害者打开分享链接即可中招）。该缺陷在 2.18.0 中修复。

#### 3.5.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 Penpot 服务与导出功能 |
| 身份认证 | 普通用户 | 需具备可编辑目标文件的低权限账号 |
| 用户交互 | 不需要（对 API 侧）/ 需要（对分享链接受害者） | 直接触发导出，或诱导受害者打开恶意分享链接 |
| 特定配置 | 否 | 使用 SVG 导出功能即可 |
| 利用复杂度 | 低 | 载荷存于填充色字段，触发导出即执行 |

**技术原理：**

SVG 导出器为生成位图蒙版调用了 ImageMagick 的 `ppmcolormask` 工具，命令字符串由代码拼接而非参数化传入，且 `exec` 经由 shell 执行；当文本对象的 `fill-color` 成为命令行的一部分时，注入的 `;`、`$()`、反引号等元字符即被 shell 解释，从而以导出服务权限执行任意命令。服务端渲染（`S:C`）使其影响可跨越安全边界。

**核心利用链：**

```text
攻击者（具备文件编辑权限）
  └─ 在某文本对象的 fill-color 中存入 shell 元字符载荷
      └─ 触发 SVG 导出（或经公开分享链接诱导他人触发）
          └─ 导出器将 fill-color 拼入 ppmcolormask 命令并 exec
              └─ shell 解释注入载荷
                  └─ 以导出服务进程权限执行任意命令
```

#### 3.6.2 漏洞摘要

Plane 是一款广受欢迎的开源自托管项目管理工具，本批次披露的缺陷集中在“认证边界与内部资源访问”：

- `CVE-2026-105636`（9.9，SSRF）：Webhook 投递任务调用 `requests.post()` 时未设置 `allow_redirects=False` 且不校验重定向目标；`validate_url()` 仅拦截原始 URL 的私有/回环/保留地址，**未校验经 302 跳转后的最终地址**。可创建工作区的用户可将 Webhook 指向攻击者可控的公网端点，由其 302 重定向至内网地址，Plane worker 随之抓取**云元数据等内部资源**并将响应体存入 `webhook_logs`。
- `CVE-2026-105639`（9.8，账号接管）：注册流程为任意提交的邮箱直接创建已登录的 User 行，不做带外所有权校验，而 `User.email` 为唯一值；攻击者可用**受害者邮箱**注册账号，枚举待处理邀请并以其身份加入工作区。
- `CVE-2026-105641`（9.8，默认密钥）：社区部署清单（`deployments/aio/community/`、`deployments/cli/community/`）内置**公开已知的 `SECRET_KEY` 与 `LIVE_SERVER_SECRET_KEY` 默认值**，若运维未覆盖则长期生效；据此可伪造 Django 签名值、绕过 live-service 认证。
- `CVE-2026-105637`（9.6，越权）：`ProjectBulkAssetEndpoint.post` 未按 URL 中的 `project_id` 约束查询，工作区 Guest 可提交同工作区其他项目的资产 UUID，将其重绑定到攻击者可控实体并获取**预签名下载 URL**，劫持他人文件。

此外，该平台同批还包含 `CVE-2026-105638`（magic-code 登录 OTP 无失败计数，9.1）、`CVE-2026-105640`（信任 Gitea/自建 GitLab OAuth 未验证邮箱，9.1）等严重项，以及 `CVE-2026-104892`（明文记录 API Key）、`CVE-2026-105630`（低权限上传 SVG 致存储型 XSS）、`CVE-2026-105632`（GraphQL 加入任意项目）等多项高危缺陷。上述均修复于 **1.4.0**。

#### 3.6.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 Plane 服务；SSRF 场景需 worker 可出站 |
| 身份认证 | 无需 / 低权限（视编号） | 105639/105641 未认证即可；105636/105637 需可创建工作区 / Guest |
| 用户交互 | 不需要 | 直接构造请求 |
| 特定配置 | 是 | 105641 依赖部署未覆盖默认密钥；105636 依赖 worker 出站能力 |

**技术原理：**

共通成因是**在授权/信任边界上过度信任用户可控输入**：SSRF 场景仅校验首跳 URL 而不跟踪重定向；注册场景信任未验证的邮箱即视为所有权证明；部署清单把生产密钥硬编码为公开默认值；实体接口仅按工作区而非项目约束资源归属。

**核心利用链（以 Webhook SSRF 为例）：**

```text
攻击者（可创建工作区）
  └─ 注册 Webhook，指向攻击者可控公网端点
      └─ 该端点返回 302 重定向到内网/云元数据地址
          └─ Plane worker 跟随重定向抓取内部资源
              └─ 响应体写入 webhook_logs → 攻击者读取敏感数据
```

### 3.8 CVE-2026-88395 — GouGuOA `keywords` 参数 SQL 注入

!!! danger "严重漏洞"

#### 3.8.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 OA 的 Web 接口 |

| 特定配置 | 否 | 常规部署即可 |
| 利用复杂度 | 低 | 单请求即可注入 |

**技术原理：**

`/home/message/rubbish` 接口将 `keywords` 参数未经参数化（预处理）即拼入 SQL 查询，攻击者可通过闭合引号、联合查询或布尔/时间盲注读取或篡改数据库内容；若数据库账号权限较高，还可能经 `INTO OUTFILE` 或存储过程升级为文件写入乃至代码执行。

**核心利用链：**

```text
攻击者
  └─ 定位暴露的 GouGuOA 接口 /home/message/rubbish
      └─ 在 keywords 参数中注入 SQL 语法
          └─ 后端拼接执行未预处理查询
              └─ 读取/篡改数据库（可能升级为文件写与 RCE）
```
