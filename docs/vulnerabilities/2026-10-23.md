### 1.3 今日重点关注

1. **`CVE-2026-111497`：Google Brotli 解码器堆缓冲区溢出：可致相邻状态破坏、内存泄露与潜在 RCE（9.2，EPSS 36%，Nuclei 已覆盖）**  
   Brotli 1.0.3–1.2.0 的解码器（`c/dec/decode.c`）存在缓冲区溢出（`CWE-252` 未检查返回值、`CWE-787` 越界写），**未认证远程攻击者可用特制 Brotli 压缩流破坏相邻解码器状态内存、泄露敏感内存、造成 DoS，或潜在执行任意代码**。修复版本为 1.0.10／1.1.1／1.2.1。Brotli 是 Web 生态的“隐形基础设施”：HTTP `Content-Encoding: br`、Node.js 内置压缩、CDN 边缘压缩、以及大量静态资源预压缩都依赖它。**这意味着一个压缩流可以打穿从边缘到应用的整条链路**，而“解压”通常发生在最没有防护的位置（网关、中间件、日志采集）。EPSS 36.0% 表明扫描器已大规模跟进。

2. **`CVE-2026-79857`：HPE Aruba AOS-8/AOS-10 批量 10.0：PAPI 协议命令注入与多处未认证 RCE（71 条）**  
   HPE 本期一次性披露 **71 条** Aruba Networking 漏洞，其中多条为 10.0：**PAPI 协议命令注入**（`CVE-2026-79857`，向 UDP 端口发送特制包即可**以特权用户在底层 OS 执行任意代码**）、**AOS-8／AOS-10 接口命令注入**（`CVE-2026-79846`／`79861`）、**认证绕过**（`CVE-2026-79844`／`79850`，AOS-10／AOS-8）、**缓冲区溢出**（`CVE-2026-79847`／`79851`／`79856`／`79859`／`79860`）、**SQL 注入**（`CVE-2026-79848`／`79849`／`79852`／`79854`）、**SSH 守护进程认证绕过**（`CVE-2026-79855`，AOS-8）、**敏感信息泄露**（`CVE-2026-79853`）。Aruba 无线控制器与 AP 是园区网的核心，**拿下控制器即可批量接管所有接入点、解密无线流量、改写网络策略**。

3. **`CVE-2026-110264`：GitLab 再曝 10.0 未认证 RCE：编译正则时的整数溢出（影响 7.0 起全部版本）**  
   GitLab CE/EE **自 7.0 起至多个分支的修复版本**（18.11.13、19.0.10、19.1.9、19.2.9、19.3.6、19.4.3、19.5.1）存在未认证 RCE（`CWE-190` 整数溢出）：**编译特制正则表达式时发生整数溢出**，导致可在服务器上执行任意代码，CVSS 10.0。这是本期报告的补齐期内**第二次**出现 GitLab 10.0（10-14 期为 `CVE-2026-97229`，同样是正则编译路径）。**同一产品在 10 天内因同一类根因（正则处理）连续产生两个 10.0**，说明其正则引擎的边界处理需要系统性加固，而非单点修复。

4. **`CVE-2026-102785`：YOOtheme Pro 签名复用 + 路径穿越写入 PNG/PHP 多形态文件（10.0）**  
   YOOtheme Pro 5.0.0–5.0.52 的**公开可访问的图片处理端点**未把“归一化后的图片操作”与“输出目标”完整绑定到请求签名上。攻击者可**复用从合法公开图片 URL 中获取的签名**，注入额外的图片操作、穿越出预期缓存目录，并把**攻击者控制的 PNG/PHP 多形态文件（polyglot）** 写入可执行的公开媒体目录，从而未认证 RCE。CVSS 10.0。这类“签名只保护了一部分参数”的设计在图片/媒体处理链路中非常常见，值得作为通用审计项。

### 1.4 综合研判

本期 537 条，严重 66 条（12.3%）、高危 177 条（33.0%）。**第一主线是“底层编码/压缩库”**：Brotli 解码器堆溢出（`CVE-2026-111497`，EPSS 36%，Nuclei 已覆盖）。这类库的特点是“无处不在但从不被单独管理”——它藏在 nginx、Node.js、CDN、甚至日志代理里，**你无法用产品清单找到它，只能用依赖清单与版本探测**。第二主线是**网络设备批量披露**：HPE Aruba 71 条、其中十余条 10.0 未认证。园区无线控制器是高价值目标（能解密无线流量、能改网络策略），但补丁窗口通常受“变更审批 + 业务连续性”约束，**建议先做“控制器管理面与 PAPI 端口的可达性收敛”**，再排期升级。第三主线是**同一根因的重复出现**：GitLab 在 10 天内第二次因“正则编译整数溢出”产生 10.0（本次影响 7.0 起全部版本，说明缺陷非常古老），Pillow 在本期继续出现多帧加载器缺陷（`CVE-2026-96639`，9.8）。第四类是**签名/校验只覆盖部分的逻辑缺陷**：YOOtheme Pro 的图片端点复用签名（10.0）、以及若干 Patchstack 侧的 WordPress 插件提权/上传。整体判断：本期属“高烈度但可利用性分化明显”的一天——Brotli 与 GitLab 需要立即行动，Aruba 需要按暴露面排期，YOOtheme 需要按“是否对外提供图片处理”判断。KEV 无新增，节奏上处在 PHP 两条被收录（10-26）之前的缓冲期。

#### 3.1.2 漏洞摘要

Google Brotli 1.0.3 至 1.2.0（全平台）的解码器实现（`c/dec/decode.c`）存在缓冲区溢出，归类 `CWE-252`（未检查返回值）与 `CWE-787`（越界写），CVSS 9.2。未认证远程攻击者可用**特制的 Brotli 压缩流**实现四类后果：**破坏相邻解码器状态内存、泄露敏感内存内容、造成拒绝服务、或潜在执行任意代码**。修复版本为 1.0.10／1.1.1／1.2.1。Brotli 的特殊性在于它几乎不可见却无处不在：HTTP 的 `Content-Encoding: br`、Node.js 内置压缩模块、CDN 边缘压缩、静态资源预压缩、部分日志与 RPC 框架。**因此一条压缩流可能在“网关解压 → 中间件解压 → 应用解压”的任意一层触发缺陷**，而解压通常发生在防护最薄弱的位置。Node.js 官方已在 10 月安全公告中为该问题发布专门补丁（引用中直接给出链接），说明上游生态已确认严重性。EPSS 36.0% 表明扫描器已大规模跟进，**属于“有模板、有公开分析、即将被批量尝试”的阶段**。

> 原文摘要（NVD）：A buffer overflow vulnerability in the Brotli decoder (c/dec/decode.c) in Google Brotli versions 1.0.3 through 1.2.0 on all platforms allows a remote unauthenticated attacker to corrupt adjacent decoder state memory, disclose sensitive memory contents, cause a denial of service, or potentially execute arbitrary code using a crafted Brotli-compressed stream.      Users need to update any Brotli libraries or binaries between 1.0.3 through 1.2.0 to the latest available version: 1.0.10 or 1.1.1 or 1.2.1.

**技术原理：**

#### 3.4.2 漏洞摘要

Joomla 扩展 YOOtheme Pro 5.0.0–5.0.52 存在未认证远程代码执行（`CWE-434` 危险类型文件上传），CVSS 10.0。其**公开可访问的图片变换（image transformation）处理器**存在签名绑定不全的问题：**归一化后的图片操作与输出目标没有被完整绑定到请求签名上**。因此攻击者可以**复用从合法公开图片 URL 中取得的签名**，在其基础上注入额外的图片操作、**穿越出预期缓存目录**，最终把一个**攻击者控制的 PNG/PHP 多形态文件（polyglot）** 写入可执行的公开媒体目录——由于文件既是合法 PNG 又是合法 PHP，既能通过图片校验，又能被 Web 服务器当脚本执行。这类设计缺陷的根源是“签名只保护了参数的一部分”：签名覆盖了“谁可以请求”，却没有覆盖“请求的具体内容与目标路径”。

## 五、当日处置建议

1. **Brotli 要按依赖清单查，不按产品清单查**：它藏在 nginx 模块、Node.js、CDN、日志代理里。建议导出 SBOM 或 `ldd` 结果检索 `brotli`，并同步确认 CDN 服务商是否已修复。
2. **GitLab 建议改为“周检查”**：10 天内两次 10.0、同一根因家族、影响范围回溯到 7.0。这类产品一旦被拿下影响整条供应链，值得提高巡检频率而非按季度打补丁。
3. **Aruba 先收敛再升级**：71 条不可能逐条处置。有效动作是：把控制器管理面、PAPI UDP 端口限制在受信网段，隔离无线管理网段，然后按维护窗口统一升级 AOS-8／AOS-10。
4. **审计“签名只保护一部分参数”的设计**：YOOtheme Pro 的教训适用于所有带签名的媒体/下载/回调 URL。检查项：签名是否覆盖全部影响输出的参数、服务端是否用相同归一化方式重算。
5. **媒体目录一律禁止解析脚本**：多形态文件（PNG+PHP）能绕过图片校验，但绕不过“该目录不解析 PHP”这条服务器配置。这是成本最低、收益最高的一条基线。
