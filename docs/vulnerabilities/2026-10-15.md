### 1.3 今日重点关注

1. **`CVE-2026-59774`：Gitea Org-mode INCLUDE 路径遍历：未认证读文件并可链至 RCE（9.8，Metasploit 模块已收录）**  
   Gitea 的 Org-mode 渲染器在处理仓库标记中的 `INCLUDE` 指令时**未限制服务端文件访问**，未认证攻击者可用一个公开仓库读取 Gitea 服务账号可访问的任意文件。若读到 `app.ini` 及其 `INTERNAL_TOKEN`，即可串联内部 logger 接口**修改 Git hook 并以服务账号执行命令**。这是本期技术含量最高的一条：它把“文件读取”升级为“完整 RCE 链”，且 Metasploit 已有 `auxiliary_gather` 模块、Nuclei 已有模板、EPSS 28.3%——**三源同时确认可武器化**。

2. **`CVE-2026-76519`：Cisco Secure Email Gateway 邮件附件处理缺陷致 root 写文件（9.8，KEV）**  
   启用文件信誉服务（file reputation）时，AMP 功能对**邮件附件处理不当**（`CWE-23` 相对路径遍历），未认证远程攻击者只需**发一封带特制附件的邮件**即可在底层系统写入任意文件，并以 **root 权限执行命令**。攻击入口是邮件——意味着无需任何网络暴露面侦察，只要能发信即可尝试。该条目 10-14 被 CISA 收录 KEV，期限 10-17。

3. **`CVE-2026-110447`：Collabora Online CODE Server 命令注入：官方确认 9–10 月已在野利用（9.2）**  
   Nextcloud 的 richdocumentscode 应用（26.4.303 之前）在 **CODE Server 未运行时**（例如刚重启）会经 `proxy.php` 触发 OS 命令注入。官方描述明确写出“**as exploited in the wild in September and October 2026**”——这是本期唯一在描述层面直接确认在野利用的编号（Cisco/PAN-OS 是在 KEV 层面确认）。仅影响“内置 CODE Server”的部署形态，独立 Collabora Online 服务器不受影响，这一区分对排查很关键。

4. **`CVE-2026-0322`：Palo Alto PAN-OS 管理面代码注入致 root RCE（8.6，KEV）**  
   PAN-OS 管理接口存在代码注入（`CWE-94`），**具备网络访问且已认证**的攻击者可以 root 权限在防火墙上执行任意代码。官方同时强调“按最佳实践将管理面限制为可信内网 IP 可将风险降到最低”。该条目已入 KEV（10-14 收录，期限 10-17）。**边界防火墙被拿下意味着整条网络策略失效**，因此即便需要认证，也应按 P0 对待——攻击者通常先通过钓鱼或弱口令获取一个低权限账号再完成提权。

### 1.4 综合研判

本期 931 条，严重 105 条（11.3%）、高危 449 条（48.2%），未评分 43 条（4.6%）需在本周内复核。从漏洞分布看，本期呈现“**三类入口同时被攻击**”的格局：邮件入口（Cisco SEG 的附件路径遍历，未认证、发信即可）、代码托管入口（Gitea 的 Org-mode 文件读取 → hook 修改 → RCE，Metasploit 已模块化）、协作办公入口（Collabora CODE Server 命令注入，官方确认 9–10 月在野利用）。这三类入口的共同特征是**位于“内部信任区”**——邮件网关、内网 Git、办公套件通常不会被当作对外攻击面来加固，但一旦被利用，攻击者获得的是“已在内部”的位置。与之并行的是 Adobe ColdFusion 的三条 10.0（`CVE-2026-105899` 任意文件上传、`CVE-2026-106624` 代码注入、`CVE-2026-106622` SSRF，同属 APSB26-144）：ColdFusion 历史上有大量 10.0 级 RCE 被实际利用，**即便本期四源均无 PoC 命中，也不宜按“低风险”处理**。另有 `CVE-2026-85714`（Stirling-PDF，管理员上传恶意 SQL 文件绕过白名单，经 H2 的 `FILE_READ`／`CSVWRITE`／`CREATE ALIAS` 触发副作用）值得注意——它说明“数据库导入功能”常是隐藏的高危入口。KEV 侧本期新增 2 条、可回溯看到另有 2 条后续收录，四条的期限均为 3 天，与上一期 Ivanti、Windows 两条叠加，**形成 10-16 至 10-17 的集中到期压力**。

### 3.1 CVE-2026-59774 — Gitea Org-mode INCLUDE 路径遍历致任意文件读取并可链至 RCE（9.8）

#### 3.1.2 漏洞摘要

Gitea 的 Org-mode 标记渲染器在处理仓库标记端点提交的 `INCLUDE` 指令时，**未阻止访问服务端文件**（`CWE-22` 路径遍历）。未认证攻击者只需借助一个**公开仓库**（自己创建或已有），即可读取 Gitea 服务账号可访问的任意文件，CVSS 9.8。真正让这条漏洞从“信息泄露”升级为“远程代码执行”的是利用链的第二段：若读取到 `app.ini` 及其中的 `INTERNAL_TOKEN`，攻击者可串联 Gitea 的内部 logger 接口（该接口以内部令牌认证），利用其写入能力**修改某个仓库的 Git hook**，从而在服务账号上下文中执行任意命令。这条链的精妙之处在于**每一段都是“合法功能”**：Org-mode 的 INCLUDE 是文档复用特性、logger 是诊断特性、hook 是扩展机制——缺陷只在于“未限制”与“令牌泄露后权限过大”。该编号已同时被 Metasploit（`auxiliary_gather/forgejo_orgmode_fileread_cve_2026_59774`）与 Nuclei 覆盖，EPSS 28.3%，是本窗口武器化程度最高的条目。

> 原文摘要（NVD）：Gitea's Org-mode markup renderer processes INCLUDE directives supplied to the repository markup endpoint without preventing access to server-side files. An unauthenticated attacker can use a suitable public repository to read files accessible to the Gitea service account. If the disclosed files include app.ini and its INTERNAL_TOKEN, the attacker can chain the disclosure with internal logger access to modify a Git hook and execute commands as the Gitea service account.

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | Gitea Web 入口（公开仓库的 markup 渲染端点） |
| 身份认证 | 无需 | 无需任何凭据即可触发 |
| 用户交互 | 不需要 | 无需受害者交互 |
| 特定配置 | 否 | 默认配置即受影响；存在公开仓库时无需任何凭据 |
| 利用复杂度 | 低 | 低（Metasploit 已有模块，Nuclei 已有模板） |

**技术原理：**

Org-mode 支持 `#+INCLUDE: "path"` 语法把外部文件内容嵌入当前文档。渲染器若在服务端解析并读取该路径，且不限制根目录，即等价于一个“任意文件读取接口”。关键在于**渲染发生在权限校验之外**：只要仓库公开，未认证用户即可触发渲染。第二段链条依赖 `INTERNAL_TOKEN` 的过度授权——该令牌设计用于服务内部组件通信，但既然被赋予了写日志/触发内部操作的能力，一旦泄露就可被外部复用；hook 目录可写则把“写文件”转成“执行代码”。

**核心利用链：**

```text
攻击者
  └─ 定位暴露的 目标组件（目标产品）
      └─ 构造含路径穿越序列的请求
          └─ 触发 CWE-22 对应处理逻辑
              └─ 读取/写入应用目录外的敏感文件
                  └─ 横向利用或持久化（视环境）
```

#### 3.4.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | ColdFusion Web/管理端口（默认 8500）可达 |

**技术原理：**

上传功能若只做前端校验或仅依赖扩展名黑名单，攻击者可用双扩展名、大小写变形、`.jsp`／`.cfm` 变体或内容类型伪造绕过，将可执行文件写入 Web 可访问目录；ColdFusion 的 `.cfm`／`.jsp` 一旦被请求即以服务进程权限执行。代码注入（`CWE-94`）则常见于表达式求值、模板编译路径，攻击者可把输入当作代码执行。两者叠加意味着“上传 + 执行”与“直接注入”两条路径同时可用。

**核心利用链：**

```text
攻击者
  └─ 定位暴露的 coldfusion（adobe）
      └─ 上传绕过类型校验的恶意文件
          └─ 触发 CWE-434 对应处理逻辑
              └─ 在服务器落地可执行内容
                  └─ 横向利用或持久化（视环境）
```

## 五、当日处置建议

1. **Gitea 先换令牌再查 hook**：Metasploit 模块已可用，意味着任何暴露的 Gitea 都可能已被“跑过一遍”。升级 1.27.1 后必须轮换 `INTERNAL_TOKEN`，并逐个仓库核对 `custom_hooks` 是否有异常脚本——只升级不清洗，等于留着后门。
2. **邮件网关按“发信即攻击”来评估**：Cisco ESA 的漏洞入口是附件，不需要端口暴露。无法立即升级时优先关掉 AMP 文件信誉服务，并检查 `/var`、`/tmp` 是否有异常文件。
3. **Collabora 的排查范围要精确**：仅“内置 CODE Server 的 Nextcloud 应用”受影响，独立 Collabora 服务器不受影响。先确认部署形态，再决定是否紧急升级，避免把资源砸在不受影响的实例上。
4. **ColdFusion 不因“无 PoC”降级**：该产品历史上的 10.0 级 RCE 几乎都被实际利用过。建议把 CFIDE 管理目录的互联网暴露作为独立高危项处理，即便补丁尚未到位。
5. **把“内部服务”当作攻击面**：Gitea、邮件网关、办公套件都在内网或 DMZ，本期三条最严重漏洞全部落在这些位置。建议在资产分级中增设“内部信任区”，并对其应用与边界同等的补丁时效要求。
6. **关注 10-16 至 10-17 的集中到期**：Ivanti、Windows（期限 10-16）与 Cisco ESA、PAN-OS（期限 10-17）四条 KEV 项在两天内集中到期，建议合并为一张冲刺表，由单一责任人跟踪闭环证据。
