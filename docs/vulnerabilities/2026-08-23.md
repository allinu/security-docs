#### 3.1.2 漏洞摘要

该漏洞存在于 Zimbra Collaboration Suite（ZCS）的 SNMP 监控组件中。当系统安装了可选的 `zimbra-snmp` 包并启用 SNMP 通知（`snmp_notify` 参数）时，由于对 SNMP 通知处理过程中不可信输入的净化不充分（sanitization failure），未认证攻击者可通过发送特制的 SMTP 请求，以 `zimbra` 用户权限执行任意操作系统命令（NVD 描述中攻击向量经 SMTP 请求触发）。处理通知的 `swatchdog` 服务在大多数安装中默认运行，放大实际攻击面。

> **公开时间/披露时间核实（经 web-search-skill 交叉核实）：** NVD `published` 为 2026-08-13；Zimbra 官方于 2026-07-20 发布 10.1.20 修复版本，CERT Polska 公告（[2026/145](https://moje.cert.pl/komunikaty/2026/145/aktywnie-wykorzystywana-podatnosc-w-zimbra-collaboration-suite/)）确认在野利用——各来源对 CERT Polska 确认时间表述不一（[Fnet 云网安转述为 08-17](http://www.baidu.com/link?url=T77NnQGdFUM0rloybxOusrtL5RtTgAVhvvNqMuWbd_sekC-uaTkWYSP6oN6P-e_Tmv9vg86QEfjDABS0fD2vCa)、公告页发布日期为 08-20），**以官方公告为准**；[CSDN 应急教程（08-22）](https://blog.csdn.net/weixin_42376192/article/details/163967141)称"2026 年 8 月多国 CERT 连续发布高危预警、进入大规模在野利用阶段"；CISA KEV 官方数据源核验：dateAdded=2026-08-21、dueDate=2026-08-24、knownRansomwareCampaignUse=Unknown。各来源时间线相互印证，无矛盾。

**本期新增状态（KEV）：** CISA 于 2026-08-21 将本漏洞（vendorProject=Synacor、product=Zimbra Collaboration Suite）新增收录至 [KEV 目录](https://www.cisa.gov/known-exploited-vulnerabilities-catalog?field_cve=CVE-2026-73570)，依据 [BOD 26-04](https://www.cisa.gov/news-events/directives/bod-26-04-prioritizing-security-updates-based-risk)（按风险优先安全更新）要求联邦机构在 **2026-08-24** 前完成修复，并执行 [取证分诊要求](https://www.cisa.gov/news-events/directives/bod-26-04-implementation-guidance-prioritizing-security-updates-based-risk)（Forensics Triage）。对非联邦机构同样具有重要参考意义：KEV 收录意味着 CISA 评估为"已在野利用"的已知漏洞，应优先于常规漏洞处置。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达邮件/SNMP 相关服务端口（攻击经 SMTP 请求触发） |
| 身份认证 | 无需 | 未认证即可利用 |
| 用户交互 | 不需要 | 直接发送特制请求 |
| 特定配置 | 是 | 安装 `zimbra-snmp` 包且启用 SNMP 通知（`snmp_notify`） |
| 利用复杂度 | 高（NVD 口径 AC:H） | 需满足特定配置组合；但默认启用组件放大风险 |

**技术原理：**

SNMP 监控组件在处理 SNMP 通知时未对不可信输入进行充分净化，攻击者注入的 shell 元字符可被拼接进系统命令执行路径，造成 OS 命令注入（CWE-78）。`swatchdog` 服务负责处理通知并默认运行，使得满足利用条件的实例比例较高。

**核心利用链：**

```text
攻击者
  └─ 发现启用 SNMP 通知的 Zimbra 实例
      └─ 发送特制 SMTP 请求（注入恶意命令）
          └─ 触发 SNMP 通知处理组件净化缺陷（CWE-78）
              └─ 以 zimbra 用户权限执行任意 shell 命令
                  └─ 落地 WebShell / 窃取数据 / 建立持久化
```

#### 3.2.2 漏洞摘要

AIT-GUI 是 NASA/JPL 开源 **AMMOS Instrument Toolkit**（Advanced Multi-Mission Operations System，用于航天器/科学仪器指令上传与遥测数据下载的地面数据系统框架）的浏览器端操作控制台，地面操作员通过它在轨实时下发指令。Cycode 研究团队（AI 辅助代码分析 + 人工验证）发现该控制台存在 **四个叠加的普通 Web 弱点**，组合后产生严重后果：

1. **网卡全绑定**：服务读取配置的 `host` 后将其忽略，实际绑定 `0.0.0.0`——即使操作员配置 `host: localhost` 也会暴露到整个可达网络；
2. **无认证/无会话/无 CSRF**：所有状态变更端点（`POST /cmd`、`POST /script/run`、`POST /seq`）无登录要求、无会话门禁、无 CSRF Token、无跨源限制；
3. **路径穿越**：`POST /seq` 与 `POST /script/run` 将用户原始输入直接拼接到根目录路径（如 `seqfile=../../../../...` 可越出目标目录）；同代码库的 `POST /scripts/load` 已有正确约束实现，但未一致应用；
4. **CSRF 跨站触发**：浏览器可跨站发送表单请求，操作员在用于控制台的同浏览器中打开恶意页面即可触发指令下发，防火墙无法阻断该向量（Cycode 用 headless 浏览器完成了零网络预检的 CSRF 复现演示）。

NVD 收录的 `CVE-2026-60112`（2026-07-29）覆盖其中"缺失认证"核心问题：任何未认证网络攻击者可调用 `Sessions.create()` 无凭据获取有效会话，随后经 `handle_cmd()` 将任意指令直接转发至 AIT 命令总线，CVSS 9.8，修复于 2.5.1；Cycode 报告（[GHSA-p9r8-2q67-fp86](https://cycode.com/blog/ait-gui-unauthenticated-command-execution/)，CVSS 9.4）披露完整 4 项问题，修复于 2.5.2（2026-08-12 发布）。**注意：** 经 GitHub 全球安全通告 API 核验，`GHSA-p9r8-2q67-fp86` 目前未收录于 GitHub 全局公告数据库（API 返回 404），Cycode 报告与媒体转载为事实来源，本站如实标注。

> **公开时间/披露时间核实（经 web-search-skill 交叉核实）：** NVD `published` 为 2026-07-29（早于公开披露）；[IT之家 08-22 报道](http://www.baidu.com/link?url=fYpS1Vyoq4-jHy66tos4OkMRL9hlwvU7O55gaBWcJI-gon9dZPAXN3qC7zVh650vle0TfxmzhwO-QnvJsdVUXtAbEs_zPv0Bran2yAvqOBi)（"9 小时前"）与 [DoNews 快讯](http://www.baidu.com/link?url=JaeIMbpNYdZTsVz77Hqk9QqCIg-fA4nH681RRjgah_2rgwUfyFWXErc7hpHV6RdreHqf4lQ6q5FXRsLc4YK2Hq)报道 Cycode 于 08-22 披露、NASA/JPL 于 **2026-08-12** 发布 2.5.2 修复（含修复提交，Cycode 研究员 Yuval Elbar 于 2026-07-10 编写修复提交，报告页面标注 Last updated 2026-08-19）；[51Testing 转载分析](http://www.baidu.com/link?url=JaeIMbpNYdZTsVz77Hqk9KCxFTN3eevCt7dJD35z9puEpc9L6FOKVHKU5ql-y9zdjb3GMlpxBuB2Ku6xlsFQO4sVUuhJQe00ljx0nL55QG3)亦指出该 GHSA 未出现在 GitHub 全局公告数据库、`CVE-2026-60112` 在该库中被列为未审查状态。NVD 与其他公开来源无时间矛盾。

| 用户交互 | 不需要（直接访问）；需要（CSRF 场景） | 直接访问端口即可；CSRF 场景需诱导操作员在控制台同浏览器访问恶意页面 |
| 特定配置 | 否 | 默认配置即可利用 |
| 利用复杂度 | 低 | 无需凭据、无交互（直接访问场景） |

**技术原理：**

AIT-GUI 的 HTTP 服务在启动时将配置读取的 host 值丢弃、绑定全部网卡接口；其所有状态变更路由（`POST /cmd`、`POST /script/run`、`POST /seq`）的调用链上不存在任何认证、授权、会话门禁或 CSRF 校验：`POST /cmd` 将 `command` 字段解析后直接交给命令总线执行；`POST /script/run` 与 `POST /seq` 将用户原始输入直接拼接文件系统路径（无越界约束，存在路径穿越）；浏览器跨站表单请求可绕过防火墙限制触发上述端点（CSRF）。NVD 收录的 `CVE-2026-60112` 核心为 `Sessions.create()` 无凭据校验即可签发会话并调用 `handle_cmd()` 下发任意指令（CWE-306）。

**核心利用链：**

```text
攻击者
  └─ 发现暴露的 AIT-GUI HTTP 服务（默认绑定 0.0.0.0）
      ├─ 直接访问：POST /cmd（command 字段）→ 命令总线 → 执行任意指令
      │             POST /script/run → 执行服务端脚本（可路径穿越）
      │             POST /seq → 执行命令序列（可路径穿越）
      └─ CSRF 向量：诱导操作员浏览器访问恶意页面
                     └─ 跨站表单请求触发 POST /cmd（无需直达目标网络）
```

#### 3.2.11 风险影响

漏洞成功利用后，可能导致：

- 未授权向航天器/科学仪器下发指令（直接影响在轨任务与设备安全）；

- 操作员浏览器被诱导触发 CSRF 时，防火墙无法阻断的隐蔽攻击路径。

## 五、当日处置建议

1. **立即处置（P0）— Zimbra `CVE-2026-73570`（KEV 已收录、处置截止 2026-08-24）：** 升级 ZCS 至 `10.1.20+`；按 CERT Polska 指引核查 `/var/log/zimbra.log` 服务状态变更特征与 Web 目录新增文件；按 CISA BOD 26-04 要求完成取证分诊；无法升级的实例禁用 `snmp_notify`/卸载 `zimbra-snmp` 并收敛暴露面。
2. **优先处置（P1）— AIT-GUI `CVE-2026-60112`（CVSS 9.8）：** 航天/科研领域部署单位核查 AMMOS Instrument Toolkit 版本并升级至 `2.5.2+`；核查服务是否意外绑定 `0.0.0.0`、是否存在未认证的 `/cmd`、`/script/run`、`/seq` 请求；前置代理强制认证并收敛访问来源。
3. **移动端排查 — ToxicPanda 2.0：** 审计设备上可疑 VPN/无障碍权限授权，检查开发者模式与无线调试是否被异常开启；企业 MDM 下发限制策略；对金融类应用用户开展防钓鱼宣导。
4. **车联网关注 — BADBOX 车机感染：** 与车机厂商确认 OTA/MQTT 更新通道安全性，将车机纳入资产监控，关注 Kaspersky 后续 IOC。
5. **区块链风险提示 — Allbridge 事件：** 跨链桥项目方核查跨链消息校验逻辑，用户关注项目方公告，谨慎参与高杠杆跨链操作。
6. **常规要求：** 对疑似遭受攻击的系统保留日志、流量、进程、文件及内存证据；完成修复后进行复测，并更新资产台账和漏洞处置记录。
