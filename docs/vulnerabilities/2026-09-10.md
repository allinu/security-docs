1. **`CVE-2026-87491`：Google Chrome V8 越界写在野 0day（2026 年第 7 个）**  
   Google 于 09-09 发布 Chrome 稳定版更新（153.0.8010.36 Linux / .36/.37 Windows、macOS），共修复 230 个安全漏洞，其中 V8 引擎越界写（CWE-787，CVSS 3.1 8.8）已遭在野利用——攻击者可通过特制 HTML 页面在沙箱内执行任意代码。CISA 当日收录 KEV，修复截止 **2026-09-23**；鉴于 09-03 的 `CVE-2026-85046`（第 36 期详录）修复窗口尚未关闭（截止 09-18），Chrome 系浏览器须连续完成两次版本线升级（详见 3.1）。

2. **微软 2026 年 9 月补丁日：2 个在野 0day + 记录级 974 CVE + 20 个可蠕虫化漏洞**  
   `CVE-2026-85880`（Windows ALPC 堆缓冲区溢出，可自低权限 AppContainer 逃逸提权 SYSTEM）与 `CVE-2026-81963`（Windows Update Stack 链接解析缺陷提权，恶意链接触发）均为已在野利用的本地提权 0day，09-08 同日入 KEV（截止 **2026-09-22**）；同批另有 RDS `CVE-2026-69525` 与 Windows DNS `CVE-2026-69730` 两个 CVSS 9.8 严重项、Exchange Server `CVE-2026-55007` 未认证 RCE（Visio 附件经内容索引触发）等。本批修复窗口统一为"尽快（微软建议 3 天内）"，详见 3.2/3.3/4.1/4.2。

3. **`CVE-2026-69414`（ShieldBreak）：官方引擎修复已发布，研究者称"补丁不完整"并公开 ShieldCrash PoC**  
   微软于 9 月初经恶意软件保护引擎 1.1.26080.3 修复 Defender 提权 0day（第 08-18 期详录时暂无补丁）；研究者 Chaotic Eclipse 于 09-07/08 发布 ShieldCrash PoC（GitHub 184★），主张特定条件下仍可触发同源问题、以 SYSTEM 权限读取任意文件且影响全部受支持 Windows——微软尚未确认。使用 Defender/终端安全产品的组织须核验引擎版本并跟踪微软回应（详见 3.4）。

### 1.4 综合研判

本期窗口是典型的"**补丁日洪峰 + 在野 0day 密集**"组合：微软 9 月补丁日创纪录地修复近千个 CVE（其中 20 个可蠕虫化），并出现 2 个**已确认在野利用的提权 0day**（ALPC、Update Stack）——二者均为本地提权形态（需先有初始立足点），但 ALPC 一项还承担"沙箱逃逸"职能，与浏览器/文档沙箱类防线直接相关；同一日 Google 修复第 7 个 2026 年 Chrome 在野 0day 并获 KEV 收录，浏览器升级连续两期（09-03、09-09）进入"在野窗口"，叠加 KEV 截止 09-18/09-23，**浏览器版本闭环应作为本周最确定的必办项**。微软侧除 2 个 0day 外，RDS（9.8）与 DNS（9.8）两个未认证远程利用形态的严重项虽暂无在野确认，但 DNS 被 ZDI 类比为 2020 年蠕虫化漏洞"SigRed"的精神续作，属 20 个可蠕虫化漏洞中最具潜在传播力的一类——**对互联网暴露的 DNS/AD/DHCP 等基础设施，建议不等在野证据直接按 P1 优先闭环**。第三风险线是 Defender「ShieldBreak」修复完整性的公开争议（ShieldCrash PoC）：若研究者主张成立，则"已装 9 月更新的全支持版 Windows + Defender 默认开启"环境仍存在本地提权面，处置上先核验引擎版本 ≥1.1.26080.3、再跟踪微软后续回应。事件类（PoisonedRefresh/F5、AI 蒸馏联合公告、APIS 跟进）按第四章简报登记。综合判断本期整体风险为**较高风险**，处置重心为"三条 KEV 在野线（浏览器 + Windows 0day）限期闭环 + 补丁日严重项一周内升级 + Defender 引擎核验跟踪"。

!!! danger "研判结论：较高风险"
    本期最主要风险点是微软 9 月补丁日与 Chrome 更新中的**三条 KEV 在野线**：所有 Windows/Chrome 用户须在 2026-09-22/09-23（KEV 截止）前完成 `CVE-2026-85880`、`CVE-2026-81963`（Windows 9 月安全更新，微软建议 3 天内）与 `CVE-2026-87491`（Chrome ≥ 153.0.8010.36/.37）的升级闭环；互联网暴露的 Exchange/RDS/DNS 服务器按 P1 于一周内升级同批补丁（`CVE-2026-55007`/`CVE-2026-69380`/`CVE-2026-69525`/`CVE-2026-69730`）；Defender 用户核验恶意软件保护引擎版本 ≥ 1.1.26080.3 并跟踪微软对 ShieldCrash「补丁不完整」主张的回应（`CVE-2026-69414`，P1）。

    Google Chrome 的 V8 JavaScript/WebAssembly 引擎存在越界写漏洞（CWE-787）：远程攻击者可通过诱导用户访问特制 HTML 页面触发，在浏览器渲染进程（沙箱）内执行任意代码。Google 已确认该漏洞存在在野利用，是 2026 年第 7 个被在野利用的 Chrome 零日；Chrome 稳定版 153.0.8010.36/.37（2026-09-09）已修复，CISA 于 09-09 当日收录 KEV，修复截止 2026-09-23。

#### 3.1.2 漏洞摘要

该漏洞位于 Chrome 的 V8 JavaScript/WebAssembly 引擎，属越界写（CWE-787）类内存破坏：当 V8 在处理特制 JavaScript 时发生越界写入，可能破坏引擎内部对象布局，被利用为沙箱内的任意代码执行原语。远程攻击者可通过**特制 HTML 页面**触发——钓鱼链接、恶意广告、被攻陷网站投递均可，受害者只需使用受影响版本 Chrome 访问该页面（用户交互限于"访问页面"本身）。成功利用可在浏览器渲染进程内执行任意代码；若叠加沙箱逃逸链，可进一步控制设备。Google 未披露在野攻击细节、攻击目标与利用链是否包含沙箱逃逸。该漏洞是 2026 年第 7 个被在野利用的 Chrome 零日——此前 6 个为：2 月 `CVE-2026-2441`（CSS 释放后使用）、3 月 `CVE-2026-3909`（Skia 越界写）与 `CVE-2026-3910`（V8 实现缺陷）、4 月 `CVE-2026-5281`（Dawn/WebGPU 释放后使用）、6 月 `CVE-2026-11645`（V8 越界内存访问）、9 月 `CVE-2026-85046`（V8 类型混淆，第 36 期详录）——其中 `CVE-2026-85046` 与本期 `CVE-2026-87491` 同在 V8 引擎、披露间隔仅 6 天，V8 攻击面研究活跃度可见一斑。09-09 的稳定版更新（153.0.8010.36/.37）共修复 230 个安全漏洞，`CVE-2026-87491` 为唯一确认在野利用项。

> 该漏洞的防御处置与第 36 期 `CVE-2026-85046` 完全同构：**浏览器为客户端软件、升级链路成熟、暴露面广**，未升级版本（尤其企业内滞留的旧版本线）须按 KEV 截止（09-23）尽快收敛。两次 V8 在野 0day 间隔不足一周，建议企业将"Chrome/Chromium 自动更新"纳入强制策略而非可选。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 受害者需访问攻击者控制的恶意页面（HTTP/HTTPS） |
| 身份认证 | 无需 | 无认证要求，依赖受害者浏览行为 |
| 用户交互 | 需要 | 需受害者使用受影响浏览器访问恶意 HTML（无需点击等额外交互；钓鱼/恶意广告/被攻陷站点均可投递） |
| 特定配置 | 否 | 无已知特定配置前置条件，默认配置受影响 |
| 利用复杂度 | 低（攻击侧） | Google 确认在野利用；越界写原语成熟、利用研究门槛相对低 |

**技术原理：**

根因是 V8 引擎在特定 JavaScript 处理路径上发生**越界写**（CWE-787）：引擎对对象/缓冲区的长度或边界假设与实际内存布局不一致，导致写入越过预期边界，破坏相邻对象数据。攻击者通过精心构造的 JavaScript 将越界写导向可控对象，可获得内存破坏原语，最终在渲染进程（沙箱）内执行任意代码。Google 未公开在野利用的完整攻击链与触发细节（Chromium 问题跟踪号 issues.chromium.org/543557673，权限受限）；沙箱逃逸部分是否存在/如何实现仍未知。

**核心利用链：**

```text
攻击者
  └─ 构造特制 HTML/JavaScript 页面（钓鱼链接/恶意广告/被攻陷站点投递）
      └─ 受害者在受影响 Chrome 中访问该页面
          └─ V8 引擎处理恶意脚本时触发越界写（CWE-787）
              └─ 破坏引擎对象布局，获得内存破坏原语
                  └─ 在渲染进程（沙箱）内执行任意代码
                      └─ （若叠加沙箱逃逸链，可进一步控制设备——细节未公开）
```

#### 3.1.11 风险影响

漏洞成功利用后，可能导致：

- 在浏览器渲染进程（沙箱）内执行任意代码；
- 读取浏览器进程可访问的内存数据（含页面内容、Cookie 会话等，取决于利用链）；
- 叠加沙箱逃逸后控制用户设备（逃逸链是否存在未公开）；
- 作为水坑/钓鱼攻击的客户端突破口，用于定向攻击高价值目标。

#### 3.1.13 修复与缓解措施

#### 官方修复

1. 将 Chrome/Chromium 升级至 `153.0.8010.36`（Linux）或 `153.0.8010.36/.37`（Windows、macOS）及以上版本；
2. 依赖 Chrome 自动更新（设置 → 关于 Chrome → 检查更新），或由企业策略统一推送；
3. 基于 Chromium 的第三方浏览器（Edge 等）跟踪各自厂商对应更新；
4. 升级后核验版本号并重启浏览器使更新生效。

#### 临时缓解

无法立即升级时，可采取：

- 解除企业终端管理策略对 Chrome 自动更新的阻塞（升级链路的常见卡点）；
- 提醒用户避免访问不明链接、不点击可疑广告与邮件内链接；
- 对高价值目标（高管、研发等）临时改用隔离浏览环境或虚拟化浏览器；
- 加强恶意 URL 网关/代理的钓鱼拦截。

#### 3.2.2 漏洞摘要

该漏洞位于 Windows 内核服务侧的 **ALPC（Advanced Local Procedure Call，高级本地过程调用）** 组件，是 2026 年 9 月补丁日两个已确认在野利用的提权 0day 之一。漏洞类型为**基于堆的缓冲区溢出**（CWE-122，并涉及未初始化资源使用 CWE-908）：攻击者可通过特制的 ALPC 消息触发越界堆写入，在内核/高权限上下文中实现内存破坏。据 HKCERT 中文公告：**若攻击者能够从低权限的 AppContainer 执行代码，即可在本地利用此漏洞逃逸沙箱并在受影响系统上提升权限，且无需额外的用户交互**——这意味着该漏洞同时承担"沙箱逃逸"与"本地提权"职能，对依赖沙箱隔离的浏览器/文档类防线构成直接威胁。微软及安全媒体口径：本地攻击者可将权限提升至 SYSTEM。由于两个在野 0day 均要求本地访问与用户级权限，攻击者通常在获得初始立足点（钓鱼、浏览器 0day 等）后将其用作提权第二步；ALPC 组件全 Windows 版本线通用，覆盖范围极广。

> **利用形态提示：** 该漏洞是"初始访问后提权"链条中的关键一环，与 3.1（Chrome 沙箱内 RCE）类客户端 0day 组合时价值最高——浏览器 0day 提供沙箱内代码执行，ALPC 0day 提供沙箱逃逸/提权，二者叠加即构成完整设备控制链。防御上除打补丁外，应重视纵深隔离与最小权限。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 否 | 本地攻击（AV:L），无需网络 |
| 身份认证 | 普通用户 | 需具备低权限本地代码执行能力（可自 AppContainer 沙箱发起） |
| 用户交互 | 不需要 | HKCERT 口径：无需额外用户交互 |
| 特定配置 | 否 | 无已知特定配置前置条件，默认配置受影响 |
| 利用复杂度 | 低（攻击侧） | 微软确认在野利用"正在被广泛利用" |

**技术原理：**

ALPC 是 Windows 用于进程间通信（IPC）的核心机制，广泛承载系统组件间的本地消息传递。漏洞根因位于 ALPC 对特定消息/对象的处理路径：对输入长度或对象状态的校验不足导致**基于堆的缓冲区溢出**（CWE-122），并涉及对未正确初始化资源的使用（CWE-908）。攻击者以低权限（或 AppContainer 沙箱）身份向 ALPC 发送特制消息，触发越界堆写入/越界读取，进而获得内核或高权限上下文中的内存破坏原语，最终将权限提升至 SYSTEM。由于 ALPC 为全系统通用组件、无版本线差异，同一利用代码可覆盖全部受支持 Windows。

**核心利用链：**

```text
攻击者（已获低权限代码执行 / AppContainer 沙箱内代码执行）
  └─ 构造特制 ALPC 消息
      └─ 触发 ALPC 组件堆缓冲区溢出（CWE-122/CWE-908）
          └─ 获得高权限上下文内存破坏原语
              └─ 提权至 SYSTEM（兼完成沙箱逃逸）
                  └─ 加载载荷/关闭防御/横向移动
```

#### 3.2.11 风险影响

漏洞成功利用后，可能导致：

- 本地低权限用户/进程将权限提升至 SYSTEM（Windows 最高权限）；
- 自 AppContainer 等沙箱环境逃逸，突破浏览器/文档等沙箱防线；
- 关闭或干扰终端防护（Defender/EDR）并加载持久化载荷；
- 读取本机全部敏感数据（凭据、密钥、配置）；
- 作为横向移动的权限基础，扩散至内网其他系统。

### 3.3 `CVE-2026-81963` — Windows Update Stack 链接解析缺陷本地提权漏洞（在野 0day）

!!! danger "高危漏洞（CVSS 3.1 = 7.8，在野利用已确认，CISA KEV 收录，修复截止 2026-09-22）"

#### 3.3.2 漏洞摘要

该漏洞位于 **Windows Update Stack（Windows 更新堆栈）**——负责 Windows 更新组件安装/维护的系统组件。漏洞类型为**访问文件前的不当链接解析（link following）**（CWE-59，并关联访问控制不当 CWE-284）：Windows Update Stack 在处理特定文件访问路径时，未正确校验符号链接/目录 junction 类对象，攻击者可借链接重定向令系统组件以更高权限访问或写入非预期位置，从而实现本地权限提升。利用入口为**诱导用户点击恶意链接**（微软官方/安全媒体口径），攻击者需具备用户级权限（本地访问），成功后可提升至更高权限。这是微软**首次确认被在野利用的 Update Stack 漏洞**；与同批 `CVE-2026-85880`（ALPC）一样，属"初始立足点之后"的提权第二步漏洞。HKCERT 与 Security Affairs/ZDI 均确认其"正在被广泛利用"。

#### 3.3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 否 | 本地攻击（AV:L），无需网络 |

| 利用复杂度 | 低（攻击侧） | 微软确认在野利用"正在被广泛利用" |

**技术原理：**

Windows Update Stack 组件在处理文件访问流程时，对路径中的链接对象（符号链接/junction）缺乏充分校验（CWE-59）：系统组件以较高权限解析文件路径，若路径可被低权限用户预先布置为指向攻击者控制位置的链接，则高权限操作会跟随链接访问/写入非预期目标，造成访问控制绕过（CWE-284）与权限提升。攻击者诱导用户点击恶意链接后，链接解析缺陷使更新堆栈以高权限处理攻击者可控的路径对象，最终实现本地提权。微软未披露在野利用的完整技术细节。

**核心利用链：**

```text
攻击者（低权限本地用户）
  └─ 布置恶意链接/目录 junction（指向攻击者控制位置）
      └─ 诱导用户点击恶意链接（或触发更新堆栈处理流程）
          └─ Windows Update Stack 高权限解析文件路径（CWE-59）
              └─ 跟随链接访问/写入非预期目标（绕过访问控制，CWE-284）
                  └─ 实现本地权限提升
```

#### 3.4.2 漏洞摘要

「ShieldBreak」是研究者 Nightmare Eclipse（Chaotic Eclipse / MSNightmare，同一人）于 2026 年 8 月公开的 **Microsoft Defender 恶意软件保护引擎（Malware Protection Engine）本地权限提升零日**，为 7 月已修复的 RoguePlanet（`CVE-2026-50656`）的补丁绕过（采用不同利用手法绕过修复），可 100% 将本地低权限提升至 SYSTEM 并绕过 AMSI。微软经约三周开发后，于 9 月初经**引擎版本 1.1.26080.3** 发布修复（Defender 恶意软件保护引擎随定义自动更新推送，无需用户操作）。本期新进展：研究者于 09-07/08 发布 **ShieldCrash** PoC，主张微软虽修复了多条利用路径但"漏掉了一个点"，特定条件下仍可触发与 ShieldBreak 相同的问题；PoC 演示 **SYSTEM 权限任意文件读取**，研究者称**安装 2026 年 9 月安全更新后的全部受支持 Windows 版本均受影响**，并称后续可能将该骨架 PoC 扩展为完整 SYSTEM 利用。截至本报告，微软未公开回应"补丁不完整"主张，第三方亦未见复现验证——该主张应视为"待验证的披露声明"。

> **风险解读：** 即便仅以"SYSTEM 任意文件读取"论，若主张成立，本地低权限攻击者可读取 SAM/SYSTEM 注册表配置单元等敏感文件（凭据材料），实际风险取决于后续是否扩展为完整利用；本站在第 08-18 期已提示该研究者披露史（Undefend、RedSun Defender 0day 等，部分后被在野利用），其 PoC 的可信度与危险性需按"中"档对待并保持跟踪。

**技术原理：**

ShieldBreak 的本质是**对 7 月修复（RoguePlanet `CVE-2026-50656`）的补丁绕过**：研究者以不同利用手法复现恶意软件保护引擎的提权缺陷（微软口径为权限提升/访问控制问题，NVD 归入 CWE-284/CWE-269），可提权至 SYSTEM 并绕过 AMSI。微软在 1.1.26080.3 中对多条利用路径进行了修复。ShieldCrash 主张：微软的修复"missed a spot"——存在一条未被封堵的条件路径，仍可触发同源缺陷。该 PoC 代码规模约 52KB（ShieldCrash.cpp），以 C++ 调用 Defender/恶意软件保护引擎客户端 API（MP 客户端接口、威胁枚举/处理结构）并内嵌资源文件（含 Warden.dll 与 eicar_com.zip），演示经特定操作序列达成 SYSTEM 上下文任意文件读取。研究者未公开完整利用代码，称"后续可能重做为完整 SYSTEM PoC"。

**核心利用链：**

```text
攻击者（本地低权限用户）
  └─ 运行 ShieldCrash PoC（调用恶意软件保护引擎客户端 API）
      └─ 触发官方修复（1.1.26080.3）未覆盖的特定条件路径（研究者主张）
          └─ 在 SYSTEM 上下文中实现任意文件读取（ShieldCrash 演示能力）
              └─ （研究者称后续或扩展为完整 SYSTEM 提权利用——未发布）
```

> 说明：研究者未公开完整技术细节与触发条件，上述链路为依据 PoC 说明与媒体披露的重构；本站不对 PoC 进行执行验证（严禁执行任何 PoC）。

**漏洞描述：**  [SophosLabs 于 2026-09-08 发布技术分析（Security Affairs 09-09 08:50 UTC 转载）](https://securityaffairs.com/198746/malware/poisonedrefresh-a-fileless-linux-rootkit-that-injects-php-web-shells-into-f5-big-ip-apm-server-memory.html)：在遭入侵的 F5 BIG-IP APM 环境中发现名为 **PoisonedRefresh** 的 Linux 植入（ESET 命名；Sophos 跟踪为 Linux/Agnt-IC），F5 确认攻击者利用的是 **`CVE-2025-53521`**——BIG-IP APM 在虚拟服务器上配置访问策略时的**未认证 RCE**（该 CVE 最初被归类为 DoS，F5 后确认为 RCE）。植入为两阶段：第一阶段藏于被篡改的 Linux umount 二进制内，感染 `/usr/sbin/httpd`、修改 SELinux 配置并嵌入 BIG-IP 升级镜像实现持久化；第二阶段为自带 loader 的独立 ELF，通过拦截 `__libc_start_main` 在 Apache 启动前执行、hook APR 模块加载器（`apr_dso_load`）并操纵 libphp 的 mmap 行为，**将 PHP WebShell 注入内存**——磁盘文件从未改变，仅运行进程可见（无文件落地，文件完整性扫描不可见）。WebShell 读取 `php://input` 中以 `BSOHAzPB` 为前缀、经流密码（密钥 `wSLjN1beuR`）加密的数据并执行，响应伪装为 HTTP 201 + text/css 的 CSS 请求；另创建本地 UNIX socket `/run/bigtlog.pipe`（认证 token `Kzwd6jM5`）将 shell 接入 `/bin/bash`，**不开放 TCP 端口**即可获得交互式访问。以上前缀/密钥/socket 路径为来源公开的检测特征（非本站主动测绘所得）。

**修复建议：**  BIG-IP APM 用户：按 F5 对 `CVE-2025-53521` 的修复与失陷评估指引处置（若疑似受影响，先按 F5 的 compromise-assessment 指引评估，勿直接套用通用 Apache/PHP 加固）；核查 795 级暴露面清单（Shadowserver 披露口径）中是否含自有资产；检测特征：`/run/bigtlog.pipe` socket、`BSOHAzPB` 前缀流量、`wSLjN1beuR` 密钥行为、内存 WebShell（需专门取证）。
