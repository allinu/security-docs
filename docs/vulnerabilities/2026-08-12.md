### 3.1 CVE-2026-53413 — Zoom 注释功能缓冲区溢出零点击远程代码执行漏洞（"Zoomsday"）

#### 3.1.2 漏洞摘要

该漏洞存在于 Zoom 客户端的**注释（annotation）功能**所依赖的专有协议中。Zoom 客户端使用 `libannotate.so` 库处理共享屏幕/白板场景下的注释对象，注释对象通过专有协议被序列化并经加密传输通道在会议参与者之间交换，接收端**自动解析一切收到的数据**，且缺乏足够的来源（origin）校验。

安全研究平台 A Security（Autonomous Offensive Security and Remediation Platform）发现，`CAnnoFormatBlock::Deserialize` 反序列化函数存在**远程可触发的栈缓冲区溢出**：由网络数据（wire）控制的计数可超过固定 128 字节缓冲区边界，导致数据覆写相邻内存（CWE-787），实现任意代码执行。由于注释协议在"观看者（viewer）"与"分享者（sharer）"之间建立直接通道，攻击者可以**逐个针对会议中的每位参与者**发送特制消息；受害者无需点击链接、无需下载任何文件、无需额外交互——**只要处于同一会议中**即可被攻击。成功利用后攻击者可窃取数据、激活麦克风/摄像头、安装恶意软件；在大型会议中，单条恶意消息可同时影响多名参与者。

该漏洞由 A Security 于 2026-08-11 与 CVE 编号分配同步公开（协调披露，先给客户留出升级时间），Zoom 同日发布安全公告 ZSB-26015 并开始滚动推送修复版本。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需与受害者加入同一 Zoom 会议（或由攻击者主持会议），经 Zoom 加密传输通道可达 |
| 身份认证 | 无需 | 无需认证即可加入会议的场景即满足条件（NVD 向量 PR:N） |
| 用户交互 | 不需要 | 零点击：受害者无需点击、下载或额外操作，仅需处于会议中（NVD 向量 UI:R 系指"参与者须处于会议"这一场景约束） |
| 特定配置 | 否 | 默认配置即受影响（所有版本 ≤ 7.0.5） |
| 利用复杂度 | 高 | NVD 向量 AC:H（需对专有注释协议进行逆向与内存布局操纵；披露方已完整逆向 libannotate.so 协议） |

**技术原理：**

注释对象经专有协议序列化后由接收端自动重建（deserialize），`CAnnoFormatBlock::Deserialize` 在重建过程中对由网络数据控制的计数**缺少边界校验**：计数可超过固定 128 字节的栈缓冲区大小，造成越界写入（CWE-787），覆写相邻栈内存，进而劫持控制流。该路径可通过 Zoom 正常加密传输触达，不需要受害者交互或插桩。披露方在 Android 客户端（闭源、部署广、原生代码攻击面大）上完成分析：先对 70 个库中的 3,762 个函数排序，发现基于 JNI 的静态分析遗漏远程可达代码，改用动态跟踪定位到 `libannotate.so` 及其专有注释协议。

**核心利用链：**

```text
攻击者
  └─ 加入/主持一个 Zoom 会议（与受害者处于同一会议）
      └─ 通过注释功能与受害者建立"观看者—分享者"直接协议通道
          └─ 发送特制序列化注释消息（经 Zoom 加密传输）
              └─ libannotate.so 自动解析消息，CAnnoFormatBlock::Deserialize 触发栈缓冲区溢出（CWE-787）
                  └─ 覆写相邻内存，劫持控制流
                      └─ 以受害者客户端进程权限执行任意代码（可窃密、开麦/开摄像头、装恶意软件）
```

#### 3.2.2 漏洞摘要

`docker cp` 是 Docker 生态中在容器与主机之间复制文件的常用命令（构建产物提取、测试结果收集、日志获取、取证等）。其实现**并非直接的文件系统复制**：Docker 守护进程（daemon）在容器文件系统上执行 `filepath.WalkDir` 遍历并生成 tar 归档，Docker CLI 接收 tar 后在**客户端机器**上解压提取。这一架构把"攻击者可控的容器文件系统"与"以用户权限运行的本地提取器"连接起来，构成安全边界——本漏洞即在该边界上被突破。

漏洞由两个缺陷组合而成（由 Imperva Red Team 的 Ron Masas 发现并命名为 "CopyEscape"）：

- **缺陷一（归档侧 TOCTOU 竞态）**：daemon 在遍历容器文件系统时锁定的是容器对象状态，但**不冻结容器内进程**。容器内进程可在 walk 过程中把目录替换为**绝对符号链接**，使 `addTarFile` 再次 Lstat 时看到的是 symlink，从而在 tar 流中出现不一致条目（先 symlink header，后跟"子文件"条目）；
- **缺陷二（解压侧符号链接处理）**：CLI 解压时对 `filepath.Join` 后的构造路径做边界检查，但实际 `os.Symlink` 使用的是**原始未检查的 `hdr.Linkname`**（可指向绝对路径）；后续子文件条目解压时内核跟随该 symlink，文件被写入用户指定目标之外的位置。

成功利用后，恶意容器可诱导 CLI **以运行 `docker cp` 的用户权限在宿主机创建/覆盖任意可写文件**：macOS 场景可覆盖 shell 启动脚本、`~/Library/LaunchAgents` 实现登录用户代码执行与持久化；Linux 场景若用户以 `sudo docker cp` 运行，可覆盖 `/usr/bin/runc`，后续任何 Docker 生命周期操作（如 `docker run`）即触发 root 代码执行。Docker Sandboxes 的 `sbx cp` 同样受影响，对 AI 代理工作流构成主机逃逸风险。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 否 | 无需网络攻击面；攻击者为容器内代码执行能力（本地/CI 场景） |
| 身份认证 | 无需 | 利用者需具备"在容器内执行代码"或"构造恶意镜像"的能力（通常已持有容器会话） |
| 用户交互 | 需要 | 需用户或自动化流程对受控容器执行 `docker cp` 命令 |
| 特定配置 | 是 | 容器须处于**运行状态**（已停止容器不受 TOCTOU 竞态影响）；Linux 提权场景需 `sudo docker cp` 等以 root 运行 |
| 利用复杂度 | 中 | 需在 walk 窗口内完成目录→符号链接替换（竞态窗口可利用容器内进程反复尝试命中）；公开 PoC 已实现稳定演示 |

**技术原理：**

`docker cp` 的归档链路为：daemon 在容器内执行 `filepath.WalkDir` 生成 tar → CLI 接收后解压。缺陷一发生在归档侧：daemon 锁定容器对象但容器内进程仍可修改文件系统，进程可在 walk 期间将目录替换为绝对 symlink，使归档中出现"symlink 头 + 子文件条目"的不一致组合。缺陷二发生在解压侧：CLI 对拼接后的目标路径做边界检查，但调用 `os.Symlink` 时使用未检查的原始 `hdr.Linkname`（可为绝对路径）；后续子文件条目解压时内核解析该 symlink，写入路径越出 `docker cp` 指定的目标目录，实现宿主机任意可写文件写入。

**核心利用链：**

```text
攻击者（已获得容器内代码执行能力 / 可控镜像）
  └─ 用户在宿主机对运行中的恶意容器执行 docker cp <container>:/data ./out
      └─ daemon 遍历容器文件系统生成 tar 归档（filepath.WalkDir）
          └─ 容器内进程在 walk 窗口内将目录替换为绝对符号链接（TOCTOU 竞态，缺陷一）
              └─ tar 流出现不一致条目：symlink 头 + "子文件"条目
                  └─ CLI 解压：边界检查基于 Join 后路径，os.Symlink 却使用未检查的绝对 hdr.Linkname（缺陷二）
                      └─ 后续子文件条目经内核跟随 symlink，写入目标目录之外
                          └─ macOS：覆盖 ~/.zshrc 等启动脚本 / ~/Library/LaunchAgents 实现登录用户代码执行与持久化
                          └─ Linux（sudo docker cp）：覆盖 /usr/bin/runc，下次 Docker 生命周期操作触发 root 代码执行
```

#### 3.2.11 风险影响

漏洞成功利用后，可能导致：

- 以 `docker cp` 运行用户权限在宿主机创建/覆盖**任意可写文件**（突破容器与宿主机边界）；
- macOS：覆盖 shell 启动脚本或写入 `~/Library/LaunchAgents`，实现登录用户代码执行与持久化；
- Linux：以 `sudo docker cp` 运行时覆盖 `/usr/bin/runc`，后续 Docker 生命周期操作触发 **root 代码执行**，完全接管宿主机；
- 篡改宿主机配置、植入后门/挖矿/勒索软件；
- Docker Sandboxes（`sbx cp`）场景下，恶意镜像可逃逸至 AI 代理宿主环境，污染或窃取代理工作流数据；
- 横向移动至同宿主其他容器与业务系统。

#### 3.3.2 漏洞摘要

ClamAV 是广泛部署的开源杀毒引擎，常用于邮件网关、文件上传扫描与端点防护，也被 Cisco Secure Endpoint Connector（Windows/macOS/Linux）内嵌使用。Cisco 安全公告披露其扫描引擎中 7 个文件格式解析器漏洞：zip 解析器存在越界写（`CVE-2026-20337`，CWE-120）与双重释放内存破坏（`CVE-2026-20338`，CWE-415）；PESpin 解析器存在整数溢出（`CVE-2026-20339`，CWE-190）；GPT 解析器在大小端转换处理中越界写（`CVE-2026-20345`，CWE-121）；PDF 解析器越界读（`CVE-2026-20346`，CWE-125）；Mach-O 解析器越界读（`CVE-2026-20347`，CWE-125）；XAR 解析器越界写（`CVE-2026-20348`，CWE-120）。

由于邮件/文件扫描流程通常自动处理不可信附件，**未认证远程攻击者只需将特制文件送入扫描链路**（如发送恶意附件邮件、上传文件）即可使 ClamAV 扫描进程崩溃，中断扫描服务（DoS）。Cisco PSIRT 已确认 `CVE-2026-20337` 与 `CVE-2026-20338` 存在公开 PoC，且未发现其他 5 个漏洞的公开 PoC，也**未发现任何漏洞的在野利用**。Windows 端 Secure Endpoint Connector 风险更高（ClamAV 以提升权限运行），Cisco 评定为 High；macOS/Linux 端为 Medium。Cisco Secure Endpoint Private Cloud 不受影响，但需向端点分发修复。

#### 3.3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 未认证远程攻击者可通过邮件附件、文件上传等渠道将恶意文件送入扫描链路 |
| 身份认证 | 无需 | NVD 向量 PR:N，无需认证 |
| 用户交互 | 不需要 | 扫描流程自动处理文件（NVD 向量 UI:N） |
| 特定配置 | 否 | 默认启用对应格式解析即受影响 |
| 利用复杂度 | 低 | NVD 向量 AC:L；`CVE-2026-20337/20338` 已有公开 PoC |

**技术原理：**

- `CVE-2026-20337`（zip）：扫描 zip 文件时对内容边界检查不当，产生越界写，可致扫描进程终止；
- `CVE-2026-20338`（zip）：处理 zip 内容时内存管理不当，触发双重释放，可致扫描进程终止；
- `CVE-2026-20339`（PESpin）：边界检查不当导致整数溢出，内存破坏，可能产生"其他扩展影响"（NVD 描述）；
- `CVE-2026-20345`（GPT）：大小端转换处理不当导致越界缓冲写；
- `CVE-2026-20346`（PDF）：PDF 内容边界检查不当导致越界读；
- `CVE-2026-20347`（Mach-O）：Mach-O 内容边界检查不当导致越界读；
- `CVE-2026-20348`（XAR）：XAR 内容边界检查不当导致越界写。

**核心利用链：**

```text
攻击者
  └─ 构造特制文件（zip / PESpin / GPT / PDF / Mach-O / XAR）
      └─ 通过邮件附件、上传接口等送入 ClamAV 扫描链路（无需认证）
          └─ 对应格式解析器触发边界缺陷（OOB 写/读、double-free、整数溢出）
              └─ 扫描进程崩溃（DoS），中断邮件/文件扫描服务
```

### 3.4 CVE-2026-42534 — F5 BIG-IP DNS 解析组件拒绝服务漏洞（Unbound jostle 逻辑缺陷）

!!! danger "高危漏洞（无官方补丁）"
    F5 BIG-IP Next SPK/CNF/for Kubernetes 与 BIG-IP DNS 多个版本内嵌的 DNS 缓存解析器（基于 NLnet Labs Unbound ≤ 1.25.0）存在 jostle 逻辑缺陷：攻击者可滥用查询使慢查询无法被替换，导致解析性能持续下降直至拒绝服务。**官方补丁尚未发布**（F5 公告 K000162784），HKCERT 于 2026-08-11 评定为"高度风险"，需以临时缓解措施先行收敛。

#### 3.4.2 漏洞摘要

该漏洞根因位于 **NLnet Labs Unbound DNS 解析器**（截至并包括 1.25.0 版本）的 **jostle 逻辑**中。Unbound 使用 jostle 机制在查询负载过高时淘汰"慢查询"，为新查询腾出处理资源；但该逻辑存在缺陷：**同一查询的重传（retransmit）会不断刷新慢查询的"年龄"（age）**，使 jostle 逻辑无法将之识别为已老化、可被替换的目标。攻击者若能向受影响的解析器发起查询（并能制造持续重传），即可使慢查询长期占用解析资源，导致**解析性能持续下降，最终拒绝服务**。

F5 的 BIG-IP DNS 系列产品（BIG-IP Next SPK、BIG-IP Next CNF、BIG-IP Next for Kubernetes、BIG-IP DNS）内嵌受影响的 Unbound 组件。HKCERT 于 2026-08-11 发布安全通告（风险等级：高度风险），指出受影响系统**暂无可修补 CVE-2026-42534 的补丁**，并给出临时处理方法（限制上游 DNS 服务器为可信内部服务器、启用 DNS over TLS、网络分段隔离 DNS 解析路径、按需禁用 DNS 缓存功能）。由于无补丁可用，处置重点是落实临时缓解并持续跟踪 F5 官方更新。

| CAPEC | `CAPEC-130` | 资源耗尽（Resource Exhaustion） |

> NVD 披露 CWE-440/CWE-911；CAPEC-130 为资源耗尽类攻击的常规对应，供参考。

#### 3.4.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需能向受影响的 BIG-IP DNS 解析器发起 DNS 查询（NVD 向量 AV:N） |
| 身份认证 | 无需 | NVD 向量 PR:N，无需认证 |
| 用户交互 | 不需要 | NVD 向量 UI:N |
| 特定配置 | 否 | 启用 DNS 缓存解析功能的默认配置即受影响 |
| 利用复杂度 | 低 | NVD 向量 AC:L |

**技术原理：**

Unbound 的 jostle 逻辑用于在高负载时淘汰运行时间过长的慢查询，以容纳新查询。本漏洞中，**同一查询的重传会 renew（刷新）慢查询的 age**，导致 jostle 逻辑无法将其判定为"已老化"进而无法替换为新查询。攻击者通过持续发送重传查询，可让大量慢查询长期占用解析器处理资源，使解析吞吐持续下降直至拒绝服务。该缺陷在 F5 产品线中通过内嵌的 Unbound 组件被引入，F5 尚未发布覆盖全部受影响版本的安全补丁。

**核心利用链：**

```text
攻击者
  └─ 向受影响 BIG-IP DNS 解析器持续发起查询（含重传）
      └─ 重传刷新慢查询 age，jostle 逻辑失效（CWE-440/CWE-911）
          └─ 慢查询无法被淘汰，长期占用解析资源
              └─ 解析性能持续下降 → 拒绝服务（DNS 服务不可用）
```

#### 3.4.11 风险影响

漏洞成功利用后，可能导致：

- BIG-IP DNS 解析性能持续下降，域名解析超时/失败（DoS）；

- 无补丁阶段攻击面持续存在，需依赖临时缓解与访问控制。

#### 3.4.13 修复与缓解措施

#### 官方修复

1. 持续跟踪 F5 官方公告 [K000162784](https://my.f5.com/manage/s/article/K000162784) 与安全公告页，补丁发布后第一时间升级至修复版本；
2. 底层 Unbound 组件（非 F5 场景）升级至 1.25.0 之后版本；
3. 升级前完成配置备份，在测试环境验证兼容性及回退方案。

#### 临时缓解

官方补丁发布前，可采取（HKCERT/F5 建议）：

- **限制上游 DNS 服务器**：确保 BIG-IP 系统上的 DNS 缓存解析器仅向受信任的内部 DNS 服务器发出查询；
- **使用 DNS over TLS（DoT）**：如系统支持，配置通过 TLS 进行 DNS 解析，防止 DNS 传输路径遭受中间人（MITM）攻击，避免攻击者注入特制 EDNS 响应；
- **网络分隔**：将 DNS 解析路径隔离，确保上游 DNS 服务器位于受信任且受保护的网络区段内；
- **限制 DNS 功能**：如不需要配置 DNS 或 DNS 缓存解析功能，将其禁用，彻底消除相关攻击面；
- 对解析器查询来源实施限流与来源校验。
