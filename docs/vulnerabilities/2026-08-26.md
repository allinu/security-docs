#### 3.1.2 漏洞摘要

miniOrange SAML 2.0 Single Sign On 是 WordPress 生态中广泛部署的 SAML SSO 插件（插件 slug：`miniorange-saml-20-single-sign-on`），用于将 WordPress 登录与身份提供商（IdP）对接。该插件同一 slug 下实际捆绑 **7 个相互独立的产品版本线**（Free 3.x–5.x、Premium 11.x–13.x、Standard 15.x–17.x、VIP 32.x/35.x 等），各版本线版本号互不关联。

- **`CVE-2026-15981`（签名验证松散布尔检查）：** 插件 `mo_saml_validate_signature()` 函数对 PHP `openssl_verify()` 的返回值执行宽松布尔判断。`openssl_verify()` 返回 1（有效）、0（无效）或 **-1（OpenSSL 处理出错）**；PHP 中 -1 为真值，导致**签名验证出错时被当作"验证成功"**。攻击者提交含攻击者可控 NameID 的 SAMLResponse，并附带一个故意构造为触发 OpenSSL 错误的畸形签名值，即可完全绕过签名校验，触发 `wp_set_auth_cookie()` 以目标账号（含管理员）登录。
- **`CVE-2026-61979`（签名算法混淆）：** 插件信任 SAMLResponse 自声明的签名算法。攻击者将算法声明为 **HMAC-SHA1**，插件便会使用 IdP 的 **RSA 公钥**作为 HMAC 密钥——而 RSA 公钥本身就是公开的（可从 IdP metadata 端点获取）。攻击者用该公钥对自行伪造的断言签名，插件即将其验证为"真实"断言，实现免认证登录。

两个漏洞相互独立，均可导致未认证攻击者以任意现有 WordPress 用户（包括管理员）身份进入 `/wp-admin`。由于公开通告仅覆盖 Free 版线（修复于 `5.4.5`），而付费版安装的版本号（13.x/16.x/20.x/26.x/32.x/35.x）均高于 5.4.5，**所有漏洞数据库、扫描器与仪表盘均将付费版站点判为"已修复"**，即使可利用代码仍在其服务器上运行。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 目标 WordPress 站点需启用该插件并暴露登录/SAML 端点（`/wp-admin`、SAML ACS 端点） |
| 身份认证 | 无需 | 两个漏洞均为未认证利用 |
| 用户交互 | 不需要 | 无受害者交互要求 |
| 特定配置 | 是 | 站点需安装并启用 miniOrange SAML 2.0 Single Sign On 插件且已配置 IdP |
| 利用复杂度 | 低（`15981`）/ 中（`61979`） | `15981` 发送畸形签名即可触发；`61979` 需先从 IdP metadata 获取 RSA 公钥（公开可得） |

**技术原理：**

- **`CVE-2026-15981`：** `mo_saml_validate_signature()` 将 `openssl_verify()` 的三态整型返回值（1/0/-1）当作布尔值处理，未对 -1（OpenSSL 处理错误）做显式排除。攻击者构造触发 OpenSSL 签名处理错误的畸形签名，使返回值为 -1，被宽松布尔判断视为"验证成功"，从而绕过 SAML 签名校验。
- **`CVE-2026-61979`：** 插件从 SAMLResponse 中读取攻击者可控的签名算法声明（`SignatureMethod`），未与服务端配置的算法白名单比对。声明 HMAC-SHA1 时，插件以 IdP 的 RSA 公钥（公开）作为 HMAC 共享密钥，攻击者可据此伪造合法签名。

**核心利用链：**

```text
攻击者
  └─ 获取 IdP metadata（提取 RSA 公钥，仅 61979 需要）
      └─ 构造恶意 SAMLResponse（攻击者可控 NameID/断言 + 畸形签名或 HMAC-SHA1 伪签名）
          └─ 提交至插件 SAML ACS 端点
              └─ 触发签名验证绕过（-1 判真 / 算法混淆）
                  └─ wp_set_auth_cookie() 以目标用户（含管理员）身份建立会话
                      └─ 进入 /wp-admin 完全控制 WordPress 站点
```

### 3.2 Keycloak `CVE-2026-18963` — 密码重置流程绕过导致未认证账户接管

!!! danger "严重漏洞"

#### 3.2.2 漏洞摘要

该漏洞位于 Keycloak 身份与访问管理核心引擎 `keycloak-services` 组件的 **reset-credentials（密码重置）流程**中。正常情况下，用户发起"忘记密码"后，Keycloak 会向注册邮箱发送验证链接，用户必须点击链接完成身份验证后才能设置新密码。受影响的版本（`26.0.0–26.7.1`）中，攻击者可以未认证身份强制任意用户进入密码重置流程，并**跳过邮箱验证链接点击环节**，直接为受害者账号设置新凭证。攻击者只需知道目标用户名或邮箱地址，即可获得该账号的完全控制权。

| 利用复杂度 | 低 | 仅需目标用户名或邮箱地址，纯 HTTP 流程驱动 |

**技术原理：**

`reset-credentials` 流程在执行凭据重置时未正确校验"邮箱验证链接已完成点击"这一前置状态。攻击者通过复现/重放 Keycloak UI 的认证会话编排（`tryAnotherWay` 凭据选择器、`startSessionPolling()` 重启 URL、`required-action` 步骤跳转等），即可在未完成身份验证的情况下推进流程到达 `UPDATE_PASSWORD` 步骤，直接提交新密码完成重置。公开 PoC 以纯 HTTP 请求（无浏览器/Selenium）驱动整个流程，无需任何前置凭证。

**核心利用链：**

```text
攻击者（仅知用户名/邮箱）
  └─ 打开目标 realm 登录页，发起授权请求（client_id/redirect_uri）
      └─ 进入 "Forgot Password" / reset-credentials 流程
          └─ 触发 tryAnotherWay 凭据选择器，提交目标用户名
              └─ 提取并重放 startSessionPolling() 重启 URL 维持认证会话
                  └─ 绕过邮箱验证链接（不点击）
                      └─ 到达 UPDATE_PASSWORD 步骤，直接设置新密码
                          └─ 以新凭证登录，完全接管目标账号
```

    ```python
    # 核心流程函数（节选）：重置流程入口与凭据选择器处理

    RESET_PATH = "login-actions/reset-credentials"
    AUTH_PATH = "login-actions/authenticate"
    REQUIRED_ACTION_PATH = "login-actions/required-action"

    def reset_entry_url(base, realm, client_id, tab_id):
        return (f"{base}/realms/{quote(realm)}/{RESET_PATH}?"
                + urlencode({"client_id": client_id, "tab_id": tab_id}))

    def auth_url(base, realm, client_id, redirect_uri):
        return (f"{base}/realms/{quote(realm)}/protocol/openid-connect/auth?"
                + urlencode({"client_id": client_id, "redirect_uri": redirect_uri,
                             "response_type": "code", "scope": "openid", "state": "poc"}))

    def gate_action(html, base_url, choose_exec=None):
        # 在重置流程页面中寻找"另一条路径"的执行令牌（tryAnotherWay）
        for action in actions_matching(html, base_url, RESET_PATH):
            gate_exec = exec_id_of(action)
            if gate_exec and gate_exec != choose_exec:
                return action
        return None

    def password_form_action(html, base_url):
        # 定位 required-action 步骤中的密码表单（UPDATE_PASSWORD）
        forms = actions_matching(html, base_url, REQUIRED_ACTION_PATH)
        if forms:
            return forms[0]
        if has_input(html, "password-new"):
            forms = all_form_actions(html, base_url)
            return forms[0] if forms else None
        return None
    ```

#### 3.3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 目标 Oracle HTTP Server / WebLogic 代理插件需可经 HTTP 访问 |
| 身份认证 | 无需 | 未认证利用 |
| 用户交互 | 不需要 | 无交互要求 |
| 特定配置 | 是 | 部署受影响版本组件并暴露 HTTP 服务 |
| 利用复杂度 | 低 | 未认证、网络可达即可（Oracle/NVD 均评"易利用"） |

**技术原理：**

组件对关键资源访问的控制校验存在缺陷，导致未认证攻击者可经 HTTP 请求对组件可访问的关键数据执行未授权的创建、删除或修改操作（CWE-284）。具体攻击向量 Oracle 官方未公开细节；CloudSEK 蜜罐观测显示该漏洞在披露后即遭快速、大范围利用，与 WebLogic 系列历史漏洞（`CVE-2020-14882/14883` 控制台 RCE、`CVE-2020-2551` IIOP RCE、`CVE-2017-10271` WLS-WSAT RCE）同期被批量扫描利用，表明攻击者将其纳入"WebLogic 易利用漏洞集"持续使用。

**核心利用链：**

```text
攻击者
  └─ 发现暴露的 Oracle HTTP Server / WebLogic 代理插件（HTTP 80/443）
      └─ 构造恶意 HTTP 请求（无需认证）
          └─ 触发不当访问控制缺陷（CWE-284）
              └─ 未授权创建/删除/修改关键数据（scope 变更，波及其他系统）
```

    ```python
            r = requests.get(args.url, timeout=args.timeout,
                             allow_redirects=True, verify=not args.insecure)
        except Exception as e:
            print(f"[UNKNOWN] Request failed: {e}")
            return 2

        powered = r.headers.get("X-Powered-By", "")
        print(f"[INFO] HTTP {r.status_code}")
        print(f"[INFO] Server: {server}")
        print(f"[INFO] X-Powered-By: {powered}")

        m = re.search(r"(\d+\.\d+\.\d+\.\d+\.\d+)", hay)
        if not m:
            print("[UNKNOWN] No version string in headers. "
                  "Verify locally via package inventory / config management.")
            return 2

        v = m.group(1)
        print(f"[INFO] Detected version-like string: {v}")
        if v in AFFECTED_TRAINS:
            print("[LIKELY AFFECTED] Version matches affected train. "
                  "Patch Oracle CPU Jan 2026.")
            return 1
        print("[OK] Version not in the simple affected list "
              "(still confirm with Oracle advisory).")
        return 0

    if __name__ == "__main__":
        sys.exit(main())
    ```

#### 3.3.11 风险影响

漏洞成功利用后，可能导致：

- 未授权创建、删除或修改 Oracle HTTP Server / 代理插件可访问的关键数据；
- 获取关键数据或全部可访问数据的未授权访问（机密性+完整性受损）；
- scope 变更导致攻击波及其他相连系统或应用；
- 以中间件为跳板进入后端业务系统（无需认证）；
- 数据篡改、业务中断或供应链下游影响。

#### 3.3.13 修复与缓解措施

#### 官方修复

1. 应用 Oracle 2026 年 1 月关键补丁更新（CPU）中针对 Oracle HTTP Server 与 WebLogic Server Proxy Plug-in 的补丁（[cpujan2026.html](https://www.oracle.com/security-alerts/cpujan2026.html)）；

3. 升级前完成配置与数据备份；
4. 在测试环境验证兼容性及回退方案；
5. 升级后核验版本、补丁状态及业务运行情况；
6. 重新执行漏洞检测并留存修复证据。

#### 临时缓解

无法立即升级时，可采取（参照 CISA KEV requiredAction：按厂商指引应用缓解措施，无法缓解则停止使用）：

- 在 WAF/IPS 增加针对 WebLogic 代理插件异常请求的拦截规则；
- 对受影响组件实施网络隔离或访问收敛；
- 加强日志审计、主机监控和异常外联检测；
- 评估在缓解措施不可用时暂时停用受影响组件（discontinue use）。

[Security Affairs 08-25 报道](https://securityaffairs.com/197784/malware/fake-minecraft-sites-are-still-spreading-weedhack-after-c2-takedown.html)（转述 [McAfee Labs 跟进报告](https://www.mcafee.com/)）与[安全圈 08-25 报道](https://mp.weixin.qq.com/s?__biz=MzIzMzE4NDU1OQ==&mid=2652078437&idx=3&sn=36d2256bc6a7af19fa430e14691fef3a)：**WeedHack** 信息窃取木马（Malware-as-a-Service，2026 年 1 月起运营，累计感染 116,464 台主机、日均新增 2,000–3,000 台）在 C2 服务器被端后**分发渠道仍在运转**——McAfee 记录 10 个活跃恶意站点与多个文件托管账号仍在传播该木马，过去一个月 McAfee WebAdvisor 拦截超 6,300 次访问尝试。攻击者利用 SEO 投毒将伪造的 Minecraft 客户端站点推至 Google 搜索结果前列（如 "Xenon Client" 前两条结果均为伪造站），仿冒站点克隆真实工具的 FAQ、安装步骤、开发者信息甚至指向真实 GitHub 仓库的链接，极具迷惑性；木马窃取会话 Cookie、密码、浏览器数据与加密钱包，并通过 **EtherHiding**（从以太坊区块链获取活跃服务器地址）维持与基础设施的联系。公开 IOC（McAfee 报告）：伪造分发域名 `nova-client.com`、`22qq-client.com` 等。

**修复建议：**  
1. 提醒用户仅从官方渠道（GitHub 官方仓库、Discord 官方社区）下载 Minecraft 客户端/模组，警惕搜索引擎置顶的"仿冒官网"；2. 终端保持实时防护开启（WebAdvisor 类拦截），对可疑安装包执行沙箱检测；3. 安全团队可将上述恶意域名加入 DNS 拦截/威胁情报黑名单；4. 对已感染主机按信息窃取木马流程处置：改密（含邮箱/钱包）、吊销会话、全盘查杀。

**漏洞描述：**  
[Sec-News 08-25 转载技术分析](https://govuln.com/news/url/bmx7)（作者 Zeddy）对 **WP2Shell** 漏洞链发现过程进行 LLM 长程代码审计复现实验。该链由研究员 @hash_kitten 借助 GPT-5.6 Sol 发现并披露（exploit broker 报价 50 万美元）：**Vuln A `CVE-2026-63030`**（REST Batch API 批量验证时请求处理器与验证结果两份列表错位，导致参数验证/清洗被绕过，CVSS 9.8，CWE-436）组合 **Vuln B `CVE-2026-60137`**（`author_exclude`/`author__not_in` 参数未逐项整数化即拼接进 SQL 条件，CVSS 5.9，CWE-89），形成**未认证 SQL 注入**，再经文章缓存、oEmbed 缓存、customize_changeset 与 Hook 机制升级为管理员权限并最终 RCE。两个 CVE 均于 **2026-07-17** 由 NVD 收录、WordPress `6.8.6`/`6.9.5`/`7.0.2` 已修复（本期非首次披露，属技术分析跟进）。分析实验结论：11 次模型审计运行均未完整复现该链，瓶颈在长程探索与跨层漏洞连接能力而非局部代码理解。

**修复建议：**  
1. 将 WordPress 升级至 `6.8.6` / `6.9.5` / `7.0.2` 及以上版本；2. 检查是否已升级（该链 7 月披露、修复已发布逾一个月，未升级站点风险较高）；3. 关注 REST API 批量端点异常请求与 `author__not_in` 类参数的注入特征日志。

## 五、当日处置建议

1. **优先处置（P0）— miniOrange SAML 插件双认证绕过（`CVE-2026-15981`/`CVE-2026-61979`，在野利用）：** 立即核查所有 WordPress 站点的 miniOrange SAML 2.0 Single Sign On 插件版本——**不得仅依赖 WordPress 后台"无可用更新"提示**，须按版本线核对（Free 版升级至 `5.4.5+`，付费版 Premium/Standard/VIP 等通过厂商渠道获取补丁）；同步排查异常管理员登录、新增账号与后台文件改动。
2. **优先处置（P0）— Oracle `CVE-2026-21962`（CVSS 10.0，KEV 处置截止 2026-08-27）：** 立即排查 Oracle HTTP Server 与 WebLogic Server Proxy Plug-in（`12.2.1.4.0`/`14.1.1.0.0`/`14.1.2.0.0`，IIS 插件 `12.2.1.4.0`）部署情况并应用 2026 年 1 月 CPU 补丁；无法立即打补丁的按 CISA 指引限制互联网访问或暂停使用，并排查 2026 年 1 月以来的中间件异常访问记录。
3. **24 小时内处置（P1）— Keycloak `CVE-2026-18963`（PoC 公开、奇安信已复现）：** 将 Keycloak 升级至 `26.7.2+`（Red Hat 用户按 RHSA-2026:56519/56520/56523/56524），升级前/后审计审计日志中无"验证邮件点击"记录却完成密码重置（UPDATE_PASSWORD）的异常事件，并对高权限账号启用额外保护。
4. **漏洞链核查 — WordPress WP2Shell（`CVE-2026-63030`+`CVE-2026-60137`）：** 确认 WordPress 版本不低于 `6.8.6`/`6.9.5`/`7.0.2`，未升级站点立即升级；关注 REST API 批量端点与 `author__not_in` 注入特征。
5. **威胁情报关注 — WeedHack 分发渠道持续活跃：** 将 `nova-client.com`、`22qq-client.com` 等伪造分发域名加入 DNS/网关拦截；向员工与玩家群体宣贯仅从官方渠道下载 Minecraft 客户端；对已感染主机执行改密、会话吊销与全盘查杀。
6. **常规要求：** 对疑似遭受攻击的系统保留日志、流量、进程、文件及内存证据；完成修复后进行复测，并更新资产台账和漏洞处置记录。
