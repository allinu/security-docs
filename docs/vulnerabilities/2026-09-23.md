### 1.4 综合研判

今日态势的核心特征是**"厂商确认在野利用 + 同日纳入 KEV + 公开利用细节密集出现"三者叠加**。本窗口内 CISA KEV 一次性新增 4 条（`CVE-2026-93616`、`CVE-2026-85102`、`CVE-2026-93952`、`CVE-2026-94127`），全部 `dueDate=2026-09-25`，且四条的攻击面高度集中于**安全边界与编排中枢**：Check Point 的管理服务器与 VPN 网关、Arista 的 SD-WAN 编排器、F5 的流量接入网关。这类设备一旦被控，攻击者获得的不只是单机权限，而是**网络流量的可见性与可控性**，因此其实际风险远高于同等 CVSS 的业务应用漏洞。

值得注意的是，Check Point 两项漏洞呈现出两种不同的时间线：`CVE-2026-85102` 于 2026-09-09 披露并修补，**三天后的 2026-09-12 即出现成波次利用尝试**，属"补丁即武器化"的典型；`CVE-2026-93616` 则是**先被利用（2026-07-23）后公开披露**，并在披露当日发布修复与 IOC。二者共同说明：对边界安全自有产品，"看到公告才排期"的响应节奏已经不足。

第二类风险来自**公开利用方法的密集出现**。`CVE-2026-65660` 的研究公开了 SafeControls 绕过的完整 gadget 链与**内存型 WebShell** 手法（不落盘、取证困难），奇安信 CERT 同日宣布已复现；WordPress Click2Shell 以完整报告与 PoC 形式公开，影响 WordPress 4.7 至 7.0 的全部版本段而无 CVE 编号，容易被资产台账遗漏；Veeam Agent 提权漏洞的 PoC 使"读取一个日志文件"即可从普通用户提升至 SYSTEM，对共享终端构成直接威胁。

综合来看，今日风险集中在**边界安全产品（P0）与协作/备份/内容平台（P1）**两端，中间层（操作系统内核、通用库、Linux 发行版组件）本期虽有条目（如 Linux 内核 RPC-over-RDMA 堆越界写、libstdc++ 整数溢出、rpcbind 未认证 DoS），但均无公开利用或在野利用证据，按常规整改节奏处理即可。

#### 3.1.2 漏洞摘要

该漏洞位于 Check Point Security Management Server（含多域管理服务器 MDS、Log Server、Multi-Domain Log Server 与 SmartEvent）的管理 Web 服务中。由于服务端对请求路径缺少有效约束，未经身份认证的攻击者可利用目录穿越把脚本上传到任意路径并执行，还可加载任意 Java 类，最终在管理服务器上以服务进程权限执行任意代码。

> 该漏洞属于典型的“预认证文件上传 + 路径穿越”组合缺陷：攻击者无需任何凭据即可写入并触发脚本，一旦得手等同于完全控制安全策略管理面（SmartConsole 管理通道、策略库、日志库与证书材料）。Check Point 同时确认其 LivePatch Take 28/29 并不修复该问题，必须安装对应的 Jumbo Hotfix 版本。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需能访问管理服务器管理 Web 服务（厂商缓解建议中明确要求收敛 TCP/19009 访问来源） |

| 利用复杂度 | 低 | 厂商已确认实际攻击发生；利用链路为路径穿越 + 文件上传 + 脚本执行 |

**技术原理：**

根本原因是管理 Web 服务在处理客户端提供的文件路径时未做规范化与白名单校验，允许“../”等相对路径片段逃逸出预期存储目录，从而把可执行的脚本文件写入服务可解析的位置；攻击者还可借同一缺陷加载任意 Java 类以扩展利用面。Check Point 在公告中提示 LivePatch 不覆盖该缺陷，必须以 Jumbo Hotfix 形式完整修复。

**核心利用链：**

```text
外部攻击者
  └─ 发现暴露的 Security Management Server 管理 Web 服务
      └─ 构造含路径穿越片段的文件上传请求（预认证）
          └─ 写入可执行脚本至任意路径
              └─ 触发脚本解析执行 / 加载任意 Java 类
                  └─ 以管理服务进程权限实现任意代码执行
                      └─ 控制安全策略管理面、读取日志库与证书材料
```

#### 3.1.11 风险影响

#### 3.2.2 漏洞摘要

该漏洞位于 Check Point Security Gateway 与 Spark Firewall 的 VPN 证书处理流程中。设备在 IPSec/远程接入 VPN 协商阶段未能正确校验证书数据的合法性，未经身份认证的远程攻击者可发送特制证书与协商报文绕过校验，进而在网关上执行任意代码。

> Check Point 于 2026-09-09 披露并发布修复，当时尚无利用证据；自 **2026-09-12** 起观测到针对 Spark 客户的成波次利用尝试，攻击来源为匿名化基础设施（VPN 与代理），证书主体普遍使用 `CN=vpn,OU=users,O=global`、`CN=vpn-user,OU=users,O=global`、`CN=vpnuser,OU=users,O=global` 等模式。该漏洞与 CVE-2026-93616 在同一天被 CISA 纳入 KEV。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可访问设备的 VPN 服务（IKE/IPSec 或 SSL VPN，典型端口 500/4500/443） |
| 身份认证 | 无需 | 预认证漏洞，利用发生在证书校验阶段 |
| 用户交互 | 不需要 | 直接向 VPN 服务发送特制协商报文 |
| 特定配置 | 是 | 需设备启用了 Site-to-Site VPN 或 Remote Access VPN |
| 利用复杂度 | 低 | 厂商已观测到规模化利用尝试，且存在公开化的攻击证书特征 |

**技术原理：**

VPN 协商过程中，网关对客户端证书的信任链与字段校验不完整，攻击者可构造带有特定主体字段的自签名证书，使网关在未完成有效身份验证的情况下继续协商流程，并在处理证书数据时触发内存/逻辑缺陷，最终以网关高权限执行代码。该缺陷位于 VPN 处理路径上，因此任何对外提供 VPN 服务的网关都属于高风险暴露面。

**核心利用链：**

```text
外部攻击者（使用匿名化出口）
  └─ 定位暴露的 Check Point VPN 端点
      └─ 使用特制证书（CN=vpn / vpn-user / vpnuser，O=global）发起协商
          └─ 网关证书校验不充分，协商继续
              └─ 触发证书数据处理路径缺陷
                  └─ 在网关上执行任意代码
                      └─ 后续常见动作：内网端口与服务扫描、横向移动
```

#### 3.2.11 风险影响

漏洞成功利用后，可能导致：

- 绕过 VPN 身份校验获得对内部网络的访问入口；
- 在安全网关上执行任意代码，进而篡改隧道与策略；
- 以网关为跳板对内网进行端口与服务扫描、横向移动；
- 窃取经由 VPN 的敏感业务流量与凭据；
- 破坏或中断远程接入服务。

#### 3.3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需网络可达 VCO Web 接口 |
| 身份认证 | 无需 | 无需租户或运维凭据 |
| 用户交互 | 不需要 | 远程直接请求 |
| 特定配置 | 是 | 需启用基于证书的 VeloCloud Edge → VCO 认证；攻击者需持有 Edge 认证证书的公开部分 |
| 利用复杂度 | 中 | 前置条件明确但已在野利用（厂商已确认） |

**技术原理：**

VCO Web 接口在处理特定请求时未对输入做充分校验，攻击者可借内部功能路径访问本应受限的特权能力，从而影响编排器主机的可用性与数据完整性。厂商提示应重点关注 nginx 访问日志中带有异常 URL 风格路径片段、编码字符、指向本地或内部服务的引用，以及高请求速率特征的请求。

**核心利用链：**

```text
外部攻击者
  └─ 定位暴露于网络的 VeloCloud Orchestrator Web 接口
      └─ 获取 VeloCloud Edge 认证证书的公开部分
          └─ 构造经编码/路径穿越风格的恶意请求
              └─ 绕过输入校验访问特权内部功能
                  └─ 影响 VCO 主机：配置变更、命令执行、数据库导出等
                      └─ 危及编排器所管理的边缘设备与业务数据
```

#### 3.4.2 漏洞摘要

该漏洞位于 F5 BIG-IP 的访问策略管理器（APM）数据面。当虚拟服务器上同时配置了 APM 访问策略与 OAuth 配置文件时，特制恶意流量可在 Traffic Management Microkernel（TMM）处理 OAuth 流程时触发堆缓冲区溢出，未经身份认证的攻击者可据此远程执行代码。该问题为数据面缺陷，控制面不受直接影响；运行于 Appliance 模式（加固配置）的 BIG-IP 同样受影响。

> F5 已明确该漏洞“已被实际利用”，CISA 同日将其纳入 KEV 并给出 2026-09-25 的整改期限。由于 BIG-IP 通常承载对外业务流量、位于互联网边界，且无需认证即可触发，本期将其列为与 Check Point 两项漏洞同级的 P0 处置项；在没有官方热修复的窗口期内，可由 F5 支持的应急 iRule 作为临时缓解，但不应视为长期方案。

#### 3.4.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可访问配置了 APM 访问策略与 OAuth profile 的虚拟服务器 |
| 身份认证 | 无需 | 预认证漏洞，发生在 OAuth 流程处理阶段 |
| 用户交互 | 不需要 | 直接发送特制网络请求 |
| 特定配置 | 是 | 虚拟服务器必须同时配置 APM 访问策略与 OAuth 配置文件 |
| 利用复杂度 | 低 | CVSS AC:L，且厂商已确认在野利用 |

**技术原理：**

缺陷存在于 TMM 数据面处理 OAuth 相关流量的代码路径中。当系统处理特制 OAuth 请求时未正确校验内存边界，导致堆内存被越界写入（CWE-122），攻击者可借此破坏堆结构并以提升后的守护进程权限执行任意代码。由于问题位于数据面，控制面管理接口可能表面上仍保持可用，使受害者在流量被完全劫持的情况下不易察觉。

**核心利用链：**

```text
外部攻击者
  └─ 定位对外暴露、且启用了 APM 访问策略 + OAuth profile 的虚拟服务器
      └─ 发送特制 OAuth 相关恶意流量（无需认证）
          └─ TMM 处理 OAuth profile 时未校验内存边界
              └─ 触发堆缓冲区溢出（CWE-122）
                  └─ 以提升后的守护进程权限执行任意代码
                      └─ 劫持/篡改经过 BIG-IP 的业务流量，或作为内网跳板
```

#### 3.5.2 漏洞摘要

该漏洞影响 Veeam Agent for Microsoft Windows。Veeam Endpoint Backup 服务在处理本地 gRPC 命名管道 `\\.\pipe\Veeam\VAW\ServiceConnectionPipe` 上的提权客户端会话时，将一个“已提权管理员主体”与客户端可控的会话 UID 绑定，但未校验该 UID 是否属于发起请求的用户或连接。由于提权会话 UID 会被写入标准用户可读的日志文件，低权限本地用户可读取有效 UID 并借其以 `NT AUTHORITY\SYSTEM` 执行命令。

> 利用门槛极低：读取一个文本文件即可完成主要利用步骤。公开 PoC 直接演示执行 `whoami` 并将输出写入文件。对共享 Windows 终端（多人使用同一主机）而言，一次低权限账号沦陷即可升级为整机接管，因此该漏洞的实战价值高于其 CVSS 分值所示。

#### 3.5.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 否 | 本地攻击，需要本机访问权限（不能远程直接触发） |
| 身份认证 | 普通用户 | 任意具备本机登录能力的低权限用户 |
| 用户交互 | 不需要 | 无需管理员交互；攻击者自行读取日志并复用 UID |
| 特定配置 | 是 | 主机上存在多个本地用户（共享终端）时风险显著升高 |
| 利用复杂度 | 低 | 公开 PoC 已提供，核心步骤为读取日志文件中的提权会话 UID |

**技术原理：**

Veeam Endpoint Backup 服务把“已提权管理员主体”缓存并绑定到一个由客户端控制的会话 UID，但未将该 UID 与请求用户或连接做绑定校验，形成会话身份混淆（session identity confusion）。同时，这些提权会话 UID 被记录到 `C:\ProgramData\Veeam\Endpoint\Svc.VeeamEndpointBackup.log`，该文件对标准用户可读，使攻击者可通过“读日志 → 复用 UID → 经命名管道请求执行命令”完成提权。

**核心利用链：**

```text
低权限本地用户
  └─ 读取 C:\ProgramData\Veeam\Endpoint\Svc.VeeamEndpointBackup.log
      └─ 提取有效的提权会话 UID（GUID）
          └─ 通过 \\.\pipe\Veeam\VAW\ServiceConnectionPipe 复用该 UID
              └─ 服务未校验 UID 与请求用户的绑定关系
                  └─ 以 NT AUTHORITY\SYSTEM 权限执行任意命令
                      └─ 完全接管主机（读取凭据、投放后门、横向移动）
```

#### 3.6.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需网络访问 SharePoint 站点 |
| 身份认证 | 普通用户 | 微软声明需认证且仅需低权限；研究者证明在允许匿名访问合适页面的部署中可与另一 ToolPane 认证缺陷组合实现预认证 RCE |
| 用户交互 | 不需要 | 无需受害者点击，网络可达即可触发 |
| 特定配置 | 部分需要 | 预认证路径依赖部署允许匿名访问合适的页面（该路径已由微软 2026-06-09 更新关闭） |
| 利用复杂度 | 低 | 公开研究包含可用利用 markup，复现门槛显著降低 |

**技术原理：**

SafeControls 的设计目标是在 SharePoint 解析页面与 Web 部件标记时阻止实例化不受信任的服务端类。本漏洞中，ToolPane 先将 Register 指令与控件标记分离并校验类型名，随后把属性值放入双引号内**重建**指令；由于内嵌引号未安全转义，恶意值可在安全检查之后插入新的 Register 指令，使安全校验与实际解析之间出现“检查—使用”错位（TOCTOU 式注入），最终注册危险类并触达代码执行 gadget。

**核心利用链：**

```text
攻击者（低权限/或匿名可达页面）
  └─ 定位可提交 Web 部件标记 / ToolPane 处理入口的 SharePoint 页面
      └─ 构造包含 Register 指令的恶意标记（属性值内含未转义双引号）
          └─ ToolPane 分离并校验类型名后重建指令
              └─ 注入额外 Register 指令，注册危险 .NET 类
                  └─ 组合 XamlServices.Parse + ExpandedWrapper + ObjectDataProvider + LosFormatter
                      └─ 在内存中执行代码（内存型 WebShell，无落盘文件）
```

#### 3.7.2 漏洞摘要

该漏洞影响 WordPress 核心（Core）组件，被命名为 **Click2Shell**。攻击者可通过特制链接，在已登录管理员浏览器中触发跨站请求伪造，进而从 WordPress.org 官方主题目录**强制安装任意主题**，并在 Customizer 预览阶段执行该（即使处于未激活状态的）主题内嵌的任意 PHP 文件。攻击者无需 WordPress 账号、安装 nonce 或管理权限，但需要一名已登录管理员访问特制 URL。

> 研究者发现：主题预览 URL 中的值会被 WordPress.org Themes API 解释一次，又被管理员浏览器中的 JavaScript 以有缺陷的方式第二次解释（双重解释/注入）。WordPress 在 7.1.1 中通过在 jQuery 选择器使用主题 slug 前进行转义并把选择器限制在真实主题卡片上完成修复。HKCERT 评级为 High Risk，并指出该漏洞影响 4.7 至 7.0 的全部版本段。

#### 3.7.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需目标站点可被攻击者访问（经浏览器与站点交互） |
| 身份认证 | 无需 | 攻击者无需任何 WordPress 账号 |
| 用户交互 | 需要 | 需一名已登录管理员访问特制 URL（可经定向钓鱼或既有 XSS 促成） |
| 特定配置 | 是 | 站点未启用 `DISALLOW_FILE_MODS`；被强制安装的主题需存在可执行的 PHP 内容 |
| 利用复杂度 | 低 | 公开完整技术报告与 PoC，利用链为模板化步骤 |

**技术原理：**

Click2Shell 是一条由三环构成的链：① 特制链接使目标站点从官方主题目录“安装”攻击者选定主题（该行为由 CSRF 触发，管理员浏览器代为发起）；② 主题即使未激活，其 PHP 仍会在 Customizer 预览阶段被执行；③ WordPress.org Themes API 与管理员浏览器 JavaScript 对同一 URL 值的**双重解释**使攻击者能够控制被加载的 PHP。WordPress 7.1.1 通过转义主题 slug 并将 jQuery 选择器限定在真实主题卡片上切断该链。

**核心利用链：**

```text
攻击者
  └─ 构造指向目标站点的特制主题预览 URL（利用双重解释）
      └─ 经钓鱼或既有 XSS 诱导已登录管理员访问
          └─ CSRF 触发：从官方目录强制安装攻击者指定主题
              └─ 管理员浏览器进入 Customizer 预览
                  └─ 未激活主题中的 PHP 被执行
                      └─ 服务端任意 PHP 代码执行（可读取 wp-config.php、创建管理员账号等）
```

#### 3.8.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需与交换机管理接口处于同一局域网（AV:A，邻接攻击者） |
| 身份认证 | 无需 | LAN 内未经身份认证即可触发 |
| 用户交互 | 不需要 | 直接向 Web 管理接口发送特制 HTTP 请求 |
| 特定配置 | 否 | 默认管理服务即存在攻击面 |
| 利用复杂度 | 低 | 厂商已确认在野利用 |

**技术原理：**

交换机 CGI 程序在解析 HTTP 请求参数时未做长度校验，导致数据写入固定长度的栈缓冲区并溢出，攻击者可通过覆盖返回地址等关键栈数据实现控制流劫持，进而以设备服务权限执行操作系统命令。

**核心利用链：**

```text
局域网内攻击者（如横向移动后的内网跳板）
  └─ 发现可访问的 GS1900 交换机 Web 管理接口
      └─ 构造超长/畸形 HTTP 请求参数
          └─ CGI 程序栈缓冲区溢出（CWE-121）
```

#### 3.8.11 风险影响

漏洞成功利用后，可能导致：

- 在交换机上执行操作系统命令并完全控制网络设备；
- 篡改 VLAN、ACL 与路由配置，静默改变流量路径；
- 实施流量镜像/劫持以窃取内网凭据与业务数据；
- 作为内网长期潜伏节点；
- 中断网络接入服务。

#### 3.8.13 修复与缓解措施

#### 官方修复

1. 按 Zyxel 2026-06-16 安全公告将 GS1900 系列交换机固件升级至指定修复版本；
2. 升级前导出设备配置备份，并在维护窗口内执行（注意网络中断影响）；
3. 升级后核验固件版本并复查管理接口访问日志。

#### 临时缓解

无法立即升级时，可采取：

- 将交换机管理接口限制在专用管理 VLAN 与可信管理网段，禁止从业务网段直接访问；
- 关闭不必要的远程管理服务（Telnet/HTTP），改用 SSH/HTTPS 并启用强认证；
- 在管理网段部署针对交换机管理接口异常请求的检测与阻断；
- 对局域网内针对交换机管理端口的异常扫描行为建立告警。

## 五、当日处置建议

1. 优先处置**已在野利用且 CISA 已给出整改期限**的 5 项：`CVE-2026-93616`、`CVE-2026-85102`、`CVE-2026-93952`、`CVE-2026-94127`（期限均为 2026-09-25）与 `CVE-2026-7273`（期限 2026-09-24）；对 Check Point 管理服务器/网关、F5 BIG-IP、Arista VCO、Zyxel GS1900 四类设备优先完成资产清点。
2. 对**互联网暴露的边界设备**（VPN 网关、应用交付网关、交换/路由设备管理面、安全厂商管理服务器）实施管理面收敛：将管理接口限定在专用管理网段，禁止从业务网段与互联网直接访问（Check Point 明确要求 TCP/19009 仅对可信 IP 开放）。
3. 对**存在公开 PoC/公开利用方法**的条目按 24 小时处置：`CVE-2026-32996`（Veeam Agent 提权，优先共享终端与备份服务器）、`CVE-2026-65660`（SharePoint，安装对应构建号补丁并排查内存型 WebShell）、WordPress Click2Shell（升级至 7.1.1，无法立即升级时启用 `DISALLOW_FILE_MODS`）、Windows Defender 更新 DoS 0-day（监控特征库更新是否停滞）。
4. 对**无 CVE 编号的条目**（WordPress Click2Shell、BigDiskBuster、WaterPlum 攻击活动、CNCERT 大模型众测通报）建立独立跟踪台账，避免因缺少 CVE 编号而在漏洞管理流程中被自动忽略。
5. 对疑似遭受攻击的系统保留日志、流量、进程、文件与**易失性内存**证据：本期 `CVE-2026-65660` 明确存在内存型 WebShell 手法，`CVE-2026-93952` 明确存在可疑 systemd 服务与文件落地，取证时需先保全再处置。
6. 完成修复后进行复测，并重点复测**"服务组件与托盘/代理组件是否均已升级"**这类部分更新陷阱（Veeam Agent 已明确提示部分完成的更新不提供有效防护）。
7. 将本期 5 项在野利用条目纳入资产台账与整改记录，并在下一期报告中复核闭环情况。
