### 3.1 CVE-2026-19478 — GitLab GraphQL 指令代码注入漏洞（未认证远程修改/删除公共项目与用户数据）

!!! danger "严重漏洞"
    自托管 GitLab CE/EE 的 GraphQL 解析器在处理携带 `@gl_introduced` 指令（版本号高于当前版本）的查询时，会把查询中攻击者可控的字段名通过 ActiveRecord 的 `public_send` 动态派发为模型方法调用；未认证远程攻击者仅需构造一条 GraphQL 查询，即可修改或删除公共项目与用户数据，无需任何凭据与用户交互。

#### 3.1.2 漏洞摘要

该漏洞位于 GitLab 的 GraphQL 层。GitLab 使用 `@gl_introduced(version: "...")` 指令实现 GraphQL schema 特性开关：当查询中标注的版本号**高于当前运行实例的版本**时，解析器会为该字段创建"回退字段（fallback field）"。由于该回退字段的解析逻辑将查询中的字段名直接经 ActiveRecord 模型的 `public_send` 动态派发，攻击者可以把任意公开方法名（如 `touch`、`destroy`、`delete`、`deactivate` 等）作为字段名注入查询，实现**未认证的任意公开方法调用**——本质是字段名到方法调用的代码注入（CWE-94）。

成功利用后，未认证攻击者可远程**修改或删除公共项目、停用/删除用户数据**，影响代码托管仓库的完整性、CI/CD 交付链与用户数据安全（CVSS 完整性/可用性影响均为高）。该漏洞由安全研究员 hiimguardian 通过 [HackerOne 漏洞赏金计划](https://hackerone.com/reports/3926431)提交；GitLab 于 **2026-08-17**（常规更新 5 天后）发布紧急补丁修复，仅影响**自托管部署**。按 GitLab 披露策略，完整技术细节通常在补丁发布约 30 天后公开。

> 官方公告：[GitLab Patch Release 19.2.4 发布说明](https://docs.gitlab.com/releases/patches/patch-release-gitlab-19-2-4-released/)；注意：**18.2–18.10 分支无对应补丁版本**，运行该范围的实例需整体升级至已修复分支。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可访问自托管 GitLab 的 GraphQL 端点 `/api/graphql` |
| 身份认证 | 无需 | 未认证即可构造查询 |
| 用户交互 | 不需要 | 全程无受害者参与 |
| 特定配置 | 否 | 默认配置即受影响（仅需实例版本落在受影响范围） |
| 利用复杂度 | 低 | 构造含 `@gl_introduced` 指令的 GraphQL 查询即可触发 |

**技术原理：**

GitLab GraphQL 解析器对 `@gl_introduced(version)` 指令的处理存在缺陷：当指令声明的版本号高于实例当前版本时，解析器会创建"回退字段"并沿用查询中的字段名；该字段解析时经 ActiveRecord `public_send` 动态调用同名公开方法。由于字段名完全由攻击者控制且无认证与白名单校验（CWE-94：对生成代码的控制不当），攻击者可调用 `touch`/`destroy`/`delete`/`deactivate` 等任意零参公开方法，实现未认证数据修改/删除。公开 PoC 仓库（davkharrr/CVE-2026-19478-PoC）通过"无害 `touch` 验证 + 版本探测"确认回退字段生效，并实现 `destroy`/`delete`/`deactivate` 等破坏性调用。

**核心利用链：**

```text
攻击者
  └─ 定位自托管 GitLab 实例（/api/graphql 端点）
      └─ 构造含 @gl_introduced(version: "999.0.0") 的 GraphQL 查询
          └─ 触发解析器创建回退字段（fallback field）
              └─ 字段名经 public_send 派发至 ActiveRecord 公开方法
                  └─ 未认证修改/删除公共项目与用户数据（touch/destroy/deactivate…）
```

### 3.2 CVE-2025-62593 — Ray 代码注入/远程代码执行漏洞（DNS 重绑定，CISA KEV 在野利用）

!!! danger "高危漏洞（已确认在野利用，KEV 处置期限 2026-08-20）"
    Ray（AI 计算引擎）2.52.0 之前版本的 Dashboard/HTTP API（默认 8265 端口）关键端点**默认无认证**，仅依赖"User-Agent 以 Mozilla 开头"的弱防护；攻击者通过 **DNS 重绑定**诱导开发者浏览器（Firefox/Safari）访问恶意页面或广告，即可向本地 Ray 集群提交恶意任务，在 head node 上以 Ray 进程用户身份执行任意代码。

#### 3.2.2 漏洞摘要

Ray 是应用广泛的 AI 计算引擎（训练/推理/分布式任务）。其 Dashboard 与 HTTP API 的多个关键端点（如 `/api/jobs`、`/api/job_agent/jobs`）**长期未启用身份认证**，此前仅靠检查 HTTP `User-Agent` 是否以 `"Mozilla"` 开头来区分"浏览器请求"与"程序请求"；但 fetch 规范允许浏览器/页面覆盖 User-Agent 头，该防护形同虚设。攻击者将恶意域名通过 **DNS 重绑定**解析到受害开发者的本地 Ray Dashboard 地址（127.0.0.1:8265），诱导受害者（Firefox/Safari 用户）访问恶意网站或广告后，页面即可跨源提交 Ray Job（entrypoint 为攻击者指定的任意命令），在集群 **head node** 上执行任意代码（GHSA-q279-jhrf-cc6v，影响 `ray < 2.52.0`）。

CISA 于 **2026-08-17** 将该漏洞收录 KEV 并确认在野利用：攻击者利用 DNS 重绑定实施代码注入获得 RCE 后，在系统内提权、横向移动、建立 C2 通道、外传敏感数据并最终破坏业务。公开威胁情报（[Bitsight RondoDox 僵尸网络分析](https://www.bitsight.com/blog/rondodox-botnet-infrastructure-analysis)）显示该类未认证 Ray API 已被僵尸网络批量利用。此外，即使不走浏览器路径，**暴露到公网的 Ray Dashboard（8265 端口）本身即可被未认证直接调用**（公开 PoC 即采用该路径演示），风险不限于开发者本机。

> 官方修复：Ray 2.52.0（[修复 commit 70e7c72](https://github.com/ray-project/ray/commit/70e7c72780bdec075dba6cad1afe0832772bfe09)）；GitHub Advisory：[GHSA-q279-jhrf-cc6v](https://github.com/advisories/GHSA-q279-jhrf-cc6v)。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 本地回环（浏览器路径）或公网暴露的 Dashboard（默认 8265 端口） |
| 身份认证 | 无需 | Dashboard/API 关键端点无认证 |
| 用户交互 | 需要（浏览器路径）/ 不需要（直接攻击暴露 API） | 前者需受害者访问恶意页面或广告 |
| 特定配置 | 是 | 运行 `< 2.52.0` 且 Dashboard API 可达（默认监听本地/配置暴露） |
| 利用复杂度 | 低 | 构造 DNS 重绑定域名 + 提交恶意 Ray Job 即可 |

**技术原理：**

1. **未认证 API**：Ray Dashboard 的 `/api/jobs` 等端点不校验身份，任意网络可达者均可提交 Job；
2. **弱 UA 防护可绕过**：原防护仅检查 `User-Agent` 是否以 `"Mozilla"` 开头，而浏览器页面可通过 fetch 规范覆盖该头；
3. **DNS 重绑定**：攻击者控制域名先在访问时返回公网 IP，随后重绑定解析为 `127.0.0.1`，使浏览器同源策略失效，页面可直接访问本地 Ray Dashboard；
4. **任意命令执行**：提交 entrypoint 为攻击者命令的 Ray Job，head node 执行该命令（CWE-94 代码注入）。

**核心利用链：**

```text
攻击者
  └─ 托管恶意网页/广告（或直接扫描暴露的 :8265 服务）
      └─ DNS 重绑定：域名解析切换到 127.0.0.1（本地 Ray Dashboard）
          └─ 浏览器跨源请求（User-Agent 校验被 fetch 规范覆盖绕过）
              └─ POST /api/jobs 提交 entrypoint 为任意命令的任务
                  └─ head node 执行命令（RCE）→ 提权/横向/C2/数据外传
```

- 作业日志中异常输出、临时文件写入（`/tmp`）；
- 异常外联、C2 通信与数据外传流量；
- 开发者浏览器访问可疑站点后出现的本地 Ray 集群异常任务。

| 检测项 | 可疑特征 |
| --- | --- |
| 请求路径 | `/api/jobs`、`/api/job_agent/jobs`、`/api/version` |

| 文件行为 | 写入 `/tmp` 等目录的非预期文件 |

#### 3.2.11 风险影响

漏洞成功利用后，可能导致：

- 在 Ray 集群 head node 上以 Ray 进程用户身份执行任意命令；
- 窃取 AI 训练/推理环境中的模型、数据与凭据；
- 利用集群节点横向移动至关联基础设施；
- 建立 C2 通道并外传敏感数据（CISA 已确认的利用行为）；
- 破坏 AI 业务可用性（任务中断、集群被用于挖矿/僵尸网络等）。

#### 3.2.13 修复与缓解措施

#### 官方修复

1. 将 Ray 升级至 `2.52.0` 或更高版本（[官方修复 commit](https://github.com/ray-project/ray/commit/70e7c72780bdec075dba6cad1afe0832772bfe09)）；
2. 升级前备份集群配置与任务定义，在测试环境验证兼容性；
3. 云托管 Ray 服务按服务商公告升级或等待托管方修复。

#### 临时缓解

无法立即升级时，可采取：

- **网络隔离**：Dashboard/API（8265 端口）仅监听内网可信网段，禁止暴露公网（防火墙/安全组收敛）；
- 在 Dashboard 前置认证代理（如 Basic Auth、OIDC、mTLS）；
- 对运行 Ray 的开发者机器开展安全提示：勿在 Ray 运行期间访问不明网站/广告，关闭不必要的 Dashboard 监听；
- 监控 `/api/jobs` 未认证访问与异常任务提交，配置告警；
- 排查公网暴露的 Ray 实例（仅限自有资产自查），发现即收敛。
