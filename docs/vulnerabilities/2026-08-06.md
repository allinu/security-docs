### 3.1 CVE-2026-70426 — Jenkins Remoting 反序列化过滤器绕过漏洞（Agent-to-Controller）

!!! danger "严重漏洞"

#### 3.1.2 漏洞摘要

Jenkins 使用 Remoting 库（通常为 `agent.jar` / `remoting.jar`）通过序列化 Java 对象在控制器与 agent 之间通信。为防御 agent 侧反序列化攻击，Jenkins 自 JEP-200 起对反序列化类实施过滤器（黑名单/白名单机制）。该漏洞存在于 Remoting 反序列化实现的**回退代码路径**（fallback path）：JEP-200 类过滤器未作用于经该路径解析的类，导致 agent 进程、在 agent 上运行的代码，以及具备 Agent/Connect 权限的攻击者，可以针对 Jenkins 核心 classpath 上的类绕过反序列化过滤器。成功利用后，攻击者可在控制器 JVM 上下文中执行任意代码，进而窃取凭据、篡改流水线、横向控制全部构建节点。

该漏洞由 Jenkins 官方于 2026-08-05 安全公告（[2026-08-05 advisory](https://www.jenkins.io/security/advisory/2026-08-05/)）披露，同批公告还修复了多个插件漏洞（如 HCL AppScan 插件凭据 ID 枚举等，不在本报告收录范围）。HKCERT 于 2026-08-06 发布中文公告（[Jenkins 多個漏洞](https://www.hkcert.org/tc/security-bulletin/jenkins-multiple-vulnerabilities_20260806)），将整体风险评为"中度风险"。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达控制器与 agent 之间的 Remoting 通信通道（默认 50000 端口或入站 agent 连接） |
| 身份认证 | 需要 | 需控制 agent 进程 / 在 agent 上执行代码，或具备 Agent/Connect 权限 |
| 用户交互 | 不需要 | 全程自动化构造序列化对象，无交互 |
| 特定配置 | 否 | 默认部署即在受影响范围 |
| 利用复杂度 | 高 | 需要先获得 agent 侧执行能力或对应权限（NVD 向量 AC:H） |

**技术原理：**

JEP-200 在 Jenkins 控制器侧对 agent 传入的反序列化对象执行类过滤器，限制可被实例化的类集合。该漏洞中，Remoting 反序列化实现存在一条回退解析路径（fallback code path），该路径在解析类时**未套用** JEP-200 过滤器，且回退路径可解析 Jenkins 核心 classpath 上的类。攻击者构造特制序列化对象（gadget 链），经回退路径解析后即可绕过过滤器限制，在控制器 JVM 中实例化危险类并触发任意代码执行。

**核心利用链：**

```text
攻击者
  └─ 获取 agent 进程控制权 / Agent/Connect 权限（或控制被攻陷的 agent）
      └─ 构造特制 Java 序列化对象（含 gadget 链）
          └─ 经 Remoting 回退代码路径发送至控制器
              └─ 绕过 JEP-200 反序列化类过滤器
                  └─ 在控制器 JVM 上下文执行任意代码
                      └─ 窃取凭据、篡改流水线、横向控制构建节点
```

#### 3.1.11 风险影响

- 在 Jenkins 控制器 JVM 上下文执行任意代码；

- 篡改流水线定义、构建产物及业务数据；
- 以控制器为跳板横向移动至全部构建节点与关联系统；

随 CVE-2026-70426 一并升级至 Jenkins 2.576（weekly）/ 2.568.2（LTS）；临时缓解：按最小权限原则收紧 Item/Configure、Item/Build、Overall/Manage 与 Agent 相关权限。

## 五、当日处置建议

1. **Jenkins 升级（P2，3 个工作日内）**：核查控制器与 agent 版本，低于 2.576（weekly）/ 2.568.2（LTS）的实例升级至修复版本；收紧 Agent/Connect 与构建相关权限，限制 8080/50000 端口的互联网暴露；同步关注同批公告涉及的插件漏洞。
2. **Cisco IOS XE/IOS 设备升级（P1）**：对照 6 份 cisco-sa-* 公告（[hardening-iosxe-V8NMuMZJ](https://sec.cloudapps.cisco.com/security/center/content/CiscoSecurityAdvisory/cisco-sa-hardening-iosxe-V8NMuMZJ) 等）使用 Cisco Software Checker 核对版本，安排维护窗口升级至加固版本；限制 SNMP/BEEP/XMCP 与 Web 管理接口暴露。
3. **Debian 服务器内核补丁**：Debian 11/12 服务器安装 LTS 内核补丁（5.10.262-1 / 6.1.180-1 及以上）并重启，优先处理涉及本地提权的内核 CVE。
4. 对互联网暴露的 VPN、网关、安全设备、中间件和管理平台开展资产排查，确认无受影响组件暴露。
5. 对疑似遭受攻击的系统保留日志、流量、进程、文件及内存证据，并开展 WebShell、恶意进程、异常账号及横向移动排查。
6. 完成修复后进行复测，并更新资产台账和漏洞处置记录；本报告全部漏洞均已发布官方补丁，无"暂无补丁"项。
