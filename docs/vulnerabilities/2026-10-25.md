### 1.3 今日重点关注

1. **`CVE-2026-115889`：Wasmtime Cranelift SSA 索引位打包溢出致 Wasm 沙箱逃逸（9.9）**  
   Cranelift 编译器后端把 **SSA value 索引做位打包**，在 release 构建中编译“足够大或特制”的 Wasm 函数时**会静默溢出**（`CWE-197` 数值截断、`CWE-843` 类型混淆）。溢出后 Cranelift 会引用错误的 IR 值，导致**任意错误编译与类型混淆**，并**在使用默认 Cranelift 后端的任意架构上逃出 Wasm 沙箱**。同批 `CVE-2026-115893`（9.9）是 aarch64 上 `br_table` 目标超过约 25.6 万时**条件分支目标计算错误**，可跳到用户可控偏移的任意代码。两条同时说明：**Wasm 的隔离保证依赖于编译器后端的正确性**，而编译器正是最难审计的部分。

2. **`CVE-2026-115933`：Postiz 令牌不区分用途：一个签名密钥签出会话、邀请、改密三种令牌（9.9）**  
   Postiz 用**同一个密钥**为 session、invitation、password reset 三类令牌签名，且**令牌本身不携带“用途标记”**（`CWE-290`／`345`／`915`）。同时，一个“刷新浏览器扩展渠道凭据”的路由**对请求中的数据签名并把结果存到请求者可读回的位置**——于是用户可以**取得一个含任意声明的合法签名令牌**，应用会把它当作会话、当作带任意角色的组织邀请、当作改密令牌，或当作企业级开通令牌。**根因不是密钥泄露，而是“令牌语义缺失”**：只要没有用途绑定，任何一条能拿到签名的路径都会击穿所有用途。

3. **`CVE-2026-115931`：Postiz 内部函数可被任意调用致任意文件读取并泄露签名密钥（9.9）**  
   Postiz 允许已登录用户请求后端“在自己已连接的渠道上执行某个函数”，但**未限制可请求的函数集合**，用户可以调用本不该从 Web 界面可达的内部 helper。其中一个 helper **从服务器磁盘读取文件**：只要用户连接一个“存储令牌为文件路径”的渠道，后端就会返回它能读到的任意文件内容——**包括环境变量**，而环境变量里放着**签发登录会话的密钥**、数据库地址与所连服务的凭据。与上一条合起来构成完整链条：**读环境变量拿到签名密钥 → 伪造任意令牌 → 接管管理员**。

4. **`CVE-2026-115557`：Python ssl 模块加入已知失陷证书 denylist（9.4）**  
   Python 在 `ssl` 模块中**为已知失陷/被攻陷的证书加入 denylist**，使这些证书**无论 `SSLContext` 策略如何配置都会被拒绝**——即使未启用证书吊销检查也生效。这条“漏洞”本质是**上游分发链被攻陷后的应急加固**（引用中出现了与某 CA 相关的异常域名）。CVSS 9.4 反映的是“若不处理则信任链被破坏”的严重程度。对使用 Python 的服务，升级解释器即可获得该保护；对自建 CA/证书分发的组织，更重要的是**复核自己的证书来源与吊销状态**。

### 1.4 综合研判

本期仅 97 条，严重 14 条（14.4%）占比偏高但总量小。**第一条主线是“沙箱的信任边界”**：Wasmtime 的两条逃逸（SSA 索引位打包溢出、aarch64 `br_table` 目标错算）说明 Wasm 隔离在实现层面并非“数学证明级”可靠。这对当前流行的用法有直接影响——**用 Wasm 做插件沙箱、多租户函数执行、以及“让 AI 生成的代码在沙箱里跑”**。建议在架构上保留第二道隔离（进程级/容器级），不要把 Wasm 当作唯一边界。**第二条主线是“令牌语义与内部函数暴露”**：Postiz 的三条（令牌不区分用途、内部函数任意调用、路径可被令牌解释为文件）构成一条“读环境变量 → 拿签名密钥 → 伪造任意身份”的完整链。这类缺陷的共同点是**功能设计时未做“能力收敛”**：一个签名密钥服务所有用途、一个执行入口服务所有函数。**第三条是协议与生态**：open62541（OPC UA 客户端）的整数溢出可被**恶意 OPC UA 服务器**利用（注意方向——是服务器攻击客户端），说明 OT 场景里“客户端信任服务器”同样是风险；Happy DOM、Twisted、Crow、Craft CMS、Camaleon CMS 的若干条目属常规 Web/框架缺陷。KEV 无新增，本期不需要应急响应，但**Wasmtime 与 Postiz 的修复应尽快推进**——前者的影响面随 Wasm 普及在扩大，后者的链条一旦被公开即等价于管理员权限。

!!! danger "研判结论：一般风险"
    本期无在野利用、无公开 PoC、无 KEV 新增，整体可按常规节奏处置。但有两个“结构性提醒”：① **不要把 Wasm 当作唯一隔离边界**——Wasmtime 的两条逃逸说明编译器后端的正确性决定了沙箱可靠性，建议在 Wasm 之外保留进程/容器级隔离；② **令牌必须绑定用途**——Postiz 的例子表明“同一密钥签所有令牌 + 令牌不带用途标记”会把任何一处签名滥用放大为全系统身份伪造。

#### 3.1.2 漏洞摘要

Wasmtime 是 Bytecode Alliance 维护的 WebAssembly 运行时。36.0.19 与 43.0.0 之前，**Cranelift 编译器后端**在把 **SSA value 索引做位打包（bit-packing）** 时存在缺陷：当编译“足够大或特制”的 Wasm 函数（含大量 SSA 值）时，**该打包在 release 构建中会静默溢出**（`CWE-197` 数值截断、`CWE-843` 类型混淆），CVSS 9.9。溢出的后果是 Cranelift **引用错误的 IR 值**，造成**任意错误编译（miscompilation）、类型混淆以及其他攻击者可控的效果**，并可在**使用默认 Cranelift 后端的任意架构上逃出 Wasm 沙箱**。同批的 `CVE-2026-115893`（9.9）是 aarch64 上的另一条逃逸：当 Wasm `br_table` 指令的目标数超过约 **256,000** 时，Cranelift 编译出的**条件分支目标不正确**，分支可跳到**用户可控偏移处的任意代码**。两条漏洞的严重性不在 CVSS，而在**信任模型的坍塌**：大量系统把 Wasm 当作“安全执行不可信代码”的唯一隔离层（插件系统、多租户函数计算、AI 生成代码的执行沙箱），一旦该层可逃逸，上层所有假设同时失效。

> 原文摘要（NVD）：Wasmtime is a runtime for WebAssembly. Prior to 36.0.19 and 43.0.0, the Cranelift compiler backend bit-packs SSA value indices in a way that can silently overflow in release builds when compiling a sufficiently large or specially crafted Wasm function with many SSA values. The overflow can make Cranelift reference incorrect IR values, causing arbitrary miscompilation, type confusion, and other attacker-controlled effects that may escape the Wasm sandbox on any architecture using the default Cranelift backend. This issue is fixed in versions 36.0.19 and 43.0.0.

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 可向 Wasmtime 提交/加载 Wasm 模块的入口 |

**技术原理：**

编译器为节省内存，常把多个小字段打包进一个字（例如把类型索引、值索引、标志位压进 32/64 位）。当索引规模超出预留位数时，必须做显式检查或提升位宽；若只在 debug 构建断言、release 构建静默截断，就会出现“编号重复/指向错误项”的情况。对 Cranelift 而言，IR 值被错误引用意味着**生成的机器码语义与源 Wasm 不一致**——这种不一致不是随机的，攻击者可通过构造特定形状的函数来影响“错误指向哪里”，从而在生成代码中埋入越权访问或控制流劫持，最终触达宿主内存。

**核心利用链：**

```text
攻击者
  └─ 定位暴露的 目标组件（目标产品）
      └─ 发送畸形输入触发缺陷逻辑
          └─ 触发 CWE-197, CWE-843 对应处理逻辑
              └─ 造成信息泄露、拒绝服务或状态破坏
                  └─ 横向利用或持久化（视环境）
```

#### 3.2.2 漏洞摘要

Postiz（开源社媒排程工具）用**同一个共享密钥**为三类令牌签名：**会话（session）、组织邀请（invitation）、密码重置（password reset）**，且**令牌本身不携带“用途标记”**（`CWE-290`、`CWE-345`、`CWE-915`），CVSS 9.9。缺陷被一条“刷新浏览器扩展渠道凭据”的路由放大：该路由**对请求中携带的数据直接签名**，并把签名结果存放到**请求者可读回的位置**。于是用户可以取得一个**含任意声明的合法签名令牌**，而应用会把它当作：会话令牌、带任意角色的组织邀请、密码重置令牌，或企业级开通（provisioning）令牌。另有一条较窄的路径（创建团队邀请）会额外签名数据。**这意味着“拿到一次签名能力”=“获得系统中任意身份”**。与同批的 `CVE-2026-115931`（内部函数任意调用 → 读环境变量 → 得到签名密钥）串起来，攻击链为：读环境变量 → 取签名密钥 → 伪造任意令牌 → 接管管理员。

> 原文摘要（NVD）：Postiz signs its session, invitation and password reset tokens with one shared secret and without any marker of what a token is for. A route that refreshes the credentials of a browser-extension channel signed data taken from the request itself and stored the result where the requesting user can read it back. A user could therefore obtain a validly signed token containing any claims they choose, which the application accepts as a session, as an organization invitation with a chosen role, as a password reset or as an enterprise provisioning token.  A second, narrower route that creates team invitations signs extra fields from the request body in the same way.

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 已登录用户（或能触发签名路由的请求） |

| 特定配置 | 否 | 默认配置即受影响 |
| 利用复杂度 | 低 | 低（已登录 + 一次签名路由调用） |

**技术原理：**

令牌（无论是 JWT 还是自定义签名串）必须满足两条：**用途绑定**（`aud`/`typ`/`purpose` 声明，且校验时比对）与**签名不可被诱导生成**（不能对用户提供的任意数据签名）。本实现两条都缺：一个密钥服务所有用途、令牌里没有 `purpose` 字段，且某条路由成为“签名预言机”。任何一处能获得签名的路径，都立即转化为对所有用途的伪造能力——这是“能力未最小化”的经典后果。

**核心利用链：**

```text
攻击者
  └─ 定位暴露的 目标组件（目标产品）
      └─ 直接访问受保护接口或伪造身份
          └─ 触发 CWE-290, CWE-345 对应处理逻辑
              └─ 绕过认证获得未授权能力
                  └─ 横向利用或持久化（视环境）
```

## 五、当日处置建议

1. **把“沙箱”做成两层**：Wasmtime 的两条逃逸说明编译器后端的正确性决定了 Wasm 隔离的上限。对高价值场景（执行 AI 生成代码、多租户插件），应在 Wasm 之外叠加进程/容器隔离与网络禁令。
2. **令牌设计的三条硬规则**：用途声明必须存在且被校验、不同用途用不同密钥（或域分离）、禁止对用户提供的数据签名。Postiz 三条缺陷分别命中这三条。
3. **内部函数/内部路由要有独立命名空间与鉴权**：Postiz 的“可按名称调用任意函数”等价于把服务端全部 helper 暴露给前端。建议对内部能力做显式白名单。
4. **OT 场景注意“客户端信任服务器”**：open62541 的溢出方向是“恶意 OPC UA 服务器攻击客户端”，这在 OT 资产盘点中常被忽略——工程师站上的客户端也是攻击面。
5. **Python 环境顺手升级**：`ssl` 模块的失陷证书 denylist 属于“装上就生效”的加固，成本极低；同时建议复核自有证书的签发链与吊销状态。
