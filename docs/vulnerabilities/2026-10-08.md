### 1.3 今日重点关注

1. **`CVE-2026-102255`：SonicWall SMA1000 未认证服务端请求伪造（SSRF）**  
   影响 SonicWall SMA1000 远程访问设备的 WorkPlace 门户，**未认证远程攻击者**可借非预期备用路径诱使设备以其身份发起请求并触达内部功能，**CVSS 10.0**。建议**立即核查边界远程接入设备的版本与暴露面并安装热修复**。

2. **`CVE-2026-76482` / `CVE-2026-76471` 等：Cisco 网络与许可基础设施批量缺陷集群**  
   Cisco 单批披露 **36 条**缺陷：**License On-Prem 签名/信任校验不当（`CVE-2026-76482`，10.0）**、**NX-OS NX-API 未认证 root 级 RCE（`CVE-2026-76471`，9.8）**、**MPLS/VXLAN/SRv6 OAM（NGOAM）未认证 RCE（`CVE-2026-76465`/`76485`/`76486`/`76501`，均 9.8）**、**APIC 多条 9.8**、**许可服务器 Web 管理口令重置校验不当（`CVE-2026-20328`，9.1）与许可 API 任意文件写入（`CVE-2026-76454`，9.1）**。建议**按 Cisco 公告分产品线紧急闭环交换机、控制器与许可服务器**。

3. **`CVE-2026-104334` / `CVE-2026-93674`（Langflow）与 `CVE-2026-107204` / `105192`（LMCache）：AI/推理组件 RCE 集群**  
   **IBM Langflow OSS（1.0.0–1.12.2）** 单批 24 条 RCE（含未认证 9.8）；**LMCache（≤ 0.5.5）** multiprocess 模式**默认监听全部网卡且无认证**，`/run_script` 未认证 RCE（9.8）与 ZeroMQ 反序列化 RCE（9.8）。建议**排查 AI 编排与推理缓存组件的版本与网络暴露并升级**。

4. **`CVE-2025-64393`（Veeam）与 `CVE-2026-59346`（VMware，已公开 PoC）：信任链与虚拟化逃逸**  
   **Veeam Backup & Replication 的 Backup Viewer 只读角色可提权至 SYSTEM（9.4）**；**VMware Workstation/Fusion VMXNET3 整数溢出致客户机逃逸（9.3，PoC 已公开，修复版本 26H1u1）**。建议**优先升级备份服务器与桌面虚拟化宿主**。

### 3.1 CVE-2026-102255 — SonicWall SMA1000 未认证服务端请求伪造（SSRF）

!!! danger "严重漏洞（未认证可远程触发，CVSS 10.0）"
    SonicWall SMA1000 远程访问设备的 WorkPlace 门户存在**未认证服务端请求伪造（SSRF）**漏洞。远程未认证攻击者可借助一条“非预期的备用访问路径”诱使设备以其自身身份发起请求，从而触达内部功能并执行未授权操作，CVSS 3.1 基础分 **10.0**。

#### 3.1.2 漏洞摘要

该漏洞位于 SonicWall SMA1000 系列远程访问设备的 WorkPlace 门户接口。厂商描述指出，由于存在**一条非预期的备用访问路径（unintended alternate access path）**，远程未认证攻击者可借此路径**以设备自身的身份发起对外/对内请求**，进而访问本应受限的内部功能并执行未授权操作。由于攻击者无需任何凭据即可触发，且设备通常直接暴露于互联网用于 SSL VPN / 远程访问，该漏洞被厂商评为**满分 10.0**。

> SonicWall 就该设备一次性发布四项缺陷的热修复，`CVE-2026-102255` 为其中 CVSS 最高者（10.0），属未认证可远程触发的 SSRF，风险面直接指向企业远程接入边界。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
|---|---|---|
| 网络可达 | 是 | 需可达 SMA1000 设备的 HTTPS 管理/门户服务 |
| 身份认证 | 无需 | 未认证远程攻击者即可触发 |
| 用户交互 | 不需要 | 直接构造 HTTP 请求 |
| 特定配置 | 是 | 依赖 WorkPlace 门户可达与非预期备用路径的可用性 |
| 利用复杂度 | 低 | 无认证、无交互，攻击面为互联网暴露设备 |

**技术原理：**

WorkPlace 门户在处理用户可控的请求目标时，未对“可访问的内部功能范围”实施充分限制，并存在一条非预期的备用访问路径，使未认证请求可被设备“代理”至内部服务或管理功能。攻击者据此以设备身份发起请求，绕过常规访问边界，读取内部信息或触发未授权操作（如管理类接口）。

**核心利用链：**

```text
攻击者
  └─ 发现互联网暴露的 SonicWall SMA1000 设备（WorkPlace 门户）
      └─ 构造指向非预期备用访问路径的未认证请求
          └─ 诱使设备以自身身份发起内部请求（SSRF）
              └─ 绕过边界访问内部功能 / 管理接口
                  └─ 执行未授权操作（信息泄露 / 配置篡改 / 进一步利用）
```

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
|---|---|---|
| 网络可达 | 是 | 需可达设备管理面/NX-API/OAM 接口（部分为数据面协议） |
| 身份认证 | 部分无需 | NX-API、OAM 与部分许可服务器缺陷未认证即可触发 |
| 用户交互 | 不需要 | 直接构造网络报文或 HTTP 请求 |
| 特定配置 | 是 | 部分缺陷需相应功能（NX-API / NGOAM / 许可服务）启用 |
| 利用复杂度 | 低至中 | 未认证接口利用门槛低；OAM 需网络可达数据面 |

**技术原理：**

Cisco 在内部安全评审中集中发现三类根因：其一，**信任与签名校验缺失**（许可服务器对签名/信任链校验不当，`CWE-347`）；其二，**输入校验不足导致的缓冲区溢出**（NX-API 与 NGOAM 处理 IP/OAM 报文时按用户可控长度写入固定缓冲，`CWE-121/122`，可致 root 级 RCE）；其三，**认证与鉴权缺失**（许可服务器口令重置流程、许可 API 与部分 Web 接口未正确校验身份，导致未认证访问或任意文件写入）。相关设备位于数据中心信任根位置，一旦被未认证接管，可导致网络中断或更大范围横向移动。

**核心利用链：**

```text
攻击者
  └─ 定位可达的 Cisco 交换机（NX-API/NGOAM）、APIC 或许可服务器
      └─ 构造未认证 HTTP 请求或特制 OAM/网络报文
          └─ 触发输入校验/认证/签名校验缺陷
              └─ 绕过认证或造成缓冲区溢出
                  └─ 以 root/管理员权限执行代码、写文件或中断服务
```

### 3.3 CVE-2026-107204 / 105192 / 107206 / 107205 — LMCache 未认证远程代码执行与信息泄露集群

!!! danger "严重漏洞（未认证可远程触发，CVSS 9.8 / 9.4 / 8.6）"
    LLM 推理缓存组件 **LMCache（≤ 0.5.5）** 在 multiprocess/distributed 模式下**默认监听全部网卡且无任何认证**：未认证远程攻击者可通过 `/run_script` 端点执行 Python 代码（9.8）、经 ZeroMQ 反序列化 RCE（9.8）、读取环境凭据与配置（9.4）并操作缓存集群控制接口（8.6）。

#### 3.3.2 漏洞摘要

LMCache 是用于大模型推理的 KV Cache 复用组件，其 multiprocess（distributed）模式为跨进程共享缓存块而开放内部通信面：**ZeroMQ ROUTER 套接字与 HTTP 控制服务默认监听全部网卡且不设认证**。攻击者在其可达时：可向 `/run_script` 端点投递脚本执行 Python 代码，并通过注入的 FastAPI app 对象取得真实 `builtins` 以绕过受保护的 `__import__`，从而 `import os` 以 LMCache 进程权限执行系统命令（`CVE-2026-107204`，9.8）；可向 ZeroMQ 套接字发送 msgpack 消息，其扩展类型 1 会在解码请求参数阶段被交给 `DeviceIPCWrapper.Deserialize` 并调用 `pickle.loads`，形成**反序列化 RCE**（`CVE-2026-105192`，9.8）；此外 multiprocess HTTP 服务器缺失认证，可经 `GET /env`、`GET /config` 读取环境凭据与配置（`CVE-2026-107206`，9.4），协调器控制 API 亦可被未认证访问以注册/注销实例、覆写配额、注入事件（`CVE-2026-107205`，8.6）。

> 该集群属“**默认不安全配置 + 缺失认证**”型缺陷，常见于 AI 推理集群内部组件，一旦推理节点网络暴露或位于共享/云网段即可被未认证利用。

#### 3.3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
|---|---|---|
| 网络可达 | 是 | 需可达 LMCache 控制的端口（默认监听全部网卡） |
| 身份认证 | 无需 | 服务未启用任何认证 |
| 用户交互 | 不需要 | 直接发送 HTTP/ZeroMQ 消息 |
| 特定配置 | 是 | 需启用 multiprocess/distributed 模式 |
| 利用复杂度 | 低 | 默认配置即暴露，无认证门槛 |

**技术原理：**

根因在于 LMCache 的进程间通信面被设计为“受信内部网络”假设：ZeroMQ ROUTER 与 HTTP 控制服务绑定 `0.0.0.0` 且无认证。`/run_script` 端点允许投递脚本，且通过注入的 FastAPI `app` 对象可恢复真实 `builtins`，绕过针对 `__import__` 的防护以实现任意代码执行；ZeroMQ 路径在解码阶段即对扩展类型 1 调用 `pickle.loads`，造成反序列化 RCE；管理端点（`/env`、`/config`、`/instances`、`/quota`、`/events`）缺失认证则可致凭据泄露与集群控制被篡改。

**核心利用链：**

```text
攻击者
  └─ 发现可达的 LMCache multiprocess/distributed 服务端口
      └─ 选择路径：
         ├─ POST /run_script 投递 Python 脚本（取得 builtins → os → 系统命令）
         └─ 向 ZeroMQ ROUTER 发送扩展类型 1 消息 → pickle.loads 反序列化
              └─ 以 LMCache 进程权限执行任意代码
                  └─ 读取 /env /config 凭据、篡改缓存与集群配额、横向移动
```

#### 3.4.2 漏洞摘要

Langflow 是开源低代码可视化 AI/Agent 编排框架（IBM 维护）。本窗口 IBM 集中披露 24 条缺陷，核心为**框架在生成与执行代码/命令时对用户可控输入处理不当**：`CVE-2026-104334`（9.8）与 `CVE-2026-93674`（9.8）分别对应**代码生成控制不当**与**OS 命令特殊元素未中和**，远程攻击者可借组件/流程定义注入并执行任意代码；其余多条 8.8 分项涉及**代码安全扫描器黑名单不完整（`CVE-2026-97655`）、依赖混淆（`CVE-2026-93675`）、输入校验与访问控制不当**等，认证后攻击者亦可实现 RCE。由于 Langflow 常被部署用于连接大模型与外部工具（含可执行代码组件），一旦暴露即可被用于执行任意命令。

> 该集群反映“**AI 编排框架的代码执行面**”风险：可视化的代码/命令组件若未严格隔离与校验，极易成为未认证或低权限 RCE 入口。

### 3.5 CVE-2026-62252 / 62253 — Homer 电信观测平台默认口令与 JWT 认证缺失

!!! danger "严重漏洞（未认证可远程触发，CVSS 9.8）"
    开源电信可观测性平台 **Homer（< 11.0.283）** 存在两项严重缺陷：全新部署使用内部认证时会以**固定默认口令 `sipcapture`** 创建 `admin` 账户且无首登强制改密（9.8）；同时 **JWT 中间件在密钥为空时直接放行所有请求**，默认安装下 `/api/v1`、`/api/v3`、`/api/v4` 全部受保护接口形同未设防（9.8）。

#### 3.5.2 漏洞摘要

Homer 是用于 VoIP/电信流量捕获与可视化的开源平台。`CVE-2026-62252`：在**使用内部认证的全新部署**中，引导流程会自动创建 `admin` 账户并将口令设为固定的 `sipcapture`（以旧式 SHA-256 十六进制存储），且**没有任何首登强制改密机制**——任何能访问登录页的攻击者均可凭公开默认口令取得管理员权限。`CVE-2026-62253`：两个 JWT 中间件函数（`JWTMiddleware`、`JWTMiddlewareV4`）在 `jwtSecret == ` 时**直接 `return next(c)` 放行**，而 JWT 密钥默认为空字符串，导致**默认安装下所有受保护 API（`/api/v1`、`/api/v3`、`/api/v4`）完全未受保护**。两项叠加使默认部署几乎无认证防线。

> 典型的“**默认配置即不安全**”组合：固定默认口令 + 空密钥放行，任何暴露在互联网的 Homer 实例都可能被直接接管。

| 条件 | 状态 | 说明 |
|---|---|---|
| 网络可达 | 是 | 需可达 Homer Web/API 服务 |
| 身份认证 | 无需 | 默认口令可登录；空密钥直接放行 API |

**技术原理：**

根因有二：其一为**引导流程缺陷**——部署引导硬编码写入默认账户与口令，且缺少强制改密，属 `CWE-798`；其二为**认证中间件逻辑缺陷**——JWT 校验在密钥为空字符串时短路放行（`CWE-306`），而密钥默认即为空，使鉴权形同虚设。攻击者据此可直接登录后台或未认证调用全部受保护 API，读取捕获的电信信令数据或篡改平台配置。

**核心利用链：**

```text
攻击者
  └─ 发现互联网/内网暴露的 Homer 实例
      ├─ 尝试默认口令：admin / sipcapture 登录后台
      └─ 或直接以空 Bearer 令牌调用 /api/v1、/api/v3、/api/v4
           └─ 获得管理员权限 / 未认证访问全部受保护接口
               └─ 读取电信信令与配置、篡改平台、进一步利用
```

#### 3.6.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
|---|---|---|
| 网络可达 | 是 | 需可达 Backstage 门户 |
| 身份认证 | 需要（普通已认证用户） | 攻击者为已认证的 Backstage 用户 |
| 用户交互 | 不需要 | 直接读取/操作任务 |
| 特定配置 | 是 | 依赖对应插件与集成模块启用 |
| 利用复杂度 | 中 | 需已认证账户与特定时序/部署条件 |

**技术原理：**

根因在于脚手架后端在任务执行数据的**访问控制**与**状态校验**上不充分：一方面未限制已认证用户读取他人任务中的内部执行数据（`CWE-200/201`），造成敏感信息（如注入的凭据、内部 URL、日志）泄露；另一方面任务状态校验存在时序/链接跟随缺陷（`CWE-59/362`），可在特定条件下影响文件或状态；此外部分集成模块对映射样式内容与输入未严格校验（`CWE-20`），可能被用于注入或越权访问。

**核心利用链：**

```text
攻击者（已认证用户）
  └─ 访问 Backstage 门户并读取他人 Scaffolder 任务
      └─ 获取任务内部执行数据（含敏感信息）
          └─ 结合集成模块缺陷扩大访问范围
              └─ 取得凭据或越权操作，威胁代码仓库/CI-CD/云资源
```

Veeam Backup & Replication 是企业级备份与容灾平台，其 **Backup Viewer** 角色本应仅具只读查看权限。该漏洞允许**拥有 Backup Viewer 角色的用户以 SYSTEM 权限在备份服务器上执行任意代码**（根因归为不可信数据反序列化 `CWE-502`）。由于备份服务器常配置高权限服务账户、可访问全域主机与虚拟化平台、并存放敏感备份数据，攻击者一旦由低权限角色提权至 SYSTEM，即可读取/篡改备份、窃取凭据、并向被保护的虚拟化环境横向扩散，危害面极大。

> 备份系统是“王冠上的珠宝”式目标：只读角色提权到 SYSTEM 意味着整个备份域的完整性、机密性与可用性同时暴露。

### 3.8 CVE-2026-59346 — VMware Workstation / Fusion VMXNET3 整数溢出致客户机逃逸

!!! danger "严重漏洞（客户机致宿主机越界写，CVSS 9.3，已公开 PoC）"

#### 3.8.2 漏洞摘要

VMXNET3 是现代 VMware 客户机的默认虚拟网卡。其 **TSO（TCP Segmentation Offload）分段**例程用 32 位 `imul` 计算“段数 × 每段大小”作为分配尺寸；当真实乘积超过 2^32 时发生回绕，分配器拿到的是被截断的小值，而随后的分段循环由 `seg_count` 驱动，仍按每段大小写入，从而在**宿主机 `vmware-vmx` 进程中造成大范围越界写**，写入内容来自客户机可控的数据包。此前针对同代码路径的修复（`CVE-2025-41236`）仅对 MSS、每段大小及其和的单项做了 ≤ 9216 的限制，**未约束真正会回绕的乘积**，因此参数仍可低于阈值而触发溢出。厂商将该问题评为**可致宿主机代码执行（虚拟机逃逸）**，CVSS 9.3（ZDI 建议 7.5）。本窗口已发现公开 PoC，其演示到宿主进程崩溃（SIGSEGV）为止。

> 客户机→宿主机逃逸属虚拟化环境最高危类别；由于 PoC 已公开且利用面向“可写原始 TX 描述符”的客户机用户，宿主机安全边界面临实际挑战。

#### 3.8.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
|---|---|---|
| 网络可达 | 否（宿主机本地） | 攻击面来自客户机内部 |
| 身份认证 | 需客户机内相应权限 | 客户机内可写原始 TX 描述符的用户（PoC 需 root） |
| 用户交互 | 不需要 | 客户机内加载模块触发 |
| 特定配置 | 是 | 客户机使用 VMXNET3 网卡且接口 up |
| 利用复杂度 | 中 | 需客户机权限与对应内核/驱动环境 |

**技术原理：**

根因是**整数溢出未在乘法层面受约束**：分段例程以 32 位 `imul` 计算 `seg_count * per_seg_size`，乘积回绕后分配尺寸被截断，而分段循环仍按 `seg_count` 与每段大小写入，导致按真实乘积所需的字节数远超已分配缓冲，形成越界写。既有修复仅约束单项字段（MSS、per_seg、其和 ≤ 9216），未约束**乘积**本身，故仍可回绕。修复方向是将乘法以 64 位进行并在进入分配器前对结果设界。

**核心利用链：**

```text
客户机内攻击者（具相应权限）
  └─ 直接写入 VMXNET3 TX 环描述符（绕过内核驱动 TSO 逻辑）
      └─ 构造使 seg_count × per_seg_size 在 32 位回绕的参数
          └─ 敲响 doorbell MMIO 寄存器触发 TSO 分段
              └─ 宿主机 vmware-vmx 分配尺寸被截断但按真实长度写入
                  └─ 宿主机进程大范围越界写（PoC 触发 SIGSEGV；厂商评为可致代码执行）
```

### 3.9 CVE-2026-92414 / CVE-2026-97720 — Apache Jackrabbit 会话固定与 Impala JWT 校验缺失

!!! danger "严重漏洞（认证绕过/会话复用，CVSS 9.3 / 9.1）"
    Apache 项目本窗口披露两项严重缺陷：**Jackrabbit WebDAV 服务器**在令牌匹配时**复用缓存认证会话且不校验凭据**（会话固定/跨用户复用，`CVE-2026-92414`，9.3）；**Impala 执行器**的 JWT/OAuth 认证实现**未校验签名**（`CVE-2026-97720`，9.1），可使未授权者访问执行器 Web 服务。

#### 3.9.2 漏洞摘要

`CVE-2026-92414`（Apache Jackrabbit，`CWE-384`）：Jackrabbit **WebDAV 服务器**在收到任意 `Lock-Token`/`TransactionId`/`SubscriptionId`/`If` 头字段令牌匹配时，会**附加上一个缓存的已认证会话，且不校验任何凭据**，导致会话固定 / 跨用户会话复用——攻击者可利用令牌匹配“借用”他人的已认证会话。影响 Jackrabbit 2.23.0–2.23.5、2.22.0–2.22.4、2.20.x（含）等系列。`CVE-2026-97720`（Apache Impala，`CWE-303`）：4.5.2 及以前的 **Impala 执行器** JWT/OAuth 认证实现不正确——**Bearer（JWT）签名未被校验**，从而使配置为接受 JWT/OAuth 的执行器 Web 服务器**接受任意（签名无效的）令牌**，未授权者即可访问执行器服务资源。

> 两项均属“**认证实现本身失守**（会话复用 / 签名不校验）”，影响面为大数据与内容仓库基础设施，须优先升级。

#### 3.9.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
|---|---|---|
| 网络可达 | 是 | 需可达 WebDAV 服务 / 执行器 Web 服务 |
| 身份认证 | 无需（绕过） | 令牌匹配即复用会话；签名不校验即接受任意令牌 |
| 用户交互 | 不需要 | 直接构造请求头 / 令牌 |
| 特定配置 | 是 | Impala 需执行器配置为接受 JWT/OAuth |
| 利用复杂度 | 低 | 认证实现缺陷，构造请求即可 |

**技术原理：**

`CVE-2026-92414`：WebDAV 服务器的会话缓存逻辑在“令牌字段匹配”时错误地将请求绑定到已缓存会话，且**缺少凭据校验**，导致攻击者可用匹配令牌取得他人已认证会话（会话固定/复用）。`CVE-2026-97720`：执行器在验证 JWT/OAuth 时**未对 Bearer JWT 的签名进行校验**（算法实现不正确），仅凭“存在令牌”即视为通过，从而接受任意（包括伪造的）令牌，使未授权者访问执行器 Web 服务。

**核心利用链：**

```text
攻击者
  ├─ Jackrabbit：构造携带匹配 Lock-Token/TransactionId 等头字段的 WebDAV 请求
  │     └─ 服务器复用缓存已认证会话且不校验凭据 → 取得他人会话
  └─ Impala：向执行器 Web 服务发送任意 Bearer JWT
        └─ 签名未被校验 → 令牌被接受 → 未授权访问执行器资源
```

### 3.10 CVE-2026-16516 — wolfSSH ECDSA 曲线标识未校验致主机密钥验证缺陷

!!! danger "严重漏洞（主机密钥验证可被绕过，CVSS 9.0）"
    嵌入式 SSH 库 **wolfSSH** 在解析 `KEXDH_REPLY` 主机密钥时**未校验 ECDSA 曲线标识是否与协商算法一致**，`ParseECCPubKey()` 直接依据 blob 中的算法字符串推导曲线，可能绕过主机密钥验证/导致密钥协商处理异常，CVSS 9.0。

#### 3.10.2 漏洞摘要

wolfSSH 是广泛用于嵌入式/物联网设备的轻量 SSH 实现。该漏洞位于其主机密钥解析逻辑：在 `ParseECCPubKey()`（`src/internal.c`）中，当处理 `KEXDH_REPLY` 主机密钥 blob 时，代码**直接使用 blob 内的算法字符串经 `NameToId`/`wcPrimeForId` 推导曲线，而未与协商阶段记录的 `ssh->handshake->pubKeyId` 进行比对**，即未验证 ECDSA 曲线标识是否与协商算法一致。这构成主机密钥/算法真实性验证不足（`CWE-345`），在中间人可达的场景下可能被滥用，破坏 SSH 会话的信任基础或导致密钥处理异常。

> 该缺陷针对“**主机密钥验证**”这一 SSH 信任根基，嵌入式 SSH 栈常用于设备管理与远程维护通道，须优先修复。

#### 3.10.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
|---|---|---|
| 网络可达 | 是 | SSH 连接可被中间人干预 |
| 身份认证 | 无需 | 主机密钥验证阶段缺陷 |

**技术原理：**

根因是**未对主机密钥 blob 中的算法/曲线标识做一致性校验**：`ParseECCPubKey()` 依据 blob 自带的算法字符串选择曲线，而不与协商得到的 `pubKeyId` 比对，使攻击者（处于中间人位置）可能以不一致的曲线标识影响主机密钥验证流程，破坏对服务器身份的信任判定。修复方式是强制校验 blob 曲线标识与协商算法一致。

**核心利用链：**

```text
攻击者（中间人位置）
  └─ 拦截客户端与 wolfSSH 服务端的 SSH 会话
      └─ 在 KEXDH_REPLY 主机密钥 blob 中提供不一致的 ECDSA 曲线标识
          └─ ParseECCPubKey() 未与协商算法比对
              └─ 主机密钥验证被绕过/异常 → 破坏 SSH 信任根基
```

### 3.12 CVE-2026-19572 — FlexNet Publisher lmadmin 硬编码认证绕过致管理员会话接管

#### 3.12.2 漏洞摘要

> 许可服务器常被忽视但处于“软件供应链可信根”位置；未认证即取得管理员会话意味着可完全控制授权服务。
