### 3.1 CVE-2026-26035 — FortiWeb 远程 RADIUS 管理认证绕过漏洞

!!! danger "严重漏洞"
    当 FortiWeb 管理员账户启用非默认的 Remote RADIUS Type 认证并开启 wildcard 设置时，认证匹配逻辑存在缺陷，远程未认证攻击者无需任何凭据，仅凭**随机用户名与密码**即可登录 FortiWeb GUI/CLI 管理界面，完全接管 Web 应用防火墙（WAF）管理权限。

#### 3.1.2 漏洞摘要

该漏洞位于 FortiWeb 的 **Remote RADIUS Type Admin Authentication**（远程 RADIUS 类型管理员认证）机制。当管理员账户配置为 RADIUS 远程认证并启用 **wildcard（通配符）** 选项时（该选项**默认禁用**，属于非默认配置），设备会把远程认证服务器上的**任意用户名**与本地定义的管理员组进行匹配，匹配逻辑存在缺陷——攻击者无需知道任何有效凭据，使用随机用户名与密码即可通过认证，登录 FortiWeb 的 GUI/CLI 管理界面。

成功利用后，攻击者可完全控制 FortiWeb（Web 应用防火墙）的管理系统：读取/篡改防护策略、绕过 WAF 规则、窃取配置与日志、植入后门管理员账户，并可能借管理通道进一步渗透内网。该漏洞由 Fortinet 内部发现，CVSS 3.1 基分 9.8（严重），攻击向量为网络（AV:N）、无需认证（PR:N）、无需用户交互（UI:N），机密性/完整性/可用性影响均为高。

> 国家信息安全漏洞库（CNNVD）已发布对应通报（CNNVD-2026-84520763），确认攻击者可完全绕过身份验证机制，以未授权身份访问 FortiWeb 后台管理功能。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 FortiWeb 管理界面（GUI/CLI 服务，通常 HTTPS/SSH 管理端口） |
| 身份认证 | 无需 | 远程未认证攻击者，使用随机用户名与密码即可登录 |
| 用户交互 | 不需要 | 无需任何交互 |
| 特定配置 | 是 | 依赖非默认配置：管理员账户为 Remote RADIUS Type 且启用 wildcard 选项 |
| 利用复杂度 | 低 | 攻击流程为构造登录请求，无需专业工具 |

**技术原理：**

FortiWeb 的 Remote RADIUS Type 管理员认证将本地"管理员组"与远程 RADIUS 服务器用户映射。启用 wildcard 设置后，系统对远程服务器上的任何用户名均按已定义的管理员组进行匹配（即"通配"匹配任意用户名），配合缺陷的认证判定逻辑，导致任意随机用户名/密码组合均可通过认证，属于典型的**认证逻辑缺陷（CWE-287）**，而非口令爆破。

**核心利用链：**

```text
攻击者
  └─ 发现暴露的 FortiWeb 管理界面（GUI/CLI）
      └─ 构造登录请求（随机用户名 + 随机密码）
          └─ 触发 wildcard 通配匹配缺陷（CWE-287）
              └─ 绕过身份认证
                  └─ 以管理员权限登录管理界面
                      └─ 篡改 WAF 策略 / 窃取配置 / 植入后门账户 / 横向渗透
```

#### 日志与行为排查

重点检查：

- FortiWeb 系统登录日志（System > Log > Authentication）中的异常登录记录；
- 使用随机用户名/密码的成功登录事件（无对应真实用户的认证成功记录）；
- WAF 策略、管理员账户、SSL 证书等配置的异常变更；
- 管理界面来源 IP 是否异常（非管理员网段、TOR/代理出口）；
- 设备是否存在异常外联或配置导出行为。

| 检测项 | 可疑特征 |

### 3.2 CVE-2026-69414 — 微软 Defender 提权零日 "ShieldBreak"

!!! danger "高危漏洞"
    Microsoft Defender 恶意软件保护引擎（Malware Protection Engine）存在本地权限提升零日漏洞（公开代号 "ShieldBreak"），可**100% 绕过** 7 月针对 `CVE-2026-50656`（RoguePlanet）的补丁，本地低权限攻击者可在 Windows 11 25H2 / Server 2025 上提权至 **SYSTEM**，并绕过 AMSI 保护；微软已确认，但**暂无官方补丁**，公开 PoC 完整可用。

#### 3.2.2 漏洞摘要

"ShieldBreak" 是安全研究员 "Nightmare Eclipse" 于 2026 年 8 月微软补丁日（8 月 11 日）公开披露的 **Microsoft Defender（Microsoft Malware Protection Engine）本地权限提升零日漏洞**，微软已确认并以 `CVE-2026-69414` 跟踪。该漏洞是 7 月已修复的 **RoguePlanet（`CVE-2026-50656`）** 的**补丁绕过**——并非简单复现原攻击路径，而是采用不同的利用手法绕过 RoguePlanet 修复，据披露者声称成功率 100%。

该漏洞允许本地低权限攻击者将权限提升至 **SYSTEM**（Windows 最高权限），且可**绕过 AMSI（反恶意软件扫描接口）** 保护机制——这意味着攻击者可在 Defender/AMSI 防护的眼皮底下执行恶意载荷。PoC 已在 Windows 11 25H2（含 Canary 渠道）与 Windows Server 2025 上验证；Windows 10 及对应服务器版本同样受影响但 PoC 暂不支持。微软已确认漏洞存在并正在开发高质量安全更新，截至报告时点**尚无官方补丁**。

> 微软官方声明（NVD 收录描述）："Microsoft is aware of an elevation of privilege in the Microsoft Malware Protection Engine in Microsoft Defender publicly referred to as 'ShieldBreak'. We are working to provide a high quality security update that addresses this vulnerability."

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 否 | 本地攻击（AV:L），无需网络 |

**技术原理：**

"ShieldBreak" 针对 Microsoft Malware Protection Engine（`MsMpEng.exe` 相关组件）的权限处理缺陷：恶意软件保护引擎通常以高权限（SYSTEM）运行，其与低权限进程之间的交互接口存在可被利用的权限校验缺陷。披露者指出，微软 7 月针对 RoguePlanet（`CVE-2026-50656`）的补丁只封堵了原攻击路径，ShieldBreak 采用**不同的利用手法**（补丁绕过）仍可完成提权，并可在提权后**绕过 AMSI**，使后续恶意载荷不被扫描接口拦截。具体技术细节以披露者公开文档与微软后续公告为准。

**核心利用链：**

```text
攻击者（本地低权限账户）
  └─ 运行公开 PoC（ShieldBreak）
      └─ 触发恶意软件保护引擎权限校验缺陷（补丁绕过 CVE-2026-50656 修复）
          └─ 提权至 SYSTEM
              └─ 绕过 AMSI 保护
                  └─ 加载恶意载荷 / 关闭防护 / 持久化
```

### 3.3 CVE-2026-70468 — FortiManager FGFM 认证绕过漏洞

!!! danger "高危漏洞"
    FortiManager 与 FortiManager Cloud 的 FGFM 协议存在认证绕过漏洞：在特定 CLI 配置（`fgfm-peercert-withoutsn`）且攻击者持有有效证书的条件下，远程未认证攻击者可**冒充任意受管 FortiGate 设备**，向 FortiManager 下发/篡改防火墙策略，影响面可扩展至整个 FortiGate 集群。

#### 3.3.2 漏洞摘要

该漏洞位于 FortiManager 与受管 FortiGate 之间的 **FGFM（FortiGate-to-FortiManager）通信协议**。当管理员在 FortiManager 上配置了特定 CLI 选项（`fgfm-peercert-withoutsn`）时，协议对对端设备的证书校验被弱化：攻击者**持有一张有效证书**并构造特制的 FGFM 请求，即可**冒充任意由该 FortiManager 管理的 FortiGate 设备**，从而获得与该设备等同的管理信任关系。

成功利用后，攻击者可借受管设备身份向 FortiManager 上报/同步恶意配置、篡改防火墙策略（含安全策略、VPN、路由等），在大型 FortiGate 集群场景下影响面可被放大，还可能进一步获取 FortiManager 中存储的敏感信息。该漏洞由 Fortinet 内部发现（Discovered: Internal），Fortinet 官方公告披露时**无已知在野利用**，CVSS 官方评分 7.3（高危），NVD 暂评为 8.1（高危）。

> 利用前提：需满足特定 CLI 配置（`fgfm-peercert-withoutsn` 被启用）**且**攻击者持有有效证书——利用门槛相对较高，但一旦满足即可大规模影响受管设备群。

#### 3.3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 FortiManager 的 FGFM 服务端口 |
| 身份认证 | 无需（但需有效证书） | 远程未认证攻击者 + 一张有效证书 |
| 用户交互 | 不需要 | 无交互 |
| 特定配置 | 是 | FortiManager 启用了 `fgfm-peercert-withoutsn` CLI 选项 |
| 利用复杂度 | 高 | 需同时满足有效证书与特定配置（NVD AC:H） |

**技术原理：**

FGFM 协议用于 FortiManager 与受管 FortiGate 之间的注册与通信，正常流程中双方通过证书相互认证。`fgfm-peercert-withoutsn` 选项启用后，协议在**缺少对端设备序列号（SN）校验**的情况下接受证书，削弱了对"对端是否为真实受管设备"的验证强度。攻击者持有有效证书并构造特制 FGFM 请求时，即可利用该弱化认证冒充任意受管 FortiGate（CWE-288：通过备用路径/信道绕过认证），进而实施策略篡改等管理操作。

**核心利用链：**

```text
攻击者（网络可达 FortiManager）
  └─ 获取/持有有效证书
      └─ 构造特制 FGFM 请求（冒充受管 FortiGate）
          └─ 触发 fgfm-peercert-withoutsn 配置下的认证弱化
              └─ 绕过设备身份认证（CWE-288）
                  └─ 以受管设备身份操作 FortiManager
                      └─ 篡改防火墙策略 / 同步恶意配置 / 窃取管理数据
```

3. **处置 FortiManager `CVE-2026-70468` 与 FortiClient `CVE-2026-70465`**：3 个工作日内升级 FortiManager 至 `7.6.2/7.4.6/7.2.10` 并禁用 `fgfm-peercert-withoutsn`；FortiClient Windows 升级至官方修复版本；
4. **Edge 浏览器批量升级**：推送 Edge `151.0.4129.86` 及以上版本，提醒终端勿访问可疑链接、勿安装不明扩展；
5. **排查 LiteLLM 供应链影响**：核查依赖清单与 CI 镜像是否引入恶意版本 `1.82.7/1.82.8`，受影响组织立即轮换 GitHub/AWS/GCP/SSH/容器仓库凭据并使会话失效；
6. 对已在野利用、已纳入CISA KEV或存在成熟PoC的漏洞立即开展资产排查；
7. 优先核查互联网暴露的VPN、网关、安全设备、中间件和管理平台（FortiWeb/FortiManager 管理端口为重点）；
8. 无法立即升级的系统应采取断网、访问控制、接口禁用或WAF拦截措施；
9. 对疑似遭受攻击的系统保留日志、流量、进程、文件及内存证据；
10. 对发现异常的主机开展WebShell、恶意进程、异常账号及横向移动排查；
11. 完成修复后进行复测，并更新资产台账和漏洞处置记录。
