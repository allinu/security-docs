### 1.3 今日重点关注

1. **`CVE-2026-84411`：MikroTik RouterOS Web 管理服务预认证整数下溢**  
   影响 MikroTik RouterOS（**< 7.24**），未认证网络攻击者可**单请求实现 root 权限任意代码执行或拒绝服务**。当前状态为**无公开 POC、厂商/CISA 未通报在野利用、已发布修复版本**，建议**立即排查并升级，同时收敛 Web 管理界面暴露面**。

2. **`CVE-2026-82042` / `CVE-2026-82041`：UTMStack 认证绕过与命令通道缺失授权**  
   前者未认证即可凭内部密钥头取得完整管理员 API 权限（9.8），后者任意已认证用户可越权向受管 agent 下发命令致**受管端点批量 RCE**（9.9）。建议**立即升级至 11.2.16 并轮换内部密钥、收敛平台暴露**。

3. **`CVE-2026-105105`：NASA-AMMOS AIT-Core ait-server 缺失认证**  
   未认证攻击者可达 ZeroMQ 端口 5559/5560 即可**注入航天器指令、窃取或伪造遥测**（9.8）。建议**立即升级至 3.1.2（默认绑定回环）并将测控总线限制在受信网段**。

4. **`CVE-2026-75937` / `CVE-2026-95102`：工业与 IoT 边界设备缺陷**  
   Digi DAL OS 设备 Web 管理界面未认证命令注入（9.4）与 Monta 充电站平台 WebSocket 缺失认证（9.4）集中反映**工业/IoT 边界“未认证即可接管”风险**，建议优先核查资产暴露面。

#### 3.1.2 漏洞摘要

该漏洞存在于 MikroTik RouterOS 的 Web 管理服务（www/webfig）对 HTTP 请求体长度的处理逻辑中。服务在解析请求体时未对长度字段做正确的边界校验，导致整数下溢，进而造成内存处理越界。漏洞在处理流程中**先于身份认证**即可触发，因此攻击者无需任何凭据。

攻击者只需向暴露的 Web 管理端口发送单个精心构造的请求，即可以 root 权限在设备上执行任意代码，或直接导致管理服务崩溃（拒绝服务）。RouterOS 广泛部署于运营商、企业与工业边缘路由器，且大量设备将 Web 管理界面暴露于互联网，风险面较大。CISA ICS 公告（ICSA-26-272-06）明确“截至目前未接到针对该漏洞的公开利用报告”。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达设备 Web 管理端口（HTTP/HTTPS，默认 80/443） |
| 身份认证 | 无需 | 漏洞在认证前触发 |
| 用户交互 | 不需要 | 直接构造 HTTP 请求 |
| 特定配置 | 是 | 需启用 Web 管理服务（www） |
| 利用复杂度 | 低 | 单个构造请求即可触发 |

**技术原理：**

Web 管理服务在解析 HTTP 请求体时依赖一个长度字段进行缓冲区/指针运算。由于校验逻辑对“声明长度 > 实际内容”的边界处理存在缺陷，相减运算产生整数下溢，得到一个超大无符号值，导致后续内存操作越界（读/写）。攻击者可通过控制该长度字段与请求体内容，将越界写转化为可控的内存破坏，最终在认证前实现 root 权限代码执行；最小化利用则为服务崩溃。

**核心利用链：**

```text
攻击者
  └─ 扫描暴露的 RouterOS Web 管理端口（80/443）
      └─ 发送构造的 HTTP 请求（请求体长度字段异常）
          └─ 触发 http 服务整数下溢
              └─ 越界写破坏内存（认证前）
                  └─ 实现 root 权限任意代码执行 / 拒绝服务
```

### 3.3 CVE-2026-82041 — UTMStack 命令 WebSocket 缺失授权致受管端点远程命令执行

!!! danger "严重漏洞"
    UTMStack 11.2.16 之前版本中，任意已认证用户（不限角色）可经命令 WebSocket 向受管 agent 下发任意操作系统命令，agent 常以 root/SYSTEM 运行，构成受管端点远程代码执行。

#### 3.3.2 漏洞摘要

该漏洞位于 `UTMIncidentCommandWebsocket.processCommand()`，其映射到 `/command/{hostname}` 的 STOMP 目的地。处理逻辑在转发命令前**既未校验角色，也无命令白名单**，因此任何已认证用户（哪怕最低权限角色）都能通过 gRPC 向任意已连接 agent 下发任意操作系统命令。

由于 UTMStack 的终端 agent 通常以 root 或 SYSTEM 运行，攻击者可借此在全部受监控端点执行命令，形成“单点越权→多点 RCE”的放大效应，波及面极广。该漏洞由 VulnCheck 作为 CNA 披露，已在 11.2.16 修复。

#### 3.3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 UTMStack 平台 |
| 身份认证 | 普通用户 | 任意已认证角色即可 |
| 用户交互 | 不需要 | 直接通过 WebSocket/STOMP 下发命令 |
| 特定配置 | 否 | 默认配置即可 |
| 利用复杂度 | 低 | 已认证后命令直达 agent |

**技术原理：**

命令下发接口把“是否已认证”当作充分条件，忽略了基于角色的授权（RBAC）与命令白名单。攻击者以低权限账号登录后，构造 STOMP 帧发往 `/command/{hostname}`，平台即将命令经 gRPC 转发至对应 agent，从而在端点以 agent 权限（多为 root/SYSTEM）执行。

**核心利用链：**

```text
低权限已认证用户
  └─ 登录 UTMStack 取得会话
      └─ 向 /command/{hostname} STOMP 目的地发送命令帧
          └─ processCommand() 无角色校验/无白名单
              └─ 命令经 gRPC 下发至 agent
                  └─ 受管端点以 root/SYSTEM 执行任意命令
```

#### 3.4.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需与设备相邻/网络可达（AV:A） |
| 身份认证 | 无需 | 未认证即可利用 |
| 用户交互 | 不需要 | 直接构造 HTTP POST |
| 特定配置 | 是 | 需启用 Web 管理界面 |
| 利用复杂度 | 低 | 无需特殊条件 |

**技术原理：**

Web 管理界面在处理表单/参数时，未对用户可控输入进行过滤或转义，直接将其拼接进以高权限执行的 shell 命令串中，导致命令注入。攻击者通过精心构造的参数值注入分隔符与命令，即可在设备上以 root 身份执行。

**核心利用链：**

```text
攻击者
  └─ 定位网络可达的 Digi 设备 Web 管理界面
      └─ 提交含注入载荷的 HTTP POST 请求
          └─ 后端的命令拼接逻辑执行注入内容
              └─ 以 root 权限执行任意操作系统命令
```

#### 3.5.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达平台 WebSocket 端点 |
| 身份认证 | 无需 | 端点缺乏认证 |
| 用户交互 | 不需要 | 直接建立 WebSocket 连接 |
| 特定配置 | 否 | 默认即可 |
| 利用复杂度 | 低 | 可直接连接冒充 |

**技术原理：**

平台后端 WebSocket 端点承担充电站与云端的身份与会话关联，却未实施必要的认证。攻击者可直接连接并冒充合法充电站，读写会话数据或下发未授权操作。相关缺陷还叠加了会话标识可预测、认证接口无限速、认证标识公开泄露等问题，放大整体风险。

**核心利用链：**

```text
攻击者
  └─ 定位 monta.app 的 WebSocket 端点
      └─ 无需认证直接建立连接
          └─ 冒充合法充电站身份
              └─ 读取敏感数据 / 执行未授权操作
                  └─ 权限提升并可能危及整个充电网络
```

### 3.6 CVE-2026-105105 — NASA-AMMOS AIT-Core ait-server 遥测/指令代理缺失认证

!!! danger "严重漏洞"
    NASA-AMMOS AIT-Core 3.1.1 及以前的 ait-server 遥测/指令 ZeroMQ 代理默认监听所有网卡且无认证，攻击者可达 5559/5560 端口即可注入航天器指令、窃取或伪造遥测。

#### 3.6.2 漏洞摘要

该漏洞存在于 NASA 开源航天器测控框架 AIT-Core 的核心组件 `ait-server`（遥测与指令代理）。其 ZeroMQ 代理默认将 XSUB/XPUB 套接字绑定到**所有网络接口**，且未启用认证与传输安全。具备网络可达性的未认证攻击者即可：

- 通过 TCP 5559 向内部主题（含 `__commands__` 指令主题）发布消息，经默认配置的 `command_stream` 与 `command-uplink` UDP 通道注入航天器指令；
- 通过 TCP 5560 订阅地面总线的指令与遥测流量，实施窃取；
- 伪造遥测或干扰指令/遥测总线。

AIT-Core **3.1.2** 将 ZeroMQ 默认绑定地址改为回环（loopback）以修复该问题。

#### 3.6.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 TCP 5559（XPUB 指令）与 5560（XSUB 遥测） |
| 身份认证 | 无需 | 代理无认证 |
| 用户交互 | 不需要 | 直接连接 ZeroMQ 总线 |
| 特定配置 | 是 | 使用默认绑定配置（监听所有接口） |
| 利用复杂度 | 低 | 可达端口即可发布/订阅 |

**技术原理：**

`ait-server` 的 ZeroMQ 代理在设计上未纳入认证与访问控制，且默认绑定 `0.0.0.0`。XSUB/XPUB 总线既承载遥测又承载指令，主题（如 `__commands__`）可被任意订阅者/发布者读写。攻击者连接后即可注入指令、窃取或伪造遥测，直接危害航天器指令链路。

**核心利用链：**

```text
攻击者
  └─ 发现可达的 ait-server ZeroMQ 端口（5559/5560）
      └─ 无认证连接 XSUB/XPUB 总线
          └─ 向 __commands__ 主题发布指令 / 订阅遥测
              └─ 指令经 command_stream 与 UDP 上行注入
                  └─ 航天器指令注入、遥测窃取或伪造
```

**技术原理：**

`ebook-convert` 支持以 recipe 作为输入并执行其中的 Python 代码。ConvertX 未对这类“可执行输入文件”做类型/内容校验，将其与普通电子书文件同等处理，导致服务端代码执行。由于转换服务常以容器/服务账号运行，攻击者可获取该进程权限，并可能借共享卷、挂载或元数据访问影响宿主资源（S:C）。

**核心利用链：**

```text
攻击者

```

### 3.8 CVE-2026-71885 — Bouncy Castle for Java MLS 实现 X.509 凭据未绑定签名密钥

!!! danger "严重漏洞"
    Bouncy Castle for Java 1.86 之前版本的 MLS（RFC 9420）实现未将 X.509 凭据绑定到 LeafNode 的 signature_key，攻击者可在无独立凭据准入校验的部署中冒充他人身份、驱逐成员并解密组消息。

#### 3.8.2 漏洞摘要

该漏洞存在于 Bouncy Castle for Java 的 Messaging Layer Security（MLS，RFC 9420）实现。`LeafNode.verify()` 仅用叶子节点自身携带的 `signature_key` 校验其签名，而**从未解析或验证凭据中的 X.509 证书链**，因此未按要求（RFC 9420 §5.3）保证终端实体证书公钥与 `signature_key` 一致。

攻击者可以“用与他人证书无关的密钥”为该叶子节点签名，却仍被 `KeyPackage.verify()` 与组内叶子校验接受为该他人的身份。在允许外部提交（external commit）且无独立凭据准入校验的部署中，未认证攻击者可以受害者身份被接纳，进而驱逐受害者、推导当前 epoch、解密后续组消息并以受害者身份发消息。仅使用 basic 凭据的部署不受影响。该缺陷为 Bouncy Castle 本轮批量修复的一部分。

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 取决于使用 MLS 的应用 |

**技术原理：**

**核心利用链：**

```text
攻击者
  └─ 取得（或构造）受害者 X.509 凭据
      └─ 用无关密钥为 LeafNode 签名
          └─ LeafNode.verify() 未校验证书链与 signature_key 绑定
              └─ KeyPackage/组叶子校验接受该身份
                  └─ 冒充受害者、驱逐成员、解密组消息
```

#### 3.11.5 利用条件与技术原理

| 条件 | 状态 | 说明 |

**技术原理：**

**核心利用链：**

```text
攻击者
  └─ 定位暴露的 OpenAM /jaxrpc/* 接口
      └─ 发送含未验证会话标识与自选类名的 SOAP 请求
          └─ 端点未认证即实例化该类
              └─ 服务崩溃 / 类路径探测 / 危险类加载
```

| 利用复杂度 | 低 | 密钥与口令为固定值 |

**技术原理：**

产品在凭证保护上使用了固定密钥与固定口令，并明文落盘日志，等于把数据库凭证“固化”在系统中。任何取得主机访问权（哪怕是低权限账号）的攻击者都可提取密钥/口令，进而认证到数据库并完全接管。

**核心利用链：**

```text
本地低权限攻击者
  └─ 读取安装配置文件 / 备份日志
      └─ 还原固定 AES 密钥-IV 或直接读取明文口令
          └─ 取得数据库超级用户凭证
              └─ 接管数据库与消息中间件
```

## 五、当日处置建议

1. 对已在野利用、已纳入 CISA KEV 或存在成熟 PoC 的漏洞立即开展资产排查——本窗口应优先关注**跨期 KEV 条目** `CVE-2026-104286`（FortiMail，当日到期）、`CVE-2026-102489`/`CVE-2026-102490`（Zammad，次日到期）；
2. 优先核查互联网暴露的**网络与工业边界设备**（MikroTik RouterOS、Digi DAL OS）、**安全运营/身份基础设施**（UTMStack、OpenAM）与**测控/开发基础设施**（NASA AIT-Core、ConvertX、GitLab AI Gateway）；
3. 对无法立即升级的系统采取断网、访问控制、接口禁用或 WAF 拦截措施，尤其是关闭不必要的 Web 管理服务与内部密钥接口；
4. 对疑似遭受攻击的系统保留日志、流量、进程、文件及内存证据；
5. 对发现异常的主机开展 WebShell、恶意进程、异常账号及横向移动排查，并轮换可能泄露的内部密钥与数据库凭证；
6. 完成修复后进行复测，并更新资产台账和漏洞处置记录。
