### 1.4 综合研判

本期核心是 CISA 连续两天新增 9 个 KEV 漏洞（2 个 CVSS 9.8、5 个高危），全部为已确认在野利用：其中 Citrix NetScaler（边界网关）与 SQL Server（核心数据库）处置截止 08-29，ownCloud 与 Linux 内核处置截止 08-30，时间窗口极为紧迫；Ajax.NET 反序列化漏洞 EPSS 极高且无官方补丁，属于"存量风险放大器"。9 个漏洞中 6 个为老漏洞（2015/2019/2022/2023 年披露）但仍在被利用，说明历史补丁欠账是当前被攻击的主要入口。综合判断今日风险显著，重点在于 4 个 P0 级 KEV 的处置窗口（08-29/08-30 截止）与 Ajax.NET 无补丁资产的隔离处置。

### 3.1 `CVE-2026-8452` — Citrix NetScaler ADC / NetScaler Gateway 内存缓冲区越界（CISA KEV，在野利用）

!!! danger "严重漏洞（KEV 收录 + 在野利用）"

#### 3.1.2 漏洞摘要

该漏洞为 NetScaler ADC/Gateway 中的内存溢出缺陷（NVD 描述为 "Memory overflow vulnerability ... leading to unpredictable or erroneous behavior and Denial of Service"）。当设备被配置为 **Gateway 类型虚拟服务器**（SSL VPN、ICA Proxy、CVPN、RDP Proxy）或 **AAA 虚拟服务器**时，远程攻击者可利用该缺陷触发不可预期行为或拒绝服务；CISA KEV 名称将其归类为"Improper Restriction of Operations within the Bounds of a Memory Buffer"。NVD 主评分为 CVSS 3.1 **9.8（严重）**，CVSS 4.0 为 8.8（高），其中可利用性指标全部为低门槛（网络可达、无需认证、无需交互）。NetScaler 网关类设备通常部署于企业网络边界并暴露于互联网，一旦被利用可能影响 VPN 接入、远程访问与 AAA 认证等核心功能，需按 KEV 窗口（截止 08-29）优先处置。

#### 3.2.2 漏洞摘要

该漏洞位于 ownCloud core 的 WebDAV API 预签名 URL（pre-signed URL）机制。当文件属主**未配置签名密钥**时，预签名 URL 仍可被接受，攻击者只要知道受害者用户名，即可在**无需任何认证**的情况下生成有效预签名 URL，访问、修改或删除该用户的任意文件（含 WebDAV 数据目录）。NVD 明确"最早受影响版本为 10.6.0"。ownCloud 自托管部署在政企、科研机构中较为常见，文件泄露/篡改后果严重；CISA 于 2026-08-27 纳入 KEV 并确认在野利用，处置截止 2026-08-30。

#### 3.3.2 漏洞摘要

该漏洞是 Microsoft SQL Server 对内部函数处理不当导致的远程代码执行缺陷（"incorrectly handles processing of internal functions"）。攻击者需要有效的 SQL Server 登录凭据（低权限，CVSS 3.1 PR:L），通过网络向数据库实例发送精心构造的查询即可触发，以服务账户权限执行任意代码。SQL Server 是企业核心数据资产，一旦被攻破即可直接访问业务数据库、横向移动；2019 年披露时即已被利用，2026 年再次因在野利用被纳入 KEV，处置截止 2026-08-29。

#### 3.3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | SQL Server 实例（默认 1433/TDS）网络可达 |
| 身份认证 | 普通用户（PR:L，需有效登录凭据） | 需可登录数据库的低权限账户 |

| 特定配置 | 否 | 官方未披露额外前置条件 |
| 利用复杂度 | 低 | AC:L |

**技术原理：**

SQL Server 在处理特定内部函数（internal functions）时存在输入处理缺陷，构造的查询可导致内存破坏并实现代码执行（官方描述未披露细节）。由于利用需要低权限数据库凭据，攻击者通常先通过弱口令、泄露凭据或其他途径获得登录能力，再触发该漏洞提升至服务账户代码执行。

**核心利用链：**

```text
攻击者
  └─ 获得 SQL Server 低权限登录凭据（弱口令/泄露/横向）
      └─ 连接数据库实例（1433/TDS）
          └─ 构造恶意查询触发内部函数处理缺陷
              └─ 以 SQL Server 服务账户执行任意代码
                  └─ 读取业务数据 / 横向移动
```

### 3.4 `CVE-2026-53362` — Linux 内核 ipv6 分片越界写（fraggap 记账错误，CISA KEV）

!!! danger "高危漏洞（KEV 收录 + 在野利用）"

#### 3.4.2 漏洞摘要

在 Linux 内核 `__ip6_append_data()` 中，当走分页分配分支（`MSG_MORE` / `NETIF_F_SG` / 大 fraglen）时，`alloclen = fragheaderlen + transhdrlen`、`pagedlen = datalen - transhdrlen`。由于 `datalen` 已包含 fraggap（`datalen = length + fraggap`），当 fraggap 非零且非首包、`transhdrlen` 为零时，前一个 skb 结转的 fraggap 字节会被复制到新 skb 线性区分片头之后，导致**线性区欠分配 fraggap 字节**、`pagedlen` 多计同样字节，复制越过 `skb->end` 写入尾部 `skb_shared_info`。无特权用户可通过 UDPv6 套接字使用 `MSG_MORE` + `MSG_SPLICE_PAGES` 触发（本地提权/内核崩溃）。修复方式为在分页分支的 `alloclen` 增加 fraggap 并从 `pagedlen` 扣除，同时移除过时的负 copy 注释与 `MSG_SPLICE_PAGES` 例外。

#### 3.4.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 否（本地触发） | 通过本地 UDPv6 套接字调用触发 |

**技术原理：**

见 3.4.2 漏洞摘要：ipv6 分页分配路径对 fraggap 的记账错误导致 `alloclen` 偏小、`pagedlen` 偏大，复制操作越过 `skb->end` 写入相邻的 `skb_shared_info`，形成堆越界写。该缺陷由 `773ba4fe9104` 引入，经 `ce650a166335` 后变为可触发（此前负 copy 值会返回 `-EINVAL`）。

**核心利用链：**

```text
攻击者（本地无特权用户）
  └─ 创建 UDPv6 套接字
      └─ 使用 MSG_MORE + MSG_SPLICE_PAGES 发送触发数据
          └─ 触发 __ip6_append_data() 分页路径 fraggap 记账错误
              └─ 越界写入 skb_shared_info（堆越界写）
                  └─ 实现本地提权或内核崩溃（DoS）
```

watch_queue 是 Linux 内核用于向用户空间传递事件通知的子系统（`kernel/watch_queue.c`）。该漏洞源于 watch_queue 过滤器（filter）处理中的越界写：本地用户可通过构造 watch 过滤器触发越界写，覆盖部分内核状态，从而获得内核权限或导致系统崩溃。NVD 描述："An out-of-bounds (OOB) memory write flaw was found in the Linux kernel's watch_queue event notification subsystem. This flaw can overwrite parts of the kernel state, potentially allowing a local user to gain privileged access or cause a denial of service on the system." 2022 年披露时已有成熟利用（Google Project Zero 等跟进），当前公开 PoC（Bonfee，497 stars）成熟度高。

### 3.7 `CVE-2015-5287` — Red Hat ABRT abrt-hook-ccpp 符号链接提权（CISA KEV，在野利用）

!!! danger "高危漏洞（KEV 收录 + 在野利用）"
    Red Hat Automatic Bug Reporting Tool（ABRT）2.7.1 之前版本的 abrt-hook-ccpp 帮助程序存在符号链接攻击：具有特定权限的本地用户可利用可预测文件名（如 `/var/tmp/abrt/abrt-hax-coredump`）实现提权。CISA 于 2026-08-26 纳入 KEV（处置截止 2026-09-09）。

#### 3.7.2 漏洞摘要

Red Hat 的 Automatic Bug Reporting Tool（ABRT）用于自动收集程序崩溃报告，其 `abrt-hook-ccpp` 帮助程序（2.7.1 之前版本）在写入核心转储文件时使用可预测文件名（如 `/var/tmp/abrt/abrt-hax-coredump`、`/var/spool/abrt/abrt-hax-coredump`），且未正确处理符号链接（NVD：symlink attack on a file with a predictable name）。具有特定权限的本地用户可通过预置符号链接，诱导 abrt-hook-ccpp 以特权身份向任意路径写入/操作文件，实现提权。该漏洞 2015 年披露修复，2026 年因在野利用再次进入 KEV，主要影响未及时升级的 RHEL/CentOS 等发行版主机。

| 厂商 | 产品/组件 | 受影响版本 | 修复版本 | 部署形态 |

#### 3.7.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 否（本地） | 本地用户操作 |
| 身份认证 | 普通用户（PR:L，"具有特定权限"） | 可触发 abrt 钩子的本地用户 |
| 用户交互 | 需要（触发崩溃报告流程） | 需制造崩溃并触发 abrt-hook-ccpp |
| 特定配置 | 是 | 系统安装并启用 ABRT |
| 利用复杂度 | 低 | AC:L |

**技术原理：**

abrt-hook-ccpp 在 `/var/tmp/abrt/`（或 `/var/spool/abrt/`）等目录下以**可预测文件名**创建核心转储相关文件，且创建前未消除符号链接（link resolution 校验缺失）。攻击者预先在该路径放置指向任意文件（如 `/etc/passwd` 或可写敏感文件）的符号链接，使 abrt-hook-ccpp 以特权身份跟随链接执行写操作，从而实现越权写入/提权（NVD 注明可与 `CVE-2015-3245` 组合）。

**核心利用链：**

```text
攻击者（本地用户）
  └─ 在 /var/tmp/abrt/ 预置指向敏感文件的符号链接（可预测文件名）
      └─ 触发程序崩溃使 abrt-hook-ccpp 处理核心转储
          └─ 特权进程跟随符号链接写入
              └─ 覆盖/创建任意路径文件
                  └─ 实现提权（可结合 CVE-2015-3245）
```

**漏洞描述：**  
[Security Affairs 08-26 报道](https://securityaffairs.com/197901/hacking/cisa-red-team-fully-compromised-two-critical-infrastructure-orgs.html)：CISA 发布红队评估公告 **AA26-237A**：对两家关键基础设施组织（A：政府服务与设施行业；B：水务废水行业）同时开展红队评估，**两家均被完全攻陷域控与云环境**，但防御结果截然不同。A 组织：红队利用仍使用**默认凭据的 Web 应用**发送可信内网钓鱼邮件，拿下 4 台工作站，再经**配置不当的 ADCS 证书模板（ESC1 缺陷）**为低权限用户申请管理员证书，全面接管域与敏感业务系统，并读取 SOC 邮件确认未被发现——A 组织 SOC 被数千误报淹没，甚至将真实告警误判为误报；B 组织：数分钟内识别初始入侵并隔离受影响主机，迫使红队转入 assume breach 模式。CISA 强调：告警基线化与过滤、默认凭据清零、ADCS 模板加固是决定防御成败的关键。
