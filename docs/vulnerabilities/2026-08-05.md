### 3.1 CVE-2026-9198 — IBM Langflow 代码注入漏洞（未认证 RCE）

!!! danger "严重漏洞"

#### 3.1.2 漏洞摘要

该漏洞存在于 IBM Langflow OSS（开源低代码 AI/LLM 应用构建平台）中。Langflow 的 `/api/v1/auto_login` 接口存在认证缺陷，可向任意网络调用者签发 SUPERUSER 级别的访问令牌；结合 `/api/v1/validate/code` 接口直接对用户提交的代码执行 `exec()`，未认证攻击者即可在默认部署（未额外配置认证防护）上实现完整的远程代码执行，无需任何凭据或用户交互。

由于 Langflow 通常以 Web 服务形态暴露于内网或互联网，且默认端口 7860 的未认证 API 面较大，该漏洞在 7 月披露后迅速出现多个公开 PoC。CISA 于 2026 年 8 月 4/5 日将其纳入 KEV 目录，确认存在在野利用，并要求联邦民事行政部门（FCEB）机构在 2026-08-07 前完成修复。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 Langflow Web 服务（默认端口 7860） |
| 身份认证 | 无需 | `/api/v1/auto_login` 可向任意调用者签发 SUPERUSER token |
| 用户交互 | 不需要 | 全程 API 调用，无交互 |
| 特定配置 | 否 | 默认部署即可利用（未额外加固时） |
| 利用复杂度 | 低 | 两个公开 API 端点链式调用即可 |

**技术原理：**

两个缺陷的链式利用：① `/api/v1/auto_login` 在未正确校验调用者身份的情况下直接签发高权限（SUPERUSER）访问令牌，构成认证绕过/越权；② `/api/v1/validate/code` 接口对用户提交的代码未经充分校验即调用 Python `exec()` 执行。二者组合后，未认证攻击者先获取 SUPERUSER 令牌，再携带令牌向代码校验接口提交恶意 Python 代码，实现任意命令执行。

**核心利用链：**

```text
攻击者
  └─ 访问暴露的 Langflow Web 服务（默认 7860 端口）
      └─ GET /api/v1/auto_login → 未认证获取 SUPERUSER access_token
          └─ POST /api/v1/validate/code（携带 SUPERUSER 令牌）
              └─ 提交含 subprocess 调用的恶意 Python 代码
                  └─ 触发 exec() 执行任意命令
                      └─ 实现远程代码执行（RCE），可进一步植入后门、窃取数据
```

#### 3.1.11 风险影响

漏洞成功利用后，可能导致：

- 未认证远程执行任意系统命令（RCE）；
- 获取 Langflow SUPERUSER 最高权限并接管平台；
- 窃取 AI 应用编排、API 密钥、模型配置及业务数据；

### 3.2 CVE-2026-34486 — Apache Tomcat EncryptInterceptor 绕过漏洞（敏感数据加密缺失）

!!! danger "严重漏洞"

#### 3.2.2 漏洞摘要

该漏洞存在于 Apache Tomcat 集群会话复制（Session Replication）所使用的 EncryptInterceptor 组件中，是 CVE-2026-29146 修复不完整的产物：修复将 `EncryptInterceptor.messageReceived()` 中的 `super.messageReceived(msg)` 移出 try-catch 异常处理块，导致解密失败时原始（密文/未加密）字节仍被继续传递给后续处理链，最终进入无过滤的 `ObjectInputStream.readObject()`，攻击者可借此绕过加密校验、读取敏感数据，并可能触发 Java 反序列化远程代码执行。

CISA 于 2026 年 8 月 4/5 日将该漏洞纳入 KEV 目录。Security Affairs 报道称其利用被关联到一名中文攻击者，该攻击者使用基于 DeepSeek 的 AI 自主攻击代理识别并利用互联网暴露的漏洞，当一条攻击路径失败时 AI 会独立搜索替代漏洞，同时攻击者还手工利用 Citrix NetScaler、Apache Tomcat、Marimo 与 IKE VPN 系统。HKCERT 提示：该漏洞仅在启用 EncryptInterceptor（非默认配置）的集群场景下影响敏感数据泄露，故其公告按"中度风险"评级。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 Tomcat 集群通信通道（Tribes 消息通道）或受影响服务端口 |
| 身份认证 | 无需 | 集群通信通道默认不校验调用者身份 |
| 用户交互 | 不需要 | 直接构造恶意消息 |
| 特定配置 | 是 | 需启用 EncryptInterceptor（非默认配置，集群会话复制场景） |
| 利用复杂度 | 低 | 解密失败后原始字节直达反序列化入口 |

**技术原理：**

CVE-2026-29146 的修复将 `EncryptInterceptor.messageReceived()` 中关键调用 `super.messageReceived(msg)` 移出 try-catch 块，异常（如解密失败）不再中断消息处理流程，原始字节被继续传递给后续处理链，最终进入无过滤的 `ObjectInputStream.readObject()`。攻击者向集群通信通道发送畸形/未加密消息即可绕过加密校验，导致敏感数据泄露；配合 Java 反序列化 gadget（如公开复现脚本使用的 ysoserial + commons-collections），可进一步实现远程代码执行。

**核心利用链：**

```text
攻击者
  └─ 发现暴露的 Tomcat 集群通信通道（如 Tribes 端口）
      └─ 构造畸形/未加密消息（绕过 EncryptInterceptor 解密校验）
          └─ 解密失败后原始字节仍进入后续处理链（super.messageReceived 移出 try-catch）
              └─ 触发无过滤的 ObjectInputStream.readObject()
                  └─ 反序列化 gadget 链 → 远程代码执行 / 敏感数据泄露
```

- 如非必需，禁用 EncryptInterceptor 相关集群会话复制功能或隔离集群通信通道；
- 限制集群通信端口（Tribes 通道）仅允许可信节点 IP 访问；
- 通过防火墙、ACL、安全组收敛 8080/8443 等管理端口的互联网暴露；
- 在 WAF/IPS 增加对 Java 反序列化流量（`AC ED 00 05` 魔数）的拦截规则；
- 加强日志审计、主机监控和异常外联检测。

## 五、当日处置建议

1. 对已在野利用、已纳入CISA KEV或存在成熟PoC的漏洞立即开展资产排查：IBM Langflow（P0）、Apache Tomcat（P0）、N-able N-central（P0），并在 2026-08-07 前完成 KEV 漏洞修复；
2. 优先核查互联网暴露的 AI 应用平台（Langflow 7860 端口）、中间件（Tomcat 8080/8443 及集群通信通道）与 MSSP 管理平台（N-central 控制台）；
3. 无法立即升级的系统应采取断网、访问控制、接口禁用或WAF拦截措施：对 Langflow 的 `/api/v1/auto_login`、`/api/v1/validate/code` 接口实施网关阻断，对 Tomcat 集群通道收敛访问，对 N-central 控制台限制可信来源访问；
4. 对疑似遭受攻击的系统保留日志、流量、进程、文件及内存证据；
5. 对发现异常的主机开展WebShell、恶意进程（svchost.exe/Cloudflared）、异常账号及横向移动排查；
6. 自建 GitLab 用户核对版本是否处于受影响区间（15.2.0–18.10.7、18.11.0–18.11.4、19.0.0–19.0.1）并及时升级；
7. 完成修复后进行复测，并更新资产台账和漏洞处置记录。
