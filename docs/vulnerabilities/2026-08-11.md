### 3.1 CVE-2026-63077 — JetBrains TeamCity agent 轮询协议反序列化未认证远程代码执行漏洞

#### 3.1.2 漏洞摘要

TeamCity 的构建代理（agent）通过轮询协议（agent polling protocol，`/app/agents/v1` 端点）从 TeamCity 服务器拉取构建任务。该漏洞存在于 agent 轮询协议的数据处理过程中：**TeamCity 配置 XStream 反序列化器时，在服务未认证 agent 请求的宽松白名单中加入了 TeamCity 协议类，却未先清空 XStream 自带的默认权限**，导致 `Map`、`Throwable` 等类型层级仍可被反序列化（CWE-502）。未认证攻击者无需任何凭据，仅构造特制的轮询请求即可绕过认证检查，借助 XStream gadget 链在 TeamCity 服务进程上下文中执行任意操作系统命令。

该漏洞于 2026-07-10 由安全研究员 Antoni Tremblay 依据协调披露机制私下报告给 JetBrains，2026-07-27 官方公开披露并发布修复版本。2026-08-05 CISA 将其收录进已知被利用漏洞目录（KEV）并确认在野利用；**2026-08-07 Rapid7 Labs 发布完整技术分析与 PoC 利用脚本（验证了修复补丁有效）**；**2026-08-10 奇安信 CERT 发布"【已复现】安全风险通告"**，确认国内安全厂商已完成漏洞复现。**所有 TeamCity On-Premises 版本均受影响**；TeamCity Cloud 实例已由厂商修复，不受影响。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需 HTTP(S) 可达 TeamCity 服务器（默认 Web 端口 8111，agent 轮询协议端点 `/app/agents/v1`） |
| 身份认证 | 无需 | 未认证攻击者即可触发（NVD 向量 PR:N；agent 端点对未认证访问开放） |
| 用户交互 | 不需要 | 无需受害者交互 |
| 特定配置 | 否 | 默认配置即受影响 |
| 利用复杂度 | 低 | NVD 向量 AC:L；公开利用脚本可直接使用 |

**技术原理：**

TeamCity 的 `jetbrains.buildServer.messages.XStreamHolder` 在配置 XStream 实例时调用 `setupSecurityIfNeeded()`：当 TeamCity 白名单非空时，仅通过 `allowTypes()` 追加 TeamCity 协议类，**未先调用 `NoTypePermission.NONE` 清空 XStream 构造器 `setupSecurity()` 已安装的默认权限**。而 XStream 1.4.20.3 默认已允许 `Map`、`Map.Entry`、`Throwable`、`Collection`、`Number` 等宽泛类型层级——攻击者利用这些默认放行类型构造恶意对象图（如 `linked-hash-map` 嵌套条目），即可在未认证的 agent 轮询请求处理过程中触发不安全的反序列化。修复版本（2026.1.3）在追加白名单前先执行 `addPermission(NoTypePermission.NONE)` 清空默认权限，并通过 `teamcity.xstream.whiteList.forced` 属性（默认 true）强制白名单为"仅允许"模式。

**核心利用链：**

```text
攻击者
  └─ 通过 HTTP(S) 访问暴露的 TeamCity 服务器（默认 8111）
      └─ 调用 /app/agents/v1/register 注册伪造 agent 会话（无需认证）
          └─ 向 /app/agents/v1/commands/error 提交携带恶意序列化对象的轮询请求
              └─ XStream 反序列化不可信数据（CWE-502，默认放行 Map/Throwable 类型）
                  └─ 利用 gadget 链在 Web 根目录写入 polyglot SQL/JSP 文件（.jspws）
                      └─ GET 请求该文件触发 JSP 执行
                          └─ 以 TeamCity 服务进程权限执行任意操作系统命令（Runtime.exec）
```

#### 3.1.11 风险影响

漏洞成功利用后，可能导致：

- 未经授权访问系统或业务接口（未认证 RCE，直接接管 TeamCity 服务器）；
- 远程执行任意系统命令（以 TeamCity 服务进程权限，多数部署为高权限服务账号）；
- 窃取 CI/CD 流水线凭据、源码仓库访问令牌、构建产物与部署密钥；
- 篡改构建流程，向产物中植入恶意代码（供应链投毒风险）；
- 植入 WebShell（`.jspws` 文件）、后门或恶意程序实现持久化；
- 横向移动至构建代理、制品库、部署环境及其他服务器或业务系统；
- 中断 CI/CD 业务服务或破坏系统可用性；
- 被勒索软件、挖矿木马或僵尸网络利用（TeamCity 历史上多次被勒索软件组织攻击）。

#### 3.1.13 修复与缓解措施

#### 官方修复

1. 将 JetBrains TeamCity 升级至 `2025.11.7` 或 `2026.1.3` 及更高版本；
2. 无法立即升级的实例，安装官方安全补丁插件（支持 2017.1+，仅修复本漏洞）；

4. 在测试环境验证兼容性及回退方案（注意 agent 与服务器版本配套）；
5. 升级后核验版本、补丁状态（Administration | Updates）及业务运行情况；
6. 重新执行漏洞检测并留存修复证据。

#### 临时缓解

无法立即升级时，可采取：

- 关闭或限制 agent 轮询协议端点的外部访问（`/app/agents/v1`）；
- 限制 8111 等管理端口和 Web 界面的互联网访问（仅内网/VPN 可达）；
- 通过防火墙、ACL、安全组仅允许可信 IP 访问；
- 在 WAF、IPS 或网关增加针对 agent 端点与反序列化特征请求的拦截规则；
- 启用身份认证、多因素认证和最小权限控制；
- 修改默认账号、默认密码及默认密钥；
- 加强日志审计、主机监控和异常外联检测（重点监控 `.jspws` 文件落盘）；
- 对高风险系统实施网络隔离或访问收敛；TeamCity Cloud 用户无需操作（厂商已修复）。

**事件描述：**  
波兰 CERT（CERT Polska）发布后续调查报告：攻击者首先攻破某风电场暴露在互联网的 **Fortinet VPN/防火墙设备**，进而通过 **Teltonika 蜂窝路由器** 建立 SSH 隧道，进入配电系统运营商（DSO）管理的**私有 APN**，再渗透至一座为约 5 万居民供热的热电联产（CHP）厂 OT 网络。攻击者在 Wago PLC 上利用 SSH 访问深入操作网络，经过约一周侦察后将 **Siemens PLC 切换至停止模式并设置密码锁定**，导致汽轮机与水处理系统停机、热电联产流程中断；随后通过破坏 Wago 控制器分区表销毁取证痕迹。Moxa 串口服务器与交换机被重配置以阻断合法访问，ABB、Schneider 变频器亦被触碰。CERT Polska 称该攻击路径（蜂窝路由器管理接口缺乏管控、私有 APN 直连 OT）此前未见公开记录。

- 蜂窝路由器（Teltonika 等）管理接口不得默认暴露，需纳入配置基线管控；  
- 私有 APN/远程运维通道与 OT 网络之间应实施严格分段与访问控制；  
- 对 PLC、RTU、串口服务器等 OT 资产实施口令轮换、可用性监控与日志外带；  
- 参考 [CERT Polska 报告原文](https://cert.pl/uploads/docs/CERT_Polska_Energy_Sector_Incident_Follow_up_Report_2025.pdf) 开展 OT 网络架构自查。
