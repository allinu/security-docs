### 1.3 今日重点关注

1. **`CVE-2026-21589`：Atlassian Data Center 全线产品未认证任意文件读取（已在野利用、PoC 公开）**  
   影响 **Bitbucket / Confluence / Jira Software / Jira Service Management / Bamboo / Crowd / Crucible / Fisheye** 等八款自建（Data Center / Server）产品，**CVSS 4.0 9.3**。未认证攻击者可通过 `atlassian-plugins-webresource` 资源路由的路径穿越缺陷读取 Web 根目录内的敏感文件（数据库密码、私钥、集成 Token、Crowd 应用凭据等）；**Security Affairs 报道详情公开数小时后即遭在野利用**。建议**立即核实所有 Atlassian DC 实例版本并按官方公告升级到修复版本**。

2. **`CVE-2026-76268`：Splunk Enterprise 未认证操作系统命令执行**  
   Splunk Enterprise `< 10.4.3` / `< 10.2.7` 的搜索头集群成员上，**Patroni REST API 对关键配置操作未要求认证**，具有网络可达性的**未认证用户可执行攻击者控制的 OS 命令**，**CVSS 9.8**。建议**排查 Splunk 搜索头集群的网络暴露并尽快升级**。

3. **`CVE-2026-84272` / `CVE-2026-16340` 等：IBM 数据平台未认证 RCE 与内存破坏集群**  
   **IBM Guardium Data Protection 12.1 / 12.2.2 的 edge-controller 组件缺失认证（`CVE-2026-84272`，9.8）**，未认证远程攻击者可执行任意容器镜像并接管受管边缘集群；**IBM DataPower Gateway 批量内存破坏 RCE（`CVE-2026-16340`/`14991`/`15762`/`14269`/`14502`/`14992` 等多条 9.8）**。建议**优先升级 API 网关与数据安全平台的边界实例**。

4. **`CVE-2026-103663`（Ollama）与 `CVE-2026-106126`（Tenable）：AI 推理与安全平台缺陷**  
   **Ollama `/api/pull` 因层摘要校验不足导致路径遍历（9.4）**，未认证远程攻击者可写入模型存储之外的路径并（在默认权限下）落入 `/usr/lib/ollama` 实现代码执行；**Tenable Identity Exposure（SaaS）的 AD 事件监听器命令注入（9.4）**，低权限认证用户可在 PDCe 上以 SYSTEM 执行命令。建议**排查 AI 推理服务暴露面与身份安全平台联动组件**。

### 3.1 CVE-2026-21589 — Atlassian Data Center 全线产品未认证任意文件读取（已在野利用）

!!! danger "严重漏洞（未认证可远程触发、已在野利用、PoC 已公开，CVSS 4.0 9.3）"
    Atlassian 自建（Data Center / Server）产品存在**未认证任意文件读取**漏洞。攻击者无需登录，通过构造包含 `..::` 序列的畸形 URL 请求，利用 `atlassian-plugins-webresource` 资源路由将 `::` 转为 `/` 的缺陷绕过路径清洗，即可读取 Tomcat Web 应用根目录内的**特定已知文件**（如 `WEB-INF/web.xml`、`WEB-INF/classes/crowd.properties`）。**该漏洞在详情公开后数小时内即被在野利用。**

#### 3.1.2 漏洞摘要

该漏洞位于 Atlassian 自建产品共享的静态资源服务库 **`atlassian-plugins-webresource`**。该库通过 `/download/resources/...` 等路由对外提供插件静态资源；在受影响版本中，`Router.unescapeSlashes()` 会在路由匹配之后将 **`::` 转换为 `/`**。攻击者只要把穿越片段构造成 **`..::`（等价于 `../`）**，即可绕过 `getResourceRelativeToWebResource()` 中针对斜杠的清洗，最终使底层 `ResourceFactory` 以应用身份读取并返回 Web 应用根目录内的文件内容。**由于无需任何认证，且读取目标是应用内已知路径的高价值文件（如数据库连接信息、密钥、第三方集成 Token、`WEB-INF/web.xml`、`WEB-INF/classes/crowd.properties`），一旦被读取将直接造成敏感凭据泄露。** 与 Crowd 集成的实例若 `crowd.properties` 可读，泄露的应用名/口令可能进一步被用于身份管理面操作。

> **厂商与研究者给定的限制：** 无目录列举能力（须已知确切文件路径）；读取范围限于 Web 应用根目录（非任意文件系统）；Atlassian Cloud 已修复，本漏洞影响**自建（Data Center / Server）**部署；其本身为**只读**原语，不直接构成 WebShell。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 Atlassian DC 产品的 HTTP(S) 服务（默认 8080/8443 或反向代理端口） |
| 身份认证 | 无需 | 未认证远程攻击者即可触发 |
| 用户交互 | 不需要 | 直接构造 HTTP GET 请求 |
| 特定配置 | 否 | 默认部署即存在资源路由；需知晓目标文件的确切路径 |
| 利用复杂度 | 低 | 无认证、无交互，PoC 已公开 |

**技术原理：**

共享库 `atlassian-plugins-webresource` 在 `/download/resources/...` 路由处理中，`Router.unescapeSlashes()` 于路由之后将 `::` 替换为 `/`。攻击者将穿越段写作 `..::`，在转换后变为 `../`，从而绕过 `getResourceRelativeToWebResource()` 对 `/` 的清洗，最终由 `ResourceFactory` 读取 Web 应用根目录内文件并回显。由于资源路由在任何认证之前即被处理，且回显内容即文件正文，构成未认证任意文件读取。

**核心利用链：**

```text
攻击者
  └─ 定位互联网/内网可达的 Atlassian Data Center 实例（Jira/Confluence/Bitbucket…）
      └─ 构造 GET /download/resources/<resource>/…/..::..::..::..::..::WEB-INF::web.xml
          └─ Router.unescapeSlashes() 将 :: 转为 /，..:: 变为 ../
              └─ getResourceRelativeToWebResource() 斜杠清洗被绕过
                  └─ ResourceFactory 读取 Web 根目录内文件并回显
                      └─ 获取 WEB-INF/web.xml、crowd.properties 等敏感凭据
```

### 3.2 CVE-2026-76268 — Splunk Enterprise 未认证操作系统命令执行（Patroni REST API）

!!! danger "严重漏洞（未认证可远程触发，CVSS 3.1 9.8）"
    Splunk Enterprise 搜索头集群成员的 **Patroni REST API** 对关键配置操作**未要求认证**。具有网络可达性的**未认证攻击者**可利用该接口**执行攻击者控制的操作系统命令**，从而完全控制 Splunk 搜索头节点。

#### 3.2.2 漏洞摘要

Splunk Enterprise 在搜索头集群（Search Head Cluster）中使用 Patroni 管理 PostgreSQL 集群，其 REST API 在搜索头集群成员上监听。受影响版本中，该接口对**关键配置操作未实施认证**，攻击者只要具备到该接口的网络可达性，即可在无需任何凭据的情况下提交恶意配置并触发**攻击者控制的操作系统命令执行**。由于 Splunk 通常汇聚海量日志与安全遥测数据，一旦被未认证接管，攻击者可读取、篡改或删除安全数据，甚至以 Splunk 服务权限横向移动。

> Cisco PSIRT 于同期发布了 Splunk Enterprise 多项内部评审缺陷（`CVE-2026-76265`/`76266`/`76269`–`76283`/`76286` 等），本条（9.8）为其最高风险项。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达搜索头集群成员的 Patroni REST API 端口 |
| 身份认证 | 无需 | 未认证远程攻击者即可触发 |
| 用户交互 | 不需要 | 直接构造 HTTP 请求 |
| 特定配置 | 是 | 依赖搜索头集群（Search Head Cluster）与 Patroni 接口可达 |
| 利用复杂度 | 低 | 无认证、无交互 |

**技术原理：**

搜索头集群成员的 Patroni REST API 暴露了配置管理端点，但受影响版本未对关键配置操作校验身份。攻击者提交恶意配置即可影响 Patroni 后续调用链路，最终以 Splunk 服务权限执行攻击者控制的 OS 命令。

**核心利用链：**

```text
攻击者
  └─ 发现可达的 Splunk 搜索头集群成员（Patroni REST API）
      └─ 提交未认证的关键配置操作请求
          └─ Patroni 处理系统调用/命令参数
              └─ 以 Splunk 服务权限执行攻击者控制的 OS 命令
```

### 3.4 CVE-2026-103663 — Ollama `/api/pull` 路径遍历致任意文件写入与代码执行

!!! danger "严重漏洞（未认证远程可达，CVSS 4.0 9.4）"
    **Ollama** 的 `/api/pull` 端点因对层摘要（layer digest）校验不足，存在**路径遍历**。未认证远程攻击者可将恶意二进制写入模型存储之外的路径，**若服务进程对 `/usr/lib/ollama`（多数 Ollama 安装的默认路径）具有写权限，即可实现代码执行**。

#### 3.4.2 漏洞摘要

Ollama 在拉取模型（`/api/pull`）时，由 `digestToPath` 函数根据层摘要拼装文件路径，但未充分校验摘要内容。攻击者可将**路径遍历序列**作为层摘要提交，使服务把下载内容写入模型存储目录之外。在服务进程对 `/usr/lib/ollama` 具有写权限的常见部署下，攻击者可覆盖/写入可执行文件，进而在下一轮启动或调用时实现代码执行。由于该端点通常无需认证即可访问，暴露于网络的 Ollama 实例面临直接风险。

> 该漏洞由 CERT Polska 协调披露，属于近期 AI 推理组件安全面持续走高的又一例证（同窗口另有 LMCache 未认证 RCE 出现在 RSS 情报流）。

#### 3.4.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 Ollama HTTP API（默认 `11434`） |
| 身份认证 | 无需 | `/api/pull` 默认无需认证 |
| 用户交互 | 部分（PoC 描述提及 UI 相关，实际以 API 直接触发为主） | 直接调用 API 即可 |
| 特定配置 | 是 | 影响程度取决于服务进程对目标路径（如 `/usr/lib/ollama`）的写权限 |
| 利用复杂度 | 低 | 无认证，构造畸形层摘要即可 |

**技术原理：**

`digestToPath` 使用攻击者可控的层摘要构造文件路径而未剥离 `../`，导致写入逃逸出模型存储目录。若写入落点位于可执行加载路径（如 `/usr/lib/ollama`），则可在后续过程中触发任意代码执行。

**核心利用链：**

```text
攻击者
  └─ 定位可达的 Ollama 服务（/api/pull）
      └─ 提交含路径遍历序列的层摘要
          └─ digestToPath 拼装路径未剥离 ../
              └─ 文件写入逃逸至模型存储之外的路径
                  └─ 写入 /usr/lib/ollama 等可执行加载路径
                      └─ 后续启动/调用时实现代码执行
```

#### 3.5.2 漏洞摘要

- **`CVE-2026-106126`（Tenable Identity Exposure, SaaS，9.4）**：AD 事件监听器存在命令注入，**低权限认证攻击者**可在 PDCe（主域控制器模拟器）上以 **SYSTEM** 执行任意命令，SaaS 侧已由厂商修复。
- **`CVE-2026-107459`（Openfind SecuShare Pro，9.3）**：存在 OS 命令注入，**未认证远程攻击者**可注入并以服务器权限执行任意 OS 命令（TWCERT 通报）。
- **`CVE-2026-105110`（Iskratel Innbox GPON ONT，9.3）**：`login.xgi` CGI 端点存在 OS 命令注入，**未认证远程攻击者**可通过 CLI 参数**以 root 权限**执行任意命令，直指运营商级光网络终端。
- **`CVE-2026-107640`（Integrics Enswitch 3.13–4.4，9.3）**：`/api/json/user/password/update/` 存在认证绕过，攻击者**省略 `reset` 参数**即可在无待重置令牌的账户上以默认空值匹配，枚举用户名后**重置管理员口令并接管账户**。
- **`CVE-2026-104075`/`104076`（TVU Networks 收发设备，固件 < 7.9，9.3）**：`POST /tvu/Login` 提交**空或缺失 UserName** 即可获取管理员会话（认证绕过）；另有缺失认证可读取敏感设备信息并修改配置。修复版本 `7.9`。

> 本批缺陷共同指向“**边界/管理面未认证可达 + 直接命令执行或账户接管**”，且部分（Iskratel ONT、TVU 设备）属运营商/广播级基础设施，暴露面与影响面需重点关注。

#### 3.5.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
|---|---|---|
| 网络可达 | 是 | 需可达各产品的 HTTP 接口（Web 管理/CGI/API） |

| 利用复杂度 | 低 | 未认证命令注入/认证绕过门槛低 |

**技术原理：**

相关产品在 Web 接口/CGI/API 处理中，将用户可控输入直接拼接进系统命令或未对关键认证参数（如重置令牌、登录用户名）做严格校验，导致命令注入或认证绕过。Iskratel 的 `login.xgi` 以 root 运行进一步放大了后果。

**核心利用链：**

```text
攻击者
  └─ 定位暴露的企业软件/网络设备 Web 接口
      └─ 构造未认证（或低权限）构造的 HTTP 请求
          └─ 触发命令拼接或认证校验缺失
              └─ 以 root/SYSTEM 执行命令 或 接管管理员账户
```

#### 3.6.2 漏洞摘要

本批缺陷集中于 Brocade Fabric OS（SAN 交换机）的管理接口与协议处理：REST API 管理接口存在命令注入（认证用户可执行任意系统命令，`CVE-2026-87680`/`87682`）；REST API 请求载荷处理存在多个栈溢出（`CVE-2026-87683`）；RBAC 校验引擎存在访问控制绕过（`CVE-2026-87681`）；管理服务器处理存在授权绕过（`CVE-2026-87659`，受损交换机可向 fabric 发送特制信息）；IKEv2 与诊断工具存在栈溢出（`CVE-2026-87665`/`87668`）。多数需认证或邻接网络（`AV:A`）条件，且不含未认证 RCE，整体风险中高。**修复版本为 Fabric OS `10.0.1`。**

> 作为数据中心 SAN 网络组件，Brocade 交换机被接管可能影响存储可用性与隔离边界，建议按公告核对型号与固件并升级。

#### 3.6.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
|---|---|---|
| 网络可达 | 是 | 需可达交换机管理接口（部分为邻接网络 `AV:A`） |
| 身份认证 | 多为认证用户 | 命令注入类需已认证；部分授权绕过类需接入 fabric |
| 用户交互 | 不需要 | 直接构造请求 |
| 特定配置 | 是 | 依赖相应管理/协议功能启用 |
| 利用复杂度 | 中 | 溢出类需构造载荷，注入类门槛较低 |

**技术原理：**

Fabric OS 在解析管理接口（REST API）与协议（IKEv2）输入时未做充分边界/授权校验，导致命令注入、栈溢出与 RBAC 绕过；受损交换机可向 fabric 注入特制信息绕过管理服务器授权。

**核心利用链：**

```text
攻击者（认证用户或 已接入 fabric 的交换机）
  └─ 访问 Fabric OS 管理接口 / 协议栈
      └─ 构造恶意 REST 载荷 / 协议报文（超长字段、越权指令）
          └─ 触发命令注入 / 栈溢出 / RBAC 绕过
              └─ 以交换机权限执行命令或越权操作
```

#### 3.7.2 漏洞摘要

- **`CVE-2026-12260`（NetBoard CRM 演示平台，10.0）**：`/module/auth/recovery.php` 的 `user-name` POST 参数存在盲注 SQL 注入（支持布尔、报错、时间与 UNION 技术），可提取后端数据库版本/类型等机密信息、篡改或删除数据。
- **`CVE-2026-85097`（WordPress Bricksforge 插件 ≤ 3.1.8.9，9.8）**：表单提交中 `temporaryFileUploads` 的 URL 字段校验不足，未认证攻击者可先经 `bricksforge_regenerate_nonce` 获取有效 nonce，随后**上传任意文件**，可能导致 RCE。
- **`CVE-2026-103646`（Ultimate Multisite < 2.17.0，9.8）**：未认证的“已登出结账”可被关联并以匹配邮箱的既有账户登录，且重复账户检查与创建查找的规范化不一致，未认证攻击者可登录为任意既有用户（含管理员）。
- **`CVE-2026-103692`（Frontend Dashboard < 3.0.5，9.8）**：对未认证用户可用的动作缺少授权与 nonce 校验，可**调用攻击者指定的 PHP 函数或类方法**。
- **`CVE-2026-107282`（AsyncHttpClient，9.4）**：跨主机请求重放更新当前请求但保留原始 origin 的目标请求与代理上下文，导致连接池选择、CONNECT 处理、realm 选择与 TLS 设置指向原 origin，可能造成**凭据跨主机泄露**。
- **`CVE-2026-95210`（GnuTLS 3.8.13，9.1）**：证书校验不当，会接受包含非法扩展的证书，破坏信任链。

> WordPress 生态在本窗口仍以“未认证→高危/严重”缺陷为主，建议对站点插件基线进行盘点与升级。

**漏洞描述：**

**修复建议：**  
按厂商公告升级；对管理面板实施服务端认证与 SQL 参数化。

## 五、当日处置建议

1. **最优先（P0，24小时内）**：全面盘点自建 Atlassian Data Center 产品（Jira/Confluence/Bitbucket/Bamboo/Crowd/Crucible/Fisheye）版本，**因 `CVE-2026-21589` 已在野利用且 PoC 公开**，尽快升级至官方修复版本；与 Crowd 集成的环境立即轮换 Crowd 应用口令并核查审计日志；
2. 对 **Splunk Enterprise 搜索头集群（`CVE-2026-76268`）**、**IBM Guardium/DataPower（`CVE-2026-84272` 等）**、**Ollama（`CVE-2026-103663`）**、**Tenable Identity Exposure（`CVE-2026-106126`）** 等未认证/缺失认证高危缺陷，优先核查互联网暴露并升级；
3. 对 **CISA KEV 本期新增 5 条（`CVE-2015-5477`、`CVE-2016-3081`、`CVE-2023-22894`、`CVE-2021-3199`、`CVE-2015-3306`，期限 2026-10-11）** 及跨期逾期项（Citrix NetScaler、FortiMail、Zammad、Cisco SD-WAN、Apple `CVE-2026-86950` 等）对照资产自查并闭环；
4. 优先核查互联网暴露的 VPN、网关、安全设备、协作平台、中间件与管理平台；对 Brocade SAN 交换机等内网设备亦应按公告升级固件；
5. 无法立即升级的系统应采取断网、访问控制、接口禁用或 WAF 拦截措施（尤其针对 Atlassian 资源路由的 `..::`/`%3a%3a` 探测）；
6. 对疑似遭受攻击的系统保留日志、流量、进程、文件及内存证据；对发现异常的主机开展 WebShell、恶意进程、异常账号及横向移动排查；
7. 完成修复后进行复测，并更新资产台账和漏洞处置记录。
