### 3.1 CVE-2026-55040 — Microsoft SharePoint JWT 令牌身份认证绕过漏洞（在野利用，PoC 公开）

#### 3.1.2 漏洞摘要

该漏洞位于 Microsoft SharePoint Server Subscription Edition 的 JWT 令牌校验管线。Rapid7 分析指出其根因为 **四个弱点串联**：外层 JWT 头使用 `alg: none`（无需签名校验）、以 SharePoint 自身 STS 证书指纹作为 `kid` 解析签名密钥而不做校验、以及传入一个"非空但从不校验"的签名（如 `AAAA`），最终 SharePoint 将该伪造令牌当作合法令牌接受。未认证攻击者无需任何凭据即可冒充 SharePoint 站点任意用户，包括管理员。

由于漏洞于 2026 年 7 月补丁日已修复，**任何未安装该补丁的 SharePoint 实例均直接暴露**。Rapid7 于 2026-08-12 公开技术分析文章与 Python PoC 后，Defused 团队观测到攻击者立即使用该 PoC 攻击其 SharePoint 蜜罐；KEVIntel 记录自 2026-07-19 起共 12 次利用尝试，其中 8 次发生在 2026-08-12~13（PoC 公开后），来源为香港、日本、荷兰、中国台湾及美国的 8 个 IP。奇安信 CERT 于 2026-08-13 发布【已复现】安全风险通告。

> 利用后果：攻击者可读取 SharePoint 场中的文档、修改数据，并可能以此为跳板深入 Microsoft 365 基础设施；微软公告注明该漏洞不影响服务可用性（A 为 N），但数据机密性与完整性影响均为高。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 SharePoint Web 服务（默认 80/443，含 STS 相关端点） |
| 身份认证 | 无需 | 未认证远程利用 |
| 用户交互 | 不需要 | 无点击、无文件打开 |
| 特定配置 | 是 | 仅影响 SharePoint Server Subscription Edition（JWT 校验管线） |
| 利用复杂度 | 低 | 公开 PoC 可直接构造伪造 JWT |

**技术原理：**

SharePoint 的 JWT 校验流程存在以下缺陷链（Rapid7 公开分析）：

1. 外层 JWT 头声明 `alg: none`，校验器未拒绝无签名算法；
2. 以 SharePoint 自身 STS 证书指纹（thumbprint）作为 `kid` 来解析签名密钥，且对该解析结果**不做真实性校验**；
3. 传入一个非空但**从不参与校验**的签名值（如 `AAAA`）；
4. 上述组合使校验器将攻击者完全可控的 JWT 接受为合法令牌。

**核心利用链：**

```text
攻击者
  └─ 发现暴露的 SharePoint Server（80/443）
      └─ 构造伪造 JWT（alg:none + kid=STS 证书指纹 + 伪签名）
          └─ 触发 JWT 校验管线缺陷链
              └─ 绕过认证，令牌被接受为合法
                  └─ 冒充任意 SharePoint 用户/管理员
                      └─ 读取/篡改文档数据，深入 M365 基础设施
```

#### 3.2.2 漏洞摘要

该漏洞存在于 Adobe Commerce（含 Commerce B2B 与 Magento Open Source）的客户会话身份处理逻辑中。由于对会话身份关联的授权校验不正确（CWE-863），未认证攻击者**无需既有客户账号、无需管理员权限、无需用户交互**，即可将当前会话切换到任意其他客户账号，从而接管受害者账号并访问其订单、地址、支付信息等隐私数据，还能以受害者身份执行下单等操作。

Adobe 于 2026-08-11 前后发布 **APSB26-92** 孤立补丁包，共修复 7 个漏洞（含本漏洞、存储型 XSS 与授权问题）；修复方式为更正 Magento 对客户身份与会话绑定的处理。安全公司 Sansec 在 Adobe 公告发布后即观测并拦截了**首批利用尝试**，其产品 Sansec Shield 已可拦截该漏洞利用。受影响的为 **2026 年 7 月及更早补丁版本**的 Commerce / Commerce B2B / Magento Open Source。

> 影响版本边界：影响 Commerce、Commerce B2B 与 Magento Open Source 截至 2026 年 7 月补丁的版本（Sansec 与 Adobe 公告口径），具体版本号以 [Adobe APSB26-92](https://helpx.adobe.com/security/products/magento/apsb26-92.html) 为准。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达商城 Web 服务（80/443） |
| 身份认证 | 无需 | 未认证利用，无需既有账号 |
| 用户交互 | 不需要 | 无点击、无文件打开 |

| 利用复杂度 | 低 | Sansec 已确认无需任何前置条件即可切换会话 |

**技术原理：**

Magento 在客户会话中绑定客户身份的方式存在授权校验缺陷：攻击者可通过构造请求改变会话所关联的客户标识，而系统未对"切换目标身份"的操作执行正确的授权检查，导致会话被切换到任意其他客户账号。Adobe 的修复更正了 Magento 对客户身份与会话关联的处理逻辑。

**核心利用链：**

```text
攻击者
  └─ 发现暴露的 Adobe Commerce 商城（80/443）
      └─ 构造会话切换请求（修改会话关联的客户标识）
          └─ 触发不正确的授权校验（CWE-863）
              └─ 会话切换到任意目标客户账号
                  └─ 读取订单/地址/隐私数据，以受害者身份操作
```

### 3.5 CVE-2026-47876 — VMware ESXi VMXNET3 虚拟网卡越界写漏洞（虚拟机逃逸）

!!! danger "严重漏洞"
    VMware ESXi 的 VMXNET3 虚拟网络适配器存在越界写（CWE-787），在虚拟机内拥有本地管理员权限的攻击者可利用该缺陷在宿主机上执行代码，构成虚拟机逃逸。

#### 3.5.2 漏洞摘要

该漏洞存在于 VMware ESXi 的 VMXNET3 虚拟网络适配器组件中。当虚拟机配置了 VMXNET3 虚拟网卡时，虚拟机内拥有**本地管理员权限**的攻击者可通过特制操作触发越界写（CWE-787），从而在**宿主机（ESXi）**上执行代码——即典型的"客户机到宿主机"虚拟机逃逸场景。NVD 说明非 VMXNET3 虚拟网卡不受影响。

由于攻击前提是虚拟机内本地管理员权限，实际利用门槛高于普通远程漏洞；但一旦被利用，攻击者将突破虚拟化隔离边界，控制宿主机及同宿主机的全部虚拟机，影响范围是跨安全域的（CVSS Scope: Changed，评分 9.3）。该漏洞随 **VMSA-2026-0006.1** 通告修复，HKCERT 于 2026-08-14 发布中文公告（整体评定"中度风险"，本站按 NVD CVSS 口径列为严重并单独展开）。

#### 3.5.11 风险影响

漏洞成功利用后，可能导致：

- 突破虚拟机隔离，在宿主机上执行代码；
- 控制宿主机及同宿主机的全部虚拟机与数据；
- 窃取虚拟化平台凭据与租户数据（跨安全域影响）；
- 篡改虚拟化环境配置，造成大规模业务中断。
