### 1.3 今日重点关注

1. **`CVE-2026-21589`：Atlassian Data Center 全线产品未认证任意文件访问**  
   影响 Bitbucket / Confluence / Jira Software / Jira Service Management / Bamboo / Crowd / Crucible / Fisheye **共 8 款私有化部署产品**，未认证远程攻击者在知晓目标文件确切名称与路径的前提下可读取 Web 应用根目录内特定文件（部分配置下可读到含凭据/密钥的敏感文件）。CVSS 4.0 = **9.3**，官方已发布各分支修复版本，建议**优先排查互联网暴露的自建 Atlassian 实例**。

2. **`CVE-2026-76752` 等：HPE Networking ClearPass Policy Manager 认证与管理面缺陷集群**  
   ClearPass Policy Manager 的 Web 管理与 API 界面存在**认证绕过**（`CVE-2026-76752`，9.8）、**SQL 注入**（`CVE-2026-79798`，9.9；`CVE-2026-76754`，9.8）、**反序列化 RCE**（`CVE-2026-76750`，9.8）、**认证绕过**（`CVE-2026-79796`，9.8）及**认证后路径遍历/缺失完整性校验**（`CVE-2026-79805`/`CVE-2026-76751`/`CVE-2026-79801`，均 9.8）。ClearPass 为网络准入（NAC/802.1X）核心，建议**立即核查版本并按 HPE 公告升级**。

3. **`CVE-2026-86360`：Dell System Update 路径遍历致 root 权限任意代码执行**  
   Dell DSU（`< 2.3.0.0`）存在路径遍历，**未认证**远程攻击者可越权访问文件系统并以 **root 权限执行任意代码**，可能导致主机与底层操作系统完全失陷。CVSS 3.1 = **9.6**，建议**优先升级至 2.3.0.0**。

4. **`CVE-2026-105857` / `CVE-2026-106102`：开源框架满分级缺陷**  
   Payload CMS 表单构建插件（`@payloadcms/plugin-form-builder < 3.90.0`）可经表单提交**远程执行代码**（**10.0**）；Quasar Framework（`< 2.22.0`）SSR 元数据序列化未做 HTML/属性编码，可注入可执行标记（**10.0**）。建议**排查自建 CMS/前端 SSR 项目依赖并升级**。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达目标 Atlassian 实例的 HTTP(S) 服务 |
| 身份认证 | 无需 | 未认证远程攻击者即可触发 |
| 用户交互 | 不需要 | 直接构造 HTTP 请求 |
| 特定配置 | 是 | 需知晓目标文件确切名称与路径；目录是否含敏感文件取决于配置 |
| 利用复杂度 | 中 | 无法枚举目录，依赖攻击者对文件名/路径的先验知识 |

**技术原理：**

受影响产品的 Web 应用根目录访问控制存在缺陷，未能对“对应用根目录内特定文件的直接请求”实施充分校验，使未认证请求可绕过预期边界读取文件。由于漏洞不允许目录枚举，攻击者需借助其他途径（如公开默认文件路径、源码/配置泄露、版本指纹推断）获得目标文件名后再发起请求；一旦命中包含数据库口令、连接密钥或加密材料的配置文件，即可造成严重后果。

**核心利用链：**

```text
攻击者
  └─ 定位互联网/内网暴露的 Atlassian Data Center 实例（如 Confluence/Bitbucket）
      └─ 依据公开默认路径或先期泄露信息推断目标文件确切名称与路径
          └─ 构造指向应用根目录内特定文件的未认证 HTTP 请求
              └─ 绕过访问控制读取文件内容
                  └─ 获取配置/凭据/密钥 → 后续凭据滥用与横向移动
```

HPE 于本窗口批量披露 ClearPass Policy Manager 与 AOS-S 交换机合计 **36 条**安全缺陷，其中 ClearPass 部分以**认证/授权类**为主。典型条目包括：`CVE-2026-76752`（Web 管理与 API 界面**认证绕过**，未认证攻击者可绕过认证取得系统管理员访问，9.8）、`CVE-2026-79798`（管理界面 **SQL 注入**，低权限即可执行任意数据库命令，9.9）、`CVE-2026-76750`（Web 界面**反序列化**致未认证 RCE，9.8）、`CVE-2026-76754`（未认证 SQL 注入，9.8）、`CVE-2026-79796`（受影响接口认证绕过，9.8）、`CVE-2026-79805`（**认证后路径遍历**，可读取与修改底层 OS 文件，9.8）、`CVE-2026-76751`/`CVE-2026-79801`（OnGuard 代理/客户端**缺失完整性校验**，未认证攻击者可引入不受信任代码，9.8）。ClearPass Policy Manager 是广泛部署于企业园区的网络准入控制（NAC/802.1X）与策略管理核心，通常与交换机、无线控制器、目录服务深度耦合，一旦被未认证接管，攻击者可下发任意准入策略、读取认证事件与凭据、并进一步渗透网络。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 ClearPass 管理面（Web/API，默认 443/22 等） |
| 身份认证 | 部分无需 / 部分低权限 | 认证绕过与多数 SQL 注入无需认证；`CVE-2026-79805` 需认证 |
| 用户交互 | 不需要 | 直接构造 HTTP/API 请求 |
| 特定配置 | 视条目而定 | 部分依赖特定接口/功能启用 |
| 利用复杂度 | 低—中 | 认证绕过与注入类利用门槛较低 |

**技术原理：**

ClearPass 管理面缺陷集中于三类根因：其一，**认证与授权校验缺失**——管理/API 接口未能正确验证会话或权限，导致未认证请求即可进入特权功能（篡改凭证、绕过准入策略）；其二，**注入类缺陷**——管理界面对输入参数未做充分参数化与转义，形成可执行任意数据库命令的 SQL 注入；其三，**数据处理类缺陷**——对不可信数据直接反序列化（可致 RCE），以及对文件路径、客户端完整性的校验不足（可致路径遍历与不受信任代码引入）。

**核心利用链：**

```text
攻击者
  └─ 定位可达的 ClearPass Policy Manager / OnGuard 接口
      └─ 构造未认证请求绕过认证（CVE-2026-76752/79796）
          └─ 或注入 SQL 执行任意数据库命令（CVE-2026-79798/76754）
              └─ 或经反序列化触发 RCE（CVE-2026-76750）
                  └─ 取得管理权限 / 读取认证数据 / 接管准入控制与底层系统
```

#### 3.3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达运行 DSU 的主机/相关服务 |
| 身份认证 | 无需 | 未认证远程攻击者 |

| 利用复杂度 | 中 | 受用户交互与部署形态影响 |

**技术原理：**

DSU 在处理外部提供的文件路径时，未对 `../` 等穿越序列与目标目录边界做充分限制，导致可越出预期目录读写文件。结合 DSU 通常以高权限（root/SYSTEM）运行的特点，攻击者可借助文件写入与执行链（如写入可被高权限加载/执行的路径）实现**以 root 权限执行任意代码**。

**核心利用链：**

```text
攻击者
  └─ 定位运行 Dell System Update 的服务器/服务端点
      └─ 构造含路径穿越序列的恶意输入
```

### 3.4 CVE-2026-96940 — Microsoft Exchange Server 弱授权致权限提升

!!! warning "高危漏洞（需认证，但提权后果严重）"

#### 3.4.2 漏洞摘要

该漏洞影响 Microsoft Exchange Server。其根因是**弱授权**：Exchange 在部分功能的权限判定上存在缺陷，使得**经过认证的攻击者**可通过网络发起请求并提升自身权限。Security Affairs 于本窗口报道，微软已就此发布**带外（out-of-band）安全更新**，并提示该缺陷“被利用的可能性高于常规”，但未披露具体利用细节。由于 Exchange 承载企业邮件与日历核心业务、并常与会话/身份体系深度耦合，权限提升后可读取敏感邮件、冒充其他用户或进一步渗透内网。

#### 3.4.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 Exchange 的 Web/服务接口 |
| 身份认证 | 普通用户（需已认证） | 攻击者需持有一个可用账号 |
| 用户交互 | 不需要 | 直接构造请求 |
| 特定配置 | 视部署而定 | 与 Exchange 版本/已装补丁相关 |
| 利用复杂度 | 低 | 认证后提权，链路相对直接 |

**技术原理：**

Exchange 对部分操作/接口的授权校验不足（弱认证），导致已认证的低权限用户可越权执行更高权限的操作，从而在网络侧完成权限提升。由于缺少足够的授权边界检查，攻击者无需额外前置条件即可在获得普通账号后放大权限。

**核心利用链：**

```text
攻击者（持有普通账号）
  └─ 登录并保持有效会话
      └─ 对弱授权接口构造越权请求
          └─ 绕过授权校验执行高权限操作
              └─ 权限提升 → 读取/篡改邮件与配置，横向渗透
```

#### 3.5.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 CSM 授权服务 / Operator / CSI 组件接口 |
| 身份认证 | 部分无需 / 部分低权限 | 缺失认证条目无需认证；Operator 条目为低权限 |
| 用户交互 | 不需要 | 直接构造 API/gRPC 请求 |
| 特定配置 | 视部署而定 | 与集群网络策略、暴露方式相关 |
| 利用复杂度 | 低 | 缺失认证 + 高权限运行环境 |

**技术原理：**

CSM 的授权服务（`csm-authorization-storage`）在 gRPC 接口上未正确实施认证，未认证请求即可调用关键功能；CSM Operator 在 reconcile `ContainerStorageModule` 自定义资源时权限边界处理不当，低权限攻击者可操纵资源使其在节点上以高权限执行，从而获得 **root**。此外，配套组件使用**硬编码凭据**与存在**模板注入**，进一步扩大攻击面。

**核心利用链：**

```text
攻击者（未认证 / 集群低权限）
  └─ 定位暴露的 CSM 授权服务 / Operator 接口
      └─ 无认证调用关键功能 或 操纵 CR 触发 reconcile
          └─ 绕过授权并提升至高权限
              └─ 获得集群节点 root / 接管存储配置
                  └─ 读写持久化数据、横向移动
```

### 3.8 CVE-2026-106102 — Quasar Framework SSR 元数据序列化注入

!!! danger "严重漏洞（满分级，影响使用 SSR 的 Vue 应用）"

#### 3.8.2 漏洞摘要

Quasar Framework `< 2.22.0` 的 SSR 专用 `getHead()` 序列化器（`ui/src/plugins/meta/Meta.js`）使用 `getAttr()` 将 `useMeta()` 提供的值插值进 `title`/`meta`/`link`/`script` 标记，**未进行 HTML 文本或带引号属性编码**；`injectServerMeta()` 又将该输出直接追加到原始服务端渲染响应中。因此，**能影响动态页面元数据的攻击者**（如帖子标题、产品名、摘要、显示名）可终止预期 HTML 上下文并在 hydration 之前注入可执行标记。客户端 `apply()` 路径因使用会编码属性的 DOM API 而不受影响。CVSS 达 **10.0**（`S:C` 且 `C:H/I:H`）。

| 厂商 | 产品/组件 | 受影响版本 | 修复版本 | 部署形态 |
|---|---|---|---|---|
| Quasar | quasar（`ui/src/plugins/meta/Meta.js` SSR 序列化） | `< 2.22.0` | `2.22.0` 或更高 | Vue.js SSR 应用（依赖引入） |

!!! warning "版本说明"
    版本范围以 GitHub Security Advisory（`GHSA-pq96-jpmf-w254`）与修复 commit（`11505afe`）为准；仅使用 SSR（服务端渲染）且存在用户可控元数据的应用受影响。

#### 3.8.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达使用 SSR 的站点 |
| 身份认证 | 无需 | 攻击者只需能影响页面元数据 |
| 用户交互 | 不需要 | 访问被注入页面即可触发 |
| 特定配置 | 是 | 需启用 SSR 且存在用户可控元数据 |
| 利用复杂度 | 低 | 注入动态标题/名称等常见字段 |

**技术原理：**

SSR 阶段服务端将 `useMeta()` 提供的元数据未编码地拼入响应 HTML，攻击者通过可控字段（如标题、产品名）闭合并逃逸属性/标签上下文，注入 `<script>` 或事件处理器等可执行标记，在 `hydration` 前于客户端执行，形成存储型/反射型 XSS，并可能结合 SSR 上下文扩展影响。

**核心利用链：**

```text
攻击者
  └─ 在可控字段（标题/名称/摘要）注入 HTML/属性载荷
      └─ SSR 服务端将未编码值拼入 head 标记
          └─ 载荷逃逸属性/标签上下文
              └─ hydration 前注入可执行标记 → 客户端代码执行
```
