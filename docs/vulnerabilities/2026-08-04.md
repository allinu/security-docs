## 3.1 CVE-2026-64531 — Linux 内核 Open vSwitch 本地提权漏洞（OVSwrap）

!!! danger "高危漏洞"

### 3.2 漏洞摘要

该漏洞存在于 Linux 内核 Open vSwitch（OVS）数据路径中。OVS 将生成的流 action 以 Netlink 属性（nlattr）形式存储，其 `nla_len` 字段为 16 位。上游提交 `a1e64addf3ff`（"net: openvswitch: remove misbehaving actions length check"）移除了总长度 64 KiB 上限的校验，使 `sw_flow_actions` 流可超过 65535 字节，但未同步收紧单个嵌套 action 的长度约束，导致 `nla_len` 字段发生整数回绕。

攻击者仅在私有用户/网络命名空间持有 `CAP_NET_ADMIN`（`unshare -Urn` 即可获得，无需初始命名空间权限）即可构造超长 CLONE action，使内核解析器落入攻击者控制的 conntrack 数据，获得任意内核读与"逐字递减"写原语，最终篡改自身凭据提权至 root。该问题根因可追溯至约 13 年前的 commit `74f84a5726c7`，2025 年 3 月移除 32 KiB 上限后漏洞变为可达。

> 奇安信 CERT 于 2026-08-04 发布"【已复现】Linux Kernel Open vSwitch 本地权限提升漏洞(CVE-2026-64531)安全风险通告"，确认 PoC 覆盖约 800 个 x86-64 内核构建，默认发行版（含 OVS 模块 + conntrack）普遍受影响。

### 3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 否 | 纯本地利用，无需网络访问 |
| 身份认证 | 普通用户 | 任意本地普通用户（无特权） |

| 特定配置 | 是 | 系统加载 openvswitch 内核模块且启用 conntrack/FTP helper；PoC 依赖非特权用户命名空间 |
| 利用复杂度 | 低 | 已公开可执行 PoC，覆盖约 800 个内核构建 |

**技术原理：**

OVS 生成的嵌套 action 流超过 65535 字节时，16 位 `nla_len` 字段发生回绕。攻击者在私有命名空间持有 `CAP_NET_ADMIN` 即可构造超长 CLONE action（含伪造的 SET action 与 conntrack labels），使内核 action 解析器（`ovs_nla_copy_actions` 等）落入攻击者控制的数据布局，形成任意内核读与"逐字递减"写原语，最终通过篡改自身进程凭据（uid/gid/capabilities）提权到 root。

**核心利用链：**

```text
普通本地用户
  └─ unshare -Urn 进入私有用户/网络命名空间（获得 CAP_NET_ADMIN）
      └─ 构造超过 64 KiB 的嵌套 OVS action 流（CLONE + 伪造 SET action）
          └─ 触发 16 位 nla_len 字段整数回绕
              └─ 内核 action 解析器落入攻击者控制的 conntrack 数据布局
                  └─ 获得任意内核读 / 逐字递减写原语
                      └─ 篡改自身凭据（uid/gid/capabilities）
                          └─ 提权至 root
```

        labels[20:24] = struct.pack(NLA_HDR, 0xFFFF, OVS_ACTION_ATTR_SET)  # nla_len 回绕

### 3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 cPanel 服务（2083/2087 等） |
| 身份认证 | 普通用户 | 任意已认证托管客户（共享主机租户） |
| 用户交互 | 不需要 | 无需交互 |
| 特定配置 | 是 | 依赖 MySQL/MariaDB 的 ANSI_QUOTES 相关行为与数据库管理功能 |
| 利用复杂度 | 低 | 公开 PoC 已验证，载荷构造简单 |

**技术原理：**

cPanel 以 root 身份执行 `CREATE DATABASE` / 重命名操作时，未正确保留用户会话的 `sql_mode`（ANSI_QUOTES）。在 ANSI_QUOTES 模式下，双引号被当作标识符定界符，而反引号失去标识符定界符语义，数据库名中的反引号可闭合标识符并把其余内容作为 SQL 执行。攻击者构造 `db\`; GRANT ALL ON *.* TO 'rce'@'%' ...; --` 形式的数据库名，即可在 MySQL root 上下文执行任意 SQL。

**核心利用链：**

```text
已认证托管客户（cPanel 控制面板）
  └─ 创建/重命名数据库，名称含反引号逃逸载荷
      └─ cPanel 以 root 身份执行 CREATE DATABASE `payload`
          └─ ANSI_QUOTES 模式下反引号失去标识符语义
              └─ 载荷被当作 SQL 在 root 上下文执行
                  └─ 创建管理员账号 / 读写文件（LOAD_FILE/INTO OUTFILE）/ UDF 命令执行
                      └─ 数据库失陷 → 视配置升级为操作系统级失陷
```

#### 日志与行为排查

重点检查（参照 N-able 安全公告与 Huntress 分析）：

- 可疑 `svchost.exe` 进程（N-central 受管端点侧）；
- Cloudflared 服务（攻击者常用于隧道回连）；
- N-central 服务器及受管端点新增账户/异常计划任务；
- 非工作时间异常 Take Control 会话、远程控制记录；
- 已知恶意 IP 的连接记录（厂商公告披露）。

### 3.11 风险影响

漏洞成功利用后，可能导致：

- N-central 服务器被完全控制（RMM 平台特权）；
- 批量控制下游受管端点（MSSP 供应链放大效应）；
- 窃取托管客户凭据与数据，定位域控并横向移动；
- 建立持久化访问，长期潜伏。

### 3.13 修复与缓解措施

#### 官方修复

1. 立即升级至 N-central 2026.3.1.7 或更高版本；
2. 升级前完成配置与数据备份，确认补丁完整性（该漏洞即因补丁不完整导致，需核对版本号）；
3. 关注 N-able 官方安全公告与 CISA KEV 更新。

#### 临时缓解

无法立即升级时，可采取：

- 限制 N-central 控制台管理接口的互联网访问（仅允许可信来源/VPN）；
- 按厂商公告排查可疑 `svchost.exe`、Cloudflared 服务及已知恶意 IP 连接；
- 核查 N-central 服务器及受管端点是否存在新增账户/异常计划任务；
- 对高风险受管端点启用额外认证与网络隔离；
- 加强日志审计与告警，监控异常 Take Control 会话。
