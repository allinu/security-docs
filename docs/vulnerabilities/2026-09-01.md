### 3.1 `QVD-2026-56805` — JeecgBoot 积木报表（JimuReport）autoexport 未授权远程代码执行漏洞

!!! danger "高危漏洞"

#### 3.1.2 漏洞摘要

该漏洞位于 JeecgBoot 生态内置的积木报表（JimuReport）组件。据[奇安信 CERT 通告](https://cn-sec.com/archives/5414871.html)（原文[微信公众号](https://mp.weixin.qq.com/s?__biz=MzU5NDgxODU1MQ==&mid=2247507288&idx=1&sn=f926aec873d115cc70e7b2c61cb8fd50)）与[长亭安全应急响应中心通告](https://cn-sec.com/archives/5414894.html)（原文[微信公众号](https://mp.weixin.qq.com/s?__biz=MzIwMDk1MjMyMg==&mid=2247493359&idx=1&sn=35f7bcc61291616d4cc0201707eba82a)）：积木报表组件 `auto/export` 导出接口存在未授权远程代码执行缺陷——执行导出（如 PDF 导出）时，服务端将请求中的查询参数并入报表查询对象，参数值以 `=` 开头时被内部表达式引擎按 Excel 公式解析，该引擎底层具备 Groovy 脚本能力且参数值未做任何过滤（JimuReport 2.5.0 仅限制了部分 Aviator 表达式特性，静态方法调用等能力仍可用）。同时 JeecgBoot 的 Shiro 过滤链将 `/jmreport/**` 配置为匿名放行，攻击者无需任何凭据即可完成利用。该漏洞由[微步 XGPT 发现并报送官方](https://www.gm7.org/archives/153155)（微步情报编号 XVE-2026-53510），官方已于 08-24 发布 JimuReport v2.5.1 修复；奇安信 CERT 与长亭于 08-31 同日公开通告并完成复现验证。

> 该漏洞为"未授权导出接口 + 表达式引擎不安全求值"组合缺陷：`=` 前缀参数被当作 Excel 公式表达式执行，底层 Groovy 能力 + Shiro 匿名放行 `/jmreport/**` 使利用门槛降为零（无需认证、默认配置、无用户交互）。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达报表服务 Web 接口（集成路径 `/jeecg-boot/jmreport/**` 或独立部署路径 `/jmreport/**`） |
| 身份认证 | 无需 | Shiro 过滤链将 `/jmreport/**` 匿名放行，未登录即可触达 |
| 用户交互 | 不需要 | — |
| 特定配置 | 否 | 默认配置即可触发 |
| 利用复杂度 | 低 | 构造以 `=` 开头的恶意参数即可，无需绕过额外机制 |

**技术原理：**

JimuReport 2.5.0 的自动导出功能（auto/export）在处理导出请求时，将请求查询参数并入报表查询对象；当参数值以 `=` 开头时，内部表达式引擎将其按 Excel 公式解析求值。该引擎底层具备 Groovy 脚本能力，且参数值未经过滤（JimuReport 2.5.0 仅限制部分 Aviator 表达式特性，静态方法调用等能力仍可用）。攻击者借助 Aviator 表达式执行链调用 Groovy，进而启动操作系统进程，命令以 JimuReport/JeecgBoot 服务进程权限执行（长亭复现验证：无需登录进入 PDF 导出流程，受控参数进入 Aviator 执行链并调用 Groovy，确认目标进程执行命令并写入文件）。

**核心利用链：**

```text
攻击者
  └─ 发现暴露的报表服务（/jmreport/** 或 /jeecg-boot/jmreport/**，Shiro 匿名放行）
      └─ 向 auto/export 导出接口发送携带以 "=" 开头的恶意参数请求
          └─ 参数被内部表达式引擎按 Excel 公式解析（底层具备 Groovy 脚本能力，未过滤）
              └─ Aviator 表达式执行 → 调用 Groovy 执行链
                  └─ 以服务进程权限执行任意系统命令（服务器沦陷/数据泄露/内网横向移动）
```

### 3.2 `CVE-2026-82222` — GiveWP 未认证 PHP 对象注入致远程代码执行

!!! danger "严重漏洞"
    影响 WordPress 捐赠插件 GiveWP（≤4.16.7.1，约 10 万站点）。未认证攻击者可绕过站点注册配置创建账号，将序列化对象（TCPDF POP 链）注入用户资料并借捐赠提交流程触发反序列化，最终以 `system()` 在 Web 服务器上执行任意命令；CVSS 3.1=10.0，研究者 Udin Chan 的 PoC 已公开。

#### 3.2.1 基本信息

| 字段 | 内容 |
| --- | --- |
| **CVE编号** | `CVE-2026-82222` |
| **CWE编号** | `CWE-502`（不可信数据反序列化，NVD 收录） |
| **漏洞名称** | GiveWP 未认证 PHP 对象注入（PHP Object Injection）致远程代码执行 |
| **漏洞类型** | 反序列化漏洞（Object Injection → RCE） |
| **风险等级** | 严重 |
| **CVSS评分** | 10.0（CVSS v3.1，NVD） |
| **CVSS向量** | `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H` |
| **EPSS评分** | 0.418%（2026-08-31 查询，百分位 0.35%） |
| **披露日期** | 2026-08-28（NVD publishedDate；Patchstack 同日披露） |

| **CISA KEV** | 否（截至 2026-09-01 快照） |

| **PoC状态** | 已公开（研究者本人及第三方多个仓库） |

| **信息可信度** | 高（NVD + Patchstack + 多个安全厂商分析交叉印证） |

#### 3.2.2 漏洞摘要

该漏洞位于 WordPress 捐赠/募款插件 [GiveWP](https://wordpress.org/plugins/give/)（Liquid Web / StellarWP 出品，全球约 10 万站点使用）。据 [Patchstack 公告](https://patchstack.com/articles/unauthenticated-php-object-injection-to-remote-code-execution-on-givewp/)与 [NVD 记录](https://nvd.nist.gov/vuln/detail/CVE-2026-82222)：GiveWP 在旧版捐赠流程中对捐赠人账号数据处理不当——注册捐赠人账号时不检查 WordPress 原生 `users_can_register` 配置（未开放注册的站点仍可创建账号），且将未经严格过滤的序列化数据（`last_name` 字段）存储进用户资料；当捐赠请求省略 `give_last` 字段时，`maybeSafeUnserialize`（`allowed_classes => false`）将对象字节原样写入会话，后续请求反序列化会话时不再有该保护，触发 TCPDF 库 `__destruct()` 的 POP 链，最终通过 `call_user_func_array('system', [cmd])` 执行任意 OS 命令。研究者 Udin Chan 通过 Patchstack 协调披露，[Security Affairs 08-31 报道](https://securityaffairs.com/198156/security/critical-givewp-flaw-lets-attackers-run-commands-on-wordpress-servers.html)指出该链可让未认证攻击者在服务器上执行命令。

> 该漏洞为"注册配置绕过 + 不安全反序列化 + 自带 POP 链（TCPDF gadget）"的组合：攻击者全程无需登录既有账号、无需用户交互，CVSS 10.0 属未认证远程代码执行。

#### 3.2.3 影响产品与版本

| 厂商 | 产品/组件 | 受影响版本 | 修复版本 | 部署形态 |
|---|---|---|---|---|
| Liquid Web / StellarWP | GiveWP（Donation Plugin and Fundraising Platform） | `≤ 4.16.7.1`（≤4.16.5.1 默认安装即可利用；4.16.6–4.16.7.1 需存在旧版捐赠表单） | `4.16.7.2`（2026-08-27 发布） | WordPress 插件（约 10 万站点） |

!!! warning "版本说明"
    版本范围以 [Patchstack 公告](https://patchstack.com/articles/unauthenticated-php-object-injection-to-remote-code-execution-on-givewp/)与 NVD 为准（"from n/a through 4.16.7.1"）。据[研究者 README](https://github.com/UdinChan/cve-2026-82222-poc)：≤4.16.5.1 的默认安装（存在已发布表单与启用网关）即可利用；4.16.6 至 4.16.7.1 需存在旧版（非 V3）表单。个别第三方仓库标注修复版为 4.16.8，与 Patchstack/NVD 的 4.16.7.2 不一致，以官方公告为准。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达启用 GiveWP 的 WordPress 站点（443/80） |
| 身份认证 | 无需 | 攻击者自行注册捐赠人账号（绕过 `users_can_register` 配置） |
| 用户交互 | 不需要 | 全程自动完成 |
| 特定配置 | 是 | 站点启用 GiveWP 且存在可达的捐赠表单（4.16.6+ 需旧版表单） |
| 利用复杂度 | 低 | 有公开 PoC 与 Docker 复现环境，无需认证 |

**技术原理：**

根因为**对用户可控数据的不安全反序列化**。GiveWP 将捐赠人 `last_name` 无严格清洗地存入用户资料；旧版捐赠流程（process-donation）在省略 `give_last` 字段时，从 usermeta 读取该值并经 `maybeSafeUnserialize`（`allowed_classes => false`）处理后写入会话——PHP 在序列化往返过程中会原样重放对象字节，使后续会话反序列化（无 `allowed_classes` 保护）得以实例化攻击者注入的类。GiveWP 自带 vendor 库（TCPDF、Symfony Session 组件、Give\TestData 工厂类）中存在可用 POP 链：`TCPDF::__destruct()` → `Symfony Session::getIterator()` → `Give\TestData\Factories\DonationFactory::__call()`（经 ProviderForwarder）→ `call_user_func_array('system', [cmd])`，命令输出随响应返回。

**核心利用链：**

```text
攻击者
  └─ 访问启用 GiveWP 的 WordPress 站点（公网可达）
      └─ POST give_action=user_register 注册捐赠人账号（不检查 users_can_register 配置，取得认证 Cookie）
          └─ 通过 /wp-admin/profile.php 将序列化 gadget（含 TCPDF POP 链）写入 last_name
              └─ 提交捐赠请求（action=give_process_donation，省略 give_last 字段）
                  └─ maybeSafeUnserialize 将对象字节原样写入 wp_give_sessions
                      └─ 携带同一 Cookie 的请求触发会话反序列化（无 allowed_classes 保护）
                          └─ TCPDF::__destruct() → Symfony Session::getIterator()
                              └─ Give\TestData ProviderForwarder::__call()
                                  └─ call_user_func_array('system', [cmd]) → 在 Web 服务器执行 OS 命令
```

#### 3.2.11 风险影响

漏洞成功利用后，可能导致：

- 在 Web 服务器上以 Web 进程权限远程执行任意系统命令；
- 获取 WordPress 站点完全控制权（可创建管理员账号）；
- 泄露捐赠人个人身份信息（姓名、邮箱、地址、支付信息等敏感数据）；
- 篡改捐赠页面、配置或业务数据；
- 植入 WebShell、后门或恶意程序；
- 以服务器为跳板横向移动至同环境其他业务系统；
- 站点被用于挂马、钓鱼或挖矿等恶意活动。

#### 3.2.13 修复与缓解措施

#### 官方修复

1. 将 GiveWP 插件升级至 `4.16.7.2` 或更高版本（[WordPress 插件页](https://wordpress.org/plugins/give/)）；
2. 升级前完成站点与数据库备份；
3. 在测试环境验证捐赠流程、表单与网关功能；
4. 升级后核验插件版本并重新执行漏洞检测；
5. 若无法确认是否已遭利用，建议排查新增用户、管理员账号、异常文件与计划任务。

#### 临时缓解

无法立即升级时，可采取：

- 若业务不依赖在线捐赠注册，关闭站点用户注册功能（降低攻击面，但无法完全阻断旧版表单利用）；
- 在 WAF 层拦截含 PHP 序列化对象特征（`O:`/`a:` 前缀）的 `last_name` 等参数；
- 监控 `give_action=user_register` 与 `give_process_donation` 的异常组合请求；
- 限制 wp-admin 目录的可达范围，加强日志审计与异常外联检测。

- 对受感染主机按反向隧道后门处置：断网隔离、排查隧道进程与持久化项。
