### 1.3 今日重点关注

1. **`CVE-2026-20079`：Cisco Secure Firewall Management Center Web 界面认证绕过（CVSS 3.1 = 10.0，未认证 → root，已入 KEV）**  
   Cisco 3 月 4 日发布、9 月 9 日更新为 v2.5 Final 的公告（`cisco-sa-onprem-fmc-authbypass-5JPp45V2`）显示：FMC 在启动时创建了一个**存在缺陷的系统进程**，未认证远程攻击者只需向 Web 管理界面发送特制 HTTP 请求即可绕过认证并执行脚本文件，最终取得底层操作系统 **root** 权限。**Cisco 明确表示无任何 workaround**，唯一处置路径为升级；CISA 于 09-09 收录 KEV，联邦机构修复截止 **2026-09-12**。互联网可达的 FMC 管理界面应视为高危暴露面，且厂商已提供失陷排查特征（见 3.1.9/3.1.10）。

2. **`CVE-2026-19490`：Citrix NetScaler ADC / NetScaler Gateway SAML HTTP-Redirect 认证绕过（CVSS 3.1 = 9.8，已入 KEV）**  
   漏洞位于 NetScaler 报文引擎 `nsppe` 的 SAML 处理路径：HTTP-Redirect 绑定在调用断言解析器时**未置严格标志**，且默认配置下「拒绝未签名断言」的判断分支被错误地指向接受路径，导致任意**无签名断言**被接受并据攻击者可控字段构造会话。当设备配置为 AAA 虚拟服务器或网关（SSL VPN / ICA Proxy / CVPN / RDP Proxy）时，未认证远程攻击者可伪造任意 NameID 的会话。Citrix 公告 `CTX696939`（2026-08-19）未提供 workaround；CISA 于 09-09 收录 KEV，截止 **2026-09-12**。GitHub 已有 12★ 公开 PoC（含无害化配置探测），详见 3.2.7。

3. **`CVE-2025-25249`：Fortinet FortiOS / FortiSwitchManager 堆缓冲区溢出（CVSS 3.1 = 9.8，在野已投递 PivotC2 远控）**  
   漏洞位于 `cw_acd` 守护进程，攻击者通过发送特制报文即可触发堆溢出并执行任意代码或命令；该 CVE 于 **2026-01-13** 由 NVD 收录（Fortinet 公告 `FG-IR-25-084`），但直到 **2026-09-09** 才因观测到在野利用（攻击者在失陷 FortiGate 设备上部署 **PivotC2** 远控木马）被 CISA 收录 KEV，修复截止 **2026-09-12**。这是一起典型的「**已披露近 8 个月、补丁早已发布、但大量设备未升级而被规模化利用**」的案例，详见 3.3。

4. **JumpServer 高危越权：低权限用户可读取他人及内部组件 AccessKey（`GHSA-6rp5-ff2m-qfrm`，CVSS 3.1 = 8.8，无 CVE）**  
   组合利用「通用过滤后端在特定查询条件下取反整个 queryset（连带抵消已施加的授权/归属约束）」与「序列化器可由客户端查询参数影响选择」两个缺陷，认证后的低权限用户可越权获取 AccessKey 记录，甚至包含其他用户与 JumpServer 内部组件的 **AccessKey secret**。受影响 `>=4.0.0,<4.10.19-lts`、`>=3.7.0,<3.10.23-lts`；已修复 `v4.10.19-lts`/`v3.10.23-lts`，临时缓解为 Nginx 拦截 `_rel` 参数。国内开源堡垒机部署面广、且 JumpServer 内 AccessKey 常关联受管主机与云凭据，建议按 P1 处置并**轮换可能泄露的 AccessKey**（详见 3.4）。

### 1.4 综合研判

本期窗口的风险结构与第 41 期（微软补丁日洪峰）显著不同，呈现「**少量、满分、未认证、边界设备、截止次日**」的四重叠加：三条最高分项分别指向防火墙集中管理平台（Cisco FMC，CVSS 10.0）、SSL VPN/应用交付网关（Citrix NetScaler，CVSS 3.1 9.8）、防火墙操作系统内核态守护进程（Fortinet `cw_acd`，CVSS 3.1 9.8），**全部为「未认证即可触发」并已被 CISA 确认在野利用**——这意味着攻击者不是在研究理论可行性，而是在按部就班地扫、打、占。更值得警惕的是三者的时间线特征：`CVE-2026-20079` 与 `CVE-2025-25249` 分别于 **2026-03-04** 与 **2026-01-13** 即已披露并发布补丁，却分别在半年与八个月后才被观测到规模化利用——这不是「零日威胁」，而是**存量未升级资产被收割**，其直接含义是：即使本期不做任何新漏洞响应，也必须先清点并升级网络边界上的 FMC / NetScaler / FortiOS 存量版本，否则补丁永远「来得及但没用上」。第二条风险线是开源堡垒机 JumpServer 的 AccessKey 越权：它不涉及系统沦陷却直接产出高价值长期凭据（AK secret），且堡垒机往往本身就是运维链路的汇聚点，一旦被用于横向，等于把「运维专用通道」变成攻击者通道，因此在无 CVE、无公开 PoC 的情况下仍建议按 P1 主动排查而非等待外部压力。第三条是持续跟踪项：MikroTik RouterOS 的 `CVE-2026-86060`/`CVE-2026-67277` 于 09-10 正式入 KEV（截止 09-13），说明第 38 期「MikroTrick」批次的处置时限被官方进一步收紧；N-able N-central `CVE-2026-86218`（CVSS v4.0 10.0，认证前 RCE）与 Adobe Commerce/Magento「StyleSmuggler」`CVE-2026-75650`（CVSS 3.1 10.0）的 KEV 截止日均为 **2026-09-11（即今日）**，须在本文发布后立即确认闭环状态。事件层面，Proofpoint 披露的 **BlueMoon** 漏洞利用套件（串接 `CVE-2026-85046` Chrome V8 类型混淆 + V8 沙箱逃逸 + `CVE-2026-85880` Windows ALPC 提权）在 **12 天内被 4 个国家级 APT 组织复用**，且存在 AI 辅助开发的明显痕迹（含交接用 markdown 文档、诊断日志、默认 `curl` 落地执行），提示「补丁已公开但未进入稳定版」的 **patch-gap 窗口**正在被国家级行为体系统化武器化——对浏览器与终端的升级节奏提出了比「跟厂商补丁日」更高的要求。综合判断本期整体风险为**较高风险**，处置重心为「三条 KEV 在野线（Cisco FMC / Citrix NetScaler / Fortinet）在 09-12 前强制闭环 + 边界存量资产版本清点 + JumpServer 凭据轮换与 `_rel` 拦截 + 今日到期的两条 KEV 延续项销项确认」。

!!! danger "研判结论：较高风险"
    本期最主要风险点是 **09-09 单批入 KEV 的三条边界设备在野漏洞**——`CVE-2026-20079`（Cisco Secure FMC，CVSS 10.0，无 workaround，未认证即得 root）、`CVE-2026-19490`（Citrix NetScaler ADC/Gateway，SAML 无签名断言伪造会话）、`CVE-2025-25249`（Fortinet FortiOS/FortiSwitchManager，`cw_acd` 堆溢出，在野投放 PivotC2），**联邦机构修复截止均为 2026-09-12**，使用单位须在 24 小时内完成「版本清点 → 升级 → 管理面收敛 → 失陷特征排查」闭环，**不得等待在野证据或 PoC 成熟**；其中 Cisco FMC 无任何缓解措施，若无法立即升级必须将其管理界面从互联网与不可信网络完全隔离。同期须确认 `CVE-2026-86218`（N-able N-central）与 `CVE-2026-75650`（Adobe Commerce/Magento）的 KEV 截止日 **2026-09-11（今日）** 闭环状态，并核查 MikroTik RouterOS `CVE-2026-86060`/`CVE-2026-67277`（KEV 截止 **09-13**，修复版本 6.49.21 / 7.23.4+ / 7.24.2+）。JumpServer 用户按 P1 处理：升级至 `v4.10.19-lts`/`v3.10.23-lts`、Nginx 层拦截 `_rel`、轮换可能暴露的 AccessKey，并对堡垒机 API 访问日志做越权查询审计。

#### 3.1.2 漏洞摘要

该漏洞位于 Cisco Secure Firewall Management Center (FMC) 的 **Web 管理界面**。FMC 是思科防火墙体系的集中管理平台，用来统一配置、监控多台物理/虚拟防火墙与 FTD 设备，涵盖入侵防御、应用控制、URL 过滤与高级恶意软件防护策略；它通常部署在管理网段，但相当数量的部署将其管理界面直接暴露在互联网或不可信网络中。漏洞根因是设备**启动时创建的一个不当系统进程**：该进程在正常认证流程之外形成了一条可被外部触发的替代执行路径（CWE-288 的「替代路径或通道」语义）。未认证的远程攻击者向 Web 界面发送**特制 HTTP 请求**即可绕过认证，进而执行设备上的一系列脚本文件与命令，最终取得底层操作系统的 root 权限——这意味着攻击者拿到的不只是防火墙策略的配置权，而是**设备操作系统本身**。由于 FMC 保存着全网防火墙策略、设备凭据与访问控制数据，root 沦陷通常等同于整个防火墙管理域的失控。Cisco 在公告中特别提示：若 FMC 管理接口不具备公网访问能力，攻击面会显著降低——这也反向说明了当前 KEV 限期整改针对的正是「管理面暴露」的部署。同批公告还包含 `CVE-2026-20131`（Java 字节流反序列化导致的 RCE，同样可提权至 root），两枚漏洞共同构成 CrackMe。

> 需强调：CVE-2026-20079 的利用**无需任何凭据、无需用户交互**（`PR:N/UI:N`），且 CVSS 的范围指标为 `S:C`（Changed），即漏洞影响可越出受影响组件本身——这与「拿到管理台权限」有本质区别，处置时应按「设备可能已被完全控制」的高标准排查。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需能访问 FMC 的 Web 管理界面（默认 HTTPS 443；管理网段或暴露面） |
| 身份认证 | 无需 | `PR:N`，完全未认证即可触发 |
| 用户交互 | 不需要 | `UI:N` |
| 特定配置 | 否 | 公告称「无论设备配置如何」均受影响（regardless of device configuration） |
| 利用复杂度 | 低 | `AC:L`；公开信息显示利用形态为特制 HTTP 请求，无复杂前置条件 |

**技术原理：**

Cisco 公告的根因表述为「an improper system process that is created at boot time」（设备启动时创建的一个不当系统进程）。结合 CWE-288 的「替代路径或通道」定性与第三方技术文章的描述，可理解为：设备在启动阶段会创建一个具有特权、但缺乏完整认证绑定的系统进程（第三方文章将其描述为「持久化的部分会话」，与 `csm_processes` / `sfsnort.sessions` 等进程/会话对象相关），攻击者通过精心构造的 HTTP 请求即可**命中这条替代通道**，把该特权上下文「升级」为一个可用的已认证会话，从而绕过 Web 界面的认证检查。由于该进程由 root 或等权身份启动，绕过认证后可直接调用设备上的脚本与命令，进而获得 root。

**核心利用链：**

```text
攻击者
  └─ 定位互联网/管理网可达的 FMC Web 管理界面（HTTPS 443）
      └─ 构造特制 HTTP 请求（利用替代路径/通道）
          └─ 命中设备启动时创建的不当系统进程 / 部分会话
              └─ 绕过 FMC Web 认证（未提供任何有效凭据）
                  └─ 以 root 级上下文执行脚本文件与命令
                      └─ 完全控制 FMC 及其管理的防火墙域（策略、凭据、审计）
```

#### 3.2.2 漏洞摘要

该漏洞位于 NetScaler 的报文引擎 `nsppe`。两步缺陷叠加导致绕过：**其一**，SAML 响应解析器（PoC 分析中的 `sub_b40a50`）在所有调用点都应携带「严格」标志，浏览器实际使用的 **POST 绑定**路径正确置位了该标志，而 **HTTP-Redirect 绑定**路径未置位——这正是 CWE-288 意义上的「替代通道」：同一个请求面（`GET /cgi/samlauth`）存在更弱的解析入口，任何能发送带 `SAMLResponse` 查询参数 GET 请求的人都能到达。**其二**，当请求不携带 `SigAlg`/`Signature` 时，处理逻辑对「拒绝未签名断言」配置字的比较分支判断错误：配置值 `2`（`rejectUnsignedAssertion ON`，即默认值）被 `je` 指令跳转到**接受**路径，只有 `STRICT`（值 `3`）才会进入拒绝日志分支。于是**默认配置**设备上，未签名断言经 Redirect 绑定被「宽松解析 + 误放行」，随后照常执行 issuer / audience / subject 校验（比对 SAML action 配置）并**完全依据攻击者提供的字段构造会话**——整条路径上没有任何摘要校验或 RSA 验签。最终效果：攻击者只需构造一个不含 `<ds:Signature>` 的 SAML Response，即可以任意 NameID 伪造一个有效网关会话；POST 绑定不受同样影响（其向解析器传递了严格标志并正确拒绝未签名输入）。前置条件为设备已配置绑定到 Gateway 或 AAA vserver 的 SAML action（常规 SAML SSO 配置，多数 SAML 部署均满足）。

> 该漏洞与 2023 年 `CVE-2023-4966`（CitrixBleed，同属 `nsppe` 内存处理缺陷）、2026 年 `CVE-2026-3055`（越界读取）同源性问题族，提示 NetScaler 的 SAML/认证解析代码长期是高风险区域，边界网关的 SAML 路径应作为常态化审计对象。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可访问网关的 `GET /cgi/samlauth`（SAML 认证端点，通常即 443 上的 SSL VPN/AAA 入口） |
| 身份认证 | 无需 | 未认证远程攻击者即可触发 |
| 用户交互 | 不需要 | 单次 GET 请求完成 |
| 特定配置 | 是 | 设备需配置 SAML action 并绑定到 Gateway 或 AAA vserver（14.1-43.56 / 13.1-61.28 之后的构建需绑定；更早构建仅需 vserver）；默认配置即满足「未签名断言被误放行」缺陷 |
| 利用复杂度 | 低 | 无需签名、无需凭据；事务型部署需提供一个有效 AuthnRequest 的 `InResponseTo`（可由网关自身预认证跳转获取） |

**技术原理：**

```text
请求 GET /cgi/samlauth?SAMLResponse=<...>
  ├─ 路由进入 HTTP-Redirect 绑定处理函数
  │    ├─ [缺陷 1] 解析器严格标志未置位（r8d=0x0）→ 宽松解析攻击者提供的 XML
  │    └─ [缺陷 2] 无 SigAlg/Signature 时，配置字 0x2（拒绝未签名=ON）
  │         └─ je 跳转至「接受」路径（仅 0x3 STRICT 才拒绝）
  ├─ 传入后续 post-parse 校验：Issuer / Audience / Recipient / InResponseTo
  │    └─ 全部与目标 SAML action 配置比对（攻击者可经 --mint 从预认证跳转中读取）
  └─ 依据攻击者可控字段构造会话 → 下发 NSC_AAAC / NSC_TASS cookie（伪装为任意 NameID）
```

**核心利用链：**

```text
攻击者
  └─ 发现暴露的 NetScaler 网关 SAML 端点（GET /cgi/samlauth）
      └─ 构造不含 <ds:Signature> 的 SAML Response（DEFLATE + Base64）
          └─ 经 HTTP-Redirect 绑定提交（宽松解析 + 未签名断言被误放行）
              └─ 篡改 Issuer/Audience/Subject/NameID 等字段绕过身份校验
                  └─ 服务端构造会话并下发 NSC_AAAC/NSC_TASS cookie
                      └─ 未授权访问 SSL VPN / ICA / RDP 等受保护资源
```

#### 资产排查

- [ ] 是否部署 NetScaler ADC / NetScaler Gateway（含 FIPS/NDcPP 版本）

- [ ] 同批 `CVE-2026-19489` 是否一并闭环

#### 日志与行为排查

重点检查：

- SAML 相关的 `nsppe` 日志（含未签名断言与拒绝/放行记录）；
- 认证成功但 `NameID` 异常（外部域名、不存在账号、与 IdP 记录不符）的会话；
- 单一源 IP 短时间内多次 `GET /cgi/samlauth` 探测请求；
- 会话建立后紧跟非常规资源的访问（VPN 内网横向、RDP/ICA 会话骤增）；
- 与 IdP 侧登录日志的**对账差异**（网关侧有成功认证、IdP 侧无对应认证事件是最强信号）。

| 检测项 | 可疑特征 |
| --- | --- |
| 请求路径 | `/cgi/samlauth`（SAML HTTP-Redirect 绑定路径） |
| 请求方法 | `GET`（带 `SAMLResponse` 查询参数） |
| 参数特征 | 缺失 `SigAlg`/`Signature` 的 `SAMLResponse`；超长/异常 Base64 编码 |
| User-Agent | 脚本类 UA、`python-requests` 等非浏览器特征 |
| 响应状态 | `302` 跳转至 `/vpn/` 并下发真实 `NSC_AAAC`/`NSC_TASS`（非删除标记 `xyz`） |
| 进程行为 | `nsppe` 处理异常断言并构造会话，无异常子进程 |
| 文件行为 | 无典型落盘行为（会话伪造型漏洞） |
| 网络行为 | 与 IdP 无交互却出现成功认证（绕过 IdP 的本地会话化） |

**关键检测线索（来自公开 PoC 的根因分析）：** NetScaler 在拒绝未签名断言时会输出日志
`SAMLIDP: Redirect Binding: Unsigned Assertion seen, denying as per action %s`；
若出现该字符串但**随后仍建立会话**，与默认配置的误放行行为不符，需重点核查；反之，配置为 `STRICT` 的设备应仅见该拒绝日志而不会话。

#### 3.2.11 风险影响

漏洞成功利用后，可能导致：

- 未经授权访问受保护的门户、VPN 与内部应用（以任意 NameID 伪造会话）；
- 获取与合法用户等价的会话凭据（`NSC_AAAC`/`NSC_TASS`），在 cookie 生命周期内长期有效；
- 绕过单点登录与多因素认证的边界控制，直达内网资源；
- 泄露账号、密钥、配置文件及业务数据；
- 以伪造身份横向移动至内网其他服务器与业务系统；
- 篡改配置或业务数据（若伪造身份具备写权限）；
- 中断业务服务或破坏系统可用性（结合同批 `CVE-2026-19489` 等）；
- 被当作初始访问跳板，衔接后续勒索软件或数据窃取行动。

#### 3.2.13 修复与缓解措施

#### 官方修复

1. 将 NetScaler ADC / NetScaler Gateway 升级至 `14.1-73.32` 或 `13.1-63.21`（或对应 FIPS/NDcPP 修复版本）及更高版本；

#### 临时缓解

- 在升级前限制网关入口来源（如仅允许必要地理区域/网络段访问 `443`）；
- 在 WAF/IPS 增加针对「`/cgi/samlauth` 且缺少 `SigAlg`/`Signature`」的拦截规则（见 3.2.10）；
- 对 SAML 配置实施最少化：非必要的 AAA vserver / Gateway 角色与 SAML action 予以禁用；
- 缩短网关会话有效期并强制重新认证；
- 加强 SAML 日志采集与 IdP 侧认证事件对账告警；
- 对已暴露且无法立即升级的实例，实施网络隔离或临时下线（**优先于**继续暴露运行）。

#### 3.3.2 漏洞摘要

该漏洞位于 Fortinet FortiOS 与 FortiSwitchManager 的 **`cw_acd` 守护进程**中，属堆缓冲区溢出（CWE-122：堆缓冲区溢出 / CWE-787：越界写）。攻击者无需凭据，仅需向受影响设备发送**特制报文**即可触发溢出，进而在设备上执行未授权代码或命令。`cw_acd` 与 FortiGate 的无线控制器/接入点管理相关功能有关（Cisco/Fortinet 生态中该守护进程常与无线及接入控制管理面绑定），其在网络栈上接收报文并解析，一旦受到畸形输入即可越界写破坏堆结构，典型后果是以该守护进程的权限（在 FortiOS 中通常具备较高系统权限）执行任意代码。

CVE 编号中的年份为 2025，说明其披露发生在 2025 年 12 月至 2026 年 1 月间（NVD 收录于 2026-01-13），Fortinet 公告 `FG-IR-25-084` 亦发布于该期间。关键事实是：**该漏洞的补丁在披露时即已提供**，而直到 2026 年 9 月才因在野规模化利用被 CISA 收录 KEV——在野活动包括在失陷的 FortiGate 设备上部署 **PivotC2** 远程访问木马，说明攻击者将其用于**边界设备的持久化立足**：先借该漏洞取得执行权限，再投放远控用于后续横向与数据窃取。这类「老 CVE + 新型远控」的组合是当前边界设备攻击的典型模式，也解释了 KEV 收录的直接触发因素（网络防御机构观测到具体攻击活动，而非漏洞本身新披露）。

#### 3.3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需能向受影响设备发送特制报文（通常为管理/控制面服务端口，视 `cw_acd` 绑定接口而定） |
| 身份认证 | 无需 | NVD CVSS `PR:N`，未认证远程利用 |
| 用户交互 | 不需要 | `UI:N` |
| 特定配置 | 待确认 | 取决于 `cw_acd` 相关功能是否启用/暴露；以厂商公告与自身环境为准 |
| 利用复杂度 | 低 | `AC:L`（NVD 评分），无公开利用细节披露 |

**技术原理：**

`cw_acd` 守护进程在接收并解析网络报文时，未对输入长度或结构做充分校验，导致构造的畸形报文可**越界写入堆内存**（CWE-122 / CWE-787）。堆上的相邻元数据或对象指针被覆盖后，攻击者可通过典型的堆利用手法获得受控写入/控制流劫持能力，进而在设备上执行任意代码或命令。由于该进程在 FortiOS 中具备较高权限，成功利用后攻击者可获得对边界设备的实质性控制；在野活动中攻击者进一步投放 **PivotC2** 远控木马以实现持久化与后续操作。

**核心利用链：**

```text
攻击者
  └─ 定位互联网暴露的 FortiGate / FortiSwitchManager 管理面
      └─ 向 cw_acd 守护进程发送特制报文（超长/畸形结构）
          └─ 触发堆缓冲区溢出（越界写）
              └─ 破坏堆元数据 / 劫持控制流
                  └─ 以守护进程权限执行任意代码或命令
                      └─ 在野活动：落地 PivotC2 远控，建立持久化与横向通道
```

#### 3.3.11 风险影响

漏洞成功利用后，可能导致：

- 未经授权在边界设备上执行代码或命令；
- 远程执行任意系统命令并取得设备控制权；
- 获取设备配置、VPN 凭据、策略与日志；
- 在设备上植入远控（如 PivotC2）并建立持久化；
- 篡改防火墙策略、开放访问通道，为后续攻击铺路；
- 以边界设备为跳板横向移动至内网服务器与业务系统；
- 泄露账号、密钥、配置文件及业务数据；
- 中断业务服务或破坏网络可用性（堡垒/网关失控可直接导致断网）；
- 被勒索软件或僵尸网络进一步利用。

#### 3.3.13 修复与缓解措施

#### 官方修复

1. 将 FortiOS / FortiSwitchManager / FortiSASE 升级至 Fortinet 公告 `FG-IR-25-084` 所列修复版本（具体版本号以厂商公告为准）；
2. **优先处置 FortiOS 6.4 全版本**（受影响的完整版本线，且已处于生命周期末端）；
3. 升级前备份配置（`execute backup config`）与证书、VPN 配置；
4. 在测试环境验证兼容性及回退方案（顺序建议：先边缘非核心设备，再核心设备）；
5. 升级后核验版本、策略与 VPN 连通性；
6. 重新执行漏洞检测与失陷排查并留存证据。

#### 临时缓解

无法立即升级时，可采取：

- 限制 FortiGate 管理界面与相关服务端口的互联网访问（仅允许可信 IP）；
- 关闭或禁用不必要的 `cw_acd` 关联功能与暴露接口；
- 在边界防火墙/WAF/IPS 增加针对性拦截规则（结合 3.3.10）；
- 启用强认证与多因素认证，限制管理员来源；
- 修改默认账号与默认密码，最小化管理员权限；
- 集中收集设备日志并重点监控异常外联与持久化变更；
- 对高风险设备实施网络隔离或临时下线；
- **按「已失陷」假设处置**：对暴露过互联网的设备执行配置审计、账户清理、凭据轮换与远控排查。

### 3.4 JumpServer AccessKey 越权泄露（`GHSA-6rp5-ff2m-qfrm`，无 CVE）— 低权限用户可读取他人及内部组件 AccessKey

!!! danger "高危漏洞（CVSS 3.1 = 8.8，厂商未分配 CVE，受影响版本为 4.x/3.x 两个 LTS 线，已有官方修复与临时缓解）"

#### 3.4.2 漏洞摘要

JumpServer 是国内使用极广的开源堡垒机（4A 运维审计系统）。本次披露的越权问题由两个独立缺陷叠加而成：

**其一，通用过滤后端的 queryset 取反语义错误。** JumpServer 此前对公共 API 列表视图统一套用了一个通用过滤后端。在特定查询条件下，该后端会**取反整个 queryset 条件，而不是仅取反客户端提交的过滤表达式**——这意味着调用方原本无权看到的数据，会被「反向筛选」出来，而已施加在 queryset 上的授权/归属（ownership）约束也会一并被削弱或绕过。

**其二，序列化器选择可被客户端影响。** API 请求所使用的序列化器本应由服务端的视图动作（action）决定，但实现中该选择可被**客户端可控的查询参数**影响，导致某个 API 请求使用了本应用于其他操作的序列化器，从而在列表响应中暴露出正常情况下不会返回的字段（典型即 AccessKey 的 secret 字段）。

两者组合后，**任何一个已认证的低权限用户**都可以通过构造带特定查询参数的 API 请求，越权读取不属于自己的 AccessKey 记录；公告明确说明「在某些情况下，返回的数据可能包含属于其他用户或 JumpServer 内部组件的 AccessKey secrets」。由于 AccessKey 在 JumpServer 中用于 API 认证且可能长期有效，若泄露的 AccessKey 关联的是更高权限账户或内部组件，攻击者即可**以该凭据的权限调用 JumpServer API**——从「低权限登录用户」升级为「高权限 API 调用者」，进而可能触达受管资产信息与其他资源。公告建议：若怀疑发生暴露，应**轮换受影响的 AccessKey**。

> 该漏洞的价值不在系统沦陷，而在**凭据**：堡垒机是运维链路的汇聚点，其 AccessKey 往往直接或间接关联受管主机与云环境，因此「只读式越权」在实战中常被用作用户接管与横向移动的前置步骤。

#### 3.4.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可访问 JumpServer 的 API 接口（Web/API 通常经 80/443 或自定端口） |
| 身份认证 | 普通用户 | 需要有效的低权限账户（`PR:L`），无需管理员权限 |
| 用户交互 | 不需要 | `UI:N` |
| 特定配置 | 否 | 默认 API 逻辑即受影响（涉及通用过滤后端与序列化器选择） |
| 利用复杂度 | 低 | `AC:L`，构造带特定查询参数（含 `_rel`）的 API 请求即可 |

**技术原理：**

```text
低权限已认证用户
  └─ 构造带 _rel 过滤参数的 API 列表请求
      └─ 通用过滤后端取反【整个 queryset 条件】（而非仅取反客户端表达式）
          └─ 连同已施加的授权/归属约束一并被抵消（Broken Access Control）
              └─ 叠加【客户端可控的序列化器选择】
                  └─ 请求使用了面向其他操作的序列化器
                      └─ 列表响应中出现了本不应返回的字段
                          └─ 得到他人/内部组件的 AccessKey（含 secret）
                              └─ 以该 AccessKey 的权限调用 JumpServer API（权限提升）
```

**核心利用链：**

```text
攻击者（低权限账户）
  └─ 登录 JumpServer → 获取有效会话/Token
      └─ 构造越权查询（_rel 条件取反 + 序列化器参数）
          └─ API 返回超出授权范围的 AccessKey 记录（含 secret）
              └─ 使用窃得的 AccessKey 调用 JumpServer API
                  └─ 以其关联权限访问受管资产信息与内部资源
                      └─ 结合堡垒机角色横向移动 / 接管运维通道
```

#### 3.4.11 风险影响

漏洞成功利用后，可能导致：

- 未经授权访问他人及内部组件的 AccessKey（含 secret）；
- 以被窃 AccessKey 的权限调用 JumpServer API，实现权限提升；
- 泄露受管资产清单、系统用户、凭据等运维核心信息；
- 篡改配置或业务数据（若窃得 AK 具备写权限）；
- 以堡垒机为跳板访问受管主机，横向移动至生产系统；
- 关闭或削弱运维审计能力（堡垒机本身即审计中枢）；
- 长期隐蔽访问（AccessKey 通常为长期有效凭据，被窃后不易察觉）；
- 中断业务服务或破坏系统可用性（越权管理操作风险）。

| 已确认在野利用 | 否（未确认） |
| 已纳入CISA KEV | 否（无 CVE，不适用） |
| 影响核心业务 | 是（堡垒机为运维与审计枢纽） |
| 涉及敏感数据 | 是（AccessKey secret、受管资产与凭据信息） |

!!! danger "综合处置优先级：P1"
    - **P0：紧急处置**，已在野利用或可直接影响核心互联网资产；
    - **P1：24小时内处置**，PoC公开且利用门槛较低；
    - **P2：3个工作日内处置**，利用条件受限或暂无成熟PoC；
    - **P3：常规整改**，风险较低或仅影响非关键场景。

    判定依据：利用门槛低（仅需低权限账户、单请求即可越权读取凭据）、泄露物为**长期有效凭据**且后果可级联放大，虽暂无公开 PoC 与在野确认，仍按 **P1（24 小时内）** 处置——先行 Nginx 拦截 `_rel`（即日生效），随后在维护窗口完成版本升级与 AccessKey 轮换。

#### 3.4.13 修复与缓解措施

#### 官方修复

1. 将 JumpServer 升级至 `v4.10.19-lts` 或 `v3.10.23-lts` 及更高版本（按自身所在 LTS 线选择，**两条线均需闭环**）；
2. 该修复包含两项变更：移除公共 API 视图中的通用 `_rel=or/not` queryset 操作后端；移除由客户端控制的序列化器 action 选择（改由服务端视图 action 决定）；对应 PR：Fix #17295；
3. 升级前备份配置、数据库与必要运行数据，并确认回退方案；
4. 在测试环境验证 API 行为与业务功能（特别是依赖查询参数过滤的功能）；
5. 升级后核验版本与 API 权限边界；
6. **轮换在受影响期间可能暴露的 AccessKey**（含内部组件 AK），并复核其权限范围；
7. 重新执行越权检测与日志审计并留存证据。

#### 临时缓解

无法立即升级时，可采取（**按官方建议顺序**）：

- **在 Nginx 层拦截携带 `_rel` 参数的请求**（返回 400），即官方给出的已知利用路径缓解（配置见 3.4.7；注意可能影响依赖该参数的功能，属临时措施）；
- 限制 JumpServer API 访问来源（仅可信网络/堡垒自访），对公网暴露实例优先收敛；
- 监控 API 中异常的过滤参数与序列化器相关查询参数；
- 若怀疑发生未授权访问，**立即轮换相关的用户与内部组件 AccessKey**；
- 收紧账户权限，最小化「可登录普通用户」数量并复核其 API 权限；
- 加强堡垒机操作审计与 API 调用审计的集中采集与告警。

### 4.5 事件动态：BlueMoon Chrome + Windows 漏洞利用套件在 12 天内被 4 个国家级 APT 组织复用

| 字段 | 内容 |
| --- | --- |
| 事件类型 | 高级威胁（APT）武器化与共享 |
| 关联漏洞 | `CVE-2026-85046`（Chrome V8 类型混淆，patch-gap 0day）、V8 沙箱逃逸（Chrome 未分配 CVE）、`CVE-2026-85880`（Windows ALPC 提权） |
| 时间线 | 首次观测 2026-08-28；12 天内扩散至 4 个国家级/间谍动机组织 |
| 披露方 | Proofpoint（Google Threat Intelligence Group、Microsoft MSTIC、Volexity 参与调查） |
| 来源 | [Security Affairs（2026-09-10）](https://securityaffairs.com/198783/apt/four-nation-state-actors-used-the-same-chrome-zero-day-exploit-kit-within-12-days.html) |

**事件描述：** Proofpoint 发布分析报告《BlueMoon》——一套串接 **Chrome 浏览器与 Microsoft Windows** 多个漏洞的利用套件：先用 `CVE-2026-85046`（Chrome V8 类型混淆，滥用 TurboFan JIT 优化缺陷，通过排序过程中篡改数组获得任意读写原语）突破渲染进程，再以**未分配 CVE 的 V8 沙箱逃逸**用攻击者 shellcode 覆写 WebAssembly 编译函数体，最后以 `CVE-2026-85880`（Windows ALPC 本地提权，第 41 期详录的 9 月补丁日 0day）完成从沙箱渲染进程到可注入 Chrome 父进程、执行任意命令的完整链。首个观察到的使用集群是**中国关联的 TA412**（亦称 JungleBamboo / Violet Typhoon / APT31 / TIDE CASTLE），首次观测时间为 **2026-08-28**；随后数日内多个间谍动机集群相继使用，多数疑与中国有关，但部分使用未归属，套件可能不限于中国关联行为体。

**两个值得防御方重点关注的结论：**
1. **「patch-gap」零日被武器化。** `CVE-2026-85046` 的修复于 **2026-08-07** 提交至 Chromium 源码树，但直到 **2026-09-03** 才随稳定版 Chrome 发布——近四周的窗口期内，公开可见的补丁本身就是一份「说明哪里有缺陷」的公开文档，Proofpoint 判断套件开发者很可能**直接利用公开补丁武器化**。这推翻了「升级到最新稳定版即安全」的默认假设：**补丁公开与稳定版落地之间的窗口，是国家级行为体的黄金作战期**。
2. **明显的 AI 辅助开发痕迹与粗糙的默认配置。** 套件含大量诊断日志、一份交接用 markdown 文档（`docs/v8-ctf-chrome-stage4-handover.md`，可用于在 AI 代理会话间传递上下文）、详尽的调试迭代注释，并反复引用 Google 的 V8CTF 漏洞赏金计划；默认后利用步骤仅是一条 `curl` 下载并执行可执行文件到 `%TEMP%`（极易被终端安全产品发现）。Proofpoint 指出这些特征「与 AI 辅助开发一致」，但无法确证。

**防御建议：**
- 浏览器升级节奏不应止于「跟随稳定版」：对高风险用户（涉密、管理、研发）应采用**更快的更新通道**或按内网灰度策略缩短版本滞后，并关注 Chromium 补丁公开（源码 commit）到稳定版发布之间的窗口；
- 终端检测重点覆盖「浏览器/文档沙箱进程逃逸 → 注入父进程 → `curl`/`certutil`/`bitsadmin` 落地执行」的链式行为（尤其 `%TEMP%` 下的可执行文件落地与执行）；
- 检查 EDR/Sysmon 对 `CVE-2026-85880`（ALPC）相关提权行为的检测覆盖，并确保 9 月 Windows 安全更新已在 **2026-09-22（KEV 截止）** 前完成；
- 结合本期 3.x 与 4.x 的边界设备项，按「AP T 优先打击边界与浏览器」的威胁模型，把浏览器、VPN/网关、防火墙管理面作为本轮加固的三个优先面。

## 五、当日处置建议

1. **对已在野利用、已纳入 CISA KEV 的漏洞立即开展资产排查并限期闭环**：本期三件边界设备项（`CVE-2026-20079` Cisco FMC、`CVE-2026-19490` Citrix NetScaler、`CVE-2025-25249` Fortinet）的 KEV 修复截止均为 **2026-09-12**，必须在 24 小时内完成版本清点与升级；Cisco FMC 无 workaround，无法升级时必须将管理面彻底隔离。
2. **今日到期的两条 KEV 延续项必须销项确认**：`CVE-2026-86218`（N-able N-central，截止 **2026-09-11**）升级至 `2026.3 Hotfix 4`、`CVE-2026-75650`（Adobe Commerce/Magento StyleSmuggler，截止 **2026-09-11**）按 `apsb26-146` 升级并**排查 Web Shell 与后门**（该漏洞自 09-04 起已被利用）；`CVE-2026-86060`/`CVE-2026-67277`（MikroTik RouterOS）KEV 截止 **2026-09-13**，按 `6.49.21 / 7.23.4 / 7.24.2` 升级。
3. **优先核查互联网暴露的 VPN、网关、安全设备、中间件和管理平台**：本期全部高风险项的落点都是「边界设备的未认证利用」，应优先清点 FMC、NetScaler、FortiGate、N-central、MikroTik 与 JumpServer 的互联网暴露情况，无业务必要时一律下线公网入口或收敛到可信网络。
4. **堡垒机凭据侧要当作独立风险线处理**：JumpServer 用户执行「Nginx 拦截 `_rel`（即日）→ 升级 `v4.10.19-lts`/`v3.10.23-lts` → **轮换 AccessKey**（含内部组件）→ 审计 API 调用来源」四步闭环，不能只打补丁不轮换凭据。
5. **无法立即升级的系统应采取断网、访问控制、接口禁用或 WAF 拦截措施**：本期 3.1.8/3.2.8/3.3.8 给出的检索语法仅作公开示例（未执行查询），内部处置应以 ACL、来源限制、功能禁用与 WAF 规则为主；**严禁使用测绘平台主动扫描互联网资产**。
6. **对疑似遭受攻击的系统保留日志、流量、进程、文件及内存证据**：Cisco 已给出 `zgrep "package_info.*license" /var/log/messages*` 的失陷排查特征（出现 `/var/tmp/license.tmp` 相关 root 调用即可能已失陷，须立即联系 Cisco TAC，且**热修复只防未来利用、不消除既有失陷**）；Fortinet 设备重点关注异常外联与 PivotC2 相关持久化。
7. **对发现异常的主机开展 WebShell、恶意进程、异常账号及横向移动排查**：Magento 站点、堡垒机与边界设备是本期最需要做「后门与凭据」排查的三类目标；越权类漏洞的受害证据往往只存在于 API 访问日志中，须做日志对账而非仅查文件。
8. **完成修复后进行复测，并更新资产台账和漏洞处置记录**：对边界设备升级后须验证 VPN/策略下发/管理面可用性，对越权类须验证权限边界（返回字段不再越权），并将处置证据与版本快照归档。
