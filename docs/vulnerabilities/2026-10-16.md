### 1.3 今日重点关注

1. **`CVE-2026-57155`：OPNsense GeoIP 导入链：路径穿越写 root 文件 → newsyslog 提权（9.9）**  
   `geoip.py` 的 `process_zip()`／`process_gzip()` 用**未校验的 CSV `country_code` 值**拼出 `/usr/local/share/GeoIP/alias` 下的输出文件名。具备 Firewall Alias Edit 权限的用户可配置攻击者控制的 GeoIP 源，上传一个 country_code 含穿越序列的压缩包，从而**以 root 身份把任意内容写入任意目录**；再结合精心构造的 `newsyslog` 片段与超大日志文件，即可完成提权。这是本期技术链条最完整的一条——**从“低权限配置项”一路走到“root 任意写”**，且 OPNsense 作为开源防火墙在中小企业与实验室广泛使用。

2. **`CVE-2026-101306`：FreeBSD SCM_RIGHTS 丢失 FD_RESOLVE_BENEATH 致 jail 逃逸（9.8）**  
   通过 `SCM_RIGHTS` 传递文件描述符时，**`FD_RESOLVE_BENEATH` 限制没有被保留**；进程可通过 Unix 域套接字把描述符发给自己即可清除该限制。收到来自另一 jail 的目录描述符后，进程可借此**突破 jail 的文件系统根限制**。FreeBSD jail 被大量用于多租户托管、网络设备固件与容器替代方案，逃逸意味着“租户 → 宿主机”的边界失效。官方公告 FreeBSD-SA-26:66.jail。

3. **`CVE-2026-98432`：Linux 内核 IPv4 选项释放时机缺陷致 UAF（9.8）**  
   `tcp_v4_syn_recv_sock()` 把 `ireq->ireq_opt` 的所有权转移给子 socket 时**未做拷贝**；另一 CPU 并发处理同一 request socket 的重传 SYN 时，`tcp_v4_send_synack()` 与 `inet_csk_route_req()` 仅在 `rcu_read_lock()` 下读取该指针，而 `ip_options_build()` 会**两次读取 `opt->optlen`**，导致 use-after-free。内核网络栈的 UAF 通常先表现为崩溃，但具备稳定触发条件后可转为提权或容器逃逸原语，**影响所有使用受影响内核版本的发行版与云主机**。

4. **`CVE-2026-93483`：Znuny/OTRS HTTPBasicAuth 信任请求头致任意用户冒充（9.5）**  
   Znuny 至 7.3.6 的 `Kernel::System::Auth::HTTPBasicAuth` 与 `CustomerAuth::HTTPBasicAuth` 模块**不仅从 `$ENV{REMOTE_USER}` 取用户名，还会读取其他来源**，导致攻击者通过操纵特定 HTTP 请求头即可冒充任意用户（含管理员），无需口令。与上一期 OTRS 的 `Remote-User` 头信任（`CVE-2026-93582`）几乎同源——**同一类“信任代理头但未校验来源”的错误在两个分支产品上重复出现**，说明这是该生态的系统性问题。

### 1.4 综合研判

本期 533 条，严重 41 条（7.7%）、高危 224 条（42.0%），无 10.0 条目，表面烈度下降，但**风险的位置更靠近底层**。第一组是**系统与虚拟化边界**：FreeBSD jail 逃逸（`CVE-2026-101306`）、Linux 内核 IPv4 UAF（`CVE-2026-98432`）、以及 QNAP 的 Qsirch 路径遍历（`CVE-2026-50619`，9.3）与 HybridDesk Station 命令注入（`CVE-2026-47786`，9.3）——NAS 类设备常被用作备份与文件共享节点，其上的“读取意外文件”往往意味着备份数据与凭据泄露。第二组是**自建基础设施的认证缺陷**：OPNsense 的 GeoIP 导入链（9.9）、Znuny 的头信任（9.5）、Better Auth 的 OAuth state 复用为 Magic Link 令牌（`CVE-2026-110862`，9.3，可造成“虚假邮箱已验证”账号）、Stela 的 Cookie 相关绕过（`CVE-2026-101287`，9.3）、EthereumAuthenticator 的未认证资源访问（`CVE-2026-19863`，9.3）。第三组是**Web 生态**：Wheels 框架的 SQL 注入（9.8）、AUTOM8N（cPanel 插件）命令注入（9.8，已有 PoC 仓库）、Wavlink 路由器系列（9.3×2）。KEV 侧新增 BeyondTrust Remote Support 与 Fortinet 历史编号各一条，期限 10-19；**BeyondTrust 属特权访问管理（PAM）产品，其被利用意味着攻击目标直指“凭据 vault”**，应给予高于其 CVSS 的关注。整体判断：本期没有“当天即被武器化”的条目，但对**内核、jail、防火墙、NAS、PAM**这五类“底层信任锚点”的处置优先级应高于同分的应用层漏洞。

#### 3.1.2 漏洞摘要

OPNsense（FreeBSD 基础的防火墙/路由平台）26.1.11 之前，Firewall Alias GeoIP 导入功能的 `process_zip()` 与 `process_gzip()` 路径（`src/opnsense/scripts/filter/lib/alias/geoip.py`）会**用 CSV 中的 `country_code` 值直接构造输出文件名**，写入 `/usr/local/share/GeoIP/alias` 目录，且未对该值做任何校验。具备 Firewall Alias Edit 权限的用户可以配置一个**攻击者控制的 GeoIP 源 URL**，上传一个 country_code 含路径穿越序列的压缩包，使攻击者控制的内容**以 root 权限写入其他已存在的目录**（文件名会被追加 `-IPv4` 或 `-IPv6` 后缀）。公告进一步说明，配合精心构造的 `newsyslog` 片段与超大日志文件，可实现提权到 root。该编号同时归入 `CWE-22`（路径遍历）、`CWE-73`（外部控制文件名或路径）、`CWE-78`（OS 命令注入），CVSS 9.9——是本窗口最高分，也是链条最完整的一条。**权限门槛看似较高（需要 Alias 编辑权限），但在实际运维中该权限常被授予网络管理员甚至自动化账号，且“配置 GeoIP 源”本身是一个看似无害的日常操作。** 另外，GitHub 上存在一个创建于 **2026-07-16** 的公开仓库（`babyshen/CVE-2026-57155`），创建时间早于官方披露约三个月——这在实践中通常意味着研究者先完成了复现再走披露流程，也提示该缺陷被独立发现的门槛并不高。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | OPNsense Web 管理面（需 Firewall Alias Edit 权限） |
| 身份认证 | 普通用户 | 需相应账号权限 |
| 用户交互 | 不需要 | 无需受害者交互 |
| 特定配置 | 是 | 需具备 Alias 编辑权限并可配置外部 GeoIP 源；默认安装即具备该功能 |
| 利用复杂度 | 低 | 中（需构造压缩包与后续提权链） |

**技术原理：**

正常情况下，GeoIP 导入流程是：下载压缩包 → 解压 → 按 country_code 生成 `xx-IPv4.txt` 之类的文件 → 供 pf 表引用。缺陷在于第三步直接把外部可控字符串拼进路径，未做“仅允许 ISO 国家码白名单”的约束。于是 `../../../../etc/` 一类的值即可把写入位置迁出目标目录。由于导入脚本由 root 执行（需要写 `/usr/local/share` 与重载 pf 表），攻击者获得的是“root 任意文件写”。**任意写之所以能变成代码执行**，是因为系统存在以 root 周期性读取的配置文件（此例为 `newsyslog` 片段）——写入一个规则让超大日志在轮转时执行动作，即完成提权。这是“低权限配置项 + root 写 + 周期性任务”三元组合的经典结构。

**核心利用链：**

```text
攻击者
  └─ 定位暴露的 目标组件（目标产品）
      └─ 构造含路径穿越序列的请求
          └─ 触发 CWE-22, CWE-73 对应处理逻辑
              └─ 读取/写入应用目录外的敏感文件
                  └─ 横向利用或持久化（视环境）
```

> 原文摘要（NVD）：SCM_RIGHTS file descriptor passing did not preserve FD_RESOLVE_BENEATH when a descriptor was transferred. `rcu_read_lock()` 只能保证“在读临界区内对象不被立即释放”，但**不能保证读取过程中对象内容不被其他路径修改或提前释放**。此处对象所有权已经转移给子 socket，母 request socket 仍可能被重传路径访问——这是所有权交接缺乏同步的典型问题。“两次读取 `optlen`”进一步扩大了竞态窗口：第一次读用于分配，第二次读用于拷贝，若两者之间对象被释放/复用，就出现长度与内容不一致的越界或 UAF 行为。

## 五、当日处置建议

1. **把“信任锚点”单独排队**：本期真正重要的是内核（Linux UAF）、隔离原语（FreeBSD jail）、防火墙（OPNsense）、NAS（QNAP）与 PAM（BeyondTrust）。这几类组件一旦被拿下，影响是“边界失效”而非“单点失守”，应按此顺序而非按 CVSS 分配资源。
2. **OPNsense 重点查两件事**：版本是否 ≥26.1.11，以及 Firewall Alias 编辑权限授给了谁。该漏洞门槛在“权限”，而权限往往被当成无害的日常运维能力。
3. **FreeBSD 环境验证隔离而非只看版本**：jail 逃逸类缺陷建议做一次实测（在 jail 内通过 SCM_RIGHTS 自传目录描述符后尝试访问上级路径），确认补丁真正生效。
4. **认证组件的两类模式检查**：一是“是否信任客户端可设置的头”（Znuny/OTRS 连续两期出现同类问题），二是“不同用途的令牌能否互换”（Better Auth 把 OAuth state 当 Magic Link 令牌用）。这两条可直接作为代码审计清单项。
5. **NAS 不当作存储设备而当作服务器管**：QNAP 同期出现路径遍历与命令注入，备份节点上通常存放着最完整的凭据与数据。建议限制管理面暴露、关闭不必要的应用（Qsirch、HybridDesk 若不用则卸载）。
6. **KEV 历史编号补录需回查台账**：`CVE-2025-61624`（Fortinet）是 2025 年编号在 2026 年才入 KEV。建议对台账中“两年以上未更新”的网络设备与安全产品做一次专项回查。
