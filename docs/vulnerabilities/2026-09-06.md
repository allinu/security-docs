### 1.3 今日重点关注

1. **QVD-2026-61751：JimuReport（积木报表）v2.5.1 未授权远程代码执行（CVSS 9.8）**  
   免登录导出接口 `/jmreport/auto/export/python/plugin` 的 X-Sign 签名使用硬编码固定密钥（`PRINT_PLUGIN_SIGN_SECRET`，随 jar 分发），攻击者可伪造任意有效签名完全绕过鉴权；导出链路将请求参数值（以 `=` 开头者）直接送入内嵌 Aviator 表达式引擎执行，并经沙箱逃逸实现任意 Java 反射调用，最终在无任何凭据下以应用权限执行任意命令。奇安信 CERT 09-05 已复现，PoC 与技术细节已公开；官方暂无修复版本，奇安信鹰图显示国内风险资产约 27 万个、关联 IP 约 1.77 万个。建议公网暴露实例立即处置（P0），升级 Aviator ≥5.4.4 并部署 WAF 拦截规则。

2. **`CVE-2026-59346` / `CVE-2026-59347`：VMware Workstation/Fusion 虚拟机逃逸双漏洞（VMSA-2026-0007）**  
   VMXNET3 虚拟网卡整数溢出（9.3，严重）与 HGFS 主机-客户机文件系统栈溢出（8.1，高危）：具备客户机内本地管理员权限的攻击者可利用该组缺陷在宿主机上执行代码（后者以 VMX 进程权限执行），官方称无任何缓解措施。影响 Workstation/Fusion 25H2 与 26H1 版本，修复版本 26H1u1。多租户/VDI/实验隔离环境须按 P1 尽快升级（详见 3.1/3.2）。

3. **`CVE-2026-19949`：WordPress All-in-One WP Migration and Backup 二阶 SQL 注入（CVSS 8.8）**  
   未认证攻击者可经 WordPress trackback 植入恶意数据，当管理员执行"恢复备份存档"（该插件核心常规操作）时触发二阶 SQL 注入，可经公开评论泄露插件导入密钥 `ai1wm_secret_key`，进而导入含可执行代码的恶意 `.wpress` 存档实现站点完全接管。影响 ≤7.109 全部版本（7.110 已于 08-20 修复）；插件安装量超 500 万，目前仅约 35% 更新，约 325 万站点仍受影响（详见 3.5）。

### 1.4 综合研判

本期窗口内无新确认在野利用事件、无新增 KEV 条目，但出现**"虚拟化边界逃逸（无缓解）+ 国产报表工具未授权 RCE（无补丁且暴露面巨大）+ 客户端组件堆溢出"**三类高影响事件，整体风险高于近期均值。QVD-2026-61751 是本期最需优先处置的条目：免认证 + PoC 公开 + 官方无补丁 + 国内资产量级达 27 万，符合"攻防不对称"典型场景——攻击者只需一条请求即可接管报表服务器，而防御侧只能靠 Aviator 依赖升级与 WAF 拦截过渡，建议公网暴露实例按 P0 在 24 小时内完成临时加固与暴露收敛，并持续跟踪官方发布版本。VMware 双漏洞的价值在于虚拟化信任边界：VM 逃逸类漏洞在公有云/VDI 环境属于高优先级（攻击者需先取得客户机内管理员权限，门槛中等），官方明确无 workaround，叠加历史同期多个 VMware 0day（如 2025 年 VMSA-2025-0004 Workstation 逃逸链）被在野利用的先例，建议虚拟化管理员按 P1 排期升级 26H1u1。FreeRDP 客户端漏洞提醒"出站远程桌面协议"同样是攻击面：恶意 RDP 服务端（社工/钓鱼/内网诱饵）即可触发客户端内存破坏，3.31.0 发布已逾一周，内嵌 FreeRDP 的发行版/瘦客户机需逐一核对版本。另两起"已修复但升级滞后"事件（WordPress 325 万站点、WHMCS 托管面板）反映**补丁发布 ≠ 补丁生效**的普遍困境，托管服务商尤其应优先核查 WHMCS 面板版本。PaperCut 校园攻击动态与 Rapid7 HAProxy 源码级后门披露则再次提示：打印管理、负载均衡等"边缘基础设施"正成为攻击者长期驻留与流量劫持的支点。

!!! danger "研判结论：一般风险（偏高）"
    今日无确认在野利用与新增 KEV，但存在一个"免认证 + PoC 公开 + 无补丁 + 巨量国内暴露"的 JimuReport RCE（P0，24 小时内完成公网暴露收敛与 Aviator ≥5.4.4 升级）与一组虚拟机逃逸漏洞（P1，本周内升级 26H1u1）。处置要求：①公网 JimuReport 实例立即执行 P0 加固并跟踪官方修复版本；②VMware Workstation/Fusion 25H2/26H1 用户本周内完成 26H1u1 升级（VDI/多租户环境优先）；③核查 FreeRDP ≤3.30.0 客户端及内嵌发行版并升级 3.31.0+；④WordPress All-in-One WP Migration 插件批量核验升级 ≥7.110；⑤WHMCS 面板尽快升级 8.13.8/9.0.8+；⑥上期延续的 Chrome `CVE-2026-85046`（KEV 截止 09-18）与 PaperCut 双 CVE（KEV 截止 09-14）继续 P0 闭环跟踪。

#### 3.1.2 漏洞摘要

该漏洞位于 VMware Workstation/Fusion 对 **VMXNET3 虚拟网卡**（VMware 为虚拟机提供的高性能半虚拟化网络适配器）的模拟处理中。VMXNET3 设备模型运行在宿主机侧的 VMX 进程中，负责在客户机与宿主机网络栈之间搬运数据包与描述符。当客户机内恶意代码（需本地管理员权限）构造特定长度的请求触发 VMXNET3 处理路径中的整数溢出时，长度计算绕过程序员的预期边界，导致越界内存访问，进而可能将客户机内的代码执行提升为**宿主机 VMX 进程上下文中的代码执行**——即虚拟机逃逸。

> Broadcom 公告对漏洞成因的描述为"integer-overflow vulnerability…A malicious actor with local administrative privileges on a virtual machine with VMXNET3 virtual network adapter may exploit this issue to execute code on the host"。具体溢出点、触发报文结构与利用原语官方未公开；VMX 进程在宿主机上以较高权限运行，一旦逃逸成功，攻击者可读取宿主机内存/文件、访问宿主机网络并横向移动。Workstation/Fusion 被广泛用于开发测试、恶意软件分析隔离、VDI 与个人多环境场景，该类产品的逃逸漏洞历史上有被在野利用的先例（如 2025 年 VMSA-2025-0004 Workstation 逃逸链）。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 否（直接利用） | 攻击者无需网络访问目标宿主机；攻击面位于客户机→宿主机设备模型交互路径 |
| 身份认证 | 需要 | 攻击者须先取得**客户机内本地管理员（root/Administrator）权限**（如攻陷客户机 OS、恶意软件运行于客户机） |
| 用户交互 | 不需要 | 纯客户机内代码触发 |
| 特定配置 | 是 | 客户机需配置 **VMXNET3 虚拟网卡**（VMware 默认推荐/常见配置之一） |
| 利用复杂度 | 中高 | 需客户机本地管理员 + VMXNET3 设备；整数溢出原语到宿主机代码执行的完整链官方未公开 |

**技术原理：**

VMXNET3 属于半虚拟化（paravirtualized）设备：客户机驱动与宿主机 VMX 进程通过共享内存描述符环（descriptor rings）交换收发队列元数据，绕过传统全虚拟化网卡的指令模拟开销。设备模拟代码在处理客户机提交的环描述符/长度字段时存在整数溢出缺陷——当某个长度/数量字段经算术运算后回绕为小于预期缓冲区大小的值时，后续拷贝/索引可越界。攻击者在客户机内（本地管理员权限）以驱动程序调用方式构造畸形描述符，即可在宿主机 VMX 进程地址空间制造越界读写原语，进而劫持执行流实现宿主机代码执行。具体触发字段与利用链细节官方未公开，本报告不作臆测。

**核心利用链（基于公告口径的概括性描述，非官方细节）：**

```text
攻击者（已取得客户机内本地管理员权限）
  └─ 客户机配置 VMXNET3 虚拟网卡
      └─ 构造畸形网卡描述符/长度字段（触发整数溢出）
          └─ VMXNET3 设备模型（宿主机 VMX 进程）越界内存访问
              └─ 获得宿主机进程上下文代码执行（虚拟机逃逸）
                  └─ （后续：读宿主机文件/内存、横向移动、攻击其他 VM）
```

> 以上为基于 Broadcom 公告文字与 VMXNET3 架构的概括性复述，非官方技术细节；严禁据此对任何系统实施验证。

#### 3.2.2 漏洞摘要

该漏洞位于 Workstation/Fusion 的 **HGFS（Host-Guest File System）组件**——用于实现"共享文件夹"功能：客户机经该通道读写宿主机指定目录（拖拽/共享目录/Unity 集成等均依赖此通道）。HGFS 请求由客户机侧驱动构造、宿主机侧 VMX 进程解析处理。当客户机内（本地管理员权限）攻击者提交特制的 HGFS 请求触发**基于栈的缓冲区溢出**时，可覆盖 VMX 进程栈上数据（返回地址/局部变量），最终以 **VMX 进程权限在宿主机上执行代码**。Broadcom 公告原文指出受影响的是 HGFS 组件的 stack-based buffer-overflow，攻击者利用后"execute code as the virtual machine's VMX process running on the host"。

> 与 3.1 的 VMXNET3 整数溢出相比，两者前置条件相同（客户机本地管理员）、目标相同（宿主机 VMX 进程），差异在组件与溢出类型；实际攻击者可任选其一或组合使用。HGFS 在默认开启"共享文件夹/拖拽"的客户机上攻击面较大；关闭共享文件夹可缩小暴露面（非官方 workaround，见 3.2.13）。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 否（直接利用） | 攻击面位于客户机→宿主机 HGFS 通道，无需网络 |
| 身份认证 | 需要 | 攻击者须先取得**客户机内本地管理员权限** |
| 用户交互 | 不需要 | 纯客户机内代码触发 |
| 特定配置 | 部分 | 漏洞存在于 HGFS 组件本身；开启"共享文件夹/拖拽"的客户机触发面更大（未开启时部分路径可能不可达，官方未细分） |
| 利用复杂度 | 中高 | 需客户机本地管理员；完整利用链官方未公开 |

**技术原理：**

HGFS 采用客户机/宿主机共享内存通道（backdoor 端口 + 共享内存）传输文件系统操作请求。宿主机侧 VMX 进程中的 HGFS 服务器解析客户机请求（打开/读取/写入/目录枚举等）时，将外部可控长度数据拷贝到**栈上固定大小缓冲区**而未正确校验边界，超长输入导致栈缓冲区溢出，可覆盖相邻栈变量与返回地址。攻击者先在客户机内取得本地管理员权限（如已控制客户机 OS），随后构造恶意 HGFS 请求触发溢出，将执行流劫持至攻击者布置的代码（位于共享内存/客户机内存中），以 VMX 进程（宿主机用户态高权限进程）身份执行。官方未公开触发请求格式与利用原语，本报告不作细节臆测。

**核心利用链（基于公告口径的概括性描述，非官方细节）：**

```text
攻击者（已取得客户机内本地管理员权限）
  └─ 客户机启用 HGFS（共享文件夹/拖拽通道）
      └─ 构造超长/畸形 HGFS 请求（文件系统操作）
          └─ VMX 进程解析时栈缓冲区溢出（CWE-121 类）
              └─ 劫持 VMX 进程执行流 → 宿主机代码执行（虚拟机逃逸）
```

> 以上为基于 Broadcom 公告文字与 HGFS 架构的概括性复述；严禁据此对任何系统实施验证。

#### 3.3.2 漏洞摘要

该漏洞源于 JimuReport v2.5.1 **自动导出功能**在身份校验与表达式执行两方面的缺陷叠加：

1. **鉴权绕过（硬编码签名密钥）**：导出接口 `/jmreport/auto/export/python/plugin` 同时标注了 `@JimuNoLoginRequired`（免登录）与 `@JimuSignature`，其唯一防护是请求头 `X-Sign` 签名校验——而该分支使用的签名密钥**硬编码于 jar 内**（`JimuReportSignatureInterceptor.PRINT_PLUGIN_SIGN_SECRET`，随制品分发等同公开）。签名算法为 `X-Sign = MD5(原始请求体 || 固定密钥).toUpperCase()`，另需携带毫秒级 `X-Timestamp`（服务端仅校验单向过期、窗口约 5 分钟）。配置项 `jeecg.jmreport.signatureSecret` 只作用于其它接口、对此分支无效，攻击者可离线伪造任意有效签名。
2. **表达式注入 + 沙箱逃逸（Aviator）**：导出链路 `autoExport → exportMore → getDbSql → getBaseSql()` 将请求中所有查询参数并入 `queryJson` 后，对**每个参数值**调用 `ExpressUtil.a(value, null)`——以 `=` 开头的值被送入内嵌的 Aviator 表达式引擎编译执行（执行前会删除全部 `=` 字符，故表达式内不能含 `=`）。Aviator 实例虽禁用了 `NewInstance/Use/Module/StaticMethods/StaticFields` 等特性且 `ALLOWED_CLASS_SET` 为空，但沙箱仅止步于编译期配置：引擎运行时状态可达可变（如 `InternalVars` 未禁用、内部变量 `__instance__` 可取得求值器单例），经属性导航（getter 反射）与 Map 下标可深入内部对象，最终实现任意 Java 反射调用与命令执行（沙箱逃逸）。

奇安信通告的危害描述为："攻击者可伪造固定密钥签名绕过认证，通过导出接口触发 Aviator 表达式 eval 与沙箱逃逸，以应用权限执行任意命令，实现服务器沦陷。"该漏洞利用条件为：**无需认证、无需特殊网络条件、无需绕过安全机制、无需用户配合**。

> JimuReport 类国产报表组件因内置定时任务、数据源连接与文件导出能力，一旦被攻破通常意味着**服务器完全沦陷 + 内网数据源可被枚举读取**；叠加国内风险资产 27 万的暴露量级，属于"一条请求打穿报表服务器"的高危场景。

#### 3.3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可访问 JimuReport Web 服务（公网暴露或内网可达均可） |
| 身份认证 | 无需 | 免登录接口 + 硬编码密钥伪造 X-Sign，完全绕过鉴权 |
| 用户交互 | 不需要 | 纯 HTTP 请求触发 |
| 特定配置 | 否 | 默认配置即可利用（第三方 PoC 标注"默认配置启动、无需任何凭据"） |
| 利用复杂度 | 低 | 奇安信"利用可能性：高"；密钥随 jar 分发、表达式语法公开 |

**技术原理：**

技术原理分三段（详见 3.3.2）：① 硬编码 `PRINT_PLUGIN_SIGN_SECRET` 使 `X-Sign` 可离线伪造（MD5(请求体+密钥) 大写），免登录注解使攻击者无需会话；② `ExpressUtil.a()` 将请求参数值（`=` 前缀）交给 Aviator 求值，结果回填 SQL 模板，参数即代码；③ Aviator 沙箱在编译期封死类符号解析与静态调用，但**运行时状态可达**（`Feature.InternalVars` 未禁用 → `__instance__` 暴露求值器单例），配合 getter 反射与 Map 下标遍历对象图，可触达 ClassLoader/反射入口完成沙箱逃逸，实现任意 Java 调用（`Runtime.exec` 等命令执行原语）。由于删除 `=` 的预处理，表达式内不得包含等号，需用反射链规避——公开 PoC 已解决该限制。

**核心利用链（基于厂商通告与公开技术描述的概括，非可执行细节）：**

```text
攻击者（无任何凭据）
  └─ POST /jmreport/auto/export/python/plugin（免登录注解接口）
      └─ 携带 X-Timestamp + X-Sign（用硬编码密钥离线伪造，MD5 签名）
          └─ 导出参数中注入以 "=" 开头的 Aviator 表达式（如反射调用链）
              └─ ExpressUtil.a() 将表达式交给 Aviator 求值（无条件执行）
                  └─ InternalVars/__instance__ 触达求值器单例 → 沙箱逃逸
                      └─ 任意 Java 反射调用 → Runtime 命令执行（RCE，应用权限）
```

> 以上为技术原理概括；严禁按此描述对任何系统实施验证或复现。

#### 3.4.2 漏洞摘要

FreeRDP 是开源远程桌面协议（RDP）实现，其客户端（xfreerdp 及各类内嵌）广泛用于跨平台连接 Windows 远程桌面与同族 RDP 服务。漏洞位于**协商阶段的 routing token 处理**：

客户端发送 X.224 Connection Request 前调用 `nego_send_negotiation_request()`：函数先分配一块**固定 512 字节**的 `wStream` 缓冲区，随后把 `nego->RoutingToken`（长度与内容均由对端可控）经 `Stream_Write` 写入——该宏本质是一次**没有剩余容量检查的 `memcpy`**——超长 token 在拷贝时即造成堆越界写。报文长度检查（`length > UINT16_MAX`）发生在写入**之后**且只校验整体长度，无法阻止越界。routing token（负载均衡信息，LB_LOAD_BALANCE_INFO cookie）本用于在负载均衡器后标识会话：恶意 RDP 服务端可在连接协商/重定向阶段下发超长 token，受害者客户端在（重连）协商时触发溢出。

> 该漏洞的攻击方向是**"恶意服务端 → 客户端"**（区别于常见的"恶意客户端打服务端"）：攻击者搭建恶意 RDP 服务端并诱导目标使用 FreeRDP 客户端连接（钓鱼/水坑/内网诱饵），或在目标与可信 RDP 服务端之间处于可注入重定向的中间人位置时投递。企业内大量 Linux 终端、VDI 客户端与运维跳板机使用 FreeRDP 系客户端，属"出站 RDP 会话"侧的隐蔽攻击面。

#### 3.4.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 受害者需能连接攻击者控制的 RDP 服务端，或攻击者处于可注入重定向的中间人位置 |
| 身份认证 | 无需 | 协商阶段发生于认证之前（预认证触发） |
| 用户交互 | 需要 | 受害者需主动连接恶意服务端（或被重定向至恶意服务端） |
| 特定配置 | 否 | 默认配置即可（routing token 解析为默认协商路径） |
| 利用复杂度 | 中 | 堆越界写原语清晰；"满足特定利用条件时可执行任意代码"（微步口径），完整 RCE 链未公开 |

**技术原理：**

RDP 连接协商（X.224 Connection Request）可携带可选的 routing token / cookie 字段，负载均衡场景用于会话保持。FreeRDP 客户端在 `nego_send_negotiation_request()` 中：

1. `wStream *s = Stream_New(NULL, 512)` 分配定长 512 字节堆缓冲区；
2. 若 `nego->RoutingToken` 非空，直接 `Stream_Write(s, nego->RoutingToken, nego->RoutingTokenLength)`——发行版该宏**无剩余容量检查**，等价于无边界 `memcpy`；
3. 必要时追加 `\r\n`；随后才检查 `length > UINT16_MAX` 并回填 TPKT 长度——长度校验发生在写入之后，且未约束单字段长度。

恶意服务端在连接/重定向阶段（Server Redirection 载荷）下发长度与内容均可控的 routing token，受害者客户端重连协商时即发生堆越界写，破坏堆元数据或相邻对象，形成内存破坏原语。

**核心利用链：**

```text
攻击者（恶意 RDP 服务端 / 可注入重定向的中间人）
  └─ 诱导受害者使用 FreeRDP 客户端（≤ 3.30.0）发起连接
      └─ 协商阶段下发超长 LB_LOAD_BALANCE_INFO routing token
          └─ nego_send_negotiation_request() 以 512B 定长缓冲 Stream_Write 拷贝
              └─ 无容量检查 memcpy → 堆越界写（内存破坏）
                  └─ （满足特定堆布局/利用条件时）客户端进程任意代码执行
```

### 3.5 `CVE-2026-19949` — WordPress All-in-One WP Migration and Backup 存档恢复二阶 SQL 注入漏洞

!!! danger "高危漏洞（CVSS 3.1 = 8.8；约 325 万站点未升级）"

#### 3.5.2 漏洞摘要

该漏洞位于 All-in-One WP Migration and Backup 插件的**存档恢复（archive restore）功能**：插件恢复备份时会重写数据库内容，此过程中对**转义反斜杠与引号的处理不正确**（对用户可控参数转义不足、对既有 SQL 查询预处理不足），形成二阶 SQL 注入。攻击链分两阶段：

1. **植入**：未认证攻击者可经 WordPress trackback（评论/回溯机制）提交精心构造的数据，使其被持久化存储；
2. **触发**：当管理员执行"恢复备份存档"（插件核心常规操作，将存储数据作为 SQL 执行）时，注入的 SQL 被执行——Wordfence 指出注入的 SQL 可经**公开评论**泄露插件的秘密导入密钥 `ai1wm_secret_key`；攻击者获取密钥后即可导入包含可执行代码的恶意 `.wpress` 存档，实现**任意代码执行与网站完全接管**。

> 利用前提是管理员"在某个时间点执行恢复操作"——Wordfence 评估认为备份/恢复是该插件的核心用途、属常规操作，因此"休眠载荷被触发是可以预期的"；停用的易受攻击版本风险较低，但若被临时激活仍可被利用。

#### 3.5.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 站点需开放 trackback/评论与后台恢复功能 |
| 身份认证 | 无需（植入阶段）/ 需管理员（触发阶段） | 植入经 trackback（未认证）；触发需管理员执行恢复操作 |
| 用户交互 | 需要 | 管理员执行"恢复备份存档"动作（常规运维操作） |
| 特定配置 | 否 | 默认配置即可（trackback/评论默认开启的站点触发面更大） |
| 利用复杂度 | 中 | 二阶注入 + 等待管理员操作；Wordfence 已给出完整技术分析 |

**技术原理：**

NVD 描述指出：插件存档恢复功能"对用户提供的参数转义不足、对既有 SQL 查询预处理不足（insufficient escaping on the user supplied parameter and lack of sufficient preparation on the existing SQL query）"，使未认证攻击者可将额外 SQL 追加进既有查询。具体而言，恢复流程重写数据库内容时对**转义反斜杠和引号**的解析有误——存储的恶意载荷（经 trackback 植入）在恢复时被错误地当作 SQL 边界处理，形成二阶注入。Wordfence 分析确认注入点可被用于经公开评论接口读取 `ai1wm_secret_key`（导入密钥），进而伪造/导入恶意备份包。`.wpress` 存档导入功能可包含 PHP 文件等可执行内容，导入即代码执行。

**核心利用链：**

```text
攻击者（未认证）
  └─ 经 WordPress trackback 植入含 SQL 载荷的数据（休眠）
      └─ 等待/诱导管理员执行"恢复备份存档"（插件核心操作）
          └─ 恢复时对反斜杠/引号转义处理错误 → 二阶 SQL 注入触发
              └─ 经公开评论泄露 ai1wm_secret_key（导入密钥）
                  └─ 构造恶意 .wpress 存档导入 → 任意代码执行（站点完全接管）
```

#### 3.5.11 风险影响

漏洞成功利用后，可能导致：

- 读取 `ai1wm_secret_key` 等敏感配置，进而导入恶意备份实现任意代码执行；

### 3.6 `CVE-2026-67398` / `CVE-2026-67399` — WHMCS 9 月安全更新双漏洞（2Checkout 网关未授权信息泄露 / 未授权对象注入 RCE）

#### 3.6.2 漏洞摘要

**`CVE-2026-67398`（2Checkout 支付网关模块，NVD 已收录）**：WHMCS 2Checkout 支付网关端点存在缺失授权缺陷（CWE-862）。NVD 描述：从 8.13.0 起至 8.13.8 之前、9.0.0 起至 9.0.8 之前以及自 4.5.0 起的全部 EOL 版本受影响；在特定条件下，未认证用户可经 2Checkout 支付网关端点获取 WHMCS 客户数据——安全圈转述细化：攻击者无需登录即可在特定条件下**枚举发票并获取客户资料**（姓名、地址、城市、州/省、邮编、国家、邮箱与电话号码）。无法立即升级的客户可临时停用 2Checkout 支付网关阻断入口。

**`CVE-2026-67399`（对象注入 → 未授权 RCE，NVD 尚未收录）**：影响 WHMCS 8.0.x 及之后版本。攻击者可向服务器提交经过构造的 Payload，再通过**多阶段请求和反序列化链**触发对象注入（object injection），在**没有登录凭据**的情况下执行任意代码。安全圈明确指出"该漏洞没有可用的客户端临时缓解方案，必须升级到最新版"。

> 两漏洞同属 WHMCS 2026 年 9 月安全更新修复范围；WHMCS 类业务支撑系统承载客户 PII 与支付/服务器管理凭据，即使仅信息泄露（67398）也可能被组合用于后续钓鱼与账户接管。可信度提示：67399 的编号、版本范围与细节暂以安全圈转述为准（本站未能访问 WHMCS 官方公告原文），NVD 收录后将更新。

#### 3.6.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可访问 WHMCS Web 服务（公网业务面板常见） |
| 身份认证 | 无需 | 两漏洞均为未认证利用（67399"没有登录凭据"；67398"无需登录"） |

**技术原理：**

- `CVE-2026-67398`：2Checkout 支付网关回调/查询端点对发票与客户信息查询缺少授权校验，攻击者可枚举发票标识（invoice ID 等）并读取关联客户 PII——WHMCS 自 4.5.0 起长期存在，说明该历史模块从未对查询类端点实施一致的授权控制。
- `CVE-2026-67399`：WHMCS 8.x 起某输入处理路径将攻击者可控数据（经多阶段请求组装）交给反序列化逻辑，形成**对象注入**；配合应用内可用 gadget 完成属性注入/方法调用链，最终在未认证条件下执行任意代码。官方未公开受影响文件与 gadget 细节（安全圈转述口径），本站不臆测具体入口。

**核心利用链（概括性描述，非官方细节）：**

```text
攻击者（未认证）
  ├─ 67398：请求 2Checkout 网关查询端点 → 枚举发票 → 读取客户 PII（姓名/地址/邮箱/电话）
  └─ 67399：提交构造 Payload → 多阶段请求组装 → 触发反序列化/对象注入链
              └─ 无凭据执行任意代码（WHMCS 服务进程权限）
                  └─ 访问 WHMCS 数据库 + 其连接的支付/注册商/服务器管理接口（潜在扩散）
```

#### 3.6.11 风险影响

漏洞成功利用后，可能导致：

- （67398）未授权枚举发票并窃取客户 PII（姓名、地址、邮箱、电话），支撑精准钓鱼与账户接管；
