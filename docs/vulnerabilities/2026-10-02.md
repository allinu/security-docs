### 1.3 今日重点关注

1. **`CVE-2026-104286`：Fortinet FortiMail 路径遍历致未认证任意文件写入**  
   影响 Fortinet FortiMail 7.2.0–7.2.9、7.4.0–7.4.8、7.6.0–7.6.6、8.0.0–8.0.1，未经身份认证的攻击者可通过构造 HTTP/HTTPS 请求在底层系统写入任意文件，CVSS 3.1 = 9.8。该编号于 **2026-10-01 被美国 CISA 新增进 KEV 目录**，整改期限 **2026-10-04**，为本窗口唯一“当日新增 KEV + 严重评分”条目，建议立即排查并升级（FG-IR-26-175）。

2. **`CVE-2026-56154` / `CVE-2026-57941` / `CVE-2026-59797`：Apache HTTP Server 2.4.69 修复 16 个 CVE**  
   Apache 于 2026-10-01 发布 2.4.69，修复 mod_rewrite lookahead 释放后使用、mod_http2 共享 `session->bbtmp` 重入释放后使用、mod_ssl `SSLRequire` 权限管理不当等问题；三条被 NVD 评为 9.8 严重，受影响范围为 `2.4.0`–`2.4.68`。httpd 部署面极广，建议按“先升 2.4.69、再核对版本”推进。

3. **`CVE-2026-102489` / `CVE-2026-102490`：Zammad 零日链已被在野利用，攻击者数秒拿到 root**  
   荷兰漏洞披露研究所（DIVD）自曝其 Zammad 工单系统被两个零日漏洞串联突破：先劫持会话并远程执行代码（`CVE-2026-102489`，Zammad 6.3.0–6.5.4 等），再由 zammad 用户本地提权至 root（`CVE-2026-102490`，影响所有版本），攻击过程由 AI 智能体自动串联，从入侵到 root 仅数秒。官方要求升级至 Zammad 7 或下线。

#### 3.1.2 漏洞摘要

该漏洞存在于 Fortinet FortiMail 的 HTTP/HTTPS 请求处理路径中。FortiMail 在处理请求所涉及的路径参数时未将路径限制在受限目录内，导致路径遍历（`../` 逃逸）。未经身份认证的远程攻击者可向邮件网关发送精心构造的 HTTP/HTTPS 请求，在底层文件系统的非预期位置写入任意文件。

由于 FortiMail 是直接处理互联网来信的邮件安全网关，且其 Web 管理/服务面通常暴露于互联网，写入任意文件往往可进一步升级为以服务权限执行代码或篡改网关行为（例如改写配置、替换组件、植入后门），从而造成邮件内容被窃取或不投递等严重后果。**该漏洞已于 2026-10-01 被 CISA 纳入 KEV，说明其已被现实世界作为攻击目标。**

> 邮件安全网关位于互联网边界并直接处理第三方来信，其“未认证 + 任意文件写入”的组合等同于边界失守，故 KEV 收录与 2026-10-04 的整改期限应予最高优先级对待。

| 条件 | 状态 | 说明 |
| --- | --- | --- |

**技术原理：**

根因是**路径遍历（CWE-22）**：服务端在把用户可控的路径片段拼接为文件系统路径时，未做规范化（canonicalization）与目录边界校验，也未拒绝 `../`、绝对路径或编码变体（如 `%2e%2e%2f`、双重编码、`..\`），致使写入位置可逃逸出预期的受限目录。由于 `C/H/I` 三项均为 High，说明一次成功利用即可同时破坏机密性、完整性与可用性——典型表现是覆盖配置文件、写入可被 Web 服务解析的脚本/模板、或破坏服务组件。

**核心利用链：**

```text
攻击者（互联网）
  └─ 探测暴露的 FortiMail HTTP/HTTPS 服务
      └─ 构造含路径遍历序列的请求（../ 或编码变体）
          └─ 触发文件写入逻辑，绕过受限目录边界
              └─ 在底层系统写入任意文件
                  └─ 进一步以服务权限执行代码 / 篡改网关行为
                      └─ 窃取邮件内容、持久化后门或中断邮件服务
```

#### 3.2.2 漏洞摘要

Apache HTTP Server 2.4.69（2026-10-01 发布）修复了 **16 个 CVE**，覆盖 mod_rewrite、mod_http2、mod_ssl、mod_dav、mod_dav_fs、mod_charset_lite、mod_proxy_html、mod_proxy_ftp、mod_proxy_uwsgi、mod_vhost_alias、mod_xml2enc、mod_auth_digest、mod_heartmonitor、mod_session_cookie、CGI 处理等组件。其中被 NVD 评为 9.8 的三条为：

- `CVE-2026-56154`：mod_rewrite 在使用前瞻表达式 `%{LA-U:HTTP:...}` 时存在释放后使用（UAF）；
- `CVE-2026-57941`：mod_http2 因共享 `session->bbtmp` 的重入导致释放后使用 / 越界写；
- `CVE-2026-59797`：mod_ssl 的 `SSLRequire` 与文件相关表达式存在权限管理不当。

**必须指出的重要差异：Apache 官方对本批多数条目的自评等级偏低**——官方将 `CVE-2026-56154` 标为 **low**、`CVE-2026-57941` 标为 **moderate**、`CVE-2026-59797` 标为 **low**，而同批 `CVE-2026-63292`（mod_vhost_alias 栈溢出）为 moderate、`CVE-2026-58415`（ap_directory_walk 越界写）为 moderate；NVD 的 9.8 评分明显高于 Apache 自评。**该差异须如实呈现：NVD 评分通常在缺陷可被远程触发且影响机密性/完整性/可用性时给出高分，而 Apache 会结合真实利用条件（如是否需要特定配置、是否需要 `.htaccess`、是否需要 CGI 目录）下调等级。** 读者应以“先升 2.4.69”为准，不必在等级差异上纠结。

> httpd 是本窗口 CVE 数量与部署面之间“杠杆”最大的组件：一个升级动作同时消解 16 个编号，其中三条被 NVD 判为 9.8。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需可访问 httpd 对外监听端口（80/443 等） |
| 身份认证 | 多数无需 | 三条 9.8 评分条目的向量均为 `PR:N`（NVD），但实际触发条件因模块与配置而异（例如 mod_ssl 条目需使用 `SSLRequire`/文件表达式、CGI 条目需目标位于启用 CGI 的目录） |
| 用户交互 | 不需要 | 无需用户交互（`UI:N`） |
| 特定配置 | 是（部分条目） | 部分条目依赖特定模块启用或特定配置（如 mod_rewrite 使用前瞻、mod_http2 启用、CGI 目录、mod_proxy 转发代理等） |
| 利用复杂度 | 低–中 | `AC:L`（NVD），但真实可利用性受配置与内存布局影响；Apache 官方对部分条目自评为 low/moderate |

**技术原理：**

本批缺陷跨越多种内存安全与权限模型问题，共性根因是**在处理并发、重入、指针生命周期或权限表达式时缺乏一致的生命周期与边界约束**：

- `CVE-2026-56154`（mod_rewrite）：前瞻表达式 `%{LA-U:HTTP:...}` 在求值过程中对请求结构的引用在后续阶段被释放，形成**释放后使用（CWE-416）**；
- `CVE-2026-57941`（mod_http2）：`session->bbtmp` 缓冲区在多路复用会话中被并发/重入访问，导致已释放缓冲区被再次写入（UAF / 越界写，CWE-416）；
- `CVE-2026-59797`（mod_ssl）：`SSLRequire` 中的文件相关 `ap_expr` 函数未按预期受权限模型约束，导致**权限管理不当（CWE-269）**，可能使本应受限的表达式访问到不应暴露的文件信息；
- 其余条目涵盖 mod_vhost_alias 栈溢出（CWE-121）、ap_directory_walk 越界写（CWE-787）、mod_charset_lite / mod_proxy_html 越界写（CWE-787）、mod_auth_digest 认证状态竞争与重放（CWE-416 / CWE-294）、mod_proxy_uwsgi 响应走私（CWE-444）等。

**核心利用链：**

```text
攻击者（互联网）
  └─ 定位目标 httpd 及启用的模块（mod_rewrite / mod_http2 / mod_ssl / mod_proxy 等）
      └─ 构造触发特定代码路径的 HTTP(S) 请求
          └─ 触发内存生命周期或权限表达式缺陷（UAF / 越界写 / 权限绕过）
              └─ 造成工作进程崩溃、信息泄露，或（在具备条件时）内存破坏以执行代码
                  └─ 中断服务或获取服务器权限
```

#### 3.3.2 漏洞摘要

华硕路由器（部分型号）在本窗口被披露两个可导致命令执行的缺陷：

- `CVE-2026-14157`（**外部可控格式化字符串**，CWE-134，CVSS 4.0 = 9.4）：远程**已认证**用户可通过 Web 管理界面上传特制文件，使格式化字符串受外部控制，从而执行任意命令；
- `CVE-2026-13313`（**活动调试代码**，CWE-489，CVSS 4.0 = 8.9）：远程已认证用户可通过特制 HTTP 请求绕过安全机制并**启用 Telnet 服务**，进而以 root 权限执行任意命令，并可能影响路由器下挂的其他设备。

两者均要求攻击者已具备管理员权限（`PR:H`），但一旦成立即为设备完全失守；`CVE-2026-13313` 的“开启 Telnet”路径尤其值得警惕，因为其把一次 Web 层绕过转化为一个长期可用的远程 shell 入口。

> 路由器是家庭与小企业网络的唯一出口，root 失守意味着全部内网流量、DNS 与凭据均处于风险之中；“开启 Telnet”尤其会留下难以察觉的持久化入口。

#### 3.3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需可访问路由器 Web 管理界面（LAN 侧或已开放的 WAN 管理端口） |
| 身份认证 | 管理员 | 两条均为 `PR:H`，需已认证的管理员权限 |
| 用户交互 | 不需要 | 无需受害者交互 |
| 特定配置 | 是 | 需可登录管理界面；`CVE-2026-13313` 依赖设备存在可被触发的调试/服务开关 |
| 利用复杂度 | 低 | `AC:L`，已认证后利用路径直接 |

**技术原理：**

`CVE-2026-14157` 属**格式化字符串（CWE-134）**：程序将用户可控数据直接作为 `printf` 族函数的格式串参数，攻击者通过 `%n`/`%s` 等格式说明符读写内存，从而在设备上执行任意命令。`CVE-2026-13313` 属**活动调试代码（CWE-489）**：固件中保留了生产环境不应启用的调试/服务开关，攻击者通过构造 HTTP 请求触发该开关，开启 Telnet 服务（通常以 root 运行），把一次 Web 层绕过升级为持久的远程 shell。

**核心利用链：**

```text
已认证攻击者（Web 管理界面）
  └─ 上传特制文件 / 发送特制 HTTP 请求
      └─ 触发格式化字符串缺陷（14157）或调试开关（13313）
          └─ 绕过安全机制 / 执行任意命令
              └─ 开启 Telnet 服务（13313）或以 root 执行命令
                  └─ 完全控制路由器，并影响下挂设备与流量
```

#### 3.4.2 漏洞摘要

Foreman 是广泛用于裸机/虚拟机生命周期管理与配置编排的开源平台，其模板引擎采用 safemode 沙箱限制可调用的方法。`CVE-2026-96658` 中，**低权限已认证攻击者**可利用沙箱对“委托方法（delegated methods）”处理不当的缺陷，把未授权函数追加进允许执行列表，从而绕过沙箱并**在承载 Foreman 的服务器上执行任意命令**（CVSS 3.1 = 9.9，作用域变更 `S:C`）。`CVE-2026-96659` 中，**具备低权限 Viewer 访问级别**的用户可通过向模板预览端点提交请求，读取本不应访问的敏感信息（CVSS 3.1 = 9.1）。

两者叠加的危害在于：攻击者只需一个低权限账号，即可先获取配置中的敏感数据（如凭据、主机信息），再进一步绕过沙箱取得服务器命令执行能力。

> 配置管理平台本身就是“跳板中的跳板”——它通常掌握着大量主机的凭据与配置权限，因此在 Foreman 上取得命令执行远比在普通应用上更具破坏性。

#### 3.4.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需可访问 Foreman Web 界面（通常位于管理网或内网） |

**技术原理：**

根因是**沙箱机制的白名单校验不严（CWE-94 / 权限不当）**：safemode 采用“允许列表”控制模板中可调用的方法，但 Foreman 对**委托方法（delegated methods）**的处理存在缺陷——攻击者可在模板中通过委托链把未授权函数“追加”到允许列表中，使沙箱认为该函数合法，从而逃逸并执行任意 Ruby/系统命令。`CVE-2026-96659` 则是**权限校验缺失（CWE-267）**，模板预览端点未正确实施 Viewer 级别应有的字段级授权，导致越权读取。

**核心利用链：**

```text
低权限已认证攻击者（Foreman 账号）
  └─ 访问模板编辑/预览功能
      └─ 构造引用委托方法的模板
          └─ 使未授权函数被追加进 safemode 允许列表
              └─ 绕过沙箱，执行任意 Ruby / 系统命令
                  └─ 以 Foreman 服务权限控制服务器并横向到受管主机
```

#### 3.5.2 漏洞摘要

Fortra 的 Core Privileged Access Manager（BoKS）是企业级 Unix/Linux 特权访问与账号管理平台，通常集中管控大量服务器的 root 凭据。本窗口 Fortra 一次性披露多条缺陷：

- `CVE-2026-79901`（**9.9**，CWE-338）：`boks_keytabmd` 在使用 keytab 管理时，**以当前 Unix 时间戳为种子生成 Active Directory 服务账号口令**。攻击者若知晓服务主体名并能估计口令变更时间，即可复现有限的候选集合并离线验证，从而猜解出服务账号口令；
- `CVE-2026-12627`（**9.8**，CWE-121）：`boks_autoregisterd` 在客户端响应处理过程中存在**栈缓冲区溢出**，网络可达的远程攻击者（未认证）可触发内存破坏，潜在导致代码执行或拒绝服务；
- `CVE-2026-79898`（**9.1**，CWE-78）：`crlserver` 存在**命令注入**。具备在 BCC / WSI REST-SOAP / `cacrl` 中添加 CRL URL 权限的已认证用户，可使 shell 命令替换在 BoKS Master 上**以 root 身份**被执行（BCC 与 WSI 为网络可达管理路径，不需本地 sudo/suexec）；
- 另有 `CVE-2026-79899`（7.9，`bccgethostcert` 不安全临时文件，本地用户可利用）与 `CVE-2026-79896`（7.5，`boks_portmux` 的 TLS ClientHello 解析越界读，可致服务终止）。

**这批缺陷的共同点是：受影响组件正是“特权的守门人”本身**——一旦被突破，攻击者获得的不只是单机权限，而是该平台所管理的全部特权凭据。

> 特权访问管理平台是所有 root 密码的集中点。它在安全体系中既是最后的防线，也是攻击者眼里价值最高的目标——“守门人”自身被攻破意味着整片服务器群同时失守。

#### 3.5.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是（12627/79898） | `boks_autoregisterd` 与 BCC/WSI 管理接口为网络可达；79901 需知晓服务主体名并估计时间 |
| 身份认证 | 部分无需 | 12627 为未认证（`PR:N`）；79898 需已认证且具备 CRL URL 添加权限（`PR:H`）；79901 需低权限（`PR:L`） |
| 用户交互 | 不需要 | 无需用户交互 |
| 特定配置 | 是（部分） | 79901 需启用 BoKS keytab 管理；79898 需具备相应管理能力 |
| 利用复杂度 | 低–中 | 12627/79898 利用路径直接；79901 需离线暴力验证，成本取决于种子熵与时间估计精度 |

**技术原理：**

- **可预测凭据（CWE-338）**：`boks_keytabmd` 以 Unix 时间戳作为 PRNG 种子，时间戳熵极低（攻击者可估计口令变更时间），使生成的 AD 服务账号口令落在一个很小的候空间内，可离线枚举验证；
- **栈缓冲区溢出（CWE-121）**：`boks_autoregisterd` 在解析客户端响应时未对长度做边界检查，攻击者发送超长响应覆盖栈上返回地址；
- **命令注入（CWE-78）**：`crlserver` 在添加 CRL URL 时未对 URL 中的 shell 元字符做过滤/转义，导致命令替换以 root 执行；
- **不安全临时文件（CWE-377）** 与 **越界读（CWE-125）** 分别导致本地竞争与远程服务崩溃。

**核心利用链：**

```text
攻击者
  └─ 探测 BoKS Master 的 autoregistration / BCC / WSI 服务
      └─ 发送超长客户端响应（12627）或含 shell 元字符的 CRL URL（79898）
          └─ 触发栈溢出 / 命令注入，以 root 执行命令
              └─ 读取 BoKS 管理的凭据库
                  └─ 横向登录全部受管服务器（特权平台失守）
```

#### 3.6.2 漏洞摘要

Kiteworks 是面向企业的安全文件共享与合规通信平台，其 Email Protection Gateway（邮件保护网关）与 Core 平台常位于企业对外通信边界。本窗口 Kiteworks 一次性披露 **71 条 CVE**（占本窗口全部有效条目的 16%），等级覆盖严重到中危，典型条目包括：

- `CVE-2026-102115`（**9.8**，CWE-640）：Core 的**口令重置流程未正确校验参数**，未认证攻击者只要知道某本地口令账户的邮箱地址，即可在不访问邮件重置链接的情况下重置其口令并以该用户身份登录，**包括拥有管理权限的账户**；
- `CVE-2026-102149`（**9.4**，CWE-306）：Email Protection Gateway 对证书可绑定的账户限制不足，攻击者可把证书关联到他人账户，影响该账户的机密性与完整性；
- `CVE-2026-102147`（**9.3**，CWE-79）：Core 存在**存储型 XSS**，未认证攻击者可植入内容，随后在查看该页面的**管理员**会话中执行任意 JavaScript；
- `CVE-2026-102095`–`CVE-2026-102106`（多条 **9.1**）：Email Protection Gateway 多处 **SSRF**，未认证远程攻击者可诱导网关发起任意出站请求；其中 `CVE-2026-102106` 为**管理服务密码校验可被绕过**（CWE-287）；
- 此外还有 `CVE-2026-102120`（8.8，节点间提权）、`CVE-2026-102125`（8.8，文档转换沙箱逃逸）、`CVE-2026-102097` 系列等。

**该批次的特点是同一天在“边界网关 + 平台核心”上集中暴露，且多条为未认证可利用**——口重重置接管（102115）与存储型 XSS→管理员会话（102147）组合，可构成“未认证 → 管理员 → 平台完全控制”的链路。

> 邮件保护网关与安全文件平台同时处于“处理外来内容”和“掌握内部凭据”的双重位置；未认证的口令重置接管叠加存储型 XSS 打管理员，是一条足以直接颠覆平台控制权的短链。

#### 3.6.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需可访问 Kiteworks Core 或 Email Protection Gateway 的对外接口 |
| 身份认证 | 多数无需 | 102115/102095 系列为 `PR:N`（未认证）；102147 存储型 XSS 亦为未认证植入 |
| 用户交互 | 部分需要 | 102147 需管理员查看被植入的页面（`UI:R`） |
| 特定配置 | 否 | 多数条目默认配置下即可触发 |
| 利用复杂度 | 低 | `AC:L`，攻击路径直接 |

**技术原理：**

本批次覆盖多种根因：**口令重置流程的弱校验（CWE-640）**——重置令牌/参数未与服务端状态绑定，知道邮箱即可重置；**存储型 XSS（CWE-79）**——用户可控内容未做输出编码即存入并在管理员页面渲染；**SSRF（CWE-918）**——邮件内容中的 URL 被服务端无限制抓取，且未做地址过滤（可访问内网/云元数据）；**认证不当（CWE-287）**——管理服务的密码校验在特定路径上被跳过；**证书与账户绑定限制不足（CWE-306）**——关键功能缺少授权校验。

**核心利用链：**

```text
未认证攻击者（互联网）
  └─ 调用 Core 口令重置接口（102115），接管管理员账户
      └─ 以管理员身份登录平台
          └─ 结合存储型 XSS（102147）或 SSRF（102095 系列）扩大控制
              └─ 读取/篡改企业文件与邮件，植入持久化
                  └─ 横向至与企业平台集成的其他系统
```

#### 3.7.2 漏洞摘要

iperf3 是广泛用于带宽与网络质量测量的开源工具，其服务端模式常被部署在测试环境、运维网络乃至暴露于互联网的探针上。本期披露两个**认证前**堆内存缺陷：

- `CVE-2026-101283`（**9.2**，CWE-122，iperf3 3.20–3.21）：`decrypt_rsa_message()` 中一个 **256 字节的 RSA 缓冲区被以攻击者可控的密文长度调用 `BIO_read`**，长度守卫仅告警而不终止，因此未认证客户端可通过超长 authtoken **堆溢出**；
- `CVE-2026-101276`（**9.2**，CWE-416，iperf3 3.21）：服务端每测试看门狗 `server_timer_proc()` 在**未取消/未 join 工作线程**的情况下释放流对象，被阻塞的工作线程随后解引用已释放的 `iperf_stream`，形成**远程未认证堆释放后使用**。

两者均在 **3.22** 修复。由于触发均在认证前，任何可连接到 iperf3 服务端端口的客户端均可尝试触发，典型后果为服务端崩溃（拒绝服务），在具备堆布局控制条件时亦可发展为代码执行。

> iperf3 通常被视为“测速小工具”，但它同样是监听端口的网络服务，且历史上常被直接暴露；认证前可触发的堆破坏缺陷不应以“工具无价值”为由被低估。

#### 3.7.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需可连接 iperf3 服务端监听端口（默认 5201/tcp） |
| 身份认证 | 无需 | 两条均为 `PR:N`，认证前即可触发 |
| 用户交互 | 不需要 | 无需用户交互 |
| 特定配置 | 部分 | 需服务端以 `-s` 监听并（对 101283）启用 RSA 认证相关代码路径 |
| 利用复杂度 | 中 | `AC:L` 但 `AT:P`（攻击条件部分依赖环境），实际可利用性受堆布局与配置影响 |

**技术原理：**

- **堆缓冲区溢出（CWE-122）**：`decrypt_rsa_message()` 固定分配 256 字节 RSA 缓冲区，却以攻击者提供的密文长度作为 `BIO_read` 的读取长度，且长度校验仅记录告警、不返回错误，导致溢出写入堆；
- **堆释放后使用（CWE-416）**：`server_timer_proc()` 作为看门狗在超时后释放 `iperf_stream` 对象，但未同步取消或 join 其工作线程；被阻塞的工作线程恢复后继续访问已释放结构，形成 UAF。

**核心利用链：**

```text
未认证攻击者（网络可达 iperf3 服务端端口）
  └─ 建立测试连接并发送超长 authtoken（101283）
      └─ decrypt_rsa_message() 以攻击者长度读取至 256 字节缓冲区
          └─ 堆溢出，破坏相邻堆元数据
              └─ 服务端崩溃（DoS），条件具备时可执行代码
  ── 或 ── 触发看门狗超时（101276）
      └─ server_timer_proc() 释放流对象但未 join 工作线程
          └─ 工作线程解引用已释放对象（UAF）
```

### 3.8 认证绕过批次 — CVE-2026-103264（Fleet）/ CVE-2026-103244（ground-station）/ CVE-2026-103655（MISP）

!!! danger "严重漏洞"

#### 3.8.2 漏洞摘要

三条缺陷分属不同产品，但**根因与后果高度一致——认证被绕过**：

- `CVE-2026-103264`（**Fleet < 4.87.0，9.3**，CWE-287）：Fleet 是开源设备管理（MDM）平台。其**设备 API 除设备 UUID 外还接受主机名与硬件序列号作为认证令牌**，而这些标识并非秘密；知晓或猜测它们的未认证攻击者可冒充 iOS/iPadOS 主机，读取设备数据并触发设备级操作（**包括安装软件与 MDM 迁移**）；
- `CVE-2026-103244`（**ground-station < 0.8.0，9.3；NVD CVSS 3.1 = 9.8**，CWE-306）：地面站软件在首次运行设置模式下，`setup.restore` 命令**未做认证**，攻击者可通过 Socket.IO 调用该命令执行任意 SQL，植入管理员用户与会话令牌，从而**无凭据以管理员身份登录并接管应用**；
- `CVE-2026-103655`（**MISP < 2.5.48，9.3**，CWE-294）：MISP 的 **TOTP 二次认证未记录某个时间步是否已被消费**，同一验证码在其有效期（约 30 秒）内可被重复使用。攻击者若在合法登录过程中捕获到验证码（网络截获、肩窥或受控客户端），即可在窗口内重放以建立第二个会话。

**共同启示：把“非秘密标识”当作认证凭据（Fleet）、把关键功能放在免认证路径上（ground-station）、以及一次性口令不具备真正的“一次性”（MISP），是三类最典型且最易被忽视的认证设计错误。**

> 认证的失败往往不在于密码算法不够强，而在于“把什么当作凭据”这一设计决策本身出错——主机名、序列号与可重放的 TOTP 码都不是秘密。

#### 3.8.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 三者均为网络可达的 API/服务（Fleet 设备 API、ground-station Socket.IO、MISP Web 登录） |
| 身份认证 | 无需 | 三条均为 `PR:N`，未认证即可尝试 |
| 用户交互 | 部分需要 | MISP 的 TOTP 重放需先捕获一个合法验证码（需观察/截获）；Fleet 与 ground-station 无需交互 |
| 特定配置 | 是 | ground-station 需处于首次运行设置模式；Fleet 需攻击者能提供主机名/序列号 |
| 利用复杂度 | 低 | `AC:L`，攻击路径直接 |

**技术原理：**

- **CWE-287（认证不当）**：Fleet 将非秘密的标识（主机名、硬件序列号）与设备 UUID 等同为认证令牌，违背“凭据必须是秘密”的基本原则；
- **CWE-306（关键功能缺失认证）**：ground-station 把可执行任意 SQL 的 `setup.restore` 暴露在免认证的 Socket.IO 通道上，首次运行设置模式成为攻击面；
- **CWE-294（认证绕过，捕获重放）**：MISP 的 TOTP 校验只验证当前时间步的有效性，未持久化记录已消费步长，使“一次性口令”实际可被重放。

**核心利用链：**

```text
未认证攻击者
  └─ 枚举非秘密标识（主机名/序列号，Fleet）
      └─ 以标识作为“令牌”调用设备 API
          └─ 读取设备数据 / 触发安装与 MDM 迁移
  ── 或 ── 通过 Socket.IO 调用 setup.restore（ground-station）
      └─ 执行任意 SQL，植入管理员与会话令牌
          └─ 以管理员身份接管应用
  ── 或 ── 捕获合法 TOTP 码并在窗口内重放（MISP）
      └─ 建立第二个有效会话，读取威胁情报与执行管理操作
```

#### 3.9.2 漏洞摘要

Zammad 是广泛使用的开源客服/工单系统（官方称有 2000+ 客户、55,000+ 用户）。荷兰漏洞披露研究所（DIVD）在自身系统被入侵后，与 Merlon Security 合作发现并披露了两个此前未知的漏洞：

- `CVE-2026-102489`（**9.4**）：**会话劫持导致以 `zammad` 用户远程执行代码**，影响 Zammad 6.3.0–6.5.4，以及 7.0.0–7.1.3（后者因环境条件不可利用）；
- `CVE-2026-102490`（**9.4**）：**所有版本（含最新 alpha）的本地 `zammad` 用户均可提权至 root**。

两者单独即属严重，串联后危害急剧放大：攻击者先劫持会话并取得以 `zammad` 用户的代码执行，再通过提权缺陷直接获得 **root**。DIVD 明确表示，**攻击由 AI 智能体自动串联与执行，从初始访问到 root 仅数秒**，随后攻击者访问其他服务并窃取数据，直至被其网络分段与应急响应阻断。**Zammad 方面的建议非常直接：“升级到版本 7，或立即下线。”** 由于 7.0.0–7.1.3 仍含 `102489`（仅因环境条件不可利用），7.0–7.1.3 不能视为安全，须升级至 **7.2 及以上**（“版本 7”的可用安全版本请以 Zammad 公告为准）。

> 本次事件有两点值得记录：一是“负责替别人找漏洞的组织自身被零日打穿”再次说明零日面前无人豁免；二是 AI 智能体把“入侵到 root”的链路从小时级压缩到秒级，防御方留给人眼判断的窗口正在消失。

| 条件 | 状态 | 说明 |

**技术原理：**

`CVE-2026-102489` 属**会话管理/授权缺陷**：攻击者可劫持合法会话并借此以 `zammad` 用户身份执行任意代码（具体触发链路 DIVD 未完整公开细节）。`CVE-2026-102490` 属**本地权限提升**：`zammad` 用户可借助系统配置或组件缺陷提升至 root（同样是“服务账户 → root”的经典提权路径）。两者串联后形成“未认证 → 代码执行 → root”的完整链条。NVD 记录未给出 CWE，本报告如实标注“未披露”。

**核心利用链：**

```text
攻击者（互联网，AI 智能体驱动）
  └─ 劫持 Zammad 合法会话（CVE-2026-102489）
      └─ 以 zammad 用户远程执行代码
          └─ 串联本地提权缺陷（CVE-2026-102490）
              └─ 获得 root（全过程约数秒）
                  └─ 访问并窃取其他服务的数据（横向）
                      └─ 被网络分段与应急响应阻断
```

#### 3.10.2 漏洞摘要

`CVE-2026-86950` 是 Apple **CoreGraphics** 组件中的**越界写（CWE-787）**缺陷。CoreGraphics 负责 Apple 各操作系统中的图形与渲染处理（包括图像与 PDF 等内容的解析），因此“处理一个恶意构造的文件”即可触发内存破坏并**导致任意代码执行**。Apple 在公告中表示：“处理恶意构造的文件可能导致任意代码执行。Apple 已知有报告称该问题可能已被用于针对特定目标个人的极复杂攻击（iOS 27 之前的版本）。”

**本窗口的关键新进展是“公开 PoC 释出”。** 据 Security Affairs 报道，研究者 Calif 分析补丁后发表了名为 **“The Great Glyph Grift”** 的详细报告，解释了字体渲染中一个小的舍入误差如何最终导致内存破坏：CoreGraphics 在把浮点坐标转换为定点格式时把每个像素细分为 4096×4096 的子网格，当某个数值过大、无法装入 32 位整数时，不同的舍入路径会导致越界写入。该漏洞由 **Meta Product Security** 发现并报告给 Apple。

受影响范围包括 **iOS 26.7 及更早（iOS 27 之前）**、**iPadOS 26.7 及更早**，以及 **macOS Tahoe** 与 **macOS Sequoia** 的受支持版本；Apple 已通过 **iOS 26.7.1、iPadOS 26.7.1、macOS Tahoe 26.7.1、macOS Sequoia 15.8.1** 修复。**KEV 期限为本报告当日（2026-10-02）**，且公开 PoC 已释出，应视为当日必办事项。

> “处理一个文件”就能触发代码执行的漏洞，危险在于它不需要任何显式的“运行”动作——操作系统只是在尽职地解析内容。而一旦公开 PoC 释出，攻击面会从定向的高级攻击迅速扩散。

#### 3.10.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 漏洞在系统处理内容（图像/PDF 等）时被触发，无需网络服务可达 |
| 身份认证 | 无需 | `PR:N` |
| 用户交互 | 需要 | `UI:R`，需受害者打开/处理恶意构造的文件（网页、邮件附件或消息） |
| 特定配置 | 否 | CoreGraphics 为系统核心组件，默认启用 |
| 利用复杂度 | 低 | `AC:L`；但因 Apple 平台的内存缓解（如 ASLR、指针认证等），实际武器化难度高于普通平台 |

**技术原理：**

根因是**越界写（CWE-787）**：CoreGraphics 在进行字体/图形抗锯齿的坐标转换时，将浮点坐标转换为定点格式（每像素 4096×4096 子网格）；当某坐标过大以致无法装入 32 位整数时，不同的舍入实现路径会产生不一致的定点结果，进而对缓冲区发生越界写入。越界写入可被用于破坏相邻内存、劫持控制流，最终在**处理文件的进程上下文**中执行任意代码。该缺陷位于系统级图形组件，影响面覆盖大量应用（凡渲染内容者皆可成为触发载体）。

**核心利用链：**

```text
攻击者（定向投递）
  └─ 构造含特制字体的恶意文件（图片/PDF/文档）
      └─ 通过网页、邮件附件或消息诱导目标打开
          └─ CoreGraphics 处理字体坐标转换
              └─ 过大坐标导致 32 位定点舍入不一致
                  └─ 触发越界写（CWE-787）
                      └─ 在渲染进程上下文实现任意代码执行
```

## 五、当日处置建议

1. **当日必办（跨期 KEV 期限）**：Apple 终端升级至 **iOS/iPadOS 26.7.1 / macOS Tahoe 26.7.1 / macOS Sequoia 15.8.1**，`CVE-2026-86950` 的 KEV 期限为**本报告当日（2026-10-02）**且公开 PoC 已释出；对已在野利用的 Citrix NetScaler 跨期条目（`CVE-2026-88771`/`88772`，已逾期 2 天）继续闭环。

3. **优先核查互联网暴露的边界与安全设备**：邮件网关（FortiMail）、Web 服务器（httpd）、家庭/企业路由器（ASUS/TP-Link）、特权访问管理（BoKS）、设备管理与情报平台（Fleet、MISP、ground-station）。
