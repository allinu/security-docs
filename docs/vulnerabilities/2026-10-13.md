### 1.3 今日重点关注

1. **`CVE-2026-109390`：AnyDesk 未认证堆溢出致 root 命令执行（9.8，PoC 已公开）**  
   AnyDesk 8.0.3 之前，会话协议 mode 5 的流包处理器**未校验载荷长度字段**（`CWE-130`），在 Linux 上已演示为**无需受害者批准桌面控制**即可获得 root 命令执行。远程桌面工具被这类漏洞命中时性质尤其严重：它本身就要求对外可达、且常被运维作为“后门式”通道使用；一旦存在未认证 RCE，攻击者可反向利用该通道批量控制内网主机。研究者已公开 PoC 目录，处置窗口很短。

2. **`CVE-2026-109575`：HAProxy Data Plane API 认证被全局关闭（9.8）**  
   `Server.ConfigureAPI()` 的认证逻辑是**进程全局**的：当同时配置了 `tls_ca` 与数值型 `tls_port` 时，它会“全局禁用共享内部请求处理器上的 Basic 认证”。由于该处理器由 HTTP、HTTPS、UNIX socket 三类监听**并发共享**，mTLS 校验也一并失效——结果是**任何能访问该端口的客户端都可无凭据调用数据面 API**，直接改写 HAProxy 配置、注入后端、劫持流量。这是“安全开关放在全局作用域”的经典反模式。

3. **`CVE-2026-85947`：Progress MarkLogic 权限缺陷致持久化管理员账号植入（9.9）**  
   12.x <12.1.0、11.x <11.3.7 的 forest 管理操作存在授权缺陷，**持有 forest 管理权限的远程攻击者可创建持久化未授权管理员账号**，随后获得服务器完全管理控制。同批还包含 `CVE-2026-9191`（9.6，TLS 校验不足）、`CVE-2026-85948`（9.9，XQuery 相关）、`CVE-2026-85955`／`85956`（9.9）。MarkLogic 常用于承载敏感文档与检索服务，“持久化管理员”意味着攻击者不必维持漏洞通道即可长期驻留。

4. **`CVE-2026-84286`：ExLlamaV3 EXL3 加载器信任模型内索引，可致受控内核调度（9.8）**  
   EXL3 加载器用**模型文件内自带的索引**选择 CUDA kernel，加载前未做越界校验（`CWE-20`／`CWE-125`／`CWE-787`），恶意模型可强制读取并调用越界函数指针，稳定触发崩溃；在特定主机内存布局下可能实现**受控的间接内核调度**。这是“模型文件即代码”的典型风险——本地推理栈的安全边界必须包含“模型来源可信”这一前提，否则下载即执行。

### 1.4 综合研判

本期 476 条，严重 33 条（6.9%）回到常态，但**高危 158 条（33.2%）与中危 215 条（45.2%）构成的“长尾”里有多条实质高危**。按风险性质可分为四组：其一，**远程运维与控制面**——AnyDesk 未认证 RCE（有 PoC）、HAProxy Data Plane API 认证全局失效、ZITADEL Login V2 会话令牌伪造（`CVE-2026-109373`，可利用时间序列猜解他人会话 Cookie，含已完成 MFA 的管理员会话）、OTRS 的 `Remote-User` 头信任（`CVE-2026-93582`，`CWE-290` 认证欺骗）。其二，**AI/Agent 组件**——ExLlamaV3 模型加载、PraisonAI 未授权 Agent 调用（可直接消耗模型额度、访问私有上下文、触发工具副作用）、obsidian-tc 的 MCP 跨 vault 越权（`CVE-2026-77366`，任何合法令牌都能指定他人 vault 读写删）、Crawl4AI 的 SSRF（经 `link_preview_config` 触达内网与云元数据）。其三，**企业数据平台**——Progress MarkLogic 一批 9.9 权限类缺陷。其四，**嵌入式与网络设备**——TRENDnet TEW-751DR/752DRU/733GR、Edimax BR-6208AC、Netcore NR268、Linksys E1700 的未认证命令注入（均为 9.3）。KEV 侧本期新增 Ivanti Connect Secure 与 Microsoft Windows 各一条、期限仅 3 天，属“必须当日闭环”的硬约束；结合上期 KEV 无新增，可判断 CISA 的收录节奏呈“隔几天集中补录”的形态。PoC 生态方面，AnyDesk 已有公开 PoC 目录，其余重点编号四源均未命中。

!!! danger "研判结论：较高风险"
    本期**同时出现“运维通道被打穿”与“AI 组件默认不安全”两条风险线**，且 AnyDesk 已有公开 PoC、KEV 又有两条 3 天期限的硬性要求。建议：① 当日核实 Ivanti Connect Secure 与 Windows 相关 KEV 项的补丁状态；② 24 小时内完成 AnyDesk 版本排查（尤其是对外暴露的中控/跳板机）；③ 对 HAProxy Data Plane API、ZITADEL、OTRS 三类“认证控制面”组件做配置核查；④ 对本地推理与 Agent 平台补上“模型/工具来源可信”这一前置约束。

#### 3.1.2 漏洞摘要

AnyDesk 8.0.3 之前的版本在会话协议 mode 5 的流包（stream packet）处理逻辑中，**未对载荷长度字段做有效性校验**（`CWE-130` 长度参数处理不当），导致堆缓冲区溢出。研究者在 Linux 平台上演示了完整利用：攻击者**无需受害者批准桌面控制**、也无需任何凭据，即可在目标主机上以 root 权限执行命令。CVSS 9.8。AnyDesk 的部署特点放大了这一漏洞的影响：它通常被运维团队安装在中控机、跳板机与员工终端上，且**为保证可远程接入，往往长期对外可达**；一旦存在未认证 RCE，攻击者可将其反转为批量控制内网的手段——把运维工具变成攻击者的命令通道。NVD 引用直接给出研究者公开的 PoC 目录（`v12-security/pocs/anydesk`），说明利用代码已经可获取。该编号 EPSS 约 1.6%，为本窗口最高，但仍远低于真正大规模扫描的水平，**当前处于“手工可利用、自动化未跟上”的阶段**。

> 原文摘要（NVD）：AnyDesk before 8.0.3 allows unauthenticated remote attackers to execute arbitrary code via a heap-based buffer overflow, as demonstrated on Linux for command execution as root without the victim approving desktop control. In the stream packet handler for mode 5 in the session protocol, a payload length value is not validated.

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | AnyDesk 服务监听端口（默认 7070/TCP，或经中继）可达 |
| 身份认证 | 无需 | 无需任何凭据即可触发 |
| 用户交互 | 不需要 | 无需受害者交互 |
| 特定配置 | 否 | 默认配置即受影响；Linux 客户端已实证可利用 |
| 利用复杂度 | 低 | 中（需构造协议包，但 PoC 已公开） |

**技术原理：**

协议解析器在处理变长字段时的标准做法是“先校验声明长度与剩余缓冲区、与字段上限的关系，再拷贝”。此处 mode 5 的流包处理器直接信任了包内的长度值，用它决定拷贝字节数，而目标缓冲区按固定上限分配，超长声明即造成堆越界写。堆溢出在具备可控写入内容与可重复触发的前提下，可通过堆布局操作用于覆盖函数指针或对象虚表，最终劫持控制流；研究者在 Linux 上以其服务的高权限（root）上下文完成利用，因此不需要额外的本地提权步骤。

**核心利用链：**

```text
攻击者
  └─ 定位暴露的 目标组件（目标产品）
      └─ 发送畸形输入触发缺陷逻辑
          └─ 触发 CWE-130 对应处理逻辑
              └─ 造成信息泄露、拒绝服务或状态破坏
                  └─ 横向利用或持久化（视环境）
```

#### 3.4.2 漏洞摘要

ExLlamaV3 的 EXL3 权重加载器在选择 CUDA kernel 时，使用**模型文件内提供的索引**，但加载前未验证该索引是否在有效范围内（`CWE-20` 输入校验不当、`CWE-125` 越界读、`CWE-787` 越界写）。因此一个恶意构造的模型文件可以迫使代码读取并调用越界的函数指针，**可稳定复现崩溃**；在特定主机内存布局配合下，攻击者可能达成“受控的间接内核调度”。CVSS 9.8，由 CERT/CC 协调披露（VU#369611）。这类漏洞重新定义了本地推理栈的信任模型：传统上“下载模型”被视为低风险动作，但当加载器把模型内容当作可信元数据使用时，**模型文件就变成了可执行输入的载体**。对企业而言，风险点集中在“模型仓库未做来源校验”“内部共享目录可写”“第三方模型转换脚本”三条路径上。

> 原文摘要（NVD）：ExLlamaV3’s EXL3 loader uses an untrusted, model-supplied index to select a CUDA kernel without first verifying that the index is within bounds. A malicious model can force the code to read and invoke an out‑of‑range function pointer, resulting in a reproducible crash. Under specific conditions involving certain host memory layouts, it may be possible for an attacker to exploit this vulnerability to achieve controlled indirect kernel dispatch during model load.

#### 3.4.5 利用条件与技术原理

| 条件 | 状态 | 说明 |

| 网络可达 | 是 | 本地模型加载（需攻击者能提供模型文件） |

**技术原理：**

模型格式通常含有描述层结构、量化参数与算子选择的元数据。当加载器把这些元数据直接用作数组下标或函数表索引，而未与合法范围比对时，越界索引即指向任意内存位置；若该位置被解释为函数指针并被调用，控制流即被劫持。GPU 侧还涉及主机与设备内存的映射关系，因此“可控性”取决于内存布局，这也解释了公告中“崩溃可稳定复现、利用需特定条件”的表述。

**核心利用链：**

```text
攻击者
  └─ 定位暴露的 目标组件（目标产品）
      └─ 发送特制长度/结构的数据包
          └─ 触发 CWE-20, CWE-125 对应处理逻辑
              └─ 破坏内存并劫持控制流
                  └─ 横向利用或持久化（视环境）
```

## 五、当日处置建议

1. **当日闭环 KEV 两项**：Ivanti Connect Secure（`CVE-2026-104935`）与 Windows（`CVE-2026-96951`）期限 2026-10-16，仅 3 天。这两项不属于本期 NVD 统计范围，容易被只看当日条目的流程漏掉，建议把 KEV 新增检查固化为每日固定动作。
2. **远程桌面工具做专项排查**：AnyDesk 已有公开 PoC，且这类工具天生对外可达。建议核查版本、禁止 7070 直连、强制走自建中继，并检查终端是否存在异常 root 子进程。
3. **控制面组件按“配置即攻击面”检查**：HAProxy Data Plane API 的失败开放、ZITADEL 的会话 Cookie 伪造、OTRS 的 Remote-User 头信任，都属“配置或实现层面的信任错位”。建议对管理面组件统一核查：认证是否按监听维度生效、是否信任客户端可伪造的头、会话令牌是否有完整性保护。
4. **把“模型文件”纳入供应链安全管理**：ExLlamaV3 的教训是模型即输入。建议对模型仓库做哈希白名单、对加载进程做权限隔离、对模型目录设只读。
5. **AI Agent 平台核查未授权端点**：PraisonAI 的 Agent 列表与调用接口无访问控制，会直接消耗模型额度并触发工具副作用。建议对 Agent 平台做一次未认证端点扫描。
6. **MarkLogic 类数据平台先查账号再打补丁**：持久化管理员账号不会因补丁而消失。升级的同时必须审计用户清单，否则补丁只堵住了入口、没清除驻留。
