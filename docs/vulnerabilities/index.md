# 每日漏洞情报归档

按日期归档每日采集的网络安全漏洞情报。

## 采集口径与数据源

每日报告以 **NVD REST API 2.0** 的发布窗口为主干（`(D-2)T21:00Z` 至 `(D-1)T21:00Z`，对应北京时间 05:00 对齐，与相邻期次无缝衔接），并叠加六类富化源做交叉核验：

| 数据源 | 角色 | 说明 |
| --- | --- | --- |
| NVD REST API 2.0 | 主干 | 漏洞本体、CVSS（4.0→3.1→3.0→2.0 降序取用）、CWE、CPE、参考链接 |
| CISA KEV | 在野利用 | 以 `dateAdded` 精确对齐当期，单独列示新增项与处置期限 |
| FIRST EPSS | 利用概率 | 未来 30 天利用概率，用于排序辅助（存在 1–3 天滞后） |
| Exploit-DB | 公开利用代码 | `files_exploits.csv` 全库 CVE 索引 |
| Metasploit Framework | 模块化利用 | `modules_metadata_base.json` 全库 references 索引 |
| Nuclei Templates | 可执行检测 | GitHub 全量目录精确匹配（非文件名猜测） |
| GitHub | 社区 PoC | 仓库检索，记录仓库名、Stars、创建时间，区分“早于披露”的 PoC |
| OSV.dev / 厂商公告 | 生态对照 | 开源组件与厂商安全公告交叉确认 |

**PoC 判定规则**：Nuclei／Metasploit／Exploit-DB／GitHub 四源任一命中即计为“已公开”，并在各漏洞小节逐条列示命中与未命中结果；NVD 引用中的 GHSA、commit 链接不计为 PoC，避免把“修复提交”误报为“利用代码”。

**已知数据滞后**：① NVD 部分条目处于 `Received` / `Awaiting Analysis`，尚未有 CVSS，故“严重/高危”计数为下限；② EPSS 数据集通常滞后 1–2 天，最新条目可能无评分；③ KEV 存在“历史编号回溯收录”，故按 `dateAdded` 而非 CVE 年份统计。

> 2026-10-10 至 2026-10-27（第 71–88 期）为停更期次的回溯补齐，采用上述同一口径重算，窗口严格衔接、无重叠（末期为覆盖至当日执行时刻的扩展窗口，已在正文注明）。
