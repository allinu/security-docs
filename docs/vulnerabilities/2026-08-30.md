### 3.1 `CVE-2026-76639` — 宇树 G1 机器人 chat_go 路径穿越致未认证 root RCE

!!! danger "高危漏洞"
    影响宇树（Unitree）G1 EDU 人形机器人固件 1.5.2 及以下版本。网络相邻攻击者可经未认证的 WebRTC-to-DDS 桥（TCP 9991）与路径穿越组合，向 bashrunner 服务可信目录写入恶意脚本并触发以 root 执行的任意命令，全程无需任何凭据。

#### 3.1.2 漏洞摘要

该漏洞由安全研究员 Olivier Laflamme 发现（约三个月研究，技术文章 [boschko.ca/g1-ble-rce](https://boschko.ca/g1-ble-rce/)），是"RCE #1"三缺陷链：① G1 的 AI 聊天机器人服务 **chat_go** 接受"知识库"上传，但对写入磁盘的文件名几乎不做校验，经典路径穿越载荷可把任意文件写入文件系统任意位置（包括另一服务 **bashrunner** 视为可信的脚本目录）；② bashrunner 以扩展名无关的方式对可信目录内容执行 `sh`；③ 硬编码的 AES-128 密钥（世界可读权限存储）可解锁一个**无主题白名单、无参与者认证**的 WebRTC-to-DDS 桥（CycloneDDS Domain 0），攻击者据此发布 DDS 控制消息重启 bashrunner、触发对植入脚本的执行，最终以 uid 0（root）运行任意命令。攻击全程无需认证，仅需网络相邻可达（TCP 9991）。

> 该机器人运行未认证的 WebRTC-to-DDS 桥（TCP 9991）并持有硬编码/弱保护的 AES 密钥，配合 chat_go 知识库上传的路径穿越与 bashrunner 的无过滤脚本执行，形成"网络相邻 → root shell"的完整链路。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需网络相邻可达 WebRTC-to-DDS 桥（TCP 9991） |
| 身份认证 | 无需 | 桥接服务无参与者认证、无主题白名单 |
| 用户交互 | 不需要 | 全程无物理接触、无用户操作 |
| 特定配置 | 是 | 依赖硬编码 AES 密钥（世界可读）与 bashrunner 可信目录机制 |
| 利用复杂度 | 低 | 路径穿越+脚本执行，利用链公开 |

**技术原理：**

chat_go 知识库上传接口对文件名缺少路径规范化校验（CWE-22），允许 `../` 穿越写入 bashrunner 的脚本执行目录；bashrunner 对该目录内的文件以 `sh` 方式执行且不校验扩展名；同时 WebRTC-to-DDS 桥（TCP 9991）无认证、无主题白名单，配合硬编码 AES 密钥即可由攻击者直接发布 DDS 控制消息操纵服务生命周期（重启 bashrunner、触发脚本执行），最终在 root 权限下执行任意命令（CWE-306）。

**核心利用链：**

```text
攻击者（网络相邻）
  └─ 发现未认证 WebRTC-to-DDS 桥（TCP 9991，硬编码 AES 密钥）
      └─ 经 DDS 控制消息重启 bashrunner 服务
          └─ chat_go 知识库上传构造 ../ 路径穿越载荷
              └─ 恶意脚本写入 bashrunner 可信脚本目录
                  └─ bashrunner 以 sh 执行（uid 0）
                      └─ 实现 root 权限任意命令执行
```

### 3.2 `CVE-2026-76640` — 宇树 G1 机器人 BLE GATT 栈溢出致未认证 root RCE

!!! danger "高危漏洞"
    影响宇树 G1 EDU 固件 1.5.2 及以下版本。蓝牙范围内的未配对攻击者可经免配对 BLE 写入、云侧解密预言机、WiFi 配置注入与 500 字节缓冲区溢出四步组合，在无任何凭据的情况下获取 root shell，并可通过被攻陷机器人对邻近 G1 重复利用。

#### 3.2.2 漏洞摘要

该漏洞是研究员 Olivier Laflamme 披露的"RCE #2"五缺陷链（[技术文章](https://boschko.ca/g1-ble-rce/)）：① GATT 特征 `0xFFE2` 以裸 WRITE 权限注册，附近 BLE 客户端**无需配对**即可写入；② 明文引导操作码 `0xF2` 可获取机器人 RSA 包裹的 AES-128 密钥 blob；③ 宇树云 API `/device/bindExtData`（global-robot-api.unitree.com）会为**任意已登录（免费）账户解密该 blob**——此前不校验账户是否拥有该机器人（云端解密预言机），单个 AES-128 密钥同时解锁 BLE v3 握手与 WiFi 配置命令；④ WiFi 配置阶段，121 字节 PSK 触发 `wpa_connect.sh` 的不安全手动回退分支，未转义数据注入未加引号的 heredoc，强制机器人加入攻击者控制的热点；⑤ 借 chat_go→bashrunner 链泄露 `btgatt-server` 的 PIE 基址后，以 1050 字节载荷写穿 500 字节的 `wifi_ssid` 缓冲区，伪造 mainloop 清理项，事件循环退出时以 root 调用 `system()` 执行攻击者命令。全程无物理接触、无配对、无凭据。

> 蓝牙免配对写入 + 云 API 解密预言机（任意账户可解） + WiFi 配置注入 + 栈溢出四步组合，使攻击者可在蓝牙范围内对任何 G1 完成未认证 root 接管，且被攻陷机器人可蠕虫式攻击邻近 G1。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需蓝牙（BLE）范围内可达 |
| 身份认证 | 无需 | GATT 特征 0xFFE2 免配对可写；云解密对任意免费账户开放 |
| 用户交互 | 不需要 | 无物理接触、无用户操作 |
| 特定配置 | 是 | 依赖云解密预言机（已修复）与 WiFi 配置回退分支 |
| 利用复杂度 | 高 | 五缺陷链，需 ASLR 绕过（借助 chat_go 链泄露 PIE 基址） |

**技术原理：**

BLE GATT 服务将特征 `0xFFE2` 注册为裸 WRITE 权限（CWE-306，免配对）；明文引导操作码返回 RSA 包裹的设备 AES-128 密钥，而宇树云 `/device/bindExtData` 接口在 2026-08 修复前对任意已登录账户返回解密结果（不校验设备所有权），形成可滥用的解密预言机；密钥解锁 WiFi 配置命令后，121 字节 PSK 触发 `wpa_connect.sh` 手动回退分支，未加引号 heredoc 注入攻击者控制的 wpa_supplicant 配置，使机器人加入攻击者热点；最后利用 chat_go→bashrunner 链泄露 `btgatt-server` PIE 基址，以 1050 字节写入溢出 500 字节 `wifi_ssid` 缓冲区（CWE-787），伪造 mainloop 清理函数指针，事件循环退出清理路径以 root 调用 `system()`。

**核心利用链：**

```text
攻击者（BLE 近场）
  └─ 免配对写入 GATT 特征 0xFFE2，获取 RSA 包裹的设备密钥 blob
      └─ 经云 API /device/bindExtData 由任意账户解密得到 AES-128 密钥
          └─ 解锁 BLE v3 握手与 WiFi 配置命令
              └─ 121 字节 PSK 触发 wpa_connect.sh 不安全回退，注入 wpa_supplicant 配置
                  └─ 机器人加入攻击者热点（进入同网段）
                      └─ 借 chat_go 链泄露 PIE 基址，1050 字节写穿 500 字节缓冲区
                          └─ 伪造清理项，system() 以 root 执行任意命令
```

### 3.3 `CVE-2026-74232` — ZBT 路由器 SPEAKINGSTONE 云控后门（出厂预置）

!!! danger "严重漏洞"

#### 3.3.2 漏洞摘要

VulnCheck 零日研究团队（研究员 Jacob Baines）在追溯此前披露的 ENDLESSDOORS 植入物时，从一台在美售卖的贴牌路由器（Deep Orange 3G/4G/LTE 路由器，实为 ZBT-WE826-T2 白牌）固件中发现两个新植入物，SPEAKINGSTONE 即其一。它由连接看门狗 **inetdetect** 拉起、以 Nim 编写、运行服务名为 **yunmgrd**：设备以 UDP 协议（内部称 zbtProtocol）向硬编码 C2 服务器（ac-link[.]com → 47.107.224[.]89，阿里云深圳；备用域 www.findmyipaddr[.]com）回连，出站报文仅做单字节 XOR 混淆（0x1f），入站命令明文且无任何认证——设备无法验证 C2 真伪，**网络路径上的任何人**都可劫持信道。支持的指令包括：任意命令执行（0x2507 cmdRun）、窃取 PPPoE 用户名密码（0x2502）、写入并激活 DNS 劫持列表（0x230b dnsSet）、开启反向 SSH 隧道（0x2405 onoff）等。VulnCheck 注册了无人持有的备用 C2 域并搭建蜜罐，截至 2026-08-21 已有 392 台设备回连（390 台位于中国、363 台为运行固件 3.0.0.4.528 的 L3_V2_8 机型——疑似中国移动网络上的运营商 CPE；最长在线设备已持续回连近两年），主 C2 ac-link[.]com 仍存活，全量影响面未知。

> 出厂固件预置的云控后门：设备主动回连 C2、入站命令明文无认证，网络路径上的攻击者可劫持信道对设备实现 root 级完全控制，并窃取宽带凭据、篡改 DNS、建立反向隧道。

#### 3.3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者位于设备与 C2 通信路径上（中间人）即可劫持；无需直接触达设备 |
| 身份认证 | 无需 | 入站命令明文、无认证、无会话 |
| 用户交互 | 不需要 | 设备持续自动回连 |
| 特定配置 | 是 | 设备固件内置该植入（出厂预置） |
| 利用复杂度 | 低 | 协议细节公开，XOR 混淆与命令格式已公开 |

**技术原理：**

固件出厂预置 yunmgrd（Nim 编写），由 inetdetect 看门狗拉起，持续经 UDP 10000 端口向硬编码 C2（ac-link[.]com / findmyipaddr[.]com）发送设备指纹信标（机型、固件、MAC、SSID、LAN IP、GPS 等，msgType 0x1001）。C2 下发的指令入站为明文、无认证（CWE-300），设备端对指令来源不做任何校验，路径上攻击者可伪造 C2 指令；出站报文仅单字节 XOR（0x1f）混淆，可被轻易还原（CWE-506 内嵌后门）。指令集含任意命令执行、PPPoE 凭据外传、DNS 劫持、反向 SSH 隧道等完整远控能力。

**核心利用链：**

```text
攻击者（网络路径中间人 / 伪造 C2）
  └─ 截获/监听设备向 ac-link[.]com 的 UDP 回连信标（明文可还原）
      └─ 伪造 C2 下发 cmdRun（0x2507）指令（无认证、无加密）
          └─ 设备以 root 执行任意命令
              ├─ pppoe（0x2502）窃取宽带 PPPoE 用户名密码
              ├─ dnsSet（0x230b）写入 DNS 劫持列表并激活
              └─ onoff（0x2405）开启反向 SSH 隧道（绕过 NAT/防火墙）
```

### 3.4 `CVE-2026-74233` — ZBT 路由器 DARKLANTERN 后门命令注入（出厂预置）

!!! danger "严重漏洞"
    影响 ZBT/Zbtlink 系列路由器固件。固件出厂预置 DARKLANTERN 后门（infosrvd 服务，UDP/9992），默认防火墙明确放行公网对该端口的入站访问；未认证攻击者只需发送一个构造的 UDP 命令包即可在设备上以 root 执行任意命令。

#### 3.4.2 漏洞摘要

DARKLANTERN 与 SPEAKINGSTONE 同为 VulnCheck 在 ZBT 白牌路由器固件中发现的出厂预置植入物，Nim 编写、由 inetdetect 看门狗拉起，运行服务名为 **infosrvd**，监听 **UDP 9992** 端口。路由器默认防火墙明确放行公网对该端口的入站（iptables 规则 `ACCEPT udp -- anywhere anywhere udp dpt:9992`），**出厂即公网可达**。协议（内部称 revProto）简单、无认证、无加密：19 字节信息探测包即返回机型、固件、MAC、SSID、公网 IP 等设备指纹；命令包（type 0x17）携带 shell 字符串，服务直接以 `system("/etc/exec/cmd " + payload)` 执行，分号即可突破固定前缀执行任意命令，无长度限制、无字符过滤。命令包的"防护"形同虚设：4 字节校验 token 为 `md5("mqonu.com" + payload)` 的后 4 个 hex 字符，密钥硬编码且不可更改，任何人可自行计算；MAC 字段校验存在**全零 MAC 直接放行**的硬编码绕过。VulnCheck 公网测绘（2026-08-18 至 08-21）发现 203 台公网可达实例，覆盖 22 国、16 种机型，其中每台设备都等于一个公网可触达的未认证 root shell。

> 出厂即公网可触达的未认证 root 后门：UDP/9992 被默认防火墙放行，命令包校验基于硬编码密钥（可伪造）+ 全零 MAC 绕过，一个数据包即 root shell。

#### 3.4.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | UDP/9992 默认被防火墙放行，公网直接可达 |
| 身份认证 | 无需 | 校验仅"硬编码密钥 token + MAC"，均可伪造/绕过 |
| 用户交互 | 不需要 | 无 |
| 特定配置 | 是 | 设备固件内置该植入（出厂预置） |
| 利用复杂度 | 低 | 协议细节与密钥公开，单包即可利用 |

**技术原理：**

infosrvd 监听 UDP/9992（CWE-506 内嵌后门；防火墙默认放行）。命令包载荷直接拼入 `system("/etc/exec/cmd " + payload)` 执行（CWE-78），分号可突破固定前缀；token 校验为 `md5("mqonu.com"+payload)` 后 4 位 hex（CWE-321，密钥硬编码、公开可伪造）；MAC 校验存在全零 MAC 硬编码放行。信息探测包（19 字节）无任何认证即返回设备完整指纹，可用于批量测绘与识别。

**核心利用链：**

```text
攻击者（公网任意位置）
  └─ 向目标 UDP/9992 发送 19 字节信息探测包（可选，用于指纹识别）
      └─ 构造命令包：payload = 恶意 shell 命令（分号突破固定前缀）
          └─ token = md5("mqonu.com" + payload) 后 4 位 hex；MAC 字段填全零（硬编码绕过）
              └─ 设备执行 system()，以 root 运行任意命令
```

#### 3.4.11 风险影响

漏洞成功利用后，可能导致：

- 公网任意位置未认证 root 接管设备（单包利用）；

- 运营商/企业网络边界设备被完全控制。

## 五、当日处置建议

1. **ZBT 路由器双后门（`CVE-2026-74232`/`CVE-2026-74233`，P0）**：立即盘点 ZBT/Zbtlink/MoreQuick/Deep Orange 等白牌路由器与 4G LTE CPE，受影响设备按"不可信设备"处置——下线、更换或隔离；边界防火墙上**默认阻断 UDP 9992 入站**与到 `ac-link[.]com`、`findmyipaddr[.]com`、`47.107.224.89` 的所有出站（DNS+IP 双封禁）；修改宽带 PPPoE 密码并核查 DNS 是否被篡改；
2. **ServiceNow AI 平台漏洞（`CVE-2026-18885`/`CVE-2026-18886`/`CVE-2026-74820`，P0；`CVE-2026-6876`，P1）**：自建与合作伙伴实例立即安装 KB3152242 对应补丁，托管实例确认更新状态；同时核对 7 月披露的 `CVE-2026-6875`（EPSS 99.5%）KB3137947 补丁是否已安装；升级前收敛实例公网暴露面并启用审计告警；
3. **宇树 G1 机器人（`CVE-2026-76639`/`CVE-2026-76640`，P1）**：部署 G1/G1 EDU 的单位确认固件版本（≤1.5.2 受影响）并升级至修复固件；限制 9991/TCP 与机器人蓝牙近场暴露，将机器人网络与业务网络隔离，评估物理安全风险；
4. 对已在野利用、已纳入 CISA KEV 或存在成熟 PoC 的漏洞立即开展资产排查（本期菲律宾事件利用的 `CVE-2023-49105` 需确认 ownCloud 实例已修复）；
5. 对疑似遭受攻击的系统保留日志、流量、进程、文件及内存证据，开展 WebShell、恶意进程、异常账号、反向隧道及横向移动排查（重点核查路由器类设备的异常外联）；
6. 完成修复后进行复测，并更新资产台账和漏洞处置记录。
