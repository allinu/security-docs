### 1.3 今日重点关注

1. **`CVE-2026-76504`：Cisco Catalyst SD-WAN Manager 未认证认证绕过（当日纳入 CISA KEV，期限 2026-10-03）**  
   攻击者只需向受影响系统的 API 发送**构造过的 HTTP 请求**，即可利用 URI 编码处理不当绕过本应限制特定 API 端点的认证规则，**以管理员（admin）用户身份访问 API**，无需任何凭据，CVSS 3.1 为 **9.8（严重）**（`AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H`）。SD-WAN Manager 是广域网的集中管控面，**通常承载全网的策略下发、设备纳管与凭据分发**。当前状态为 **已纳入 CISA KEV（`dateAdded` 2026-09-30）+ 已发布补丁（Cisco 安全公告）**，**建议立即核对外网暴露面并升级**。

2. **`CVE-2026-88772`（关联 `CVE-2026-88771`）：Citrix NetScaler ADC/Gateway 零日在野利用，出现定制工具 WHIPSHOT / SLAPSHOT（KEV 期限 2026-09-30，已逾期 1 天）**  
   `CVE-2026-88772` 为 DTLS 处理的内存溢出，可致**远程代码执行或拒绝服务**（NVD 3.1 = 8.1，`AV:N/AC:H`；Citrix 4.0 评分为 **9.5**，`AV:N/AC:H/PR:N/UI:N`，**两者差异源于评分体系与攻击复杂度判定，见 3.2.1**）；**在 Gateway 上 DTLS 对 VPN 虚拟服务器默认开启**，攻击发生在**登录前的首次握手阶段**。Mandiant/GTIG 确认该漏洞自 **2026 年 9 月上旬**起被利用，攻击成功后植入伪装成 `.deb`/`.sig` 的 PHP WebShell（`WHIPSHOT`）与 Python 代理/隧道（`SLAPSHOT`）并以 root 权限横向进入内网，受影响行业包括政府、金融、教育与法律服务（北美、欧洲）。**状态为已在野利用 + 已纳入 CISA KEV（期限已逾期）+ 已发布补丁**，**建议立即升级或临时关闭 DTLS 并封禁入站 UDP/443**。

3. **Apache MINA SSHD 认证绕过族（`CVE-2026-77185`、`CVE-2026-94053`、`CVE-2026-94052` 均为 9.1）**  
   `CVE-2026-77185`（**9.1**）为 `sshd-core` 异步认证机制逻辑缺陷，可**跳过公钥/主机基认证的签名校验**；`CVE-2026-94053`（**9.1**）为 `sshd-ldap` 组件 LDAP 过滤器元字符未转义，**用户名与口令均为 `*` 即可通过认证**；`CVE-2026-94052`（**9.1**）为 `sshd-ldap` 的 `LdapPasswordAuthenticator` 缺失校验直接绕过认证；`CVE-2026-93994`（8.1）为多认证（双公钥）方案下**同一把密钥提交两次即可通过**。**MINA SSHD 被大量 Java 中间件、CI/CD 与自研系统内嵌**，凡以该库作为 SSH 服务端（尤其启用 `sshd-ldap` 或以 SSH 作为运维/自动化入口）者应**当日在核对版本后升级至 2.20.0 或 3.0.0-M6**。

#### 3.1.2 漏洞摘要

该漏洞位于 Cisco Catalyst SD-WAN Manager 的 **API 会话认证管理**逻辑中，根因是**对 HTTP 请求中 URI 编码的处理不当**（`CWE-177`）：系统对某个特定 API 端点设置了一条认证规则以限制访问，但由于 URI 编码未被正确规范化，攻击者可构造等价但编码形式不同的请求路径，使该请求**在认证规则匹配阶段“看起来”不指向受保护端点，而在后续处理阶段又被解析为受保护端点**，从而**完全绕过认证**。根据 Cisco 公告，成功利用可使**未认证的远程攻击者获得 admin 用户权限并访问 API**。

该漏洞的严重性由三点决定：**其一，无需任何身份认证（`PR:N`）与用户交互（`UI:N`），攻击复杂度低（`AC:L`）；其二，受影响对象是 SD-WAN 的集中管理面，通常纳管全网分支设备、承载策略下发的 TLS 凭据；其三，CISA 已将其纳入 KEV 目录并给出 2026-10-03 的整改期限**，说明其构成“对联邦网络具有重大风险”的已知被利用漏洞。

> 示例：攻击者从互联网直接向暴露的 SD-WAN Manager 管理接口发送一条经过特殊编码的 HTTP 请求（例如对受限 API 路径中的字符采用双重编码或非规范编码），认证规则因路径未规范化而未生效，请求进入业务处理流程后由后端还原为管理员接口调用，攻击者遂以 admin 身份读取配置、下发策略或提取设备与凭据信息。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需能访问 SD-WAN Manager 的 HTTPS 管理接口（常见 443/8443） |
| 身份认证 | 无需 | `PR:N`，无需任何账号或权限 |
| 用户交互 | 不需要 | `UI:N` |
| 特定配置 | 否 | 缺陷位于 API 认证规则处理路径，无需特殊开关 |
| 利用复杂度 | 低 | `AC:L`，仅需构造编码变形的 HTTP 请求 |

**技术原理：**

认证绕过的本质是**“安全决策路径”与“业务处理路径”对同一请求的解析结果不一致**（解析差异 / parser differential）。SD-WAN Manager 在收到请求后，先依据 URI 的字符串/编码形态判断其是否命中受保护的 API 端点并施加认证规则；但由于 URI 编码未被正确规范化（如未对 `%2e`、双重编码或大小写/分隔符变体做归一化），攻击者可使**“认证判定阶段”看到的是一个不受限路径，而“后端路由阶段”看到的是受限的管理员端点**。两者之间的差异即为认证绕过。Cisco 的修复方向是对 URI 编码做规范化处理，使认证判定与后端路由基于同一规范化结果。

**核心利用链：**

```text
攻击者
  └─ 发现互联网可达的 SD-WAN Manager 管理接口
      └─ 构造对受限 API 端点路径做编码变形的 HTTP 请求
          └─ 认证规则因 URI 未规范化而未匹配（判定为“不受保护”）
              └─ 请求进入后端并还原为管理员 API 调用
                  └─ 未认证获得 admin 会话能力
                      └─ 读取配置、下发策略、获取设备与凭据信息
```

### 3.2 CVE-2026-88772（关联 CVE-2026-88771）— Citrix NetScaler DTLS 零日在野利用：WHIPSHOT 与 SLAPSHOT

!!! danger "严重漏洞（已确认在野利用，CISA KEV 期限 2026-09-30 已逾期）"
    Citrix NetScaler ADC/Gateway 在 DTLS 处理上存在内存溢出，攻击者可在**登录前的首次握手阶段**以特制/分片记录头破坏 packet engine 堆内存，**以 root 权限在底层 FreeBSD 上执行任意代码**，随后植入伪装 WebShell（`WHIPSHOT`）并部署代理隧道（`SLAPSHOT`）横向进入内网。在 Gateway 上 DTLS 对 VPN 虚拟服务器**默认开启**，攻击无需任何凭据。

#### 3.2.2 漏洞摘要

该漏洞存在于 Citrix NetScaler ADC 与 NetScaler Gateway 的 **packet engine 对 DTLS（UDP 上的 TLS）流量的处理逻辑**中。攻击**发生在设备与客户端建立加密连接的首次握手阶段，早于任何登录**：`packet engine` 在解析 DTLS 记录头时缺少必要的长度/边界校验，攻击者投递**特制或分片的记录头**即可**破坏堆内存边界**（`CWE-119`），进而**劫持控制流并以 root 权限在底层 FreeBSD 系统上执行 Shellcode**。

根据 Google Threat Intelligence Group 的报告，**成功利用会在设备日志中留下两类痕迹**：（1）`SSL_HANDSHAKE_FAILURE`，客户端版本为 `DTLSv1.0`，原因为 `"Handshake failure-Internal Error"`；（2）**packet engine 进程崩溃且看门狗未能将其重启**。攻击者进入后首先安装 WebShell——通过修改 `httpd.conf` **将 `.deb`（或更隐蔽的 `.sig`）文件类型标记为可执行 PHP**，从而让伪装成 Debian 安装包/签名的 WebShell 得以运行，并配置重定向使对无害 `.ico` 文件的请求实际由隐藏的 PHP Shell 处理（部分请求还返回“看似正常”的 404 但处理耗时异常）；为长期维持 root，安装器将 `/bin/sh` 设为 **setuid**，随后**强制重启设备**以固化改动。工具层面，**`WHIPSHOT`** 为上述 PHP WebShell（从顺序 HTTP 头字段读取 Base64 编码命令，经本地回环转发执行，关闭自身错误输出并恒返回 404），**`SLAPSHOT`** 为 Python 编写的**代理/隧道**（打开本地端口将 TCP 流量转发进入内网，空闲 15 分钟关闭会话、无活动 10 分钟自毁并删除端口与锁文件）。受影响行业覆盖**北美与欧洲的政府、金融服务、教育与法律服务**；GTIG 指出此类边缘设备零日约占 2025 年企业相关零日漏洞的一半。

> 示例：攻击者向暴露在互联网的 NetScaler Gateway 的 UDP/443 发送畸形或被分片的 DTLS 记录头，在**未提供任何凭据**的情况下触发握手路径中的堆溢出，获得 root Shellcode 执行；随后以伪装扩展名的 PHP WebShell 建立持久化，并用 Python 隧道将内网 TCP 流量引出，最终在设备上完成凭据探索与横向移动。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达设备的 **UDP/443（DTLS）**；Gateway 的 VPN 虚拟服务器默认开启 DTLS |
| 身份认证 | 无需 | 利用发生在**登录前的握手阶段**，`PR:N` |
| 用户交互 | 不需要 | `UI:N` |
| 特定配置 | 是 | 需 **DTLS 处于启用状态**（Gateway VPN vServer 默认开启；管理员可 `-dtls OFF` 关闭） |
| 利用复杂度 | 高（NVD `AC:H`）/ 中（厂商 4.0 `AC:H`） | 需具备针对该内存破坏缺陷的利用能力；但攻击者已在实际活动中掌握 |

**技术原理：**

NetScaler 的 packet engine 在处理入站 DTLS 流量以建立加密连接时，对记录头的长度/偏移字段缺少充分校验。攻击者发送**畸形或被分片的记录头**，使解析器计算出错误的缓冲区边界，**写入越过已分配内存区域并破坏堆上相邻对象**。在获得可控的堆破坏原语后，攻击者可将控制流重定向到注入的 Shellcode；由于 packet engine **本身以 root 运行**，代码执行直接获得 root 权限——这解释了为何“第一次获取 root 很容易”。持久化阶段通过修改 Apache 配置把非脚本扩展名当作 PHP 执行，并使用 setuid `/bin/sh` + 强制重启来跨越重启保留权限。

**核心利用链：**

```text
攻击者
  └─ 定位互联网可达的 NetScaler Gateway（UDP/443，DTLS 默认开启）
      └─ 发送畸形/分片的 DTLS 记录头（登录前握手阶段）
          └─ packet engine 堆内存边界破坏
              └─ 控制流劫持 → 以 root 执行 Shellcode（FreeBSD 底层系统）
                  └─ 修改 httpd.conf 将 .deb/.sig 视为可执行 PHP
                      └─ 投放 WHIPSHOT（PHP WebShell）+ 部署 SLAPSHOT（Python 隧道）
                          └─ /bin/sh setuid + 强制重启固化权限
                              └─ 内网横向移动、凭据探索与数据外传
```

#### 3.2.11 风险影响

漏洞成功利用后，可能导致：

- 未经授权访问系统或业务接口（登录前即完成利用）；
- 远程执行任意系统命令（**root 权限**）；
- 获取应用、系统或数据库权限（设备底层 FreeBSD 的 root）；
- 泄露账号、密钥、配置文件及业务数据（设备所涉全部凭据）；
- 篡改网站页面、配置或业务数据（篡改 `httpd.conf` 等设备配置）；
- 植入 WebShell、后门或恶意程序（`WHIPSHOT`、`SLAPSHOT`）；
- 横向移动至其他服务器或业务系统（经 Python 隧道进入内网）；
- 中断业务服务或破坏系统可用性（强制重启、拒绝服务）；
- 被勒索软件、挖矿木马或僵尸网络利用。

#### 3.2.13 修复与缓解措施

#### 官方修复

1. 将 ADC/Gateway 升级至 `14.1-73.37`、`13.1-64.23`（FIPS/NDcPP 对应版本）或更高；
2. 同步修复同批在野利用的 `CVE-2026-88771`（同一版本修复）；
3. 升级前完成配置备份与业务影响评估（远程接入网关隔离会造成业务中断，须安排维护窗口）；
4. 升级后执行设备重启并核验版本；
5. **升级后（而非之前）轮换设备所涉全部凭据**：管理员账号、SSH 密钥、TLS 证书、LDAP/RADIUS 凭据等；
6. 重新执行检测规则并留存修复证据。

#### 临时缓解

无法立即升级时，可采取：

- 关闭 DTLS（`-dtls OFF`）并阻断入站 UDP/443（**仅阻断本漏洞路径，不能防护 `CVE-2026-88771`**）；
- 限制 VPN 门户与管理接口的互联网访问，仅允许可信来源；
- 在 WAF/IPS 或网关增加针对性拦截规则（对 DTLS 效果有限）；
- 启用多因素认证和最小权限控制；
- 修改默认账号、默认密码及默认密钥；
- 加强日志审计与异常外联检测（重点关注 3.2.9 的行为特征）；
- 对高风险设备实施网络隔离或访问收敛。

### 3.3 CVE-2026-86131 — WatchGuard Fireware OS BOVPN over TLS 客户端配置代码注入（root RCE）

!!! danger "严重漏洞（同批修复 15 个 Fireware OS 缺陷）"
    Fireware OS 在处理 BOVPN over TLS 客户端配置时存在代码注入缺陷，**控制对端 VPN 服务器的攻击者**可在受害 Firebox 上**以 root 权限执行任意命令**。BOVPN over TLS 使用 TCP/443（常被防火墙放通的端口），且利用**无需用户交互或前置权限**。

#### 3.3.2 漏洞摘要

该漏洞位于 WatchGuard Fireware OS 的 **BOVPN over TLS 客户端配置处理**路径中（`CWE-94` 代码注入，结合 `CWE-295`/`CWE-829` 的证书与信任域问题）。BOVPN over TLS 采用客户端—服务器模型，用于在 Firebox 设备之间建立 VPN 隧道，并可**将 VPN 流量承载于 TCP/443**（该端口通常被网络防火墙放通）。当 Firebox 作为**客户端**连接一个由攻击者控制的远程 VPN 服务器时，**对端返回的配置/证书内容未经过充分校验即被用于代码路径**，攻击者可据此在**连接方的 Firebox 上以 root 权限执行任意命令**。

其危险点在于：**攻击者并不需要攻破受害 Firebox 的认证，只需“成为它要连接的那台 VPN 服务器”**——而这在“分支设备主动连接总部/对端”的典型 BOVPN 拓扑中，攻击者可能通过网络位置（DNS 劫持、路由劫持、或控制被信任的对端）获得。同批 WatchGuard 发布的 15 个漏洞中还包含 DHCP `fingerd` 栈溢出（`CVE-2026-81433`，8.7，相邻网络未认证 RCE）、`wgagent` 资源耗尽（`CVE-2026-86104`，8.7）、认证进程与 NetFlow 空指针（`CVE-2026-86134`、`CVE-2026-86128`，8.7/8.2）、`iked` 整数下溢（`CVE-2026-86132`/`86133`，8.2）、SAML 授权缺陷（`CVE-2026-86101`，7.2，可越权获得 Mobile VPN with SSL 访问）等。

> 示例：攻击者通过 DNS/路由劫持或控制“对端”设备，使受害 Firebox 在建立 BOVPN over TLS 隧道时连接到自己，随后返回特制配置，触发客户端配置处理路径中的代码注入，从而以 root 身份在受害设备上执行命令。

#### 3.3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | Firebox 作为客户端连接 BOVPN over TLS 对端（TCP/443） |
| 身份认证 | 无需 | `PR:N`，无需受害设备的任何账号 |
| 用户交互 | 不需要 | `UI:N` |
| 特定配置 | 是 | 需启用并使用 **BOVPN over TLS**，且攻击者可控制/冒充对端服务器 |
| 利用复杂度 | 低（`AC:L`），但需满足 `AT:P`（控制对端） | 关键前提是攻击者控制对端 VPN 服务器 |

**技术原理：**

Fireware OS 在作为 BOVPN over TLS 客户端接收并处理对端下发的配置（与证书/信任链校验）时，未对可执行内容做充分隔离与校验，导致**不可信控制域的数据进入代码执行路径**（`CWE-829`），并形成**代码注入**（`CWE-94`）。由于处理进程本身以高权限运行，注入的命令以 **root** 身份在 Firebox 上执行。WatchGuard 通过加固客户端配置处理与证书校验完成修复。

**核心利用链：**

```text
攻击者（控制/冒充对端 VPN 服务器）
  └─ 获取受害 Firebox 的 BOVPN over TLS 连接（TCP/443）
      └─ 返回特制客户端配置/证书内容
          └─ Fireware OS 代码注入路径被触发
              └─ 以 root 权限在受害 Firebox 上执行任意命令
                  └─ 读取配置与凭据、篡改策略、作为内网跳板
```

### 3.4 Apache MINA SSHD 认证绕过族（CVE-2026-77185 / 94053 / 94052 / 93994）

!!! danger "严重漏洞族（一次披露 8 条认证相关缺陷，两条 9.1 分可致完全认证绕过）"
    Apache MINA SSHD 在同一窗口披露 8 条认证相关漏洞。其中 `CVE-2026-77185`（`sshd-core` 异步认证缺陷可跳过公钥/主机基认证签名校验）、`CVE-2026-94053`（`sshd-ldap` LDAP 过滤器元字符未转义，**用户名与口令均为 `*` 即可通过**）、`CVE-2026-94052`（`sshd-ldap` 缺失校验直接绕过认证）三条均为 **9.1 分**。该库被大量 Java 中间件与自研系统内嵌，**凡以它作为 SSH 服务端者风险极高**。

#### 3.4.2 漏洞摘要

Apache MINA SSHD 是一个 Java 客户端/服务端 SSH 库，广泛内嵌于 Java 应用、CI/CD 与运维平台。本批 8 条缺陷集中在**认证机制**上，可归纳为三类：

- **`CVE-2026-77185`（9.1，`sshd-core`）**：库中实现“异步认证（asynchronous authentication）”机制的逻辑存在缺陷。**该机制须由服务端显式编码启用**；一旦启用，缺陷可能导致**跳过公钥或主机基认证的签名校验，或返回错误结果**——即攻击者无需持有私钥即可通过公钥/主机基认证。修复版本同时**禁止该异步机制与公钥/主机基认证组合使用**（若使用则关闭会话并记录日志）。
- **`CVE-2026-94053`（9.1，`sshd-ldap`）**：`sshd-ldap` 在构造 LDAP 过滤器时**未转义元字符**，导致 **LDAP 注入**——公告明确指出**用户名与口令均为 `*` 即可成功认证**。仅在使用 `sshd-ldap` 并配置 LDAP 做口令/公钥认证的服务端受影响。
- **`CVE-2026-94052`（9.1，`sshd-ldap`）**：`LdapPasswordAuthenticator` **缺失校验**，直接绕过认证检查。同为可选组件 `sshd-ldap` 的场景。
- **`CVE-2026-93994`（8.1，`sshd-core`）**：多认证方案（如要求两把不同公钥，等价于 OpenSSH 的 `AuthenticationMethods "publickey,publickey"`）下，服务端**未强制两次提交的密钥不同**，用户**把同一把公钥提交两次即可通过**，构成部分认证绕过。

**关键限定：** `sshd-ldap` 为可选组件，**仅在使用该组件并相应配置的服务端受影响**，`sshd-core` 内置的口令认证机制不受 `94052`/`94053` 影响；`77185` 亦要求服务端显式启用异步认证机制。因此**精确的资产判定应基于“是否内嵌 MINA SSHD + 是否启用对应机制/组件”**，而非笼统认定所有 Java SSH 服务端。

> 示例：内嵌 MINA SSHD 并以 `sshd-ldap` 对接企业 LDAP 的运维/跳板系统，攻击者仅需以用户名 `*`、口令 `*` 发起 SSH 认证即可登上系统；或在内嵌该库并以异步认证 + 公钥登录的自研系统中，攻击者无需私钥即可通过认证。

#### 3.4.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达目标 SSH 服务端口（默认 TCP/22） |
| 身份认证 | 无需（`PR:N`；`93994` 为 `PR:L`） | 认证缺陷本身即为绕过手段 |
| 用户交互 | 不需要 | `UI:N` |
| 特定配置 | 是 | `77185` 需启用异步认证；`94052`/`94053` 需使用 `sshd-ldap`；`93994` 需配置多认证方案 |
| 利用复杂度 | 低 | `AC:L`，攻击面为 SSH 认证流程 |

**技术原理：** 四类缺陷均属“**认证决策被绕过或弱化**”。`77185` 是异步认证状态机与签名校验的**逻辑错误**（校验被跳过或结果被错误返回）；`94053` 是**输入未按 RFC 4515 转义**导致 LDAP 过滤器被注入（`*` 作为通配符使过滤器恒真）；`94052` 是**缺失关键校验步骤**；`93994` 是**多认证方案缺少“密钥互异”约束**，使双因素退化为单因素。

**核心利用链：**

```text
攻击者
  └─ 识别内嵌 Apache MINA SSHD 的 SSH 服务（默认 TCP/22）
      ├─ 若启用 sshd-ldap：以用户名 "*" 与口令 "*" 发起认证（LDAP 注入恒真）
      ├─ 或利用 LdapPasswordAuthenticator 缺失校验直接通过
      ├─ 或对启用异步认证 + 公钥/主机基认证的服务端跳过签名校验
      └─ 或对双公钥多认证方案重复提交同一密钥
          └─ 未授权获得 SSH 登录能力
              └─ 读取数据、执行命令、横向移动
```

#### 3.4.11 风险影响

漏洞成功利用后，可能导致：

- 未经授权访问系统或业务接口（**未授权 SSH 登录**）；
- 远程执行任意系统命令（登录后视账户权限）；
- 获取应用、系统或数据库权限；
- 泄露账号、密钥、配置文件及业务数据；
- 篡改网站页面、配置或业务数据；
- 植入 WebShell、后门或恶意程序（经 `authorized_keys`/密钥）；
- 横向移动至其他服务器或业务系统（SSH 为其天然通道）；
- 中断业务服务或破坏系统可用性；
- 被勒索软件、挖矿木马或僵尸网络利用。

#### 3.4.13 修复与缓解措施

#### 官方修复

1. 将 Apache MINA SSHD 升级至 `2.20.0` 或 `3.0.0-M6` 或更高；
2. 确认升级后异步认证不再与公钥/主机基认证组合使用；
3. 升级前完成依赖影响评估与回归测试（SSH 登录、自动化脚本、CI 流程）；
4. 备份相关配置与密钥；
5. 升级后核验版本与认证行为；
6. 重新执行日志审计并留存修复证据。

#### 临时缓解

无法立即升级时，可采取：

- 停用 `sshd-ldap` 组件或以其他方式实现 LDAP 认证（直至升级）；
- 关闭“异步认证”机制（若自研服务端显式启用了它）；
- 对 SSH 服务实施来源 IP 白名单与网络收敛；

### 3.5 CVE-2026-103110 — Pexip Infinity 未认证远程代码执行（同批 10 条）

!!! danger "严重漏洞（会议/协作平台节点未认证 RCE）"
    Pexip Infinity 会议节点（Conferencing Node）在输入校验上存在缺陷，**远程攻击者可未认证地在节点内以非特权用户身份执行代码**；同批还披露了节点间越权 RCE（`CVE-2026-103105`，8.8）与本地提权至 root（`CVE-2026-103106`，7.8）。视频会议/协作平台常直接面向互联网且承载音视频与屏幕共享，风险面较大。

#### 3.5.2 漏洞摘要

该漏洞位于 Pexip Infinity 的会议节点中，源于**输入校验不充分**（`CWE-787` 越界写），公告明确“**允许远程攻击者在 Pexip Infinity Conferencing Node 内以非特权用户身份远程执行代码**”。同批 10 条缺陷构成一个完整的“从外围到内核”的利用面：

- **`CVE-2026-103110`（9.8）**：未认证远程代码执行（非特权用户）。
- **`CVE-2026-103105`（8.8）**：内部 API 越权，**具本地节点访问权限的攻击者可在另一节点上以非特权用户身份执行代码**（`AV:A`）——即节点间横向。
- **`CVE-2026-103106`（7.8）**：内部服务输入校验缺陷，**具本地访问（含经其他漏洞取得 RCE 或管理员权限）者可提权至 root**——为“RCE→root”提供阶梯。
- **`CVE-2026-103101`/`103102`（均 8.6）**：Web 服务器与信令实现缺陷致节点不可用/软件中止（拒绝服务）。

**组合风险：** `103110`（未认证 RCE）单独即为严重；若与 `103105`（节点间 RCE）和 `103106`（本地提权至 root）串联，则**可从未认证的外围一路推进到节点 root 并在集群内横向**——这对“节点常分布于 DMZ 且与管理网互通”的会议平台尤具威胁。

> 示例：攻击者向暴露的 Pexip 会议节点发起构造的请求，触发输入校验缺陷并在节点内以非特权用户执行代码；随后借助节点间越权（`103105`）在相邻节点执行代码，再经本地提权缺陷（`103106`）取得 root，最终控制整个会议集群。

#### 3.5.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达会议节点的相关服务端口（非特权用户 RCE） |
| 身份认证 | 无需 | `PR:N` |
| 用户交互 | 不需要 | `UI:N` |
| 特定配置 | 否 | 默认部署即可（以官方公告为准） |
| 利用复杂度 | 低 | `AC:L` |

**技术原理：** 会议节点在解析外部输入时未充分校验长度/边界，构成**越界写**并可能被转化为受控的内存破坏，进而以服务进程（非特权用户）身份执行代码。`103105` 则是**内部 API 越权**（相邻网络 `AV:A`），使已落地一个节点的攻击者得以在**另一个节点**上执行代码；`103106` 的**本地提权**则把非特权执行升级为 root。三者叠加构成“外围 RCE → 集群横向 → 内核权限”的链式风险。

**核心利用链：**

```text
攻击者
  └─ 面向互联网的 Pexip 会议节点
      └─ 触发输入校验缺陷（越界写）→ 非特权用户 RCE（CVE-2026-103110）
          └─ 经内部 API 越权在相邻节点执行代码（CVE-2026-103105）
              └─ 经本地提权缺陷取得节点 root（CVE-2026-103106）
                  └─ 控制会议集群、窃取凭据与音视频数据、横向进入内网
```

#### 3.5.11 风险影响

漏洞成功利用后，可能导致：

- 未经授权访问系统或业务接口；
- 远程执行任意系统命令（节点内非特权用户，可进一步提权 root）；
- 获取应用、系统或数据库权限；
- 泄露账号、密钥、配置文件及业务数据（含音视频与协作内容）；
- 篡改网站页面、配置或业务数据；
- 植入 WebShell、后门或恶意程序；
- 横向移动至其他服务器或业务系统（节点间越权 + 进入内网）；
- 中断业务服务或破坏系统可用性（拒绝服务）；
- 被勒索软件、挖矿木马或僵尸网络利用。

### 3.6 CVE-2026-93903 — LiteSpeed Web Server 内部重定向 URL 校验缺陷

!!! danger "严重漏洞（Web 服务器/中间件层）"
    LiteSpeed Web Server（LSWS）`6.3.7 build 1` 之前版本在“内部重定向 URL 校验”上于特定边界情形处理不当，官方 4.0 评分为 **9.4**（`AV:N/AC:L/PR:L/UI:N`，含子项影响）。LSWS 及以其为内核的 OpenLiteSpeed 在国内建站场景中被广泛使用，属典型的“升级即闭环”类缺陷。

#### 3.6.2 漏洞摘要

该漏洞位于 LiteSpeed Web Server 的**内部重定向 URL 校验**逻辑中，官方表述为“在某一‘边界情形（corner case）’下处理不当”，映射为 `CWE-174`（**对字符的两次解码**）。其风险在于：当服务器对 URL 进行解码/校验的顺序或次数不一致时，**校验阶段看到的字符串与最终用于路由/内部重定向的字符串不一致**，攻击者可能借此**绕过既定的访问控制或路径限制**（例如访问本应受限的路径、触发内部重定向到非预期目标），并在 4.0 评分中体现为对系统与后续系统的完整性与可用性的高影响（`SC:H/SI:H/SA:H`）。鉴于 Web 服务器处于请求处理的最前端，此类校验缺陷的后果可延伸至站点应用与后端资源。

> 示例：攻击者构造含双重编码（如 `%25xx` 形式）的 URL，使服务器的校验逻辑与内部重定向逻辑对同一路径得出不同结论，从而绕过路径限制或触发非预期的内部重定向。

#### 3.6.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 Web 服务端口（80/443 等） |
| 身份认证 | 低权限（`PR:L`） | 4.0 向量判定为低权限 |
| 用户交互 | 不需要 | `UI:N` |
| 特定配置 | 是 | 取决于站点内部重定向/路径限制的配置 |
| 利用复杂度 | 低 | `AC:L` |

**技术原理：** Web 服务器在处理请求路径时通常会做 URL 解码与规范化以进行安全检查（如拒绝路径穿越、限制访问目录）。当**同一数据被解码两次**而校验仅基于其中一次结果时，就会出现“**校验看 A、路由用 B**”的解析差异。攻击者可构造双重编码的路径，使安全检查阶段认为路径合法，而内部重定向阶段解析出受限或敏感的目标。LiteSpeed 通过在 `6.3.7 build 1` 修正校验逻辑完成修复。

**核心利用链：**

```text
攻击者
  └─ 向 LiteSpeed Web Server 发送双重编码的 URL 请求
      └─ 安全检查阶段对路径解码一次并判定为合法
          └─ 内部重定向阶段再次解码，解析出受限/非预期目标
              └─ 绕过访问控制或触发非预期内部重定向
                  └─ 访问受限资源或影响站点与后端
```
