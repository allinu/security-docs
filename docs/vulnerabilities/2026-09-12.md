### 1.3 今日重点关注

1. **`CVE-2026-85706`：GitLab CE/EE 未认证路径遍历致任意文件读取（CVSS 10.0，CISA KEV 09-11 新增，修复截止 09-14）**  
   GitLab 已于 2026-09-10 发布修复版本 19.1.8 / 19.2.6 / 19.3.2。漏洞位于 `repository/commits` 与 `repository/files` 接口：Rails 处理器在处理上传参数时**直接从请求字段 `file.path` 读取磁盘路径并 `File.open`，且发生在认证之前**；由于 GitLab Workhorse 的路由正则基于转义路径、而 Puma/Grape 先解码 `%XX`，对静态段做百分号编码（如 `%63ommits`/`%72epository`/`%66iles`）即可绕过 Workhorse 重写，落入通用 API 代理。未认证攻击者可读取服务器任意本地文件（如 `gitlab.yml`、`gitlab-secrets.json`），进而伪造会话、接管账户。GitHub 已出现 ≥3 个公开 PoC，CISA 于 09-11 收录 KEV，联邦机构修复截止 **2026-09-14**。

2. **`CVE-2026-15409`：SonicWall SMA1000 WorkPlace WebSocket 代理 SSRF 致未认证 RCE（CVSS 10.0，大规模在野利用）**  
   漏洞位于 SMA1000 的 WorkPlace 门户 `/wsproxy`：未认证攻击者构造特制请求，使设备连接其本机 **1050** 端口上的 CouchDB/Erlang 服务，再用固件中的**硬编码 cookie**完成 Erlang distribution 握手并访问 `couchdb@127.0.0.1` 节点，最终以 `couchdb` 账户权限执行系统命令。Rapid7 于 07-15 发布 PoC，攻击者 07-16 已改造为 50 线程批量扫描器；Hunt.io 将其与 07-17 公布攻击事件的**英国 King's Lynn and West Norfolk 地方议会**相关联（中等置信度）。在 250 台目标设备中，168 台泄露的 LDAP 配置包含跨 160 个域、255 个内网 LDAP 服务器的 **534 个 AD 账户凭据**，9 台丢失 SAM/LSA 机密，5 台经完整 DCSync 复制了整个 AD 数据库。

3. **`CVE-2026-20079` + `CVE-2026-20316`：Cisco Secure FMC 认证绕过被三个威胁集群在野利用（含 Qilin 勒索软件，KEV 截止今日 09-12）**  
   Cisco Talos 于 2026-09-11 披露三个攻击集群：**UAT-12197** 利用 `CVE-2026-20079` 向 Tomcat webroot 投放 JSP WebShell 与 JAR 命令执行器并窃取凭据；**UAT-11823**（工具与 Sandworm 重叠）通过 `CVE-2026-20079` 或静态凭据进入，建立 Netcat 反弹 Shell、采集配置并安装模块化 ELF 恶意软件 **Cyclops Blink**；**UAT-11988（Qilin 勒索团伙）** 使用静态凭据（`CVE-2026-20316`）初始访问，进行域侦察、部署 SOCKS5 代理与反向 SSH 隧道（转发 389/636/88/445/135/5985），关闭 AV 后投放 **Qilin** 勒索软件。KEV 修复截止 **2026-09-12（今日）**。

### 1.4 综合研判

本期与前两期的结构性差异在于：**风险的重心从「网络边界安全设备」扩展到「开发/制品基础设施」**。GitLab（`CVE-2026-85706`）与 JFrog Artifactory（`CVE-2026-82329`）同属软件供应链的关键节点，前者可读取含密钥的本地文件、后者可直接铸造平台管理员令牌——两者叠加意味着攻击者无需触碰终端即可拿到「源码 + 制品 + 凭据」的三重入口，对拥有私有化 GitLab / Artifactory 的研发型组织而言，其影响半径往往超过单台边界设备失陷。第二条线是网络边界的**存量收割**：`CVE-2026-15409` 早在 2026-07-14 即被 CISA 收录 KEV（截止 07-17），但直到本期仍观测到针对 250 台 SMA1000 的规模化利用并造成 AD 域级别的凭据外泄，说明「补丁已发布」与「资产已升级」之间的鸿沟仍是本期最确定的风险来源；`CVE-2026-20079` 亦然——Cisco 3 月即修复，KEV 截止今日 09-12，Talos 却仍在披露新的在野集群（含勒索软件落地）。第三条线是**凭据与后门的长期化**：Cyclops Blink 这类模块化 ELF 后门、JSP WebShell、SOCKS5/反向 SSH 隧道与 DCSync 的组合，表明攻击者在边界设备失陷后已形成「持久化 + 横向 + 凭据回传」的完整链路，单纯升级单个漏洞不足以清除。综合判断本期整体风险为**较高风险**，处置重心为「GitLab 09-14 前强制升级 + SonicWall SMA1000 存量清点与失陷排查 + Cisco FMC 今日 KEV 销项与后门清扫 + JFrog Artifactory 管理员令牌轮换」。

!!! danger "研判结论：较高风险"
    本期最主要风险点是**新增 KEV 的 GitLab 未认证任意文件读取（`CVE-2026-85706`，CVSS 10.0，修复截止 2026-09-14）**与**持续大规模利用的 SonicWall SMA1000（`CVE-2026-15409`，CVSS 10.0）**：前者需在 72 小时内将 GitLab CE/EE 升级至 `19.1.8`/`19.2.6`/`19.3.2`，并**轮换 `gitlab-secrets.json` 涉及的密钥、重置会话与个人访问令牌**；后者须立即清点并升级 SMA1000（2026 年 6 月热修复前版本均受影响），且因历史大规模利用已造成域凭据外泄，**必须把「升级」升级为「升级 + 失陷排查 + 全域凭据轮换」**。同期须完成 Cisco Secure FMC 两条 KEV 项（`CVE-2026-20079` 截止**今日 09-12**、`CVE-2026-20316`）的版本清点与后门排查，重点检查 Tomcat webroot、`license.tmp`、Netcat 反弹与反向 SSH；JFrog Artifactory 需升级至修复版本并**轮换全部管理员令牌**（`CVE-2026-82329` 可未认证铸造 admin 令牌）。所有边界与研发基础设施的处置均不得等待在野证据或 PoC 成熟。

### 3.1 `CVE-2026-85706` — GitLab CE/EE 未认证路径遍历致任意文件读取

!!! danger "严重漏洞（CVSS 10.0，未认证，CISA KEV 本期新增，修复截止 2026-09-14，PoC 已公开）"

#### 3.1.2 漏洞摘要

GitLab 是广泛部署于企业与研发团队的 DevOps 平台，其仓库文件与提交接口（`POST :id/repository/commits`、`POST`/`PUT :id/repository/files/:file_path`）位于 GitLab Workhorse 的 `requestBodyUploader` 处理路径之后。漏洞根因是**认证与路径校验的错位**：Rails 处理器相信请求字段 `file.path` 提供的磁盘路径，并在任何认证检查之前就执行 `File.open`；同时 `require_gitlab_workhorse!` 并不能充当认证——Workhorse 的签名往返组件会为每个经其代理的请求附上有效的 `Gitlab-Workhorse-Api-Request` JWT，因此任何"漏过"路由正则、落到通用 API 代理的请求都会通过该检查。正常情形下 Workhorse 会先重写请求、使其命中受保护路径，但**其路由正则匹配的是转义路径（`EscapedPath()` 外加从不解码 `%XX` 的 `path.Clean` 克隆），而 Puma 在 Grape 路由前会解码 `%XX`**——这一编码不一致即是绕过点：对路由静态段进行百分号编码（`%63ommits`、`%72epository`、`%66iles`）、追加结尾斜杠或 `.json` 后缀，Workhorse 的正则即匹配失败，请求直落 Rails 仍路由至存在缺陷的处理器。成功利用后，攻击者可在**未认证**状态下读取服务器本地任意文件；对 GitLab 而言，`/etc/gitlab/gitlab-secrets.json`、`config/gitlab.yml` 等文件一旦泄露，攻击者可据此伪造会话或重置凭据，进而接管账户与项目（含私有仓库、CI/CD 变量与密钥）。

> 示例说明：该漏洞不依赖用户交互或特定插件，默认配置下 `repository/files` 接口的读取发生在项目权限校验之前，因此即使目标项目不可匿名访问，"文件是否可读"本身也可作为**文件存在性预言机**，用于探测目标环境。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | HTTP/HTTPS（默认 443 或自建端口），需可访问 GitLab Web 与 `/api/v4/` |
| 身份认证 | 无需 | 读取发生在认证之前，未认证即可触发 |
| 用户交互 | 不需要 | 纯服务端请求，无需诱导用户点击 |
| 特定配置 | 否 | 默认配置即可，无需启用特殊功能；`repository/files` 路径无需项目匿名可读 |
| 利用复杂度 | 低 | 预置 PoC 已枚举可用绕过形式，可直接复现 |

**技术原理：**

漏洞本质是**路径规范化的双重解码不一致**叠加**认证前的不安全文件读取**。Workhorse 用 `EscapedPath()`（保留 `%XX`）构造并匹配路由正则，Puma/Grape 则先解码后再路由，二者对同一 URL 的"路径"理解不同；对静态段编码 `%XX` 会让 Workhorse 的 `UploadPathHandler` 判定该请求无需重写而直接转发，但解码后 Rails 仍路由到 `FilesController`/`CommitsController` 中**先读文件、后鉴权**的处理分支。处理器信任 `file.path` 字段（本应由 Workhorse 覆盖），从而形成从"请求字段"到"磁盘路径"的任意读取。

**核心利用链：**

```text
攻击者
  └─ 发现暴露的 GitLab Web / API（443 或自建端口）
      └─ 对 API 路由静态段做百分号编码构造绕过路径（%63ommits / %72epository / %66iles）
          └─ 令 GitLab Workhorse 路由正则失配 → 请求直落通用 API 代理（携带有效 Workhorse JWT）
              └─ Rails 处理器在鉴权前 File.open(file.path)
                  └─ 读取服务器任意本地文件（如 gitlab-secrets.json / gitlab.yml）
                      └─ 伪造会话 / 重置凭据 → 接管账户与项目
```

#### 3.2.2 漏洞摘要

SonicWall SMA1000 是面向远程访问的 SSL VPN/应用门户设备，其 WorkPlace 门户在 `/wsproxy` 提供 WebSocket 代理。漏洞源于该代理**未对目标地址做充分校验**（SSRF）：攻击者构造特制请求，即可让设备向**自身本地回环**的 1050 端口发起连接——该端口上运行着 CouchDB 相关的 Erlang 服务。随后攻击者利用**固件中硬编码的 Erlang cookie** 完成 distribution 握手，接入 `couchdb@127.0.0.1` 节点，并通过 RPC 调用（如 `os:cmd/1`）以 `couchdb` 账户权限执行任意系统命令。整条链路可完全自动化，数秒内即可完成，攻击门槛低。成功利用后，攻击者可将该设备作为跳板进入内网：Hunt.io 记录到攻击者向选定设备部署 **Impacket `secretsdump`** 的独立 Linux 版本，用于从内网 Windows 系统远程窃取凭据——由于组织通常对防火墙/VPN 设备底层操作系统的可见性远低于受 EDR 监控的 Windows/Linux 主机，该方法有助于规避检测。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可访问 WorkPlace 门户（典型 443 端口）与 `/wsproxy` 端点 |
| 身份认证 | 无需 | 未认证即可触发 |
| 用户交互 | 不需要 | 纯服务端请求 |
| 特定配置 | 是 | 需 WorkPlace 门户/WebSocket 代理处于可访问状态 |
| 利用复杂度 | 低 | 自动化后数秒完成 |

**技术原理：**

WorkPlace 的 WebSocket 代理未限制可代理的目标地址，允许攻击者指定**设备本地回环地址与端口 1050**。该端口上的 CouchDB 相关 Erlang 服务使用**固件中硬编码的 cookie** 作为 distribution 认证凭据，攻击者掌握该 cookie 后即可完成 Erlang 节点握手并接入 `couchdb@127.0.0.1` 节点，进而调用 `os:cmd/1` 等 RPC 以 `couchdb` 权限执行系统命令。SSRF 在此充当了"突破网络边界、直达本机管理接口"的通道。

**核心利用链：**

```text
攻击者
  └─ 访问 WorkPlace 门户 /wsproxy（未认证）
      └─ 构造特制 WebSocket 请求，指定目标为 127.0.0.1:1050
          └─ 利用固件硬编码 cookie 完成 Erlang distribution 握手
              └─ 接入 couchdb@127.0.0.1 节点并发送 RPC（os:cmd/1）
                  └─ 以 couchdb 账户权限执行系统命令
                      └─ 部署 Impacket secretsdump → 窃取内网 Windows 凭据 / DCSync
```

### 3.3 `CVE-2026-82329` — JFrog Artifactory 默认配置下未认证认证绕过致管理员令牌铸造

#### 3.3.2 漏洞摘要

JFrog Artifactory 是广泛用于软件供应链的制品仓库，其自建版默认安装时由 JFrog Access 服务负责集群 `join` JWT 的校验。缺陷在于 `JoinKeyAccess.tryResolveJoinKeys()` 构造受信任"附加 join key"集合时使用 `config.split(",")` 且**未过滤空串**：在未配置附加 key 的默认情形下，值 `""` 被解析为 `[""]`，从而把一个**空白 join key** 加入受信任集合；而 `getSigningKey("")` 经 `pkcs7(<empty>, 32)` 派生出 **32 字节 `0x20`**——这是一个完全公开、可预测的 HMAC 密钥。因此任意未认证攻击者都能伪造合法 join JWT（`alg=HS256`、`kid=SHA256("")`、`skip_node_registration=true`），提交到**无需认证**的 `/access/api/v1/registry/join` 即获得带 `admin` 作用域的 SERVICE 令牌，再通过 `/access/api/v1/tokens` 将其兑换为 `applied-permissions/admin` 的平台管理员访问令牌。攻击者据此可读取全部服务器配置、列举并窃取所有访问令牌，并在 Pro/Enterprise 版本创建管理员用户，实现对 Artifactory 的完全接管——鉴于 Artifactory 常存放构建产物与依赖，接管后即可篡改依赖、污染供应链。关联漏洞 `CVE-2026-66014`（NVD CVSS 3.1 = 9.8）为内部请求处理中的认证弱点，可与本漏洞形成组合利用。

#### 3.3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可访问 Artifactory 的 Access 服务（默认 8082 或统一端口） |
| 身份认证 | 无需 | `/access/api/v1/registry/join` 无认证 |
| 用户交互 | 不需要 | 纯服务端请求 |
| 特定配置 | 是 | **默认配置即满足**（未配置附加 join key 即触发空白密钥缺陷） |
| 利用复杂度 | 低 | 预置 PoC 可一键验证/铸造管理员令牌 |

**技术原理：**

根因是**受信任密钥集合被污染为空串密钥**：`split(",")` 在默认配置下产生 `[""]`，YAML 解析后空串常被反序列化为 `null`，进一步使受信任集合中残留空白 key；`getSigningKey("")` 恒定派生 32 字节 `0x20`，等于把 HMAC 密钥公开。加之 `RegistryNoAuthResource` 的 join 接口**无需认证**、`skip_node_registration=true` 直接赋予 `admin` 作用域，攻击链得以在无凭据条件下闭环。补丁在 `JoinKeyAccess` 增加 `.filter(Strings::isNotBlank)`、在 `JoinKeyHashPair` 拒绝 null/blank，并将 Project 资源由 SERVICE 收紧为 ADMIN。

**核心利用链：**

```text
未认证攻击者
  └─ 伪造 join JWT（alg=HS256，kid=SHA256("")，密钥=32B 0x20，skip_node_registration=true）
      └─ POST /access/api/v1/registry/join（无需认证）→ HTTP 201，返回 scope=admin 的 SERVICE 令牌
          └─ POST /access/api/v1/tokens（scope=applied-permissions/admin&audience=*）
              └─ 获得平台管理员访问令牌
                  └─ 读取全局配置 / 列举并窃取所有访问令牌 / 创建管理员用户 → 接管 Artifactory
```

    BLANK_SECRET = b' ' * 32                     # JoinKeyUtils.getSigningKey("") == pkcs7(empty,32)
    BLANK_KID    = hashlib.sha256(b"").hexdigest()  # kid 选定被误信任的空白 join key

    def forge_join_jwt(service_id="jfrt@01"):
        header  = {"alg": "HS256", "typ": "JWT"}
        payload = {
            "iat": int(time.time()),          # 服务端校验 30s 新鲜度窗口
            "service_id": service_id,          # 非空 → 铸造令牌的主体
            "kid": BLANK_KID,                  # 选取被误信任的空白 join key
            "skip_node_registration": True,    # → joinWithoutNodeRegistration() → scope("admin")
        }
        signing_input = b64u(json.dumps(header,separators=(",",":")).encode()) + b"." \
                      + b64u(json.dumps(payload,separators=(",",":")).encode())
        sig = hmac.new(BLANK_SECRET, signing_input, hashlib.sha256).digest()
        return (signing_input + b"." + b64u(sig)).decode()

    # 2) POST {base}/access/api/v1/tokens  scope=applied-permissions/admin&audience=* → 平台管理员令牌

### 3.4 `CVE-2026-20079` — Cisco Secure Firewall Management Center 认证绕过在野利用（Qilin 勒索与三集群）

!!! danger "严重漏洞（CVSS 3.1 = 10.0，未认证 → root，CISA KEV 截止 2026-09-12，本期披露三集群在野利用）"

#### 3.4.2 漏洞摘要

Cisco Secure FMC 是统一管理多台物理/虚拟防火墙与 FTD 设备的集中平台，保存着全网防火墙策略、设备凭据与访问控制数据；其管理界面通常部署在管理网段，但不少部署将其暴露在互联网或不可信网络。漏洞根因是设备**启动时创建的一个不当系统进程**，在正常认证流程之外形成了一条可被外部触发的替代执行路径。未认证远程攻击者向 Web 界面发送特制 HTTP 请求即可绕过认证，执行设备上的脚本文件与命令，最终取得底层操作系统 root 权限——等同于整个防火墙管理域失控。Cisco 强调：若 FMC 管理接口不具备公网访问能力，攻击面会显著降低。

**本期新增的在野利用情报（Cisco Talos 2026-09-11）：** Talos 识别出三个攻击集群：

- **UAT-12197**：利用 `CVE-2026-20079` 在 CSM Tomcat webroot 投放 **JSP WebShell**（对参数 `F6C1F0E7` 做 Base64 解码以加载 Java 类）与 **JAR 命令执行器**，查询内部数据库并窃取用户认证数据与凭据；
- **UAT-11823**（工具与 **Sandworm** 重叠）：通过 `CVE-2026-20079` 或**静态凭据**进入，建立 **Netcat 反向 Shell**、采集设备配置，并安装模块化 ELF 恶意软件 **Cyclops Blink**（持久访问、DoH 解析、数据包嗅探）；其手法包括用 Makeself 更新磁盘上的 `license.tmp` 以植入恶意拷贝；
- **UAT-11988（Qilin 勒索团伙）**：使用静态凭据（`CVE-2026-20316`）初始访问，进行大范围域侦察，部署 **Python SOCKS5 代理**与**反向 SSH 隧道**（转发 LDAP 389 / LDAPS 636 / Kerberos 88 / SMB 445 / NETBIOS 135 / WinRM 5985），关闭杀软后投放 **Qilin** 勒索软件。

#### 3.4.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可访问 FMC Web 管理界面（默认 443） |
| 身份认证 | 无需 | 未认证远程即可触发 |
| 用户交互 | 不需要 | 纯服务端请求 |
| 特定配置 | 否 | 与管理界面是否暴露强相关（未暴露则攻击面显著降低） |
| 利用复杂度 | 低 | 单次特制 HTTP 请求 |

**技术原理：**

设备启动时创建的系统进程存在设计缺陷，在标准认证流程之外引入了一条替代执行路径（CWE-288）。攻击者无需有效凭据，仅通过构造特制 HTTP 请求即可触发该路径完成认证绕过，随后执行设备上的脚本文件，借此获得 root 权限。由于 FMC 汇聚全网防火墙策略与凭据，root 沦陷可直接导致管理域失控；攻击者进一步投放 WebShell、后门（Cyclops Blink）或勒索软件（Qilin）。

**核心利用链：**

```text
攻击者
  └─ 发现暴露的 FMC Web 管理界面（443）
      └─ 发送特制 HTTP 请求触发启动时的缺陷系统进程
          └─ 绕过认证执行设备脚本
              └─ 取得底层操作系统 root 权限
                  └─ 投放 JSP WebShell / Cyclops Blink 后门 / Qilin 勒索软件
                      └─ 域侦察 + SOCKS5/反向 SSH 隧道 → 窃取凭据 / 加密数据
```

| 影响产品 | ClamAV（PESpin 文件格式解析器） |
| 影响版本 | 以 Cisco ClamAV 安全公告 `cisco-sa-clamav-88cFYyxR` 为准 |
| PoC状态 | 未公开 |
| 在野利用 | 未发现 |
| 修复版本 | 升级至含修复的 ClamAV 版本（以官方公告为准） |

**漏洞描述：**  
ClamAV 的 PESpin 文件格式解析器在扫描 PESpin 打包文件时**边界检查不当**，未认证远程攻击者可通过提交特制文件触发内存破坏（越界写 / 整数溢出），导致拒绝服务（DoS），并可能造成进一步影响。微步在线研究响应中心于 2026-09-11 发布《原创漏洞｜ClamAV PESpin 解包器堆缓冲区溢出漏洞》分析，NVD 对应记录为 `CVE-2026-20217`（published 2026-07-01）与关联的 `CVE-2026-20339`（published 2026-08-07）。**注：微步文章与 NVD 记录的对应关系系依据主题（PESpin 解析器、堆/内存破坏）判断，具体 CVE 编号以厂商与微步原文为准。**

**修复建议：**  
升级至含修复的 ClamAV 版本；在邮件/文件网关前置文件类型/大小限制，避免未过滤文件直达 ClamAV 扫描；对可疑 PESpin 样本保持监控。

## 五、当日处置建议

1. 对已在野利用、已纳入CISA KEV或存在成熟PoC的漏洞立即开展资产排查；
2. 优先核查互联网暴露的VPN、网关、安全设备、中间件和管理平台；
3. 无法立即升级的系统应采取断网、访问控制、接口禁用或WAF拦截措施；
4. 对疑似遭受攻击的系统保留日志、流量、进程、文件及内存证据；
5. 对发现异常的主机开展WebShell、恶意进程、异常账号及横向移动排查；
