#### 3.1.2 漏洞摘要

该漏洞位于 Chrome 的 V8 JavaScript/WebAssembly 引擎。根据 Serotav 公开技术分析（标题直译为"当排序导致混淆"）及第三方摘要，漏洞与 V8 引擎对 `Array.prototype.sort`（数组排序）路径的类型处理有关：在 Maglev/Turbofan 编译器对排序过程实施内联优化时，若排序回调执行期间数组的元素类型/表示发生变化（元素种类迁移或 Map 变化），编译器基于过期类型假设生成的代码可能以错误类型访问对象，形成类型混淆（CWE-843），进而被利用为沙箱内的任意代码执行原语。远程攻击者可通过诱导用户访问特制 HTML 页面触发（钓鱼链接、恶意广告、被攻陷网站投递均可），成功利用可在浏览器渲染进程内执行任意代码；若叠加沙箱逃逸链，可进一步控制设备。Google 未披露在野攻击细节与目标，该漏洞是 2026 年第 6 个被在野利用的 Chrome 零日（此前 5 个详见第 36 期 3.1.1 注）。修复方式为升级至 `152.0.7977.82/.83`（2026-09-03 稳定版更新共修复 12 个安全漏洞，`CVE-2026-85046` 为唯一确认在野利用项）。

> 技术细节公开的防御意义：完整根因分析公开后，安全研究者与攻击者可同等获得触发原理，基于该原语定制利用的成本显著下降——"细节公开即利用风险上升"，未升级浏览器（尤其是企业内滞留的旧版本）须按 KEV 时限尽快收敛。

**技术原理：**

根因是 V8 引擎（Maglev/Turbofan 编译器）在 `Array.prototype.sort` 内联优化路径上对对象类型（Map/元素种类）的假设与实际运行状态不一致（CWE-843 类型混淆）：排序过程若伴随元素表示形态变化（典型如自定义比较器回调改写数组元素），编译器生成的优化代码仍按旧类型访问对象，攻击者可通过精心构造的 JavaScript 令错误类型访问落到可控对象上，获得越界读写/任意对象伪造能力，最终在渲染进程（沙箱）内执行任意代码。修复 commit `e0562d87ad9c17042b581582c99237d798572e67`（V8 上游）与 Chrome Stable 152 更新同步推送；Chrome 问题跟踪号 issues.chromium.org/542403045（权限受限）。Google 未公开在野利用的完整攻击链，沙箱逃逸部分是否存在/如何实现仍未知。

**核心利用链：**

```text
攻击者
  └─ 构造恶意 HTML/JS 页面（含 Array.prototype.sort 类型混淆触发序列）
      └─ 诱导受害者使用受影响 Chrome/Chromium 访问（钓鱼/广告/被攻陷站点）
          └─ 排序内联路径触发类型混淆（CWE-843）
              └─ 获得渲染进程内任意代码执行（沙箱内）
                  └─ （若存在沙箱逃逸链）进一步控制操作系统/设备
```

#### 3.1.11 风险影响

漏洞成功利用后，可能导致：

- 在浏览器渲染进程（沙箱）内执行任意代码（访问恶意网页即触发，无需其他交互）；

- 叠加沙箱逃逸链后实现设备级控制（Google 未披露是否已有完整链在野）；
- 企业环境中滞留旧版本浏览器成为 Web 投毒/鱼叉攻击的稳定入口。

#### 3.1.13 修复与缓解措施

#### 官方修复

1. 将 Google Chrome 升级至 `152.0.7977.82`（Linux）/ `152.0.7977.82/.83`（Windows、macOS）或更高版本（Chrome 菜单 → 帮助 → 关于 Google Chrome 自动更新，或企业策略推送）；

#### 3.2.2 漏洞摘要

ConnectWise 官方公告（2026-09-03）确认：ScreenConnect Remote Access 的 **Remote Access Support（远程支持）与 Access（远程接入）会话中的文件传输行为**存在安全问题，影响 **Cloud 与 On-Premise 两种部署形态**；官方未随公告披露 CVE 与根因细节，仅说明 CVE 编号与正式修复将在"一周内"发布，并建议合作伙伴在修复前**禁用文件传输功能**（THN 报道口径）。

Huntress 的观测研究（2026-09-03 公开）展示了该缺陷的现实利用形态：攻击者通过社会工程诱导等手段在受害主机建立**被篡改/伪造的 ScreenConnect 客户端**实例，此类客户端会在**新接入的 ScreenConnect 端点**上自动传输并执行同一组四阶段 VBScript 脚本（`1.vbs` → `4.vbs`），形成"类蠕虫"式跨主机扩散；Huntress 记录的载荷覆盖：持久化、**额外的 ScreenConnect 安装**（扩大控制面）、隧道工具、**安全防护配置篡改**与**加密货币挖矿**。由于文件传输发生在远程支持工具的内部通道内，流量与行为均"像正常远程支持"，EDR/终端防护难以区分合法运维与恶意投递。ConnectWise 与 Huntress 均强调：这不是 ScreenConnect 服务器被攻破的单一事件，而是远程支持生态（MSP/IT 帮助台→终端）信任链被利用的模式性风险。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需可达 ScreenConnect 会话/接入端点（Cloud 或 On-Premise 通道） |

**技术原理：**

官方未披露根因细节。据 Huntress 观测与媒体转述，攻击链的技术要点是：**远程支持会话的文件传输通道缺少对传输内容的充分约束/校验**——被篡改的 ScreenConnect 客户端可在会话建立后（含新端点接入时）自动向对端传输并执行文件（四阶段 VBScript：`1.vbs`–`4.vbs`，用于系统发现、拉取/启动后续组件）。该行为"寄生"在远程支持工具的正常文件传输语义内，受害者侧看到的是一次例行远程支持文件操作，攻击载荷因此绕过基于文件签名/进程信任的终端检测。ConnectWise 在修复中预计将对文件传输行为施加更严格的校验/授权边界（具体以官方补丁说明为准，本报告不推测）。

**核心利用链（据 Huntress/THN 公开观测，非本站验证）：**

```text
攻击者
  └─ 社工诱导受害者在主机安装被篡改的 ScreenConnect 客户端（伪造安装/捆绑投递）
      └─ 客户端接入 ScreenConnect 会话（Support/Access）
          └─ 新端点接入时经文件传输通道自动下发 1.vbs–4.vbs（四阶段 VBScript 链）
              └─ 脚本执行系统发现、拉取/启动后续载荷（隧道、安全防护篡改、挖矿、持久化等）
                  └─ 在接入端点建立额外 ScreenConnect 安装/持久控制（类蠕虫扩散）
```
