### 1.3 今日重点关注

1. **`CVE-2026-76461`：Cisco Secure Email Gateway 邮件解析 SQL 注入致 root 权限命令执行**  
   影响 Cisco AsyncOS for Cisco Secure Email Gateway（物理与虚拟版本，且"与设备配置无关"）。未经身份认证的远程攻击者只需发送一封包含恶意 SQL 语句的邮件，即可在底层操作系统上以 **root 权限执行任意命令**。该漏洞已被"广泛利用"（HKCERT 公告原文备注），CISA 于 **2026-09-14 将其纳入 KEV 目录，整改截止日期为 2026-09-17（限期约 3 天）**，Cisco 已直接联系检测到恶意活动的 Secure Email Cloud 客户。**建议立即升级至 `16.5.0-780`（官方首选）或 `15.5.5-014`／`16.0.4-302`，并立刻回溯 `mail_logs`。**（详见 3.1）

2. **`CVE-2026-85102` / `CVE-2026-85103`：Check Point VPN 两个 CVSS 9.8 严重漏洞**

3. **`CVE-2026-82329` + `CVE-2026-42016` / `CVE-2026-42018`：JFrog Artifactory 预认证管理员接管与组合利用链**

### 1.4 综合研判

今日态势呈现"**厂商批量加固 + 在野利用快速武器化**"的叠加特征。三个方向同时告警：一是 Cisco 邮件安全网关被"单封邮件打穿至 root"，且 CISA 给出的整改窗口仅 3 天（截止 2026-09-17），邮件网关是典型的"互联网可达 + 承载敏感身份凭据"资产，一旦失陷将直接成为攻击者进入内网的桥头堡，并可能被用于批量读取/伪造邮件；二是 Check Point VPN 两个 9.8 分漏洞虽暂无公开 PoC，但荷兰 NCSC 已明确"预计很快出现利用尝试"，VPN 网关与 Site-to-Site 通道一旦被突破，等于把攻击者直接放进内网，且 EoS 版本（R80–R81.10）范围广、存量多；三是 JFrog Artifactory 侧的攻击链已在野运行近一个月，攻击者以"制品仓库 → 管理员令牌 → 恶意插件/后门"的方式建立持久化，这类资产往往由研发团队持有、补丁流程独立于安全团队，是当前最容易被忽略的高价值目标。此外，本期一条行业动态值得关注：安全内参援引的"首个 AI 智能体驱动的大规模漏洞利用"报道称数天内攻陷近 400 家企业，与 ENISA 关于"前沿 AI 正在压缩漏洞发现到利用的时间差"的评估相互印证，意味着**从"漏洞公开"到"出现利用"的窗口期正在系统性缩短，以"PoC 是否公开"作为处置优先级依据的传统做法需要向"是否互联网可达 + 是否含敏感凭据"倾斜**。本地为公开文档站、无内部资产台账，本章风险评估以公开信息与通用资产暴露面为基准。

#### 3.1.2 漏洞摘要

该漏洞存在于 Cisco AsyncOS 邮件安全网关的**邮件解析逻辑**中，成因是解析流程对输入校验不足，导致攻击者可控内容被拼入后台 SQL 语句执行。由于该组件在网关内部以高权限身份运行并与底层操作系统交互，SQL 执行权限可被进一步用于在底层操作系统上以 **root 权限**执行任意命令。

与多数需要特定功能启用的漏洞不同，Cisco 明确说明本漏洞"影响 Cisco Secure Email Gateway 的物理与虚拟版本，**无论设备配置如何**"，即默认配置即在风险之中；攻击入口为标准 SMTP 邮件投递，因此**任何能从互联网接收邮件的邮件安全网关都是潜在靶标**。Cisco 同时提示：由于成功利用后攻击者获得 root 权限，**入侵痕迹（日志、文件）可能被攻击者清除或隐藏**，因此必须交叉核对设备之外的网络与防火墙日志。

> 示例：攻击者向目标域投递一封特制邮件 → 网关邮件解析器将邮件内容中的恶意 SQL 语句送入后台查询 → 通过数据库侧命令执行能力（如 `COPY ... TO PROGRAM` 一类语句）落地 shell → 以 root 身份在网关设备上执行命令 → 横向读取网关内存储的账号凭据、邮件内容与配置，或直接从网关发起外联。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需能向受影响网关投递邮件（标准 SMTP，通常 25/587 端口对外可达，或经前置 MX/中继转发） |
| 身份认证 | 无需 | 未认证远程攻击者即可触发 |
| 用户交互 | 不需要 | 无需收件人点击或打开附件 |
| 特定配置 | 否 | Cisco 明确"无论设备配置如何"均受影响 |
| 利用复杂度 | 低 | 攻击载荷为邮件正文/字段中的恶意 SQL 语句，无需内存布局等复杂条件 |

**技术原理：**

邮件解析逻辑对邮件头/正文中的输入未做充分校验与转义，攻击者可控数据被直接拼接到后台数据库查询中，形成 SQL 注入。Cisco 公告将此漏洞归入 CWE-707（中和不当/注入类）分组披露。由于 AsyncOS 的邮件解析进程在设备上以高权限运行，且能够通过数据库能力调用底层系统命令（攻击者可构造 `COPY ... TO PROGRAM` 一类 SQL 语句触发系统命令执行），注入最终跃迁为**操作系统 root 权限命令执行**。

**核心利用链：**

```text
攻击者
  └─ 定位互联网可达的 Cisco Secure Email Gateway（SMTP 入口）
      └─ 投递一封含恶意 SQL 语句的特制邮件
          └─ 触发邮件解析逻辑中的 SQL 注入（校验不足）
              └─ 执行任意 SQL 语句（含 COPY ... TO PROGRAM 类命令执行语句）
                  └─ 以 root 权限在底层操作系统执行命令
                      └─ 读取凭据/邮件/配置、植入持久化、清理日志或外联
```

重点检查：

- ESA 邮件日志 `mail_logs`（厂商官方 IOC 检索入口）；

- 从网关设备主动发起的异常外联与文件上传/下载；

- 网关进程异常拉起 shell、下载工具的行为。

| 检测项 | 可疑特征 |
| --- | --- |
| 请求路径 | 不适用（攻击面为 SMTP 邮件投递，而非 HTTP 路径） |

| 文件行为 | 写入临时目录、Web 目录或启动目录的可疑脚本与二进制 |
| 网络行为 | 网关设备向外部 IP 的异常上传（厂商明确提示的核查方向） |

#### 3.1.11 风险影响

漏洞成功利用后，可能导致：

- 以 root 权限远程执行任意系统命令；
- 读取网关中存储的邮件内容、账号凭据、中继与集成配置；
- 篡改邮件流与配置（如静默放行、窃取附件、伪造发信域）；
- 植入 WebShell、后门或恶意程序；
- 以邮件网关为跳板横向移动至内网其他服务器；
- 中断邮件与安全过滤服务；
- 利用后攻击者获得 root 权限，可能导致日志与入侵痕迹被清理、掩盖。

#### 3.1.13 修复与缓解措施

#### 官方修复

1. 将 Cisco Secure Email Gateway（AsyncOS）升级至官方修复版本：`15.5 及更早` → `15.5.5-014`；`16.0` → `16.0.4-302`；`16.5` → **`16.5.0-780`（Cisco 强烈建议迁移至此版本）**；
2. 升级路径：Web 管理界面 `System Administration > System Upgrade > Upgrade Options > Download and Install`，或 CLI 执行 `upgrade` 后选择 `DOWNLOADINSTALL`；升级完成后设备将自动重启；
3. Cisco 已将所有 Cisco Secure Email Cloud 设备升级至 `16.5.0-780`，云服务客户可向 Cisco 支持确认；
4. 升级前完成配置与邮件队列状态备份，评估重启带来的邮件投递中断窗口；
5. 升级后核验版本号，并确认 `mail_logs` 中不再出现可疑 SQL 语句；
6. 保留升级记录与核验结果，作为 KEV（截止 2026-09-17）整改证据。

#### 临时缓解

Cisco 明确本批次漏洞**无可用 workaround**，但无法立即升级时，可采取以下收紧措施降低暴露面：

- 将邮件安全网关的管理接口（443/8443）从互联网撤除，仅允许管理网段访问；
- 在网关前置过滤设备/防火墙，仅允许已知可信主机向设备发送管理流量（分层防火墙策略）；
- 对邮件接收链路增加前置 MX/中继，并在中继侧加强异常邮件检测与拦截；
- 将邮件与管理功能拆分到不同网络接口，降低管理面被触及的概率；
- 加强 `mail_logs` 与外部网络/防火墙日志的集中采集与告警，确保设备之外仍保留证据；
- 部署针对性 WAF/IPS/网关内容拦截规则，拦截邮件正文与头部中的 SQL 注入类载荷。

#### 3.2.2 漏洞摘要

Cisco 表示，其 Secure Email Gateway 与 Secure Email and Web Manager 工程团队开展了内部安全评审，产出了一批软件加固版本，用于修复多个内部发现的漏洞。为简化披露流程，Cisco **按底层缺陷类别（CWE）分组，并为每组分配一个 CVE 编号**，单个 CVE 的 CVSS 分数代表该 CWE 类别下"最具影响力的单个底层漏洞"的最高潜在严重性。因此 `CVE-2026-20353` 并非单一漏洞，而是一个**加固缺陷组的集合标识**。

该批次共包含 5 个 CVE：`CVE-2026-76440`（CWE-23 路径遍历，9.8）、`CVE-2026-76441`（CWE-284 访问控制不当，9.8）、`CVE-2026-20353`（CWE-664 资源生命周期，9.8）、`CVE-2026-76443`（CWE-707 注入类中性化不当，9.8）、`CVE-2026-76442`（CWE-1284 输入数量校验不当，7.5）。Cisco 明确"其中一个已知被主动利用"，指向 `CVE-2026-76461`（归入 CWE-707 分组）。

```text

```

#### 3.3.2 漏洞摘要

该漏洞存在于 Check Point Quantum Security Gateway 处理 **VPN 协商**（含 Remote Access 与 Site-to-Site）的过程中：VPN 协商阶段对证书信任的校验不当（CWE-295），导致**未经身份认证的外部攻击者可以绕过安全检查，并在 Security Gateway 上执行任意代码**。攻击者一旦成功利用，网关将不再是可信边界，而会变成攻击者进入内网的落脚点：可读取或篡改机密数据、破坏业务连续性，并以此为跳板向内网横向移动。

Check Point 于 2026-09-07 建立公告、2026-09-09 发布修复，荷兰 NCSC 于 2026-09-14 发布公开警告，指出两个漏洞（本漏洞与 `CVE-2026-85103`）CVSS 均为 9.8，"评估利用可能性与潜在危害均为高，预计很快出现利用尝试，建议尽快安装更新"；对使用 Site-to-Site VPN 的组织，NCSC 还建议**禁用 implied rules 并将 VPN 访问限制到特定可信 IP**。

#### 3.3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需能访问网关的 VPN 服务端口：IKE `UDP/500`、NAT-T `UDP/4500`（Remote Access 场景通常为 `TCP/443` 门户 + VPN 隧道） |
| 身份认证 | 无需 | 未认证外部攻击者可触发 |
| 用户交互 | 不需要 | — |
| 特定配置 | 是（受影响的具体 VPN 配置与版本相关） | 建议禁用 implied rules 并限制 VPN 访问源 IP；本地管理的 Spark 防火墙不适用该缓解 |
| 利用复杂度 | 低 | 与标准 VPN 协商流程交互即可触发 |

**技术原理：**

VPN 协商过程中，网关对等方证书的信任链校验存在缺陷（CWE-295），攻击者可借此在协商阶段绕过安全检查：在 Remote Access 与 Site-to-Site 场景下，攻击者可用未通过完整信任校验的证书/身份完成协商阶段的关键判定，从而绕过认证并触达网关上的可执行代码路径（厂商描述为"在网关上执行任意代码"）。Check Point 将本问题与 `CVE-2026-85103` 视为同一批紧急安全更新（LivePatch `BUNDLE_URGENT_SECURITY_UPDATE_*` Take 24），且两者由 `cpcert` 相关进程承载（厂商验证命令中 `cpcert:cpca*`、`cpcert:iked*`、`cpcert:vpn*`、`cpcert:vpnrad*`、`cpcert:wstlsd*`、`cpcert_cprid:cprid*` 均标注了这两个 CVE）。

**核心利用链：**

```text
攻击者
  └─ 定位对外暴露的 Check Point 网关（UDP/500、UDP/4500，或 Remote Access 门户 443）
      └─ 发起 VPN 协商（IKE / 证书交换）
          └─ 利用证书信任校验不当（CWE-295）绕过安全检查
              └─ 在 Security Gateway 上执行任意代码
                  └─ 读取/篡改机密数据、破坏业务、以内网落脚点横向移动
```

#### 3.3.11 风险影响

漏洞成功利用后，可能导致：

- 未认证攻击者在 Security Gateway 上执行任意代码；
- 绕过 VPN 安全检查并建立未授权访问通道；
- 读取或篡改机密数据、VPN 凭据与预共享密钥；
- 以内网落脚点横向移动至其他服务器或业务系统；
- 破坏业务连续性、中断远程接入与站点互联；
- 篡改安全策略与配置，长期维持访问。

#### 3.4.2 漏洞摘要

该漏洞位于 Check Point **VPN 证书的 ASN.1 解码流程**中，属于堆缓冲区溢出（CWE-122）。远程攻击者可通过向受影响系统提供特制的证书/ASN.1 结构触发解析越界写，进而在 **Security Management Server、Security Gateway 与 Spark 防火墙**上实现任意代码执行。

与 3.3（`CVE-2026-85102`，证书信任校验不当）相比，本漏洞是更为底层的内存安全问题：前者是"校验逻辑被绕过"，后者是"解析逻辑越界"。两者共用同一批紧急安全更新（LivePatch `BUNDLE_URGENT_SECURITY_UPDATE_*AUTOUPDATE` Take 24），且厂商给出的验证命令中 `cpcert:cpca*`、`cpcert:iked*`、`cpcert:vpn*`、`cpcert:vpnrad*`、`cpcert:wstlsd*`、`cpcert_cprid:cprid*` 进程同时标注了这两个 CVE，说明二者由 VPN 证书处理链路中的同一组组件承载。由于管理服务器同样受影响，**该漏洞的影响面比 3.3 更大**：管理服务器失陷意味着攻击者可能直接掌控安全策略与全网网关。

#### 3.4.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需能向受影响系统提交可进入 VPN 证书解析流程的数据（VPN 协商端口 `UDP/500`、`UDP/4500`，管理服务器相关证书处理接口） |
| 身份认证 | 无需 | 未认证远程攻击者可触发 |
| 用户交互 | 不需要 | 无需管理员导入证书或人工操作 |
| 特定配置 | 视部署形态而定 | 需触发证书 ASN.1 解码路径（如证书交换/校验流程） |
| 利用复杂度 | 低（厂商评定 AC:L，但内存破坏型漏洞的实际利用需精心构造数据） |

**技术原理：**

VPN 证书在解析前需经过 ASN.1 解码。实现对输入长度与结构的校验不足，在解码特制证书时发生堆缓冲区越界写（CWE-122），可被用于破坏堆元数据并最终实现任意代码执行。由于该解码流程在管理服务器与网关上均可达（且部分路径无需认证），厂商将严重级别定为 CRITICAL；`cpcert` 系列进程（cpca、iked、vpn、vpnrad、wstlsd、cprid）均为该链路组件，因此修复以 LivePatch 覆盖这些进程的方式交付。

**核心利用链：**

```text
攻击者
  └─ 定位对外暴露的 Check Point 网关 / 可达的管理服务器
      └─ 构造特制证书（异常 ASN.1 长度/结构）
          └─ 触发 VPN 证书 ASN.1 解码堆溢出（CWE-122）
              └─ 破坏堆结构 → 实现任意代码执行
                  └─ 控制网关/管理服务器（可影响全网安全策略）
```

#### 3.5.2 漏洞摘要

该漏洞是自托管 JFrog Artifactory 的**认证实现弱点**，厂商描述为"在默认配置下，具备网络访问能力的未认证攻击者可获取管理员权限"。第三方 PoC 仓库（`dinosn/cve-2026-82329-jfrog-artifactory`）在 7.161.19 与 7.161.20 两个官方镜像上做了 A/B 复现，并基于对闭源 JFrog Access 服务的**字节码差异比对**定位到根因：JFrog Access 在验证集群 "join" JWT 时使用平台 join key 作为 HMAC 密钥，而某处缺陷使**空白 join key 被静默加入可信校验集合**——`getSigningKey("")` 推导出完全可预测的 32 字节密钥，攻击者可据此伪造合法的 join JWT，经**无需认证的注册接口**换取 `SERVICE` 令牌（scope 为 admin），再换取具备 `applied-permissions/admin` 的**全量管理员平台令牌**，最终读取整个服务器配置、列举并窃取全部访问令牌、创建管理员账号。

需要强调的是：该 CVE 并非孤立利用。Security Affairs 援引 Wiz 的研究指出，攻击者将 `CVE-2026-42016`、`CVE-2026-42018` 与本漏洞串联，实现"**权限提升 → 令牌窃取 → 持久化管理员 → 恶意插件/后门**"的完整链路，攻击窗口覆盖 2026-08-15 至 2026-09-08。Artifactory 作为制品仓库，通常同时持有源码包、构建产物、CI/CD 凭据与部署令牌，失陷后可直接污染软件供应链，风险外溢程度高于一般业务系统。

#### 3.5.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需能访问 Artifactory 的 Access/Router 接口（默认 `8082`/`8081`，常经反向代理以 `443` 暴露） |
| 身份认证 | 无需 | 全链路未认证（PoC 三步均无需凭据） |
| 用户交互 | 不需要 | — |
| 特定配置 | 是 | 厂商描述为"默认配置下"；第三方复现使用官方默认镜像，未做额外弱化配置 |
| 利用复杂度 | 低 | PoC 已完整公开，Docker 环境可一键复现 |

**技术原理：**

JFrog Access 服务在验证集群 join JWT 时，以平台 join key 作为 HMAC 密钥校验签名。缺陷导致**空白 join key 被加入可信密钥集合**，其派生值（PoC 分析为对空字符串做 PKCS#7 填充后的 32 字节常量）完全可预测，从而使攻击者可以伪造 `alg=HS256`、`kid=SHA256("")` 的合法 join JWT（携带任意 `service_id`、`skip_node_registration=true`）。随后：

1. 调用**无需认证**的注册接口（`RegistryNoAuthResource`）提交该 JWT，服务端返回 `SERVICE` 令牌（scope 为 admin）；
2. 持该令牌调用令牌签发接口并使用 `scope=applied-permissions/admin&audience=*` 换取**平台管理员令牌**；
3. 以管理员令牌读取全量系统配置、列举并窃取所有访问令牌，进而在 Pro/Enterprise 版本中创建管理员用户与仓库。

PoC 的验证方式为"无害回显"，即以**管理员专属接口是否可访问**（未认证时应返回 401）作为判定依据，而非执行破坏性操作。

**核心利用链：**

```text
攻击者
  └─ 发现暴露的自托管 JFrog Artifactory（默认 8082 / 反代 443）
      └─ 伪造集群 join JWT（利用空白 join key 被静默信任）
          └─ 调用无需认证的注册接口 → 获得 SERVICE 令牌（scope=admin）
              └─ 换取具备 applied-permissions/admin 的平台管理员令牌
                  └─ 读取全量配置、列举并窃取所有访问令牌
                      └─ 创建持久管理员账号 / 部署恶意插件 / 安装后门
                          └─ 组合 CVE-2026-42016、CVE-2026-42018 形成完整攻击链（在野已观测）
```

- 将 Access/Router 接口（`8082`/`8081`）严格限制在可信网络（研发网段/VPN），禁止互联网可达；
- 在反向代理/WAF 层对 `/access/api/v1/registry/join`、`/access/api/v1/tokens` 等接口增加来源白名单与异常检测；
- 关闭匿名访问并轮换 join key 等平台密钥（若版本支持）；
- 强制管理员与集成账号使用最小权限、启用多因素认证；
- 启用并集中采集 Artifactory 审计日志，对管理员令牌签发设置实时告警；
- 对制品仓库实施网络隔离，限制其对外主动连接。

!!! danger "高危漏洞"

#### 3.6.2 漏洞摘要

`CVE-2026-42016`：JFrog Artifactory（自托管）在 7.133.11 之前的版本中，令牌校验**只验证签名与签发者，不校验令牌的授权范围（scope）**，因此持有低权限令牌的攻击者可将其"兑换"为管理员作用域令牌，实现权限提升。厂商 CWE 分类为 CWE-863（授权不当），NVD 主评 CVSS 8.8。

`CVE-2026-42018`：在产品已关闭匿名访问的前提下，Artifactory 仍可能**向未认证调用者返回内部匿名用户令牌**，从而暴露本不应可达的敏感资源。厂商 CWE 分类为 CWE-287（认证不当），CVSS 7.5。

两者组合后构成本期最完整的攻击链：先用 `CVE-2026-42018` 以未认证身份获得匿名 JWT，再用 `CVE-2026-42016` 将该低权限令牌提升为管理员作用域令牌（研究方还在链中加入 `CVE-2026-82329` 与 `CVE-2026-65616` 以获取真实签名的管理员令牌），最终完成在野观测到的"接管 → 持久化 → 后门"三步。Security Affairs 援引 Wiz 的表述指出，"攻击者已被观察到将两个 Artifactory 漏洞与另一个严重漏洞 `CVE-2026-82329` 组合利用"。

#### 3.6.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 攻击者需能访问 Artifactory 接口（默认 `8081`/`8082`，常经反代暴露） |
| 身份认证 | 无需（42018）／低权限令牌即可（42016） | 组合链全流程未认证 |
| 用户交互 | 不需要 | — |

**技术原理：**

- `CVE-2026-42018`：实现未正确处理"匿名访问已关闭"这一状态，导致匿名用户令牌被返回给未认证调用者，攻击者由此获得一个可参与后续令牌交换的低权限凭据；
- `CVE-2026-42016`：令牌校验逻辑仅验证 JWT 签名与签发者（trust of signature/issuer），未验证令牌被授予的 scope，攻击者因而可将低权限令牌用于管理员级操作，实现提权；
- 二者与 `CVE-2026-82329`（默认 join key 缺陷致管理员令牌伪造）叠加后，攻击者可以稳定获得真实签名的管理员令牌，并落地恶意插件与后门。

**核心利用链：**

```text
攻击者
  └─ 发现暴露的自托管 JFrog Artifactory
      └─ Step 1-2：利用 CVE-2026-42018 获得匿名 JWT 并兑换 access/refresh 令牌对
          └─ Step 3：利用 CVE-2026-42016 将低权限令牌提升为管理员作用域令牌
              （研究方链路另叠加 CVE-2026-82329 / CVE-2026-65616 获取真实签名管理员令牌）
              └─ Step 4-5：上传 payload、写入恶意 logback 配置等实现持久化
                  └─ 在野结果：接管自托管服务器、创建管理员账号、部署恶意插件、安装后门
```

#### 3.6.11 风险影响

漏洞成功利用后，可能导致：

- 未认证攻击者经令牌交换获得管理员作用域权限；
- 窃取内部匿名用户令牌与全部访问令牌；
- 创建持久管理员账号、部署恶意插件与后门；
- 篡改制品、污染构建产物，造成软件供应链风险；
- 读取内部源码、构件与部署配置；
- 中断构建、发布与制品分发业务。

#### 3.6.13 修复与缓解措施

#### 官方修复

1. 将自托管 JFrog Artifactory 升级至 `7.133.11` 或更高版本（`CVE-2026-42016` 的最低修复版本），并确认 `CVE-2026-42018` 与 `CVE-2026-82329` 亦已修复（第三方资料建议 `7.161.15+`，最终以厂商公告为准）；
2. 升级前备份配置、数据库、插件与制品元数据，评估流水线中断窗口；
3. 升级后**立即轮换全部访问令牌、集成密钥、匿名/服务账号凭据与管理员口令**（因匿名令牌与管理员令牌可能已被窃取）；
4. 审计并清理未知管理员账号、未知作用域令牌与未知插件；
5. 检查配置目录（logback 等）与启动项是否被篡改，必要时从可信备份重建实例；
6. 留存升级、轮换与审计证据，满足 KEV 2026-09-25 期限。

#### 临时缓解

- 将 Access/Router 接口限制在可信网络，禁止互联网与非授权网段可达；
- 在反代/WAF 层对令牌与上传/导入接口增加来源白名单、频率限制与异常告警；
- 关闭匿名访问并确认关闭后不再返回任何匿名令牌；
- 收敛管理员权限、启用多因素认证、建立令牌有效期与轮换机制；
- 加强 Artifactory 审计日志集中采集，对"低权限令牌兑换管理员作用域"设置实时告警；
- 对制品仓库实施网络隔离，限制其主动外联。

## 五、当日处置建议

1. **立即排查 Cisco 邮件安全网关（P0，截止 2026-09-17）**：核查是否部署 Cisco Secure Email Gateway／Secure Email and Web Manager 及其版本，升级至 `16.5.0-780`（或按版本对应 `15.5.5-014`／`16.0.4-302`），并用 `grep -i "COPY.*TO PROGRAM" mail_logs` 回溯日志、交叉核对设备之外的防火墙与网络日志；
2. **立即排查自建 JFrog Artifactory（P0，截止 2026-09-25）**：核查版本（`CVE-2026-42016` 影响 `< 7.133.11`），升级后**务必轮换全部访问令牌与集成密钥**、审计管理员账号与令牌作用域、排查插件目录与 logback 等配置是否被篡改（对应 3.5、3.6 的在野攻击链）；
3. **24 小时内处置 Check Point VPN 与集中管理面（P1）**：核验 LivePatch take 24／Jumbo Hotfix（`cpinfo -y CPupdates`、`cplp list`），Site-to-Site VPN 禁用 implied rules 并将 `UDP/500`、`UDP/4500` 限制到特定可信对端 IP，优先覆盖 Security Management Server；
4. 对面向互联网的邮件网关、VPN、制品仓库、安全设备管理面开展一次专项暴露面复核，禁止管理接口对互联网开放；
5. 对已在野利用的漏洞（`CVE-2026-76461`、`CVE-2026-82329`、`CVE-2026-42016`、`CVE-2026-42018`）留存证据：设备内外日志、流量、进程、文件与内存快照，重点排查异常管理员账号、恶意插件/后门、异常外联与数据外传；
