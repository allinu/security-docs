### 3.1 CVE-2026-64849 — MLflow Webhook 服务端请求伪造（SSRF）漏洞

!!! danger "严重漏洞"

#### 3.1.2 漏洞摘要

MLflow 是开源 AI 工程平台（面向 Agent、大语言模型与机器学习模型，月下载量超 6000 万）。漏洞位于模型注册 Webhook 的测试端点 `POST /api/2.0/mlflow/webhooks/{id}/test`：`mlflow/utils/validation.py` 中的 `_validate_webhook_url()` 仅对**原始 URL** 做校验，而 `mlflow/webhooks/delivery.py` 在投递时**跟随重定向并重新解析 hostname 且不固定已验证地址**，导致攻击者可借重定向（或 DNS 重绑定）绕过 SSRF 防护，让 MLflow 服务器代为访问内部服务或云元数据端点（如 `169.254.169.254`），并获取 `response_status` 与 `response_body` 回显，进而窃取临时云凭据与密钥。该问题为**对先前修复的绕过**（重定向处理缺陷）。

[watchTowr](https://thehackernews.com/2026/08/attackers-exploit-mlflow-ssrf-flaw-to.html) 通过全球蜜罐网络（Attacker Eye）观测到：CVE 于 2026-08-17 分配后数小时内，攻击者即对互联网暴露的 MLflow 实例发起无差别扫描，利用该漏洞访问云元数据服务并窃取凭据与密钥。

> 官方公告：[GitHub Advisory GHSA-7gwp-5pfp-969j](https://github.com/mlflow/mlflow/security/advisories/GHSA-7gwp-5pfp-969j)、[CISA KEV 查询](https://www.cisa.gov/known-exploited-vulnerabilities-catalog?field_cve=CVE-2026-64849)

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需访问暴露的 MLflow Tracking Server HTTP 接口（默认端口 5000） |
| 身份认证 | 无需 | Webhook 创建与测试接口未认证（受影响版本） |
| 用户交互 | 不需要 | — |
| 特定配置 | 否 | Webhook 功能为受影响版本默认组件 |
| 利用复杂度 | 低 | 仅需构造重定向链（如 httpbin 302 或自定义跳转） |

**技术原理：**

漏洞根因是**校验与请求分离**：创建 Webhook 时仅校验原始 URL，而实际投递（含测试触发）时 `delivery.py` 会跟随 HTTP 重定向并重新解析目标 hostname，却不固定（pinning）校验通过的地址。攻击者提交一个指向"合法外网地址（如 httpbin.org 的 redirect 接口）"的 Webhook URL，其重定向目标指向内网或云元数据地址，即可让服务端代为请求并回显响应。

**核心利用链：**

```text
攻击者
  └─ 发现暴露的 MLflow Tracking Server（HTTP 接口）
      └─ 创建 Webhook：url 指向可控重定向地址（如 httpbin 302）
          └─ 触发 POST /api/2.0/mlflow/webhooks/{id}/test
              └─ delivery.py 跟随重定向、重新解析 hostname（未固定校验地址）
                  └─ 请求云元数据端点 169.254.169.254 或内网服务
                      └─ 回显 response_status / response_body，窃取云凭据与密钥
```

#### 3.2.2 漏洞摘要

TrueConf Server 是 TrueConf 公司出品的视频会议与协作平台（支持 Windows 与 Linux）。该漏洞由卡巴斯基首席安全研究员 Vyacheslav Kopeytsev 发现：**未认证远程攻击者**可通过网络访问 **4307/TCP 端口**，调用一个**未文档化函数**在服务器上执行任意脚本，影响 TrueConf Server 5.3.X 至 5.3.8、5.4.X 至 5.4.8、5.5.X 至 5.5.4 及 5.3 之前的所有版本。

该漏洞的实战风险由 [Kaspersky 2026-08-12 攻击报告](https://ics-cert.kaspersky.com/publications/reports/2026/08/12/head-mare-exploits-vulnerabilities-in-trueconf-server-to-deliver-phantomcore-malware/)确认：**Head Mare** 组织（此前被归类为"hacktivist"，因 TTP 复杂度提升被卡巴斯基重新定性为 APT）于 **2026 年 7 月**对俄罗斯组织发起攻击，利用未修补的 TrueConf Server 漏洞获取 Web Shell 权限，进而收集 IT 基础设施信息、获取 TrueConf 数据库特权访问，最终**将官方 TrueConf Client 安装包替换为植入 PhantomCore 后门的恶意版本**，使所有连接到被控服务器的会议参与者感染（PhantomCore 与 PhantomGraph 双后门，供应链式传播）。

> 官方公告：[Kaspersky ICS-CERT KLCERT-26-057](https://ics-cert.kaspersky.com/advisories/2026/08/11/trueconf-server-missing-authentication-for-critical-function/)、[CISA KEV 查询](https://www.cisa.gov/known-exploited-vulnerabilities-catalog?field_cve=CVE-2026-72529)

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |

**技术原理：**

TrueConf Server 的 4307/TCP 服务中存在**未文档化函数**，该函数未实施身份认证与授权校验，远程攻击者可未经认证直接调用并**执行任意脚本**，达成完整的机密性/完整性/可用性影响（CVSS 9.8）。

**核心利用链：**

```text
攻击者
  └─ 发现暴露的 TrueConf Server（4307/TCP）
      └─ 未认证调用未文档化函数执行任意脚本
          └─ 写入 Web Shell 建立持久化（Kaspersky 观测到 Web Shell）
              └─ 收集 IT 基础设施信息、获取数据库特权访问
                  └─ 篡改 TrueConf Client 安装包，投放 PhantomCore/PhantomGraph 后门
                      └─ 会议参与者客户端被供应链式感染
```

#### 3.3.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需访问 TrueConf Server 的 4307/TCP 端口 |
| 身份认证 | 无需 | 未认证即可利用 |
| 用户交互 | 不需要 | — |
| 特定配置 | 否 | 默认配置受影响 |
| 利用复杂度 | 高 | 需构造特制脚本以逃逸隔离环境（AC:H） |

**技术原理：**

TrueConf Server 将脚本执行置于隔离环境中，但**隔离边界实现存在缺陷**：攻击者提交特制脚本可突破隔离限制，在宿主机操作系统上下文执行任意代码（CWE-94 代码注入 + 沙箱逃逸）。与 `CVE-2026-72529` 组合时，攻击者先获得脚本执行能力，再借本漏洞完成到宿主机的权限提升。

**核心利用链：**

```text
攻击者
  └─ 发现暴露的 TrueConf Server（4307/TCP）
      └─ （组合 72529）未认证调用未文档化函数
          └─ 提交特制脚本尝试逃逸隔离环境
              └─ 突破沙箱边界（CWE-94 代码注入）
                  └─ 在宿主机操作系统执行任意代码（提权至宿主）
                      └─ 篡改安装包/横向移动/植入后门
```

### 3.4 CVE-2026-32475 — Elementor Pro 未授权任意文件上传致远程代码执行漏洞

!!! danger "严重漏洞"

#### 3.4.2 漏洞摘要

Elementor Pro 是广泛部署的商业 WordPress 页面构建插件。漏洞位于 **Forms（表单）模块的 File Upload（文件上传）字段**：插件对上传文件类型检查存在缺陷，**未认证攻击者**可绕过文件类型校验，上传包含恶意内容的 **PHP 文件**，进而通过 Web 访问触发**远程代码执行**，实现网站完全沦陷（CVSS 9.0，影响范围扩展 S:C 至插件所在宿主环境）。问题于 2026-07-16 报告给 Elementor Pro 厂商，修复版本 **4.2.2 于 2026-08-19 发布**。

由于 Elementor Pro 在 WordPress 生态中装机量巨大（大量企业站、商城站依赖表单功能），该漏洞的实际暴露面值得高度关注；[Patchstack 分析](https://patchstack.com/articles/critical-unauthenticated-file-upload-to-rce-in-elementor-pro-plugin)确认攻击无需任何账号权限。

#### 3.4.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需访问启用了 Forms 文件上传功能的 WordPress 站点 |
| 身份认证 | 无需 | 未认证即可利用 |
| 用户交互 | 不需要 | 需目标站点存在含 File Upload 字段的表单（常见默认能力） |
| 特定配置 | 是 | 站点需启用 Forms 模块文件上传字段（广泛默认可用） |
| 利用复杂度 | 高 | 需绕过文件类型/内容检查（AC:H） |

**技术原理：**

漏洞根因是 Elementor Pro Forms 模块文件上传处理逻辑中**文件类型校验可被绕过**：攻击者可通过构造特殊文件名/内容（如利用 MIME 类型混淆、双扩展名或校验顺序缺陷）上传 PHP 脚本，随后直接访问上传文件触发代码执行（CWE-434 不受限制的危险类型文件上传）。

**核心利用链：**

```text
攻击者
  └─ 发现使用 Elementor Pro（≤ 4.2.1）且启用表单文件上传的站点
      └─ 构造恶意文件绕过文件类型/内容检查（未认证）
          └─ 经 Forms File Upload 字段上传 PHP 载荷
              └─ 直接访问上传文件（Web 路径）
                  └─ 触发 PHP 代码执行（RCE）
                      └─ 植入 WebShell/后门，完全控制站点（含宿主环境）
```

### 3.5 QVD-2026-56312 — JeecgBoot 权限绕过与 SQL 注入组合漏洞

!!! danger "高危漏洞"

#### 3.5.2 漏洞摘要

JeecgBoot 是由北京国炬信息技术有限公司开发的开源低代码开发平台（基于 Spring Boot 与 MyBatis-Plus，提供权限管理、数据字典、在线表单、报表设计、微服务扩展等能力，广泛应用于企业级信息化系统快速构建）。漏洞为**权限绕过与 SQL 注入的组合**：

1. **权限绕过**：JeecgBoot 的 Shiro 权限过滤链中配置有 `/*/**/*.js` 等**静态资源匿名放行规则**，攻击者在 API 路径后附加静态资源后缀（如 `.js`）即可命中放行规则，**绕过 JWT 认证**，以匿名身份访问 `/sys/dict/getDictItems/*` 等敏感数据接口；
2. **SQL 注入**：四段式字典码中的 `filterSql` 参数过滤不完善，恶意 SQL 被直接拼接进查询语句的 WHERE 子句，攻击者可通过**布尔盲注**窃取数据库中的敏感信息（用户账号、口令哈希、手机号、业务数据等），进一步可导致数据泄露、数据篡改乃至服务器沦陷。

[奇安信鹰图资产测绘平台](https://mp.weixin.qq.com/s?__biz=MzU5NDgxODU1MQ==&mid=2247507173&idx=1&sn=31742a3353f86d4f518ddb16f2f7956f)数据显示，该漏洞关联的**国内风险资产总数为 61,084 个，关联 IP 总数为 12,751 个**，影响量级为"万级"，利用可能性评级"高"。官方**尚未发布修复补丁**，仅能实施临时缓解措施。

#### 3.5.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需访问暴露的 JeecgBoot 应用 HTTP 接口 |
| 身份认证 | 无需 | 利用路径附加 `.js` 后缀绕过 JWT 认证后匿名访问 |
| 用户交互 | 不需要 | — |
| 特定配置 | 否 | 默认 Shiro 过滤链配置受影响 |
| 利用复杂度 | 低 | 奇安信已复现，路径匹配差异稳定可触发 |

**技术原理：**

漏洞根因有二：其一，Shiro 权限过滤链将 `/*/**/*.js` 等静态资源路径设为匿名放行，且**路由匹配差异**允许在 API 路径后附加 `.js` 后缀命中放行规则（如 `/sys/dict/getDictItems/xxx.js`），从而绕过 JWT 认证中间件；其二，字典查询接口 `/sys/dict/getDictItems/*` 的 `filterSql` 参数未做充分过滤，恶意 SQL 被直接拼接进查询语句 WHERE 子句，攻击者可通过布尔盲注逐位提取数据库内容。

**核心利用链：**

```text
攻击者
  └─ 发现暴露的 JeecgBoot 应用
      └─ 在 API 路径后附加 .js 静态资源后缀
          └─ 命中 /*/**/*.js 匿名放行规则，绕过 JWT 认证
              └─ 匿名访问 /sys/dict/getDictItems/* 等敏感接口
                  └─ 构造 filterSql 参数注入恶意 SQL（布尔盲注）
                      └─ 窃取用户账号、口令哈希、手机号与业务数据
```
