### 1.3 今日重点关注

1. **`CVE-2026-76460`：Cisco Identity Services Engine（ISE/ISE-PIC）API 认证控制不足致认证绕过**  
   影响 Cisco ISE 与 ISE-PIC 全部在维护版本（3.1/3.2/3.3/3.4/3.5 的补丁前版本），**无需任何凭据**即可通过特制请求绕过 Web 管理界面完成认证，CVSS 3.1 = **10.0**。Cisco PSIRT 明确表示**已掌握实际在野利用**，并提示利用成功后攻击者可获得 **root 权限的命令执行**、可能清除或隐藏取证痕迹；该漏洞已纳入 **CISA KEV**，整改截止 **2026-09-19**。建议立即排查对外暴露的 ISE 管理面并升级至 3.1 Patch 12 / 3.2 Patch 11 / 3.3 Patch 12 / 3.4 Patch 7 / 3.5 Patch 4。

2. **`CVE-2026-87886`：Acronis Backup（cPanel & WHM 插件 / Plesk 扩展）不安全文件权限致 Linux 本地权限提升**  
   攻击者可通过被错误授权的文件与备份服务交互，以低权限账户**提升至 root**，CVSS = **7.8**。Acronis 确认已在 **cPanel & WHM 部署环境中观测到「有限、定向」在野利用**（依据单起客户报告，Plesk 侧暂未见利用），并同批纳入 **CISA KEV**。修复版本为 cPanel & WHM 插件 `1.9.3 HF3`、Plesk 扩展 `1.8.11`；受影响运维主体以主机托管商、MSP 与多租户虚拟主机平台为主。

3. **Cisco 2026-09-16 大规模安全公告批次（同批 77 个新 CVE，41 个影响 ISE/ISE-PIC）**  
   除 `CVE-2026-76460` 外，同批还包含 `CVE-2026-76423`（10.0，REST API 认证绕过/RCE/SQLi/XXE）、`CVE-2026-20130`（10.0）、`CVE-2026-20192`（10.0）、`CVE-2026-20176`（9.9）等，另 **28 个影响 Secure Firewall 产品线**（ASA/FTD/FMC，含 `CVE-2026-20242` 9.8 未认证 root 命令执行、`CVE-2026-20324` 9.9 sftunnel root 命令执行）；HKCERT 于 2026-09-17 另发批次公告，覆盖 Secure Firewall 与 IOS XR 的 **22 个 CVE**。该批次与 `CVE-2026-76460` 的紧急处置应合并排期。

### 1.4 综合研判

本期窗口内公开漏洞总量不大（新增可直接处置的 CVE 仅 2 个），但**质量与紧迫性显著偏高**：其一，`CVE-2026-76460` 是 **CVSS 10.0 且已在野利用的网络准入控制（NAC）核心组件认证绕过**，ISE 通常承载 802.1X、MAB、Guest 与 TACACS+/RADIUS 策略，一旦被攻陷，攻击者不仅可读取设备配置与身份库，还被视为**具备向网络与终端侧横向扩展的现实条件**，且 Cisco 明确其在拿下 root 后可清除痕迹，取证与抑制窗口被压缩；其二，`CVE-2026-87886` 面向 **多租户托管/虚拟主机场景**，本地低权限到 root 的提权在共享主机环境中天然意味着租户隔离失效；其三，Cisco 同批 77 个新 CVE 与 HKCERT 的两份批次公告（思科 22 项、Mozilla 78 项）说明**大量修复已就绪**，当前主要风险是"补丁未落地"而非"无补丁可用"。从威胁面看，本期无 CVE 的动态同样值得关注：`SilkParasite/SpiceRAT` 显示针对中亚政府与能源/电信部门的长期窃密活动已延续至 **2022 年**，`CHOSEN BRICK` 则把社交工程、Telegram C2 与 Defender 排除项组合用于**针对个人（记者、活动人士）的人身安全威胁**，二者均属"技术门槛不高、社会影响大"的类型。本地资产侧，本站为公开文档站点，无 ISE、Acronis 备份插件、Firewall 管理面等受影响资产的资产台账可关联，相关字段按规范填「不适用/待核查」。

!!! danger "研判结论：较高风险"
    今日最主要风险点为 **`CVE-2026-76460`（Cisco ISE/ISE-PIC，CVSS 10.0，无需认证且在野利用，KEV 整改截止 2026-09-19）** 与 **`CVE-2026-87886`（Acronis Backup cPanel/WHM、Plesk，本地提权且已定向利用）**。要求：**在 2026-09-19 前**完成两枚 CVE 的资产排查与补丁升级，对无法立即升级的 ISE 管理面立即实施基础设施 ACL（iACL）与网络收敛，并按 Cisco 官方建议核查各节点 `access.log` 是否存在可疑用户名、必要时重装节点并从配置备份恢复。

### 3.1 `CVE-2026-76460` — Cisco Identity Services Engine API 认证绕过

!!! danger "严重漏洞"
    影响 Cisco Identity Services Engine（ISE）与 ISE Passive Identity Connector（ISE-PIC）全部在维护版本的补丁前版本，**无需身份认证、无需用户交互**即可通过特制请求绕过 Web 管理界面完成认证；Cisco 确认在野利用，且提示利用成功后攻击者可能获得 **root 权限的命令执行**，进而清除或隐藏取证痕迹。

#### 3.1.2 漏洞摘要

该漏洞位于 Cisco Identity Services Engine（ISE）暴露的 API 组件中。Cisco 安全公告指出，其成因为**某个 API 端点上的认证控制不足**（对应 `CWE-648`「特权 API 使用不当」）。攻击者无需持有任何有效凭据，只需向受影响的 API 端点发送**构造过的请求**，即可**绕过基于 Web 的管理界面完成认证**，从而在设备上获得未授权访问。

> 与常见的"认证后提权"不同，本漏洞的利用**起点即无凭据**：攻击者在网络可达的前提下（默认管理面为 HTTPS，通常位于 443/TCP 或其重定向端口）即可直接发起尝试，因此对"管理面暴露于互联网/宽泛内网段"的部署形态风险最高。Cisco 进一步提示，利用成功后威胁行为者**可能获得 root 权限的命令执行能力**，这意味着攻击者可读取或篡改策略与身份数据、并在设备内尝试清除日志等取证痕迹，进而要求防守方在设备之外（网络与防火墙侧）交叉核验异常外联与上传行为。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 ISE/ISE-PIC 的 API/管理面（HTTPS，通常 443/TCP；分布式部署须逐节点评估） |
| 身份认证 | 无需 | 漏洞本体即为认证绕过，攻击者不需要任何账号或令牌 |
| 用户交互 | 不需要 | 纯服务端请求触发 |
| 特定配置 | 否 | Cisco 明确"无论设备配置如何均受影响" |
| 利用复杂度 | 低 | `AC:L`、`PR:N`、`UI:N`，CISA SSVC 判定 `automatable=yes`；无公开细节降低门槛，但无特殊前置条件 |

**技术原理：**

Cisco 公告将根因归结为**API 端点认证控制不足**（`CWE-648`）。可以确定的是：受影响 API 在被调用时未对调用者施加与其特权等级相匹配的认证校验，导致本应仅对已认证（且通常为高权限）会话开放的功能，被未认证请求直接命中。由于 ISE 的管理界面与 REST API 共享同一套对外服务入口（`ise-kong` API 网关），攻击面集中在 API 网关层。

需要说明的是：截至本报告编制时，**官方与本报告检索范围内均未公开具体的脆弱端点路径与请求构造细节**（Cisco 未披露、PoC 未公开），因此本节不对利用载荷形态作任何推测。

**核心利用链：**

```text
无凭据攻击者
  └─ 定位网络可达的 Cisco ISE / ISE-PIC 管理面（HTTPS）
      └─ 向受影响的 API 端点发送构造请求（绕过认证校验）
          └─ 获得设备未授权访问（等效管理面权限）
              └─ 进一步获得 root 权限的命令执行（Cisco 官方提示）
                  └─ 读取/篡改策略与身份数据、尝试清除或隐藏取证痕迹
                      └─ 借设备网络位置向终端与网络侧扩展（须结合环境评估）
```

#### 3.1.9 检测与排查

#### 资产排查

- [ ] 是否部署 Cisco ISE 或 ISE-PIC（含分布式部署的全部节点）
- [ ] 当前版本是否处于影响范围（3.1–3.5 对应补丁前版本；3.0 是否仍在运行）

- [ ] 是否存在默认账号、弱口令或默认配置
- [ ] 是否已安装官方补丁或采取缓解措施（iACL 是否落地）
- [ ] 是否已按 Cisco 建议对每个节点检查 `access.log`

#### 日志与行为排查

重点检查：

- ISE 节点 `access.log`（`ise-kong/access.log` 与 `apigateway/access.log`）中的**异常用户名**（Cisco 给出的示例排查对象为 `dummyuser`）；
- ISE 审计与管理员操作日志、认证/授权失败与异常成功记录；
- 分布式部署中**每个节点**的日志（不可只查 PAN/主节点）；
- 设备侧异常进程、计划任务与新增本地账户；
- 设备对外发起的**异常上传**（如向外部 IP 上传配置或日志）与**异常下载**（从可疑 IP 拉取文件）；
- 网络侧（防火墙、代理、DNS）与设备日志的**交叉比对**——Cisco 明确因攻击者可清除痕迹，须在设备之外进行核验；
- WAF/IPS 与态势感知中针对 ISE 管理面的异常请求特征。

| 检测项 | 可疑特征 |
| --- | --- |
| 请求路径 | 面向 API 网关（`ise-kong` / `apigateway`）的、非管理界面前端发起的直接 API 调用 |
| 请求方法 | `GET/POST/PUT` 均可（官方未披露具体方法，不作推定） |
| 参数特征 | 本报告未取得公开载荷特征，不作推定 |
| User-Agent | 异常空 UA、脚本类 UA（curl/python-requests）访问管理 API |
| 响应状态 | 无凭据会话获得 `200/2xx` 成功响应（"无需认证即成功"是关键异常信号） |
| 进程行为 | ISE 节点出现非预期命令解释器调用、异常子进程（后利用 root 命令执行迹象） |
| 文件行为 | 日志目录被清理/截断、`apigateway` 日志缺失或被改写 |
| 网络行为 | ISE 节点向外部 IP 发起异常上传/下载；非常规时间的管理面外联 |

#### 3.1.11 风险影响

漏洞成功利用后，可能导致：

- 未经授权访问 Cisco ISE 管理面与 REST API；
- 以 root 权限执行任意系统命令（Cisco 官方明确提示）；
- 读取、篡改或删除网络准入策略、身份库与设备信任配置，间接影响全网接入控制（802.1X/MAB/Guest/TACACS+）；
- 泄露账号、密钥、证书与配置文件等敏感数据；
- 植入后门、WebShell 或恶意程序，并借设备网络位置横向移动；
- 清理、隐藏取证痕迹，导致事件溯源与根因判定困难；
- 中断网络准入服务，影响办公网络、无线与远程接入可用性。

#### 3.1.13 修复与缓解措施

#### 官方修复

1. 将 Cisco ISE / ISE-PIC 升级至对应修复版本：`3.1 Patch 12`、`3.2 Patch 11`、`3.3 Patch 12`、`3.4 Patch 7`、`3.5 Patch 4`；
2. 运行 ISE Software Release `3.0` 的环境已终止软件维护，须迁移至受支持版本（无 3.0 专项补丁）；
3. 分布式部署须**逐节点**升级并核验（Cisco 特别要求逐节点排查日志）；
4. 升级前完成配置备份与业务数据备份（Cisco 支持通过配置备份恢复）；
5. 在测试环境验证兼容性及回退方案（ISE 升级涉及策略与证书，需评估中断窗口）；
6. 升级后核验版本、补丁状态及接入认证业务运行情况；
7. 若怀疑已被利用，Cisco 建议**重装受影响节点（re-image）并从配置备份恢复**，而非仅做清除。

#### 临时缓解

无法立即升级时，可采取：

- 使用基础设施访问控制列表（**iACL**）仅放行必要的管理与控制平面流量到 ISE 设备（Cisco 官方给出的唯一缓解措施）；
- 将 ISE 管理面从互联网完全下架，改为运维专网/跳板机访问；
- 通过防火墙、ACL、安全组限制管理面来源 IP，关闭非必要端口（如同时开放的 8443）；
- 在 WAF/IPS/网关侧对管理 API 增加认证前拦截与速率限制；
- 启用强身份认证与多因素认证，修改默认账号与默认密码/密钥；
- 加强日志审计（尤其 `access.log` 与管理员操作审计）与主机监控，**并将日志外送**以防本机痕迹被清除；
- 对关键节点实施网络隔离或访问收敛，并提升该资产的监控等级。

### 3.2 `CVE-2026-87886` — Acronis Backup（cPanel & WHM / Plesk）本地权限提升

!!! danger "高危漏洞"
    影响 Acronis Backup 的 cPanel & WHM 插件与 Plesk 扩展；持有低权限的本地攻击者可通过不安全文件权限操纵备份服务使用的文件，无需用户交互即可**提升至 root**。Acronis 确认在 cPanel & WHM 部署环境中出现「有限、定向」在野利用，并同批纳入 CISA KEV。

#### 3.2.2 漏洞摘要

该漏洞存在于 **Acronis Backup 的 cPanel & WHM 插件**与 **Plesk 扩展**中。这两类组件把 cPanel/WHM、Plesk 控制面板与 Acronis 云备份基础设施连接起来，使主机托管商、MSP 与服务器管理员可在控制面板内直接备份与恢复站点、文件、数据库、邮箱及托管账户。由于相关组件在 Linux 主机上以高权限服务形态运行，但部分文件的权限设置不安全（`CWE-276`），**持有普通/低权限账户的攻击者可操纵备份服务所使用的文件，从而以 root 权限执行代码**。

> 攻击前提是"已获得服务器上的低权限访问"（如被攻陷的共享主机租户账户、Web 应用被拿下的 `www-data` 角色等），因此本漏洞的典型作用是**后利用阶段的提权与隔离突破**：在多租户托管环境中，一旦单一租户的权限边界可用本漏洞击穿，其他租户的数据与整台宿主机都将暴露。Acronis 强调已观测到针对 cPanel & WHM 部署的"有限、定向"利用，但**未公布利用时间、攻击者收益与任何 IOC**，技术细节按厂商要求暂缓披露。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 否（本地） | 属本地漏洞，需已在目标主机上取得可执行权限 |
| 身份认证 | 普通用户 | 需持有主机上的低权限账户/代码执行能力 |
| 用户交互 | 不需要 | 厂商与媒体明确"no user interaction" |
| 特定配置 | 是 | 需安装受影响插件/扩展且存在不安全的文件权限配置 |
| 利用复杂度 | 低 | CVSS 字符串表明"低复杂度"，无需攻击者不可控的特殊条件 |

**技术原理：**

Acronis 公告将根因描述为**不安全文件权限**（CISA KEV 归类 `CWE-276`）：备份插件/扩展安装的文件或目录被赋予了过宽的可写权限（或属主/模式不当），而相关文件又被以高权限运行的备份服务读取或执行。低权限攻击者据此可"操纵备份服务所使用的文件"，在服务以 root 身份执行路径复用时实现权限提升。

需要说明的是：**厂商为给管理员留出补丁窗口，明确暂不公开进一步技术细节**，本报告不对具体可写文件路径、服务单元或触发时序作任何推测；上述原理仅依据官方与媒体已公开的一致表述归纳。

**核心利用链：**

```text
已获得低权限立足点的攻击者（如被攻陷的共享主机租户、Web 服务账户）
  └─ 定位 Acronis Backup 插件/扩展安装的权限不当文件与目录
      └─ 写入/替换被高权限备份服务读取或执行的文件内容
          └─ 等待或触发备份服务以 root 身份执行相关操作
              └─ 实现本地权限提升（低权限 → root）
                  └─ 突破租户隔离，读取/篡改宿主机及其他租户数据
```

#### 3.2.11 风险影响

漏洞成功利用后，可能导致：

- 以 root 权限在宿主机上执行任意代码；
- 突破共享主机/多租户隔离，访问或篡改其他租户的站点、数据库与邮箱数据；
- 获取 Acronis 备份凭据、云存储密钥等敏感信息，进而触及备份数据通路；
- 篡改网站页面、配置或业务数据；
- 植入 WebShell、后门或恶意程序；
- 横向移动至同主机其他服务或内网其他服务器；
- 中断备份服务与业务服务可用性（含备份数据被破坏导致恢复链断裂）；
- 被勒索软件、挖矿木马或僵尸网络利用。

#### 3.2.13 修复与缓解措施

#### 官方修复

1. 将 **Acronis Backup plugin for cPanel & WHM** 升级至 `1.9.3 HF3`（受影响构建号早于 `1.9.3.1021`）；

5. 在测试环境验证备份/恢复任务兼容性及回退方案；
6. 升级后核验插件版本与构建号，并抽查一次备份与恢复任务；

#### 临时缓解

无法立即升级时，可采取：

- 暂时停用或卸载 Acronis Backup 插件/扩展（备份链路改由独立通道执行）；
- 限制 `2083/2087/8443` 控制面板端口的互联网访问，仅允许可信 IP 与管理网段；
- 对备份插件安装目录实施严格权限收敛与文件完整性监控（FIM）；
- 强制控制面板与租户账户使用强口令与多因素认证；
- 及时修补同主机上的 Web 应用漏洞，消除攻击者获取低权限立足点的入口；
- 加强审计日志外送与主机 EDR 监控，重点检测备份服务异常子进程；
- 对高风险多租户主机实施隔离收敛，并提高备份数据的离线/不可变保护级别。

| 在野利用 | 已确认（至少自 2025 年起） |
| 修复版本 | 不适用（以检测、清除与账户加固为主） |

**漏洞描述：**  
英国 NCSC、美国 FBI 与荷兰 AIVD 联合发布预警，将伊朗国家背景行为体使用的 Windows 恶意软件家族正式命名为 **CHOSEN BRICK**。攻击以**社交消息应用（WhatsApp/Telegram）建立信任**为起点，冒充受害者熟人（`T1589` 情报收集、`T1566.003` 网络钓鱼）或平台技术支持，随后投递伪装为 Pictory、RunwayML、Norton Antivirus、Telegram、Adobe Flash Player、KeePass 安装包乃至"核磁共振检查结果"的诱饵文件；文件展示可信的**诱饵界面**，后台静默安装主体。恶意软件**通过注册表 Run 键实现持久化**、尝试为自身添加 **Microsoft Defender 排除项**，并**使用 Telegram 机器人（每台设备独立 bot ID）作为 C2**，新版还引入 HTTPS/SOCKS5 代理（`T1090.002`）；数据经 Telegram 机器人与云对象存储（VultrObjects、StorjShare，`T1567.002`）外传。样本中出现互斥体名 `ytyjyujyu` 与 `noi672pp434awkc12f`，并出现形如 `C:\Windows \SysWOW64`（"Windows"后含**异常空格**）的非标准路径以规避白名单。当工作设备防护严密时，攻击者会转向请求目标在个人设备上打开文件。

**修复建议：**  
对高风险个人与组织：避免从链接/附件安装软件；启用抗钓鱼 MFA、应用白名单、邮件安全与端点监控；在 DNS/代理日志中关注 `api.telegram.org`、`backblazeb2.com`、`vultrobjects.com`、`storjshare.io`、`iproyal.com`、`lightningproxies.net` 的异常出现（这些域名本身合法，需结合上下文判断）；检查 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的陌生项（历史值名如 `SMQDService`、`winappx`，但**名称会变化，不可作为固定 IOC**）；同时为高风险人员的**个人设备**提供安全指引。

来源：[Security Affairs：Chosen Brick, Iran's Surveillance Malware](https://securityaffairs.com/199217/malware/chosen-brick-irans-surveillance-malware.html)

### 无 CVE — NightmareStresser 被国际联合执法取缔（Operation PowerOFF）

| 字段 | 内容 |
| --- | --- |
| 风险等级 | 中危（定性，态势类） |

| CWE编号 | 不适用 |

| 影响范围 | 美国阿拉斯加地区及全球受害者 |

| 在野利用 | 已确认（2022 年以来数十万次实际或尝试性 DDoS 攻击） |
| 修复版本 | 不适用（执法行动） |

**漏洞描述：**  
美国司法部宣布，经法院授权**查封长期运营的 DDoS-for-hire（Booter/Stresser）服务平台 NightmareStresser 相关域名**。据查封令宣誓书，该平台自 2022 年以来被用于对全球受害者发起**数十万次实际或尝试性 DDoS 攻击**，受害对象包括教育机构、政府机构、游戏平台与大量个人用户。行动由 FBI 安克雷奇外地办事处主导技术执行，加拿大皇家骑警联邦警务西北区协助，属国际联合行动 **Operation PowerOFF** 的一部分（2026 年 4 月该行动曾在 21 国同步打击 53 个域名、逮捕 4 名运营者并向 7.5 万余名平台用户发出警告信；2024 年 12 月另有 27 个 booter 站点被关停）。DOJ 表示此类服务因门槛极低（付费即用、常用加密货币支付）而持续滋生，此次行动同时包含公众教育环节。

**修复建议：**  
被 DDoS 影响风险较高的组织应保持 DDoS 防护与流量清洗能力可用、配置 CDN/Anycast 吸收、对关键服务实施速率限制与降级预案；同时预期**替代平台将快速出现**（历史执法经验显示 booter 平台具有高替代性），不应因单次取缔而放松防护；若曾遭受相关攻击，可结合日志留存配合执法取证。

来源：[Security Affairs：NightmareStresser Goes Offline in Global DDoS-for-Hire Crackdown](https://securityaffairs.com/199251/cyber-crime/nightmarestresser-goes-offline-in-global-ddos-for-hire-crackdown.html)

### 无 CVE — 跨国油轮遭网络攻击致通信中断约 30 小时：海事关键基础设施风险

| 字段 | 内容 |
| --- | --- |

| PoC状态 | 不适用 |

**漏洞描述：**  
据 CBS News 报道并经 Security Affairs 转述，美国海岸警卫队人员与 FBI 探员在**上月登船检查两艘驶往德克萨斯州的能源油轮**。其中 VL Prosperity（利比里亚籍、长约 1,093 英尺、载油约 230 万桶）于 8 月 7 日在直布罗陀海峡附近遭网络攻击，伊朗官方媒体随后指认该船并称攻击者进入推进、导航与货物系统，**通信中断约 30 小时**。美国海岸警卫队网络司令部司令 Amy Grable 少将表示，调查人员在评估船上 IT 及其他系统后**确实发现了恶意网络活动**，但登船时未发现船舶不适航的证据，也**未公开将攻击归因于伊朗**，两起攻击是否关联仍在调查中。Grable 强调现代商船高度联网，攻击可能造成"阻塞航道、污染事故及其他港口与水道安全隐患"，而美国港口年吞吐约 **5.4 万亿美元** 贸易额。该事件属海岸警卫队网络保护团队过去一年约 40–50 次任务之一。

**修复建议：**  
航运与港口相关组织应核查船上 IT 与 OT/关键安全系统（推进、导航、货物）的**网络分段与隔离是否有效**，禁止 IT 侧直接可达关键控制系统；加强船舶远程运维通道（卫星链路、远程支持）的访问控制与多因素认证；建立靠港期间与航行期间的基线流量监控与异常外联检测；将船舶网络事件纳入岸基应急响应与取证流程，并与海岸警卫队/船级社等主管机构保持通报渠道。

## 五、当日处置建议

1. **【最高优先级，限 2026-09-19 前】** 对 Cisco ISE / ISE-PIC 开展资产清点，按 3.1 节升级至 `3.1 Patch 12` / `3.2 Patch 11` / `3.3 Patch 12` / `3.4 Patch 7` / `3.5 Patch 4`；无法立即升级的，**立即以 iACL 收敛管理面**并将日志外送，随后对**每个节点**执行 `show logging application ise-kong/access.log | include dummyuser` 排查；如怀疑已被利用，按 Cisco 建议重装节点并从配置备份恢复；
2. **【最高优先级，限 2026-09-19 前】** 对托管/虚拟主机平台清点 Acronis Backup 的 cPanel & WHM 插件（`<1.9.3.1021`）与 Plesk 扩展（`<1.8.11.638`），升级至 `1.9.3 HF3` / `1.8.11`，并对备份插件目录实施权限收敛与文件完整性监控；
3. 将 Cisco 2026-09-16 批次（41 个 ISE CVE、28 个 Secure Firewall CVE）与 HKCERT 思科批次（22 个 CVE）**作为整体补丁窗口排期**，优先处置互联网暴露的 ASA/FTD/FMC 管理面与应用（含 `CVE-2026-20242` 未认证 root 命令执行）；
4. 完成 Mozilla 批次（78 个 CVE）终端侧闭环：Firefox `156`／ESR `115.41` / `140.16` / `153.3`，Thunderbird `140.16` / `153.3` / `156`；
5. 延续处置期限临近项：`CVE-2026-58704`（Google Pixel，KEV 期限 **2026-09-19**）请移动终端负责人按时闭环；`CVE-2026-76461`（Cisco Secure Email Gateway，KEV 期限 2026-09-17）如已过期请立即补办并留档；
6. 对**网络准入与身份基础设施**（ISE/NAC、RADIUS/TACACS+、证书与密钥库）开展专项审计：核查异常管理员会话、证书与密钥是否可能外泄、策略与身份库是否被篡改；
7. 对高风险管理对象（记者、活动人士、NGO）落实 CHOSEN BRICK 相关指引：抗钓鱼 MFA、应用白名单、端点监控，并将个人设备纳入安全提示范围；检查注册表 Run 键与 Defender 排除项是否被恶意添加；
8. 电信、能源、铁路与政府相关行业组织，按 4 章 SilkParasite 条目在边界与 DNS/代理日志中比对公开 IOC（RTX 页面哈希、铁路伪造证书、仿冒域名）；
9. 保留并**外送**关键日志（主机审计、网络、云端），确保在攻击者具备 root 与痕迹清除能力时仍可完成取证；
10. 完成修复后进行复测，并更新资产台账与漏洞处置记录。
