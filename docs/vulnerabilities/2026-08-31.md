### 1.3 今日重点关注

1. **`CVE-2026-81578` + `CVE-2026-82078`：PaperCut NG/MF 预认证 RCE 链（在野利用确认）**  
   打印管理软件 PaperCut NG/MF 的认证绕过（`CVE-2026-81578`，8.8）与数据库连接器不安全动态类加载（`CVE-2026-82078`，9.4）可链式组合，未认证远程攻击者可修改服务器配置并加载任意 Java 字节码，最终以服务进程权限执行任意代码。厂商已于 08-27 确认在野利用并发布紧急补丁（Emergency Patch Release 2），Huntress 确认两个客户环境遭利用并完整复现攻击链；但截至 08-30，受跟踪实例仍有 47% 未打补丁，公网暴露的打印管理服务器风险极高，建议立即安装紧急补丁并将 Web 接口收敛至可信 IP。

2. **`CVE-2026-77537`/`CVE-2026-77550`/`CVE-2026-77554`：UniFi 生态三连满分漏洞（CVSS 3.1 均 10.0，无需认证）**  
   Ubiquiti SAB-067 公告一次性修复 UniFi 生态 22 个漏洞，其中 3 个 10.0 满分漏洞分别位于 UniFi Protect（摄像头管理平台，命令注入）、UniFi OS（网关/云钥匙等，CRLF 认证绕过）、UniFi Talk（语音系统，命令注入），均可被网络可达的未认证攻击者利用获取设备完全控制权，影响摄像头、OS 服务器、云网关、Dream Machine、企业防火墙等全线产品，需尽快升级至公告修复版本。

3. **`CVE-2026-65643`：cPanel 域名停放功能任意文件写 → root 代码执行**  
   任意已认证托管账号（可添加停放/addon 域名）可利用 cPanel & WHM 域名停放功能向服务器任意位置写入文件，并以 root 权限执行代码，完全接管共享服务器。在共享/转售主机场景下"已认证账号"并非有效边界（注册即可获得），实际威胁接近未认证；受影响为全部受支持版本，需升级至 11.110.0.141 / 11.134.0.53 / 11.136.0.37 / 11.138.0.2（WP Squared 11.138.1.7）及以上。

### 1.4 综合研判

本期窗口内集中出现三组高风险漏洞：PaperCut 预认证 RCE 链（**已在野利用确认**、全球数万机构部署的打印管理软件、47% 实例未打补丁）、UniFi 生态三连 10.0 未认证漏洞（覆盖摄像头/网关/语音全线安全基础设施）、cPanel 租户到 root 提权（共享主机行业性风险）。叠加本期为"安全设备自身漏洞"（UniFi）与"基础设施软件在野利用"（PaperCut）的组合，处置窗口短、影响面大。

### 3.1 `CVE-2026-81578` — PaperCut NG/MF Web 管理接口认证绕过（配置篡改）

!!! danger "高危漏洞"
    影响 PaperCut NG/MF 打印管理软件。未经身份认证的远程攻击者可通过构造特殊请求，使服务器"显示"一个页面却实际执行另一个页面的后台动作（权限校验错位），从而在未登录状态下修改系统配置；与 `CVE-2026-82078` 链式组合可形成预认证远程代码执行，且已在野利用。

#### 3.1.2 漏洞摘要

该漏洞位于 PaperCut NG/MF 的 Web 管理接口。据 [PaperCut 官方安全公告](https://www.papercut.com/kb/Main/security-bulletin-27-aug-2026-urgent-security-advisory/)与 [NVD 描述](https://nvd.nist.gov/vuln/detail/CVE-2026-81578)：在特定条件下，指向管理功能的未认证远程请求可在访问校验完成之前触发后台动作——服务器按"显示的页面"校验权限，却按"实际执行的页面"执行动作（权限校验错位，security check / action 分离缺陷）。未认证攻击者可借此修改某些系统配置参数。该漏洞单独利用可导致配置篡改（如修改数据库驱动配置），与 `CVE-2026-82078`（数据库连接器不安全动态类加载）链式组合后，即可加载任意 Java 字节码，形成**预认证远程代码执行**。

> 该漏洞为"权限校验错位"型缺陷：PaperCut 对"页面"做权限校验却对"动作"放行，未认证请求可触发管理后台动作；单看影响为配置篡改（高危），链式利用后为预认证 RCE（严重）。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 PaperCut 应用服务器 Web 接口（默认端口 9191/9192 或经反代暴露的 443） |
| 身份认证 | 无需 | 未认证即可触发 |
| 用户交互 | 不需要 | — |
| 特定配置 | 否 | 默认配置即可触发 |
| 利用复杂度 | 低 | 构造特殊请求即可触发权限校验错位 |

**技术原理：**

PaperCut Web 管理接口在处理请求时，对"将要显示的页面"执行权限校验，但对"实际执行动作"的页面不校验或校验滞后（access validation 与 backend action 分离）。攻击者构造"显示无权限页面、执行管理动作"的特殊请求，使后台在访问校验完成前执行管理操作，从而在未认证状态下修改系统配置（如数据库驱动配置项）。

**核心利用链：**

```text
攻击者（未认证，公网可达 PaperCut Web 接口）
  └─ 构造页面/动作错位的特殊请求
      └─ 触发管理后台动作（绕过访问校验）
          └─ 修改系统配置（数据库驱动名称等）── CVE-2026-81578
              └─ 配合 CVE-2026-82078 加载任意 Java 类
                  └─ 以 PaperCut 服务进程权限执行任意代码
```

### 3.2 `CVE-2026-82078` — PaperCut NG/MF 数据库连接器不安全动态类加载（链式 RCE）

!!! danger "严重漏洞"
    影响 PaperCut NG/MF 打印管理软件。数据库连接工具根据可配置的驱动名称动态实例化数据库驱动类且不做白名单校验，一旦攻击者（通过 `CVE-2026-81578` 等途径）篡改配置参数，即可加载驻留于应用 classpath 的任意 Java 字节码，以 PaperCut 服务进程权限执行任意代码。该链路已被确认在野利用。

#### 3.2.2 漏洞摘要

该漏洞位于 PaperCut NG/MF 的数据库连接工具（database connection utilities）。应用根据可配置的数据库驱动名称动态实例化驱动类，但未对驱动名做白名单校验（[NVD 描述](https://nvd.nist.gov/vuln/detail/CVE-2026-82078)与[厂商公告](https://www.papercut.com/kb/Main/security-bulletin-27-aug-2026-urgent-security-advisory/)均确认）。一旦攻击者能够操纵系统配置参数（如通过 `CVE-2026-81578` 的未认证配置篡改），即可让应用加载并实例化任意 Java 类——将恶意类放置于应用 classpath 后即可触发任意 Java 字节码执行，代码运行于 PaperCut 服务进程的安全上下文。Huntress 在对全新未打补丁的 PaperCut NG 25.0.11.75758 的复现中，从远程系统触发未经认证的代码执行，并在真实环境观测到恶意 Java 类文件被直接投放到 PaperCut 安装目录（Huntress 报告：[papercut-actively-exploited](https://www.huntress.com/blog/papercut-actively-exploited)）。

> 该漏洞单独利用需要"配置操纵"前提（CVSS 4.0 前置条件 PR:H），但与 `CVE-2026-81578`（未认证配置篡改）组合后即成为预认证 RCE，实际威胁显著高于单条评分。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 PaperCut 应用服务器 Web 接口 |
| 身份认证 | 无需（链式）/ 需高权限（单漏洞） | 单漏洞需能操纵配置参数；与 `CVE-2026-81578` 链式组合后无需认证 |
| 用户交互 | 不需要 | — |
| 特定配置 | 否 | 需将恶意类置于应用 classpath（利用者自备载荷） |
| 利用复杂度 | 低 | 驱动类名可控且无白名单校验 |

**技术原理：**

PaperCut 数据库连接工具在建立数据库连接时，依据配置中的驱动名称（driver name）调用反射机制实例化驱动类。由于未对驱动名称进行白名单/允许列表校验，攻击者可将驱动名指向任意驻留于应用 classpath 的类。攻击者先投放恶意 Java 类（.class 文件）到 PaperCut 安装目录（classpath 内），再通过配置篡改将驱动名指向该恶意类，触发类实例化/加载，恶意字节码即以 PaperCut 服务进程权限执行。Huntress 观测到的载荷具备执行命令、将结果写入临时文件、随后删除输出文件与服务器日志的清理能力。

**核心利用链：**

```text
攻击者（未认证）
  ├─ CVE-2026-81578：未认证修改配置（数据库驱动名 → 恶意类名）
  └─ 投放恶意 .class 至 PaperCut 安装目录（classpath）
      └─ 触发数据库连接（动态加载恶意驱动类）── CVE-2026-82078
          └─ 恶意字节码以服务进程权限执行（RCE）
              └─ 写入输出 → 删除 .out 与 server.log 掩盖痕迹
```

#### 3.4.2 漏洞摘要

该漏洞位于运行 UniFi OS 的设备与实例。据 [NVD 描述](https://nvd.nist.gov/vuln/detail/CVE-2026-77550)与 [Ubiquiti SAB-067 公告](https://community.ui.com/releases/Security-Advisory-Bulletin-067/fc4a3488-7c43-4628-8bab-f715e96dbfc9)：对 CRLF 序列（回车/换行）的中和处理不当（CWE-93）可被网络访问者利用，绕过 UniFi OS 设备或实例的认证。影响范围包括 UniFi OS Server、Cloud Keys、网络录像机（NVR）、Dream Machine、云网关（Cloud Gateways）、Dream Router、Dream Wall、企业防火墙核心（Enterprise Firewall Core）及其他设备；UniFi Express（≤ 4.0.16）同样受影响。CVSS 3.1 评分 10.0（未认证、网络可达、影响范围扩展）。攻击者成功绕过认证后即可获得设备管理权限，配置网络、查看监控、获取凭据。

#### 3.4.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 UniFi OS 管理接口（8443 等） |
| 身份认证 | 无需 | 未认证即可利用 |
| 用户交互 | 不需要 | — |
| 特定配置 | 否 | 默认配置即可触发 |
| 利用复杂度 | 低 | 构造含 CRLF 的请求即可触发 |

**技术原理：**

UniFi OS 的认证/会话处理组件在解析 HTTP 请求时未对 CRLF（`\r\n`）序列进行正确中和，攻击者可在请求头或请求行中注入 CRLF 字符，操纵会话标识、请求头拆分（header splitting）或日志注入，从而绕过认证校验（如伪造会话/管理上下文）。成功绕过认证后，攻击者以管理身份访问设备控制接口。

**核心利用链：**

```text
攻击者（未认证，网络可达 UniFi OS 管理接口）
  └─ 构造携带 CRLF 序列的请求（头/行注入）
      └─ 触发 CWE-93 CRLF 中和缺陷
          └─ 绕过认证校验
              └─ 以管理权限访问设备/实例
                  └─ 配置网络、读取凭据、控制监控等
```

**核心利用链：**

```text

      └─ 触发输入校验缺陷（CWE-20）
          └─ 命令注入在宿主机执行
              └─ 获取语音系统/宿主机完全控制权
```

#### 3.6.2 漏洞摘要

该漏洞位于 cPanel & WebHost Manager（WHM）的域名停放（domain parking）与 addon 域名功能。据 [The Hacker News 报道](https://thehackernews.com/2026/08/critical-cpanel-flaw-could-let-one.html)与 [cPanel 官方安全公告](https://support.cpanel.net/hc/en-us/articles/)：任意已认证托管账号（其账号被允许添加停放/addon 域名）可通过该功能在服务器文件系统任意位置创建文件，"成功利用可导致以 root 用户执行代码，攻击者获得服务器完全控制权"（cPanel 客户通知原文）。漏洞影响全部受支持版本的 cPanel & WHM（厂商公告同时列明 WP Squared 修复版本，未提及 DNSOnly）。cPanel 于 2026-08-27 发布安全公告并推送修复版本，配置每日自动更新的服务器会自动接收补丁构建。该漏洞与 07 月修复的 cPanel 系列提权漏洞（`CVE-2026-58048`/`CVE-2026-58047`，08-04 期已收录）属同类"托管租户→root"问题，是 cPanel 连续第三个月修复同类缺陷。

> 该漏洞为"已认证低权限账号 → root"型提权，单看前置条件为认证用户，但在共享/转售主机场景中"注册账号即可获得"，实际威胁接近未认证；叠加"任意文件写"能力，可覆盖服务器上所有租户数据。

#### 3.6.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需可达 cPanel 服务（2083/2087/2086/2082 等端口） |
| 身份认证 | 已认证托管账号 | 任意已认证账号（允许添加停放/addon 域名）；共享主机场景门槛极低 |
| 用户交互 | 不需要 | — |
| 特定配置 | 是 | 账号须具有添加停放/addon 域名的权限（共享主机默认具备） |
| 利用复杂度 | 低 | 通过正常功能入口触发 |

**技术原理：**

cPanel 的域名停放与 addon 域名功能在创建/管理停放域名时，对用户可控的文件路径（如域名/目录相关参数）缺乏充分的路径校验与净化，导致已认证账号可将文件写入文件系统任意位置（任意文件写）。结合可写路径落在可执行上下文（如 cron、启动脚本、Web 可执行目录或系统目录）后，即可触发以 root 权限执行的代码（cPanel 以 root 运行系统级操作）。厂商公告确认"成功利用可导致以 root 用户执行代码，攻击者获得服务器完全控制权"。

**核心利用链：**

```text
攻击者（任意已认证托管账号，共享/转售主机）
  └─ 通过 cPanel 域名停放/addon 域名功能提交恶意路径
      └─ 触发路径校验缺失（任意文件写）
          └─ 在服务器任意位置写入文件（落入可执行上下文）
              └─ 触发以 root 执行代码
                  └─ 完全接管服务器（所有租户数据/库/邮件/凭据）
```

**漏洞描述：**  
[Security Affairs 08-30 报道](https://securityaffairs.com/198143/cyber-crime/extortion-group-fulcrumsec-claims-86gb-manchester-airports-group-data-theft.html)：勒索/敲诈组织 FulcrumSec 声称窃取了曼彻斯特机场集团（MAG，旗下含曼彻斯特、伦敦斯坦斯特德、东米德兰三座机场）约 86GB 数据。MAG 于 08-27 披露数据泄露事件，官方口径称影响约 870 万客户（多为邮箱地址），涉及停车、休息室、Fast Track 预订与机场 WiFi 注册数据（邮箱、电话、车牌、邮编）。FulcrumSec 则向 [BleepingComputer](https://www.bleepingcomputer.com/news/security/fulcrumsec-claims-manchester-airports-hack-theft-of-86-gb-of-data/) 展示了更详细的样本：含 21.5GB 曼彻斯特客户数据导出（个人标识、历史预订、营销信息），并称窃取的数据含近 20 万条 2026 年剩余时间的出行预订记录（日期、时间、预订信息关联个人身份信息）。FulcrumSec 声称的入侵途径尤其值得警惕：在网站客户端 JavaScript 中发现了机场专用的 Iterable API 凭据——该代码运行于用户浏览器，任何用开发者工具查看网站的人都能看到。若该说法属实，攻击者无需高深技术，仅凭暴露在客户端代码中的 API 凭据即可入侵。BleepingComputer 已对部分样本与真实旅客购买记录进行交叉验证（Fast Track 预订、到达时间、航站楼、支付金额匹配）。国内"安全圈"公众号亦于 08-30 以"英国三机场客户数据遭窃！邮箱电话车牌全泄露"为题转述（[原文链接](https://mp.weixin.qq.com/s?__biz=MzIzMzE4NDU1OQ==&mid=2652078524&idx=3&sn=6b700d549588250c08bb92ec6a50e2e7)）。该事件为数据泄露/配置缺陷类动态（客户端 API 凭据暴露），暂无 CVE。

**修复建议：**  
- 关注 MAG 官方后续披露与 FulcrumSec 数据发布情况；受影响的旅客建议留意钓鱼邮件与身份冒用风险；
- 事件根因为**客户端 JavaScript 中暴露第三方（Iterable）API 凭据**：任何将第三方 API 凭据用于前端调用的组织均应审计密钥轮换策略，将凭据置于服务端代理后透传；
- 安全团队应核查自身站点是否存在前端硬编码 API 密钥/令牌，并启用密钥泄露检测与轮换机制。
