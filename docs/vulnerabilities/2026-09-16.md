### 1.3 今日重点关注

1. **`CVE-2026-51990`：搜狗输入法 Windows 版"一键 RCE"（国内 CERT 渠道首次明确 CVE 编号）**  
   奇安信 CERT 于 2026-09-15 发布《【已复现】搜狗输入法 Windows 版远程代码执行漏洞（CVE-2026-51990）安全风险通告》，微步在线研究响应中心亦于前一日发布"已复现 | 搜狗输入法 1-click RCE"。据公开归因资料，该漏洞由 `sgbiz:` 自定义协议处理器参数校验缺失、URL 未受限跳转与**内嵌 Chromium 80 陈旧引擎沙箱关闭**三处弱点叠加构成，受害者**单击一次特制链接**即可在 Windows 终端执行任意代码；存在中国关联行为体 **UNC3569** 借此投放 **GRAYRABBIT** 后门的公开归因，目标集中于政府与国防部门。腾讯已于 2026-04-21 推送 `16.3.0.3498` 修复，但内嵌浏览器内核仍未更新，**残余风险仍在**。**建议：终端侧统一核查输入法版本并升级至 `16.3.0.3498+`，对 `sgbiz:` 协议处理器与 `biz_helper.exe` 实施强制收敛。**（详见 3.1）

2. **`CVE-2026-85046` + `CVE-2026-87491` + `CVE-2026-85880`：Chrome / Windows 零日利用链被两个中国关联组织"同码复用"**  
   Volexity 披露：攻击者自 2026-09-01 起以美国某大学网站 XSS 为跳板投放钓鱼链接，串接 Chrome V8 类型混淆 `CVE-2026-85046` → V8 越界写 `CVE-2026-87491`（沙箱逃逸）→ Windows ALPC 堆溢出 `CVE-2026-85880`（渲染进程越狱），最终分别下发 **GRIMWEDGE**（JScript 后门，内存驻留于 `msiexec.exe`）与 **SUPERSTOMP + LONGTALE**（伪装成 Gemini 助手的恶意 Chrome 扩展，记录按键、窃取 Cookie 与会话令牌）。核心三漏洞**均已在 CISA KEV 目录中**，整改截止分别为 2026-09-18（`85046`）与 2026-09-23（`87491`）、2026-09-22（`85880`），且 `CVE-2026-85046` 存在多个公开 PoC 仓库。（详见 3.2）

3. **`CVE-2026-76461`：Cisco Secure Email Gateway 邮件解析 SQL 注入（第 46 期已详录，本期官方侧信息补全）**  
   本期窗口内 Security Affairs 两篇报道确认 **CISA 已将 `CVE-2026-76461` 正式纳入 KEV 目录**（官方 `dateAdded=2026-09-14`），**整改截止 2026-09-17（即明日）**；Cisco 同步给出可落地的日志排查命令（在 `mail_logs` 中检索 `COPY.*TO PROGRAM` 特征）。该漏洞可被**未认证远程攻击者以单封邮件**触发，从而以 **root 权限**执行任意命令。**凡部署 Cisco Secure Email Gateway（含物理与虚拟）的组织须在今日内完成升级至 `16.5.0-780`（或按版本对应 `15.5.5-014`／`16.0.4-302`）并回溯日志。**（详见 3.3）

### 1.4 综合研判

今日态势呈现"**在野 KEV 集中到期 + 终端侧弱点被系统性武器化**"的双重压力，且**时间维度比漏洞数量更值得警惕**。一方面，`CVE-2026-76461` 的 KEV 整改期限落在**明日（2026-09-17）**，`CVE-2026-85046` 落在 **2026-09-18**，两条期限紧邻，且二者分别位于"邮件安全网关"与"浏览器 + Windows 终端"两个绕不开的资产面——邮件网关是互联网可达且承载身份凭据的边界资产，一次性配置疏漏即可导致 root 级沦陷；浏览器则是全员终端，其"Chromium 源码已修但 Chrome 稳定版未发"的 **patch-gap** 特征已被两个独立 APT 组织在两周内同码复用，说明补丁"上游已修"不等于"用户已获修复"。另一方面，本期三条**无 CVE 编号**的披露勾勒出另一条更隐蔽的风险线：LiteSpeed Enterprise 使**单个低权限共享主机租户**即可绕过 CageFS 拿到整机 root（本月第三次同类事件）、Telegram Desktop 让**两年前的一条消息**在导出 HTML 被打开时才引爆存储型 XSS、日本数字厅则用**"补丁早已存在但设备未升级 + 运维账号被冒用"**的方式泄露 24.6 万条政府雇员个人信息。三者共同指向同一结论：**当前造成实际损失的主因已从"未知漏洞"转向"已知漏洞未闭环 + 终端与共享环境隔离边界失效"**。此外，搜狗输入法的 CVE 编号在国内 CERT 渠道落地，把一个此前仅存在于研究方标题中的线索转变为可核查的编号，但其"是否入 KEV""是否已有公开 PoC"在官方数据库中均未获证实，提示对中文聚合类来源需保持"编号可信、状态待核"的分层判断。本地为公开文档站、无内部资产台账，本章风险评估以公开信息与通用资产暴露面为基准。

!!! danger "研判结论：高风险"
    今日为**高风险**态势：**Cisco Secure Email Gateway `CVE-2026-76461` 的 KEV 整改期限为 2026-09-17（明日）**，Chrome `CVE-2026-85046` 为 2026-09-18，窗口极窄且均已确认在野利用。处置要求：① 今日内完成 Cisco 邮件安全网关（含 Secure Email and Web Manager）升级与 `mail_logs` 回溯，确认是否命中 `COPY.*TO PROGRAM` 特征；② 24 小时内将 Chrome 升级至 **152.0.7977.82/.83 以上**（并确认已跨越 `CVE-2026-87491` 所需的 153.0.8010.36 线）、完成 Windows 2026-09 累积更新闭环，并在终端侧排查伪装成 Gemini 助手的可疑浏览器扩展与 `msiexec.exe` 异常加载 JScript 的行为；③ 3 个工作日内核查搜狗输入法版本（≥ `16.3.0.3498`）并收敛 `sgbiz:` 协议处理器，同时对共享主机环境升级 LiteSpeed Enterprise 至 `6.3.7`；④ 建立"补丁已存在但未升级"的存量资产专项清单，优先覆盖邮件网关、VPN、共享主机与终端浏览器四类资产。

### 3.1 `CVE-2026-51990` — 搜狗输入法 Windows 版一键远程代码执行

!!! danger "严重漏洞"
    该漏洞影响 Windows 版搜狗输入法（< `16.3.0.3498`）。受害者仅需在浏览器中**单击一次**特制链接，即可触发其注册的 `sgbiz:` 协议处理器并借内嵌的 Chromium 80 陈旧引擎（沙箱关闭、同源策略禁用）执行任意代码，形成"单次交互即可远程执行代码"的高危利用面；公开归因指向中国关联行为体 **UNC3569** 借此投放 **GRAYRABBIT** 后门，目标集中于政府与国防部门。

#### 3.1.1 基本信息

| 字段 | 内容 |

#### 3.1.2 漏洞摘要

该漏洞影响腾讯搜狗输入法的 Windows 版本。据公开归因资料，攻击链由三处弱点叠加构成：其一，输入法注册的 `sgbiz:` 自定义协议处理器未对命令行参数做充分校验，导致可在调用其辅助程序（`biz_helper.exe`）时注入参数；其二，处理器对可打开的 URL 未作来源与目标限制，可被引导至攻击者控制的页面；其三，也是危害放大器——其内嵌的 Chromium 80 引擎长期未升级，**沙箱被关闭且同源策略被禁用**，同时保留了 2021 年的历史 V8 漏洞 `CVE-2021-38003`。三者串联后，受害者**只需单击一次特制链接**，即可在本地以用户上下文执行任意代码。

> 由于该进程通常运行于交互式用户会话（多为管理员或具备高权限的办公终端），成功利用后可读取本机文件、导出浏览器凭据并进一步投放后门。公开归因称中国关联行为体 UNC3569 借此投放 **GRAYRABBIT** 后门（具备远程命令 Shell、双向文件传输与反射加载模块能力，C2 使用 443 端口上的 RC4 混淆原始 TCP），攻击目标集中于政府与国防部门。

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 否（无需目标可被外网直连） | 属**客户端侧**攻击：由受害者访问攻击者页面或点击链接触发，目标终端无需开放端口 |
| 身份认证 | 无需 | 攻击者不需要在目标系统上拥有任何账号 |
| 用户交互 | 需要 | 需要受害者**单击一次特制链接**（一键利用），不涉及文件下载确认等其他交互 |
| 特定配置 | 是 | 依赖目标终端已安装受影响版本搜狗输入法，且 `sgbiz:` 协议处理器保持默认注册状态 |
| 利用复杂度 | 低 | 公开归因称利用链已被工具化，且内嵌引擎沙箱关闭、同源策略禁用，显著降低了利用门槛 |

**技术原理：**

问题的根本原因是**信任边界错置**：输入法作为本地高权限宿主，却允许源自不可信网页的 URI 调用其自定义协议处理器，且在参数传递、URL 目标与内嵌浏览器安全策略三处均缺少校验与加固。具体表现为输入校验缺失（命令行参数可被拼接控制）、访问控制失当（协议处理器未限制调用来源与目标域）、以及**使用了生命周期已终止且安全配置被削弱的第三方浏览器引擎组件**——后者把"一次点击"直接降格为"一次代码执行"。

**核心利用链：**

```text
攻击者
  └─ 投放特制链接（钓鱼邮件 / 即时消息 / 网页跳转）
      └─ 受害者单击，操作系统按注册表调用 sgbiz: 协议处理器
          └─ 处理器未校验命令行参数与目标 URL（可注入、可任意跳转）
              └─ 内嵌 Chromium 80 引擎加载攻击者页面（沙箱关闭、同源策略禁用）
                  └─ 复用历史 V8 缺陷实现代码执行
                      └─ 在用户上下文投递 GRAYRABBIT 后门（443 端口 RC4 混淆 C2）
```

#### 3.1.11 风险影响

漏洞成功利用后，可能导致：

- 未经授权在终端用户上下文执行任意代码；
- 远程执行任意系统命令（经后门通道下发）；
- 获取应用、系统或数据库权限（受终端用户权限决定，管理员终端影响更大）；
- 泄露账号、密钥、配置文件及业务数据（浏览器凭据、会话令牌、本地文档）；
- 篡改终端配置、浏览器扩展与业务数据；
- 植入后门或恶意程序（GRAYRABBIT 具备远程 Shell、文件传输与模块反射加载能力）；
- 横向移动至其他服务器或业务系统（借高权限用户会话凭据）；
- 被用于长期潜伏与情报窃取（目标集中于政府与国防部门）。

    判定说明：该漏洞虽无公开 PoC、KEV 状态未获官方证实，但其**利用门槛极低（单击即触发）+ 覆盖面极广（全员终端）+ 内嵌引擎沙箱已关闭且不可由用户侧修复**，一旦被武器化将直接形成终端沦陷，故按 **P1** 处置，即 **24 小时内**完成版本核查与协议处理器收敛。

#### 3.1.13 修复与缓解措施

#### 官方修复

1. 将搜狗输入法（Windows 版）升级至 `16.3.0.3498` 或更高版本；
2. 通过企业软件分发（SCCM/Intune/终端管理平台）统一推送升级，避免依赖用户自助更新；
3. 升级前完成终端配置与业务兼容性验证，确认输入法在办公系统、远程桌面与虚拟桌面场景下工作正常；
4. 升级后核验版本号，并**确认组策略中的 `sgbiz:` 协议处理器限制已生效**；
5. 重新执行终端软件版本巡检并留存修复证据；
6. 关注厂商是否发布进一步修复内嵌浏览器引擎（沙箱化）的版本，作为后续跟踪项。

#### 临时缓解

无法立即升级时，可采取：

- 通过组策略/注册表**禁用或收敛 `sgbiz:` 协议处理器**，阻断网页触发的调用路径；
- 使用应用控制策略限制 `biz_helper.exe` 的执行（仅允许受信任父进程或直接禁止）；
- 在终端 EDR/IPS 中增加针对浏览器拉起输入法辅助程序的行为拦截规则；
- 对高安全终端（高管、运维、财务、涉密人员）优先实施升级或直接卸载替换其他输入法；
- 在邮件网关与 Web 网关侧对含 `sgbiz:` 的链接实施阻断与告警；
- 限制普通用户的本地管理员权限，降低利用成功后的权限上限；
- 加强终端日志审计、异常外联检测与浏览器扩展审计；
- 对高风险终端实施网络访问收敛与最小权限控制。

### 3.2 `CVE-2026-85046` + `CVE-2026-87491` + `CVE-2026-85880` — Chrome / Windows 零日利用链被两个中国关联组织同码复用

#### 3.2.2 漏洞摘要

Volexity 于本期窗口内披露的完整报告显示，两个中国关联的行为体自 2026-09-01 起，对多家非政府组织（NGO）使用**同一条 Chrome / Windows 零日利用链**，并在获得代码执行后分别下发不同后门。攻击入口是一次鱼叉式钓鱼：邮件将受害者引导至**某美国大学的合法网站**，该站存在跨站脚本缺陷，攻击者借此把访问者重定向到自己控制的服务器，随后投放多阶段利用。

#### 3.2.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | 需受害者访问攻击者控制的页面（本案经合法大学站点 XSS 重定向达成） |
| 身份认证 | 无需 | 攻击者不需要目标系统账号 |
| 用户交互 | 需要 | 需受害者点击钓鱼邮件中的链接并在浏览器中打开恶意页面 |
| 特定配置 | 否 | 不依赖特殊配置，默认安装且在受影响版本区间内即可 |
| 利用复杂度 | 低（对攻击者已完成工具化的前提而言） | 链条本身复杂，但公开归因显示两个组织复用同一套已调试完成的代码，并保留 13 个 URL 参数用于测试、断点、遥测与灰度投放 |

**技术原理：**

`CVE-2026-85046` 的根因在于 V8 的内联 `Array.prototype.sort` 优化**接受了多态的元素类型反馈**（同时存在 `PACKED_SMI_ELEMENTS` 与 `PACKED_ELEMENTS`）。当比较函数中调用 `arr.fill(0)` 时，接收者 map 会由对象数组**回迁**为 SMI 数组，而排序后的 map 校验之所以通过，是因为原反馈集合中本就包含该 map；随后的回写步骤便把**对象指针写入了声明为纯 SMI 的数组**，形成类型混淆。官方修复方式是在内联排序前增加前置条件：要求反馈中所有接收者 map 共享同一 `elements_kind`。

**核心利用链：**

```text
攻击者
  └─ 鱼叉钓鱼邮件 → 合法但存在 XSS 的高校站点 → 重定向至攻击者服务器
      └─ 恶意页面加载（14 个阶段 / 13 个 URL 参数支持测试与灰度）
          ├─ CVE-2026-85046：V8 内联 sort 类型混淆 → 沙箱内任意读写
          ├─ CVE-2026-87491：V8 越界写 → 逃逸 V8 沙箱
          └─ CVE-2026-85880：Windows ALPC 堆溢出 → 逃出渲染进程、注入 Chrome 浏览器进程
              ├─ UTA0560 → GRIMWEDGE（JScript 后门，内存驻留于 msiexec.exe）
              └─ JungleBamboo → SUPERSTOMP → LONGTALE（伪装成 Gemini 助手的恶意 Chrome 扩展）
```

重点检查：

- 代理/网关日志中指向高校站点后被重定向至陌生域名的访问链；

- Chrome 配置文件的完整性校验与哈希异常（SUPERSTOMP 会剥离新式加密哈希、伪造旧式 HMAC 值）；
- 主机侧异常进程树（浏览器进程注入后拉起脚本宿主）；
- 外联行为的 TLS 指纹与目的地异常（后门与 C2 通信）；
- 用户会话中被大量读取的浏览器凭据存储与 Cookie 数据库。

#### 3.2.11 风险影响

漏洞成功利用后，可能导致：

- 未经授权在终端执行代码（浏览器进程内）；
- 逃逸浏览器沙箱并注入浏览器主进程，突破浏览器安全边界；
- 获取浏览器凭据、Cookie 与会话令牌（LONGTALE 扩展持续记录按键与截图）；
- 泄露业务数据与聊天记录、导出浏览器保存的账号密钥；
- 篡改浏览器配置、扩展与业务数据（借伪造旧式 HMAC 使篡改被视为合法）；
- 植入浏览器扩展型后门与内存驻留后门，长期潜伏；
- 横向移动至其他服务器或业务系统（借会话令牌与凭据）；
- 被国家级行为体用于针对 NGO、政府与国防领域的情报窃取。

#### 3.2.13 修复与缓解措施

#### 官方修复

1. 将 Google Chrome 升级至 `153.0.8010.36` 或更高版本（该版本同时覆盖 `CVE-2026-85046` 所需的 `152.0.7977.82` 线）；

#### 临时缓解

无法立即升级时，可采取：

- 通过组策略强制浏览器版本下限与自动更新，禁止降级；
- 启用浏览器扩展白名单（仅允许组织批准的企业扩展），阻断 LONGTALE 这类扩展落地；

- 加强 EDR 对浏览器进程注入、`msiexec.exe` 加载 JScript 与异常外联的拦截；
- 对高风险人群（NGO、政府、国防、航空航天相关岗位）实施更严格的浏览收敛策略；
- 对高敏感终端实施网络隔离或强制使用带外浏览器隔离方案；
- 加强日志审计与主机监控，保留浏览器与主机侧取证材料；
- 定期轮换浏览器凭据与会话令牌，减少凭据被窃后的影响。

#### 3.3.2 漏洞摘要

该漏洞源于邮件解析逻辑中的**输入校验不足**：攻击者通过向受影响设备发送包含恶意 SQL 语句的构造邮件，即可触发任意 SQL 语句执行，并进一步在底层操作系统上以 **root 权限**执行任意命令。受影响范围为 Cisco Secure Email Gateway 的**物理与虚拟版本，且与设备配置无关**；Cisco 明确表示**没有可用的临时规避措施**，只能通过升级修复。

> **本期新增信息：** Cisco 给出可操作的失陷排查命令——在设备 CLI 中对 `mail_logs` 检索形如 `COPY.*TO PROGRAM` 的 SQL 语句特征：`cisco-esa> grep -i "COPY.*TO PROGRAM" [IronPort Text Mail Logs]`，输出中出现任何条目即可能指示恶意活动；若设备属于集群，须逐台检查。Cisco 同时提示：由于利用成功后攻击者已获得 root 权限，**失陷证据与 IOC 可能被攻击者清除或隐藏**，因此强烈建议结合设备之外的网络日志与防火墙日志交叉核查（例如从受影响设备向外部 IP 的非预期上传、从恶意 IP 的下载）。对于 Cisco Secure Email Cloud，无 CLI 权限的管理员可能无法自行核查，Cisco 已直接联系检测到恶意活动的云客户。

| 特定配置 | 否 | Cisco 明确"与设备配置无关"，即任意配置下均可受影响 |
| 利用复杂度 | 低 | 单封邮件即可触发，且无可用临时规避措施 |

**技术原理：** 邮件解析逻辑在将邮件内容交由后端处理时，未对可进入 SQL 语句上下文的特殊元素做充分中和，导致恶意 SQL 语句被当作指令执行；由于解析组件与底层 SQLite 等数据库交互时权限较高，SQL 执行最终被放大为**以 root 权限执行系统命令**（例如通过 SQL 的文件写入/程序执行特性落地并运行命令）。这属于典型的"输入校验缺失 + 组件权限过高"叠加放大路径。

**核心利用链：**

```text
攻击者
  └─ 向受影响邮件网关投递特制邮件（SMTP，无需认证）
      └─ 邮件解析逻辑未充分校验，恶意 SQL 语句进入语句上下文
          └─ SQL 语句被执行（COPY ... TO PROGRAM 类特征）
              └─ 以 root 权限执行操作系统命令
                  └─ 取得设备控制权（证据可能被清除，需外部日志交叉验证）
```

#### 3.3.11 风险影响

漏洞成功利用后，可能导致：

- 未经授权访问邮件网关系统与业务接口；
- 以 **root 权限**远程执行任意系统命令；
- 获取设备、系统与数据库权限；
- 泄露邮件内容、账号、密钥与配置文件；
- 篡改网关配置、邮件路由与过滤策略（为后续攻击铺路）；
- 植入后门或恶意程序，并**清除或隐藏失陷证据**；
- 横向移动至其他服务器或业务系统（网关常具备对内网与身份系统的访问能力）；
- 中断邮件服务或破坏系统可用性。

#### 3.3.13 修复与缓解措施

#### 官方修复

1. 将 Cisco Secure Email Gateway（AsyncOS）升级至官方修复版本：`16.5.0-780`（官方首选）或按分支 `15.5.5-014` / `16.0.4-302`；
2. 通过设备 Web 管理界面的 `System Administration > System Upgrade > Upgrade Options` 执行在线升级；
3. 升级前完成设备配置与邮件流备份，确认集群升级顺序与业务窗口；
4. 在测试环境验证兼容性及回退方案（邮件流、过滤策略、与下游系统集成）；
5. 升级后核验版本与补丁状态，并对集群**逐台**完成核验；
6. **立即回溯 `mail_logs`（官方特征 `COPY.*TO PROGRAM`）并留存修复证据**；
7. 同步核查同批加固公告涉及的其它 CVE 是否已闭环。

#### 临时缓解

**Cisco 明确说明该漏洞没有可用的临时规避措施**，因此以下措施<u>不能替代升级，仅用于降低风险窗口</u>：

- 将管理接口（HTTP/HTTPS/SSH）限制为仅可信管理网段访问，禁止互联网直连；
- 通过上游邮件安全网关或云邮件清洗（如 Secure Email Cloud）对入向邮件做前置过滤与内容检测；
- 在防火墙、IDS/IPS 与 WAF 侧增加针对 SQL 语句特征（`COPY ... TO PROGRAM` 等）的检测与告警；
- 加强对网关设备的日志审计、主机监控与异常外联检测，并**将日志外送至独立 SIEM**（防止被攻击者清除）；
- 收紧网关设备上的账号与密钥，轮换可能已暴露的凭据；
- 对高风险设备实施网络隔离与访问收敛，并在设备之外保留独立网络侧检测能力。

| 影响产品 | Telegram Desktop（`4.15.1` 起引入缺陷，`6.9.4` 首个修复 beta，`7.0.1` 首个修复稳定版） |
| 影响版本 | 引入于 2024 年 2 月、`4.15.1`（2024 年 3 月）进入稳定版；修复前所有版本 |
| PoC状态 | 已公开（研究方称提交了完整 PoC 与视频演示） |
| 在野利用 | 未发现 |
| 修复版本 | `7.0.1`（2026-07-14 发布；更新客户端**无法修复已导出的旧 HTML 文件**） |

**漏洞描述：**  
ExPatch 研究者在 Telegram Desktop 的 HTML 导出功能中发现存储型跨站脚本：应用在 `export_output_html.cpp` 中把**内联键盘按钮文本直接写入 HTML 输出**，未调用同文件内已有的 `SerializeString()` 转义函数（该函数会对消息文本、发件人名称等做转义，却未应用于按钮文本）。因此，按钮文本中的 `<script>` 等标签在导出页面被当作真实标记解析。攻击者**无需加入目标群组**——只需一个机器人构造包含特制内联键盘的消息并被转发进目标会话，载荷即可在消息历史中潜伏数月甚至数年，待有人导出会话并在浏览器中打开该 HTML 文件时才触发：可读取导出文档中的消息、发件人、时间戳与元数据并外传至攻击者服务器，还能读取导出文件的本地路径（泄露操作系统与目录结构），甚至把页面替换为伪造的"Telegram 验证页"。该缺陷在生产环境中存在超过两年（2024 年 2 月至 2026 年 6 月修复），修复方式为对内联键盘按钮文本应用转义，并同时修补了 JavaScript `onclick` 处理器中的注入问题。

**修复建议：**  
升级 Telegram Desktop 至 `7.0.1` 以上并保持最新；**对 2026-07 之前导出的 HTML 会话文件一律视为不可信**，不要在日常浏览器中直接打开（如确需查阅，应在隔离环境或经审查后打开）；使用 Telegram 保存会话用于合规、调查或业务记录的组织应**在升级后重新生成导出**。参考：[Security Affairs 报道](https://securityaffairs.com/199076/security/telegram-desktop-flaw-could-turn-old-chat-exports-into-data-theft-traps.html)。

### 未披露编号 — 日本数字厅 GSS 平台 VPN 入侵致约 24.6 万条政府雇员信息泄露

| 字段 | 内容 |
| --- | --- |
| 风险等级 | 中危（来源称该 VPN 漏洞为"中危、且非零日"） |
| CVSS评分 | 未披露 |
| CWE编号 | 未披露 |
| 影响产品 | 未公开厂商的 VPN 网络连接设备（日本数字厅 Government Solution Service 平台） |
| 影响版本 | 未公开 |
| PoC状态 | 未发现 |
| 在野利用 | 已确认（已被实际入侵与文件访问） |
| 修复版本 | 补丁**在事发前已存在**，但因未及时升级而被利用 |

**漏洞描述：**  
日本数字厅披露，攻击者利用 GSS 平台所用 VPN 设备的一个漏洞进入该共享网络平台，冒用**一名运维保障人员的账号**大量浏览服务器文件，可能导致约 **246,000 条**政府雇员、公职人员与承包商个人信息外泄（约 23.6 万个姓名、23.1 万个邮箱、9.4 万个电话号码、约 1000 个物理地址；不含 My Number、银行账号与养老金编号）。事件于 2026-06-25 检测到异常文件访问、2026-07-09 确认入侵方式，同年 7 月 15 日通报隐私监管机构，**2026-09-11 才对外公开（距检测 78 天、距确认入侵方式 63 天）**。数字厅同日停用该运维账号并切断受影响设备的外部通信。GSS 连接 23 个日本中央部门与机构，属典型"单点失陷、影响面成倍放大"的共享基础设施。**该漏洞并非零日**——补丁在攻击发生时早已可用。

**修复建议：**  
对承载共享政务／企业服务的 VPN 与远程接入设备建立"补丁可用即必须闭环"的强制流程，并将**运维账号**纳入高优先级审计对象（强多因素认证、来源限制、会话录制与行为基线）；对长期未升级且互联网可达的边界设备优先清点与替换。参考：[Security Affairs 报道](https://securityaffairs.com/199090/security/non-zero-day-vpn-flaw-left-japan-government-shared-network-platform-exposed-246000-records-at-risk.html)、[日本数字厅公告（2026-09-11）](https://www.digital.go.jp/news/2026-0911-01)。
