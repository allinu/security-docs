### 1.3 今日重点关注

1. **供应链安全：朝鲜"蓝宝石雪"（Sapphire Sleet）操控 npm 包供应链**  
   据 [安全圈](https://mp.weixin.qq.com/s?__biz=MzIzMzE4NDU1OQ==&mid=2652078127&idx=3&sn=d19e98b1f7dd0926263b1ea3ef9675e1) 报道，朝鲜背景组织"蓝宝石雪"操控 npm 包供应链，Axios 等四款知名库沦陷。公开渠道信息核实：AWS 安全团队将 **typo-crypto、debug、chalk、axios** 四个被投毒的 npm 包归因于同一朝鲜背景组织（微软追踪代号 Sapphire Sleet），axios 事件系攻击者利用一名主要维护者泄露的 npm 账号凭据、绕过 GitHub Actions CI/CD 发布恶意版本（axios@1.14.1 / axios@0.30.4）。建议立即排查依赖树并审查 npm 发布凭据。

2. **恶意代码技术：朝鲜 npm 恶意包采用"NullReceiver"区块链 C2 隐藏手法**  
   [OpenSourceMalware 研究报告](https://opensourcemalware.com/blog/nullreceiver-dprk-c2-technique)（2026-08-02 发布）披露：DPRK 关联恶意包 `bianira-ui@1.27.0`、`fluid-type-ui@2.0.8` 将 C2 IP 直接编码在零值、零数据的以太坊转账收款地址字节中，无需智能合约与载荷字段，是对 EtherHiding 技术的改进，检测难度更高。

3. **浏览器生态：Chrome 近 3 个版本累计修复 1442 个安全漏洞**  
   据 [安全圈](https://mp.weixin.qq.com/s?__biz=MzIzMzE4NDU1OQ==&mid=2652078127&idx=2&sn=6ae0e3468281094b71a924e772335be6) 报道，谷歌 Chrome 149.x、150.x、151.x 三个主要版本共修复 1442 个安全漏洞，超过此前 23 个主要版本修复总数，建议及时升级浏览器及企业侧 WebView 组件。

### 1.4 综合研判

当日订阅源与公开情报未发现新披露的含 CVE 编号的高危/严重漏洞条目，漏洞面整体平稳；主要风险集中在**开源软件供应链投毒**方向：朝鲜背景组织同时活跃于 npm 生态（axios/debug/chalk/typo-crypto 投毒归因落地、NullReceiver 新型 C2 手法披露），受影响面覆盖大量使用 npm 的开发团队与 CI/CD 环境。综合判断为低风险，但供应链排查与凭据治理应作为当日本质安全工作的重点。

!!! danger "研判结论：低风险"
    今日无新披露高危/严重 CVE，主要风险为 npm 供应链投毒（axios 等四库 + 朝鲜 NullReceiver 恶意包）：处置要求为立即核查项目依赖树与锁文件、审计 npm 发布凭据（启用 2FA/粒度令牌），并对开源依赖实施完整性校验与来源核验。

## 安全事件：朝鲜"蓝宝石雪"（Sapphire Sleet）操控 npm 包供应链——axios 等四款库沦陷

| 字段 | 内容 |
| --- | --- |
| CVE编号 | 不适用（供应链攻击事件） |
| 风险等级 | 高危（供应链投毒，影响面广） |
| 影响产品 | 使用 npm 生态的开源项目（axios、debug、chalk、typo-crypto 的消费者） |
| PoC状态 | 不适用 |
| 在野利用 | 已确认（恶意版本已在 npm 发布并被安装） |
| 修复版本 | 不适用（见修复建议） |

**事件描述：**  
[安全圈报道](https://mp.weixin.qq.com/s?__biz=MzIzMzE4NDU1OQ==&mid=2652078127&idx=3&sn=d19e98b1f7dd0926263b1ea3ef9675e1)称朝鲜黑客组织"蓝宝石雪"操控 npm 包供应链，Axios 等四款库沦陷。公开渠道核实：Amazon（AWS）安全团队公开将 **typo-crypto、debug、chalk、axios** 四个被投毒的 npm 包归因于同一朝鲜背景组织 Sapphire Sleet（微软追踪代号），归因置信度为中等，依据为共享的 C2 基础设施与 TTP（trojanized NPM 包、post-install 钩子、代码复用）。其中 axios 事件中，攻击者利用一名主要维护者泄露的 npm 账号凭据，绕过项目正常的 GitHub Actions CI/CD 流程发布恶意版本（axios@1.14.1 / axios@0.30.4）；chalk 与 debug 的劫持事件分别在被发现约 16 个月与 10 个月后才完成归因。参考：[The Register](https://www.theregister.com/cyber-crime/2026/07/30/amazon-links-four-poisoned-npm-packages-to-one-north-korean-crew/5281120)、[The Stack](https://www.thestack.technology/amazon-north-korea-npm-attacks/)、[The Hacker News](https://thehackernews.com/2026/07/amazon-links-debug-and-chalk-npm-hijack.html)、[SC Media](https://www.scworld.com/news/amazon-attributes-axios-debug-chalk-npm-attacks-to-dprks-sapphire-sleet)。该组织长期从事加密货币盗窃、虚假招聘与针对开发者的社工攻击。

**修复/排查建议：**  
检查项目锁文件与依赖树中是否出现上述库的非官方版本；审查 CI/CD 与 npm 发布凭据（启用 2FA 与 OAuth/粒度令牌）；对存量依赖执行完整性校验（`npm ci` + lockfile 核验）。

## 恶意代码研究：NullReceiver——朝鲜 npm 恶意包以"空白转账"隐藏 C2 地址

| 字段 | 内容 |
| --- | --- |
| CVE编号 | 不适用（恶意代码研究，无 CVE） |
| 风险等级 | 中危（新型 C2 隐藏手法，检测难度高） |
| 影响产品 | npm 生态（`bianira-ui@1.27.0`、`fluid-type-ui@2.0.8`，Tailwind CSS 插件仿冒克隆） |
| PoC状态 | 不适用 |
| 在野利用 | 已确认（恶意包已发布，关联 DPRK "Contagious Interview" 活动） |
| 修复版本 | 不适用（删除恶意包依赖） |

**技术描述：**  
[OpenSourceMalware](https://opensourcemalware.com/blog/nullreceiver-dprk-c2-technique)（2026-08-02 发布）披露：DPRK 关联的 Node.js RAT 恶意包（`bianira-ui@1.27.0`、`fluid-type-ui@2.0.8`，均为合法 Tailwind CSS 插件的仿冒克隆）采用名为 **NullReceiver** 的区块链 C2 解析技术——将 C2 IP 直接编码在零值、零数据的以太坊转账"收款地址"字节中，恶意代码通过查询攻击者钱包最近一笔出账交易的收款地址解码出 C2 IP，无智能合约、无载荷字段。相比 EtherHiding：无固定目标地址（每次查询均为全新一次性地址）、无可指纹化字段、交易成本最低，常规基于 EtherHiding 的检测难以覆盖；弱点为发送方钱包在战役内复用，一旦识别即可持续监控。

**IOC：**
| 类型 | IOC | 说明 |
| --- | --- | --- |
| npm 包 | `bianira-ui@1.27.0` | 恶意包（仿冒 Tailwind CSS 插件） |
| npm 包 | `fluid-type-ui@2.0.8` | 恶意包（仿冒 Tailwind CSS 插件） |
| ETH 地址 | `0xa322e5f3d311d3080e6f0121063e9adc2490ef1a` | 攻击者以太坊钱包 |
| ETH 地址 | `0xa658863ea658863e68656c6c6f6970626f742121` | NullReceiver 编码收款地址（含 C2 信息） |
| IP | `166.88.134.62`（443/80） | C2 基础设施 |

**排查建议：**  
检查项目依赖树是否含上述恶意包；EDR/网关监控对 `166.88.134.62` 的外联行为；关注 DPRK "Contagious Interview" 活动攻击手法（虚假招聘、仿冒插件）。

# 五、当日处置建议

1. 对已在野利用、已纳入CISA KEV或存在成熟PoC的漏洞立即开展资产排查（当日无新增条目，此项按存量台账执行）；
2. 优先核查互联网暴露的VPN、网关、安全设备、中间件和管理平台；
3. 无法立即升级的系统应采取断网、访问控制、接口禁用或WAF拦截措施；
4. 对疑似遭受攻击的系统保留日志、流量、进程、文件及内存证据；
5. 对发现异常的主机开展WebShell、恶意进程、异常账号及横向移动排查；
6. 完成修复后进行复测，并更新资产台账和漏洞处置记录；
7. **针对 npm 供应链投毒**：全量核验项目 lockfile 与依赖树（重点：axios/debug/chalk/typo-crypto 及其传递依赖），审计 npm 发布凭据与 CI/CD 流水线，启用 2FA/粒度令牌，禁用已废弃账号；
8. **针对 NullReceiver 恶意包**：排查 `bianira-ui`、`fluid-type-ui` 依赖，监控对 `166.88.134.62` 的外联，向团队宣贯仿冒插件与虚假招聘攻击手法。
