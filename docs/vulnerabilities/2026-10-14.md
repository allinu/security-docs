### 1.3 今日重点关注

1. **`CVE-2026-104935`：Ivanti Connect Secure 认证绕过已在野利用（KEV，EPSS 86.8%，Nuclei 已覆盖）**  
   ICS 25.1.3.0 之前存在欺骗型认证绕过（`CWE-290`），**未认证远程攻击者可执行任意命令**；22.7R2.14 及更早版本不受影响。该条目 2026-10-13 被 CISA 收录进 KEV（期限 10-16），**EPSS 达 86.8%**，且 Nuclei 已有可用模板——三者同时成立意味着“确认在野 + 可批量验证”。Ivanti 系列设备是近三年被反复利用的边界目标（VPN 网关），一旦存在认证绕过，攻击者可直接进入内网并部署后门。**这是本期唯一的 P0 条目。**

2. **`CVE-2026-97229`：GitLab CE/EE 未认证 RCE（CVSS 10.0，已出现 PoC 仓库）**  
   19.2 <19.2.8、19.3 <19.3.5、19.4 <19.4.2 存在**未认证远程代码执行**：因正则校验不足，攻击者可通过 CI/CD 配置中特制的正则表达式在 GitLab 服务器上执行任意代码（`CWE-190` 整数溢出）。GitLab 承载源码与 CI 凭据，被拿下等于**整条软件供应链失守**——攻击者可篡改构建产物、窃取部署密钥。GitHub 上已检出多个 PoC 仓库，EPSS 约 18.4%，属“正在爬升”的典型曲线。

3. **`CVE-2026-103849`：Adobe Commerce 模板引擎注入（10.0）与 AEM 授权错误（10.0）同日披露**  
   Adobe Commerce 存在模板引擎特殊元素未中和（`CWE-1336`），**可导致任意代码执行且无需用户交互，范围变更**，CVSS 10.0；同批 Adobe Experience Manager 三条 `CWE-863` 不正确授权亦为 10.0（`CVE-2026-48382`／`48383`／`90532`）。Commerce 是电商核心系统，AEM 常用于对外门户，**两者都直接暴露业务与支付链路**。Commerce 条目已出现公开研究仓库（`dinosn/cve-2026-103849-blockstrap-lab`）。

4. **`CVE-2026-105016`：微软 10 月补丁星期二：1384 条中 60 条严重，QUIC/Outlook/打印驱动为重点**  
   微软本批条目以“堆溢出 + UAF + 未授权指针解引用”为主，典型代表：`CVE-2026-105016`（Microsoft QUIC 堆溢出，9.8，未认证远程代码执行）、`CVE-2026-100219`（QUIC UAF，9.8）、`CVE-2026-70242`／`70291`（Outlook 堆溢出，9.8）、`CVE-2026-70147`／`70153`（PostScript 打印驱动堆溢出，9.8）、`CVE-2026-100202`（Windows 消息队列 UAF，9.8）、`CVE-2026-70096`（Rich Text Edit 控件堆溢出）。**QUIC 协议栈的未认证 RCE 应作为本批最高优先级**——它在 HTTP/3、SMB over QUIC 与各类云边通信中广泛启用。

### 1.4 综合研判

本期 2307 条，严重 157 条（6.8%）、高危 1354 条（58.7%），量级为本轮回溯期最高。结构上有三个必须分开处理的部分。**第一部分是“确定性在野威胁”**：Ivanti Connect Secure `CVE-2026-104935` 同时满足 KEV 收录、EPSS 86.8%、Nuclei 模板可用三项条件，且 Ivanti 网关历来是 APT 的重点目标（历史上多次出现认证绕过被用于植入后门），因此本期处置必须以它为第一优先，且不能只打补丁——**必须做完整性核查**（Ivanti 设备被攻陷后常需整机重置而非仅升级）。**第二部分是“满分漏洞群”**：GitLab（10.0，未认证 RCE，已有 PoC）、Adobe Commerce（10.0，模板注入）、AEM 三条（10.0，授权错误）、Dockhand（10.0，静态资源后缀绕过认证）、Podman（10.0，镜像注解可降级沙箱约束）、SAP Cloud SDK for Python（10.0，OAuth2 SSRF 致客户端凭据外泄）、WMS MobileServer（10.0，中间件在非 GET/HEAD 方法上完全跳过认证）、NVIDIA AIStore（10.0，K8s PodSpec legacy 初始化）、ProPhoenix Law RMS（`CVE-2024-34323`，历史编号但本期才入 NVD，IDOR 10.0）。这些编号的 10.0 多数来自“范围变更（S:C）”与“无需交互”，**实际利用门槛差异极大**，需按可达性排序而非按分数排序。**第三部分是“批量维护性条目”**：微软 1384 条中大量为同类内存破坏的不同组件变体，适合以“月度补丁基线”方式统一处置，不必逐条研判；但其中 QUIC 协议栈（`CVE-2026-105016`／`CVE-2026-100219`）与打印驱动（`CVE-2026-70147`／`70153`）因“未认证 + 网络可达”应单独提出。KEV 侧本期新增 4 条（AhsayCBS 两条、Cisco Secure Email Gateway、Palo Alto PAN-OS），期限 10-17，均为 3 天窗口，叠加前一期 Ivanti 与 Windows 两条（期限 10-16），**本期同时存在 6 条 3 天期限的硬约束**。

#### 3.1.2 漏洞摘要

Ivanti Connect Secure（ICS）25.1.3.0 之前版本存在**欺骗型认证绕过**（`CWE-290`），远程未认证攻击者可借此执行任意命令；官方明确 22.7R2.14 及更早版本不受影响，说明缺陷由较新的代码路径引入。该编号于 2026-10-13 被 CISA 收录进 KEV（处置期限 2026-10-16），**EPSS 达 86.8%（99.7 百分位）**，是本轮回溯期内唯一超过 50% 的条目；Nuclei 官方模板库已收录对应检测模板，可直接用于资产自查。Ivanti 网关是近年被反复利用的边界设备，历史上多次出现“认证绕过 → 植入后门 → 长期驻留”的完整攻击链，且**部分案例中攻击者在设备上留下的持久化机制不会因升级而消失**，因此处置必须包含完整性核查与必要时的整机重置。CVSS 8.6（NVD 侧），但结合在野利用与设备位置，实际风险等级应上调。

> 原文摘要（NVD）：Authentication bypass by spoofing in ICS before version 25.1.3.0 allows a remote unauthenticated attacker to execute arbitrary commands. This does not impact ICS version 22.7R2.14 or prior.

#### 3.1.5 利用条件与技术原理

| 条件 | 状态 | 说明 |
| --- | --- | --- |
| 网络可达 | 是 | ICS 管理面与用户认证面（HTTPS）可达 |
| 身份认证 | 无需 | 无需任何凭据即可触发 |
| 用户交互 | 不需要 | 无需受害者交互 |
| 特定配置 | 否 | 默认部署即受影响；22.7R2.14 及更早版本不受影响 |
| 利用复杂度 | 低 | 低（未认证、Nuclei 可验证、EPSS 86.8%） |

**技术原理：**

`CWE-290`（使用欺骗绕过认证）通常源于认证判断依赖了可被外部构造的“标识”而非密码学证明，例如信任某个头字段、序列化令牌、或设备自身的客户端标识。攻击者通过伪造该标识，使服务端认为请求已完成认证。在 VPN 网关场景下，这类缺陷往往出现在“会话恢复”“设备指纹校验”“SSO 断言解析”等路径上；一旦绕过成功，攻击者即获得网关的管理/策略执行上下文，可执行命令、修改访问策略、读取已建立会话。

**核心利用链：**

```text
攻击者
  └─ 定位暴露的 connect_secure（ivanti）
      └─ 直接访问受保护接口或伪造身份
          └─ 触发 CWE-290 对应处理逻辑
              └─ 绕过认证获得未授权能力
                  └─ 横向利用或持久化（视环境）
```

## 五、当日处置建议

1. **Ivanti 按“可能已失陷”处置，而非仅打补丁**：EPSS 86.8% + KEV 收录意味着已存在实际利用。升级前先跑完整性检查工具，升级后轮换全部凭据与证书，并回溯设备日志寻找后门痕迹；对曾暴露公网的实例，考虑整机重置。
2. **GitLab 用确切补丁版本闭环**：19.2.8 / 19.3.5 / 19.4.2 三条分支各不同，仅升大版本无效。升级后必须轮换 Runner 令牌与 CI 变量中的云凭据——PoC 已公开，凭据可能已被读取。
3. **微软批次按“协议栈优先”排序**：1384 条不必逐条研判，但 QUIC（`CVE-2026-105016`／`100219`）与打印驱动（`CVE-2026-70147`／`70153`）因未认证网络可达应提前；其余按月度补丁基线统一推进。
4. **Adobe 产品线合并处置**：Commerce（10.0 模板注入）与 AEM（三条 10.0 授权错误）同批披露，建议由同一责任人统一升级，并同步审计二开模板代码——**官方补丁不能修复自研的模板拼接**。
5. **容器与编排侧注意“绕过约束”类漏洞**：Podman 允许镜像注解覆盖 `--cap-drop=ALL` 等创建限制，本质是“不可信镜像可降低沙箱强度”。建议对镜像注解做准入校验，并在准入控制器中禁止 checkpoint 相关注解。
6. **6 条 3 天期限的 KEV 项需统一跟踪**：AhsayCBS×2、Cisco SEG、PAN-OS（期限 10-17）与 Ivanti、Windows（期限 10-16）应合并为一张冲刺清单，避免分散在不同责任人口中丢失。
